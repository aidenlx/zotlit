# Reader Surface State is one vanilla store per PDF view

The Mark Popup's renderer is superseded by [ADR 0065](0065-the-mark-popup-is-one-preact-root-on-obsidians-popover.md): it is one Preact root that the Mark Popup Host renders from this store. The store stays vanilla, and the Creation Toolbar stays vanilla DOM.

The zustand store is superseded by the amendment "The Reader Surface Model" below: the state is a writable Effect atom, and each renderer watches a derived atom of it. The rest of this record stands.

The surfaces ZotLit puts inside Obsidian's PDF reader draw from one Reader Surface State per bound PDF view: a zustand vanilla store with `subscribeWithSelector`, created by the binding and disposed with it. It holds plain data: the armed tool, mark visibility, every tool's colour, the Editing Capability, and the clock a cooldown is read against. The renderers stay vanilla DOM on Obsidian's primitives, and [ADR 0042](0042-the-surfaces-inside-the-pdf-reader-are-vanilla-dom-on-obsidians-popover.md) stays in force: the store is state, not a rendering framework, and no Preact root enters the reader.

A press on a Creation Toolbar button moved focus into the PDF view, the focus refresh probed Zotero, and the probe announced a capability change. The Creation Toolbar, Mark Creation, Mark Selection, and the binding each heard that announcement on their own subscription, and each redrew in full. The node under the pointer was gone before the pointer came up, so the click never fired.

## Considered Options

- **Guards at each subscriber** (rejected): each of the three modules compares what it heard against what it last drew. The comparison is written three times, and the next signal adds a fourth.
- **A Preact root with signals or a store hook** (rejected): the diff it brings is the fix, but it reverses ADR 0042 for five flat controls and a popup row, and it brings a component tree into Obsidian's toolbar.
- **One vanilla store per view, with selectors and structural equality** (chosen): the annot-view and note-preview stores already use this shape. A selector composes the existing model functions, a structural equality decides whether the model changed, and a renderer draws only on a real change.

## Consequences

- The binding is the one adapter from external signals to state. It hears `capability-changed` once, reads the Attachment's capability, and ingests it with the current instant. A capability with the same meaning — the same `capabilityReason` and, for a cooldown, the same deadline — keeps the held object, so no subscriber fires.
- Reducers are exported free functions that call `setState`: arm a tool, set a tool colour (which also writes the settings-backed tool colour store), toggle marks, ingest a capability, tick the clock. Selectors are exported pure functions over the state.
- The Creation Toolbar subscribes to its selector with a structural equality over its flat control records. Its renderer builds its nodes once and patches icon, tooltip, colour, pressed state, and disabled state in place, so a real change during a press still lands the click. A press reads the disabled gate from the last model drawn.
- The capability affordance subscribes to its own selector. The binding's cooldown interval runs only while the capability is a cooldown, and each tick re-reads the capability, because a cooldown lapses without an announcement. The toolbar reads its copy against the instant the capability was ingested, so the tick moves the affordance alone.
- Mark Creation and Mark Selection subscribe to the capability slice with the capability equality, and refresh their popups on a real change only. A comment being typed survives an announcement that changed nothing.
- The popup inputs keyed to the selected Annotation, the floating-surface union, and the repository's selection-keyed events stay outside the store for now.

## Amendment: the floating surface, the mirrors, and one popup host

The Reader Surface State now also holds the floating surface as one discriminated union: none, a selected Annotation Mark (its key, the stack under the press point with its index, the quiet flag a Mark Landing sets, and whether the comment editor is open), or a captured text selection (the placed selection, its anchor as a page fraction, whether the comment sheet is open, and whether a create is in flight). Only one floating surface can stand, because the type holds one. It also mirrors the Attachment's Annotation records and, by Annotation key, the mutation states and comment drafts the Mark Popup reads. The binding writes the records on every refresh and ingests `mutation-changed`, `comment-draft-changed`, `comment-draft-hidden`, and `annotation-deleted`, as it ingests the capability. The reducers normalise in the same update: a selected Annotation the records no longer hold stands down, and a draft that is hidden or turns into a Write Conflict closes its editor. One Mark Popup Host owns the single Mark Popup and opens, moves, and closes it from the union alone; Mark Selection and Mark Creation keep their gestures, rows, actions, and writes, and give the host an anchor reader and a row renderer. A change of variant kind, selected key, or commenting rebuilds the row; every other change refreshes it in place, so the comment editor keeps its caret. The anchors stay geometry that the owners read from the page when the host asks; they are not state. This replaces the last two consequences above: the popups refresh through the host rather than through their own capability subscriptions, and the union, the mirrors, and the selection-keyed events are in the store. Each refresh also takes the mutation state and the comment draft every record already holds, because those can stand before the view hears them announced. When an anchor reads `null`, a captured selection is cleared with its popup, and a selected Annotation Mark keeps its selection while its popup hides. The host's `contains` answers the owners' test of whether a press landed inside the popup. ADR 0042 stays in force.

## Amendment: the Live Stroke and the Pending Strokes

The Reader Surface State also holds the Live Stroke (its page, its smoothed path, its width, and its colour, published once per animation frame) and the Pending Strokes (one entry per ink create in flight, with its rounded paths). These are PDF-space model data that the gesture produced, not client-space anchors, so the rule that anchors stay out of the store still holds. The Live Stroke is not a floating-surface variant: a stroke opens no popup and dismisses none. A Pending Stroke leaves the store in the same update that ingests its record, so no frame shows the stroke twice and no frame shows it missing; a failed create removes it. See [ADR 0057](0057-ink-is-stored-as-zotero-smooths-it-and-one-stroke-is-one-annotation.md).

## Amendment: the Reader Surface Model

The Reader Surface State lives in the Reader Surface Model (`reader-surface-model.ts`), the per-leaf model shape of [ADR 0082](0082-obsidian-views-read-effect-services-through-view-atoms.md) under the reader's vanilla-DOM surfaces. The state is one kept-alive writable atom. Each thing a surface draws is one derived atom with the equality the store's selector carried: the Creation Toolbar, the capability affordance, the capability, the floating head, the selected keys, the Geometry Edit, the capture, the Text Draft, the Live Stroke, the Pending Strokes, the armed tool, and the Mark Popup's floating surface with its row. A renderer watches its atom through `watch` (`src/lib/view-atoms.ts`), which hears a change in the update that made it, as the store did.

- Each binding holds its model in its own atom registry. `bindingResources` (`operations.ts`) acquires the registry on the binding's Scope before the binding's writes, so the registry closes after them, and a create that settles as the view closes still writes its state; `operations.test.ts` closes a Scope on a create in flight to hold that order.
- The reducers are pure transitions in `reader-surface-state.ts`: each takes the state and answers the next one, or the same state when nothing changes, and a caller runs it with `update`. A gesture that acts on what the transition decided (the end of a Geometry Edit, of a capture, of a Text Draft) runs a step with `modify`, which answers that result. A same-state transition notifies no renderer.
- `reader-surface-state.ts` stays plain code that keeps `Temporal`; `reader-surface-model.ts` holds the Effect imports.
- The per-Annotation facts a refresh reads are ingested in one update.
- Watchers of one derived atom hear a change together, in the order its node was first built; the Mark Popup Host watches its own atom and is built after the owners, so an editor that closes is still let go before the host redraws.
