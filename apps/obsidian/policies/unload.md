# Unload

Unload closes the plugin's runtime Scope and every layer Scope under it. The close stops every pending run, and code outside Effect sees that stop in one of two shapes. The reviewer checks each part below.

- **Every run stops.** A bridge run lives in the bridge's Scope (`lib/effect-bridge.ts`, `bridgeOver`): `effectBridge(runtime)` uses the runtime's Scope, `scopedBridge` the layer's. At unload, `runPromise` rejects with an `AbortError` (`lib/abort-error.ts`), and `runPromiseExit` resolves with an interrupt-only Exit, which `valueOr` or `settleAtEdge` (`lib/signal-edge.ts`) maps to the caller's released answer. Where the caller acts on an empty answer (an empty list that shows a "No PDF attachment" notice), the released answer is a distinct value, such as `undefined`, and the caller does nothing for it (`attachment-open/handle.ts`).
- **A waiting caller stays silent.** A caller that awaits a run treats the unload's `AbortError` as no outcome: no notice, no log. `toast` (`lib/toast.ts`) and the notifier's `reportProgress` / `reportOutcome` (`lib/notifier.ts`) already pass over it; other code tests it with `AbortError.test`. A fire-and-forget call on an edge handle's Promise member adds `.catch(passAborted)` (`lib/abort-error.ts`).
- **A call fired and forgotten** from a DOM, editor or observer callback runs through `bridge.runAndForget`: unload stops it quietly, and any other failure stays an unhandled rejection, so the service or the caller handles that failure.
- **A write finishes its step.** A write step that an interrupt would leave half-done (a created note before its stamp, a template conversion, a settings save) is an `Effect.uninterruptible` region in its service, so the Scope close waits for that step and no longer: the `write` of `template/service.ts`, the write regions in `profile/service.ts`, `flush` in `settings/service.ts` (`CODING_STANDARDS.md` → Interruption gives its test). A write whose outcome is known when its layer closes keeps that answer: an accepted send, a refused send (a 412) and an accepted create. A send still in flight at the close answers `unknown-outcome`.
- **A captured runner is scoped.** A service that keeps a runner for later callbacks builds it on a Scope: the layer's `FiberSet.runtime` (`protocol/register.ts`), or `scopedBridge` (`citekey-reading/service.ts`); the plugin runtime's bridge is `effectBridge(runtime)` (`services/plugin-runtime.ts`). A Promise core that needs its runners while a protected write finishes uses `forkedBridge` (`template/service.ts`), so the close waits for that write with its runs still open. `zotlit-services/scoped-runner` checks every service.
