# Services

The `zotlit-services` lint rules cover the mechanical part of the service architecture. The reviewer checks the rest:

- **Effect shape.** An Effect service's tag shape is Effect-native: its methods return `Effect`s, a generator method through `Effect.fn` (`CODING_STANDARDS.md` → Effect), and state others watch is a `changes` Stream. Its layer is a `layer<Name>` export beside the tag (`layerUseLedger`), or a `layer<Name>(deps)` function when it takes plain inputs (`layerLogOutput(plugin)`).
- **Bridge.** Callers outside Effect — legacy services and views — hold the tag's service itself and the container's `bridge` (an `EffectBridge`, `@/lib/effect-bridge`). `build.ts` reads the service once, `useValue({ release: () => runtime.runSync(Release) })`; consumers type their deps as a `Pick<Release["Service"], …>` beside a `Pick<EffectBridge, …>`, and run each call through it: `bridge.runSync(…)`, `bridge.runPromise(…)`, `bridge.subscribe(stream, …)`. Nothing else calls `runtime.runSync` / `runtime.runPromise`, which fail or rebuild after unload: a callback that needs a service gets it read once at build. A call a caller fires and forgets (`void bridge.runPromise(…)`) cannot fail: the service handles its own failure, or the caller adds `catchCause` and logs. The bridge is the migration seam, not the target: a consumer that converts to Effect yields the tag and drops its `bridge` dep, until the bridge is left only where a callback from outside Effect (an Obsidian event, a React handler) enters it.
- **Plain adapter (backlog).** A `<service>/plain.ts` adapter (`plainZoteroReads`) runs each method on the runtime and returns values and Promises. The ones left retire into the bridge (#1710); write no new one.
- **Engine in a layer.** A large state machine may stay a plain class that the layer owns (`zotero-local-api/session.ts`): it publishes its events through a callback the layer turns into Streams, and reaches other services through `scopedBridge`, the bridge over the layer's own Scope; a callback the layer writes for it may read a service with the layer's context runner instead (`httpPort: () => run(pref.current).httpPort`). `localApiPort` is a port over the tag and the bridge with the old synchronous surface. It is made twice: once in `build.ts`, for a still-legacy consumer, and once inside `layerAnnotationRepository`, for the repository's engine core.
- **Conversion scope.** A legacy service changes to Effect only in a change made for that conversion. The legacy list in `oxlint.config.ts` is the conversion backlog: the change takes the file off it, injects the service through `useValue`, and drops `ready` from its consumers' `Pick` deps and awaits.
- **Leaves first.** Convert a service once its dependencies are in the Layer graph. A legacy dependency enters the graph through `serviceLayer` when an Effect service first needs it, rather than through the container. `QueryClients` was bridged ahead of any Effect consumer, by decision; the Annotation Repository layer and the Excerpt Image display now yield it, so its bridge serves the legacy consumers that remain.
