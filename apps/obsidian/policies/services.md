# Services

The `zotlit-services` lint rules cover the mechanical part of the service architecture. The reviewer checks the rest:

- **Effect shape.** An Effect service's tag shape is Effect-native: its methods return `Effect`s, each method with arguments through `Effect.fn("<Tag>.<method>")`, or `Effect.fnUntraced` on a per-message or per-item hot path (`CODING_STANDARDS.md` → Effect; `effecttsgo/effect-fn-opportunity` checks it); a member with no arguments is an `Effect` value traced with `Effect.withSpan("<Tag>.<member>")` (`effecttsgo/lazy-effect` reports a zero-argument method), and state others watch is a `changes` Stream. Its layer is a `layer<Name>` export beside the tag (`layerUseLedger`), or a `layer<Name>(deps)` function when it takes plain inputs (`layerLogOutput(plugin)`).
- **Bridge.** Callers outside Effect — legacy services and views — hold the tag's service itself and the container's `bridge` (an `EffectBridge`, `@/lib/effect-bridge`). `build.ts` reads the service once, `useValue({ release: () => runtime.runSync(Release) })`; consumers type their deps as a `Pick<Release["Service"], …>` beside a `Pick<EffectBridge, …>`, and run each call through it: `bridge.runSync(…)`, `bridge.runPromise(…)`, `bridge.subscribe(stream, …)`. Unload interrupts every bridge run, so no member that a view awaits finishes after unload: `runPromiseExit` resolves with an interrupt-only Exit, and `runPromise` rejects with an `AbortError` (`@/lib/abort-error`). A write that must not stop half-done is an `Effect.uninterruptible` region in its service. Nothing else calls `runtime.runSync` / `runtime.runPromise`, which fail or rebuild after unload: a callback that needs a service gets it read once at build. A call a caller fires and forgets runs through `bridge.runAndForget(…)`: unload interrupts it quietly, and any other failure surfaces as an unhandled rejection, so the service handles its own failure, or the caller adds `catchCause` and logs. A fire-and-forget call through an edge handle's Promise member adds `.catch(passAborted)`, which passes over the unload's `AbortError`. The bridge is the migration seam, not the target: a consumer that converts to Effect yields the tag and drops its `bridge` dep, until the bridge is left only where a callback from outside Effect (an Obsidian event, a React handler) enters it.
- **Edge handle.** Views and legacy callers that a later slice converts may hold an edge handle in place of the tag's service and the bridge: one object per tag that `build.ts` builds over the bridge (`bindQuery`, `bindItemLookup`). Each member runs one call through the bridge and maps its Exit to the caller's answer (`valueOr`); the handle holds no other logic. A member whose call has no released answer runs through `bridge.runPromise`, so the caller gets the value, the failure, or the unload's `AbortError`, which `toast`, `notifier` and `passAborted` pass over. A handle may also serve Effect functions over several tags (`bindNoteActions` for the note commands and menu entries) until its callers convert. A handle may serve the Effect functions of one feature (`bindTemplateData` for the Template data reads) until its callers convert.
- **Plain adapter (backlog).** A `<service>/plain.ts` adapter (`plainZoteroReads`) runs each method on the runtime and returns values and Promises. The ones left retire into the bridge (#1710); write no new one.
- **Engine in a layer.** A state machine with concurrency of its own is Effect code in its layer: the Zotero Local API session (`zotero-local-api/session.ts`) keeps its state in `Ref`s, shares one request in flight between callers through a slot, as the Capability Probe does, queues work per key with a `Semaphore`, runs background work on the layer's Scope, bounds a request with `Effect.timeoutOrElse`, reads the `Clock`, and cancels by interruption rather than by `AbortSignal`. A large state machine that coordinates none of that is Effect functions over one state record that its layer builds: the Annotation Repository core (`annotation-repository/core/`) takes the `CoreState` as its first parameter, `yield*`s the services the record holds (`ZoteroLocalApi["Service"]`, `ZoteroReads["Service"]`, `QueryClients["Service"]`), and publishes its events through a callback the layer turns into Streams. The layer's members `yield*` the core functions. Callbacks that a library calls (TanStack Query read and mutation functions) and the `Disposable` that `hold` answers are its edges, and run through `scopedBridge`, the bridge over the layer's own Scope.
- **Conversion scope.** A legacy service changes to Effect only in a change made for that conversion. The legacy list in `oxlint.config.ts` is the conversion backlog: the change takes the file off it, injects the service through `useValue`, and drops `ready` from its consumers' `Pick` deps and awaits.
- **Leaves first.** Convert a service once its dependencies are in the Layer graph. A legacy dependency enters the graph through `serviceLayer` when an Effect service first needs it, rather than through the container. `QueryClients` was bridged ahead of any Effect consumer, by decision; the Annotation Repository layer and the Excerpt Image display now yield it, so its bridge serves the legacy consumers that remain.
