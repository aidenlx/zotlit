ZotLit 直接通过 Zotero 数据库读取您的文献库。ZotLit Companion（Zotero 配套插件）确保最近的变动能够即时被读取，并将 Zotero 内的操作与 Obsidian 无缝串联。即时同步更新（live updates）则提供了可选的第三种连接机制。

ZotLit 支持 Zotero 9 及更高版本，且必须安装配套插件 Companion。如需直接在 Obsidian 中保存批注的修改，需要使用 Zotero 10 或更高版本。在 Zotero 9 下，您可以阅读 PDF 及其标注，但无法直接将标注编辑写回。

## 读取 Zotero 数据库

Zotero 在运行期间可能会将最新的写入暂存在单独的数据库缓存文件中。ZotLit 采用专门的读取模式（read mode）直接访问您的文献库，且绝不会与 Zotero 产生读写冲突或导致数据库锁定。

默认的 <UiLabel name={m.settings_db_read_mode_auto()} /> 设置会自动选取当前环境下最优的读取模式。在 macOS 和 Linux 上，它会优先尝试使用 <UiLabel name={m.settings_db_read_mode_reflink()} />。在 APFS、Btrfs 以及开启了写时复制（reflink）的 XFS 文件系统上，自动模式会使用轻量快照副本。在 Windows 和其他常见文件系统（例如 ext4）上，自动模式会回退到 <UiLabel name={m.settings_db_read_mode_immutable()} />。您随时可以在设置中手动指定。

<UiLabel name={m.settings_db_read_mode_reflink()} />
会为数据库创建快速、轻量的瞬时快照。它能即时看到未提交到主库文件的最新改动，也是自动模式在任何支持克隆特性的
macOS 或 Linux 文件系统上的首选方案。

<UiLabel name={m.settings_db_read_mode_immutable()} /> 直接以 SQLite
的只读不可变模式（immutable
mode）读取数据库主文件，无需额外生成副本文件。这是在不支持文件克隆时的默认回退模式。由于该模式仅读取主数据库文件，尚未写入主文件的最新变动会暂留在
Zotero 独立的预写式日志（WAL）中，直到 Zotero 触发检查点写入。

Companion 插件通过自动将最新更改写入主文件，确保 ZotLit 随时能够读取到最新数据。其自带的 <UiLabel name={m["zotero.prefs_wal_checkpoint.label"]()} /> 设置项默认处于开启状态。这一数据库检查点功能无需开启[即时同步更新](/docs/how-to/set-up-live-updates)即可独立稳定运行。

<UiLabel name={m.settings_db_read_mode_copy()} />
可以在任何文件系统上正常运作，并且同样能读取到最新变动。但由于其每次都需要完整复制整个数据库文件，因此速度较慢且会消耗额外的磁盘空间，尤其是在大型
Zotero
文献库中。自动模式绝不会主动选择此项，仅在其他模式均不可用时建议手动选用。

有关各个选项的完整列表与技术解释，请参阅[设置参考](/docs/reference/settings)。

### 单设备独立的路径解析机制

Zotero 的个人配置文件目录（profile directory）和数据目录（data directory）属于特定计算机上的绝对文件系统路径。ZotLit 采用单设备独立解析策略：在每台设备上，它都会自动侦测默认的 Zotero 配置文件（读取 `profiles.ini`）及对应的数据目录。如果您的 Zotero 数据存放于非标准目录，您只需在该特定设备上配置设备覆盖项（Device Override）。该覆盖项保存在本地环境（按单仓库、单设备划分），绝不会通过云端在多设备间同步，因此一台电脑上的路径设置绝不会误覆盖另一台电脑。

详细的分步操作说明请参阅[在多台设备上同步使用 ZotLit](/docs/how-to/sync-across-devices)。

## ZotLit Companion 配套插件

Companion 插件在 Zotero 内部扩展了右键菜单操作。这些动作包括：打开、更新或导入笔记，以及在 Obsidian 中直接打开条目的 PDF。Companion 还可以向 Obsidian 主动推送即时变动事件。

Companion 确保 Zotero 的主数据库文件随时处于最新状态。Zotero 会使用预写式日志（WAL）来暂存最新变动，随后再批量刷写至主文件。Companion 会在 Zotero 更新文献库后主动要求 Zotero 将更改立即刷写至主库文件。此行为默认开启，且无需运行任何后台服务器。

Companion 本身不运行任何后台监听服务。它的右键菜单操作通过构造 `obsidian://zotlit/...` 自定义协议链接并交由操作系统处理，随后由系统自动调度唤起 Obsidian。这套机制在 Obsidian 未开启任何本地服务器或网络端口时也能完全正常工作。

## 协议链接与即时同步更新的区别

ZotLit 在 Zotero 与 Obsidian 之间提供了两种不同的通信机制，它们定位不同且彼此独立：

### 协议链接（无需启用服务器）

Zotero 的右键菜单使用标准的 `obsidian://` 协议链接。无论 Obsidian 是否在后台保持运行，操作系统都会正确响应并将指令送达 Obsidian。

### 即时同步更新（需要本地服务器）

即时同步更新通过 Obsidian 内部运行的轻量 HTTP 监听服务器接收来自 Companion 的实时事件推送。它适用于希望在 Zotero 中添加高亮或修改条目后无需任何手动点击即可让 Obsidian 自动同步的深度工作流。

When you right-click an item in Zotero and choose a ZotLit action (open note, update note, import, open PDF), the Companion builds an `obsidian://zotlit/...` URL and opens it. Obsidian receives the URL and ZotLit handles the action.

Protocol links work out of the box after you install ZotLit and the Companion. They carry a source identifier so ZotLit only processes links originating from the expected Zotero install.

<Callout type="info" title="Batch actions and the URL length limit">
  Batch operations (selecting many items in Zotero) may exceed the URL length
  limit. When this happens, the Companion falls back to an HTTP request to the
  ZotLit server. If the server is not enabled, Zotero shows a notice asking you
  to enable it or select fewer items.
</Callout>

### Live updates (server required)

Live updates are a push channel. The Companion sends HTTP notifications to Obsidian as you read and annotate in the Zotero PDF reader, powering the annotation view's reader-following mode. After the Companion finishes its work on the main database file, it also sends a payload-free signal telling ZotLit to refresh, so changes appear right away.

The database checkpoint that writes those changes into the main file works independently of live updates. Live updates only add the signal that tells ZotLit when to refresh.

Live updates require two things enabled:

- **In Obsidian:** the ZotLit server (a local HTTP listener on port 9091 by default), with <UiLabel name={m.settings_live_updates_enabled_name()} /> on.
- **In Zotero:** the Companion's notify preference, pointed at the same address.

Both sides carry a source identifier and a protocol version. The server discards requests from unrecognized Zotero installs (source mismatch) and rejects requests with an incompatible protocol version.

<Callout type="info" title="Off by default">
  Both the Obsidian server and the Companion's notify preference are disabled by
  default. Protocol links handle all context-menu actions without them. Enable
  live updates only when you want real-time push from Zotero.
</Callout>

## Saving annotation changes to Zotero

The database connection only reads. When you edit an annotation in Obsidian, ZotLit sends the change to Zotero while Zotero is running. Zotero saves it like an annotation you made in its own reader, so the change syncs with your Zotero library.

ZotLit sends these changes through Zotero's local API, a connection that Zotero provides for other applications on the same computer. Two things must be in place:

- **In Zotero:** **Allow other applications on this computer to communicate with Zotero** is on, under Settings → Advanced.
- **Your permission:** the first time you allow editing, Zotero shows a permission dialog. You choose **Always Allow** once. ZotLit saves this permission for the current vault on the current device only, so you give it once for each vault on each computer.

This connection does not use protocol links or the ZotLit server. For the steps, see [Edit PDF annotations in Obsidian](/docs/how-to/edit-pdf-annotations).

## How the pieces fit together

ZotLit can read the database while Zotero is closed. Install the Companion in Zotero to keep data current after changes. Protocol links and live updates also depend on the Companion.
