ZotLit reads the literal Pandoc citation keys you write — `@doe2024` and clusters such as `[see @doe2024, p. 3; @smith2020]` — and treats them as citations. **Citation key indexing** tracks them across your vault. **Citation key styling** is the editor and reading-view surface of that index: a recognized key is styled and clickable while you write, and each citation shows its formatted text in Live Preview and in reading view.

Both settings live in **Settings → ZotLit → Citations**. **Citation key indexing** is on by default and is the master switch; **Citation key styling** is on by default and takes effect only while indexing is on.

<Callout type="info" title="Upgrading from Citation Key Links">
  Citation Key Links is retired. ZotLit carries your stored toggle into
  **Citation key styling**, so clicking a citation key keeps working. The new
  feature no longer patches Obsidian editor internals, and it recognizes bare
  keys, not only bracketed ones.
</Callout>

## What gets recognized

ZotLit follows Pandoc's own citation grammar, so the text you write for Pandoc is the text ZotLit reads:

- `@key` — a bare author-in-text citation.
- `-@key` — the same citation with the author suppressed.
- `[@key]`, `[@key, p. 3]`, `[see @a, p. 3; @b]` — a citation cluster, with prefixes, locators, and several keys.
- `@{https://example.com/paper}` — a braced key, for a key that contains characters the bare form cannot carry.

Trailing punctuation is not part of a key, and text that only looks like a citation is left alone: `user@example.com` and a URL containing `@` stay plain text.

Text that Obsidian's editor classifies as code, math, a `%%` comment, frontmatter, or a URL is never read as a citation, so code samples and links never gain citation styling.

## What happens in the editor

Styling comes from ZotLit's own editor decorations rather than from Obsidian's link machinery, so it applies to bare keys as well as bracketed ones.

### Source mode

In Source mode, each recognized key is styled like an internal link, so you can see at a glance which text ZotLit reads as a citation. You always see the raw text you wrote. Click a key to open its literature note; `Ctrl`/`Cmd`-click or middle-click opens it in a new tab.

### Live Preview [#live-preview]

In Live Preview, ZotLit goes a step further: each whole citation — a bare `@key`, `-@key`, or a cluster such as `[see @a, p. 3; @b]` — is replaced with its formatted citation text, rendered in the style **References style** selects. This is the same text [reading view](#reading-mode) and the references sidebar show, so your draft reads like the exported document.

Without the Pandoc Engine installed, each key shows its `Creators (Year)` summary instead, and the brackets, prefixes, and locators you wrote stay as written.

A citation whose keys do not match any live Zotero item shows unresolved styling and is not clickable.

#### Editing around a rendered citation

The raw text comes back the moment the cursor or selection touches the rendered citation at either end, and it stays visible while the citation text is still being read. When the editor loses focus, all citations show their formatted text. Cursor motion steps over a rendered citation as one unit, and backspace removes it whole — editing is never blocked.

#### Click and hover

A rendered citation is clickable the same way a marked key is: click opens the literature note, `Ctrl`/`Cmd`-click or middle-click opens a new tab. Hover shows the page preview when the item resolves to exactly one literature note. A citation naming several works opens a menu listing each work so you pick which note to open; hover stays silent for a multi-work citation.

## How click resolution works

A click on a citation key resolves it against Zotero's native citation key field in the **Default library**. When a Zotero item carries that key and already has a literature note, ZotLit opens the note. When the item exists but has no literature note yet, ZotLit runs the usual create-then-open flow.

If no Zotero item carries the key, a notice appears: "No Zotero item with citation key `@{key}`." If the Zotero database is unavailable, ZotLit shows "Open the Zotero database to look up citation key `@{key}`."

For the full step-by-step details, see [Open a note from a citation key](/docs/how-to/create-and-open-notes#open-a-note-from-a-citation-key).

## What happens in reading view [#reading-mode]

Reading view replaces each citation with its formatted text, rendered in the style **References style** selects — the same text the references sidebar shows.

Without the Pandoc Engine installed, each key shows the `Creators (Year)` summary instead, and the brackets, prefixes, and locators you wrote stay as written.

Wikilinks in reading view are left untouched, so reading view stays plain Obsidian for them.

## Resolution and the `citekey` frontmatter field

Citation key resolution is database-first: ZotLit resolves a literal key such as `@doe2024` against Zotero's own native citation key field, scoped to the configured **Default library**. A key whose Zotero item exists styles and renders as a normal citation in the editor, reading view, and the references sidebar, even when the item has no literature note yet. A key that matches no Zotero item is the error state: unresolved styling in the editor and an error row in the references sidebar showing the raw key.

The lookup is scoped to a single library. Citation keys kept only in Better BibTeX's own database, rather than in Zotero's native citation key field, stay unresolved.

Resolution refreshes automatically when the Zotero database changes. Re-keying an item in Zotero updates the editor and sidebar on the next refresh. There is a brief moment after startup or a refresh where keys read as unresolved before the lookup warms; they restyle on their own.

The default Managed Frontmatter list includes a `citekey` field backed by `zt.citationKey`. ZotLit still writes this field into new literature notes for interoperability with other tools, but ZotLit itself does not read it for resolution. You can edit, rename, or remove this ordinary managed field. The `zotero-key` property remains the system identity for literature notes.

### Wikilink citation display

When Wikilink Citations is on, a literature note wikilink without a fragment displays the item's native Zotero citation key. When the item carries no citation key, the note's filename is the fallback.
