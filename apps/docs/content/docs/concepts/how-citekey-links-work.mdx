ZotLit turns literal Pandoc citation keys and Literature Note wikilinks into readable, navigable citations.

The Citation Index tracks each Citation Occurrence in your vault. An occurrence can be a literal citation key or a Literature Note wikilink. The references sidebar and citation treatments read from this shared index.

**Citation key indexing** is on by default and controls literal citation keys. **Wikilink citations** is an opt-in setting for Literature Note wikilinks. Both settings are under **Settings → ZotLit → Citations**.

<Callout type="info" title="Upgrading from Citation Key Links">
  Citation Key Links is retired. ZotLit moves its stored value to **Citation key
  styling**, so your existing click preference remains active. The new treatment
  also recognizes bare citation keys.
</Callout>

## Literal citation keys

Citekey Indexing recognizes the Pandoc citation syntax you already write:

- `@key` is a bare author-in-text citation.
- `-@key` suppresses the author.
- `[@key]`, `[@key, p. 3]`, and `[see @a, p. 3; @b]` are Citation Clusters.
- `@{https://example.com/paper}` is a braced key for characters that a bare key cannot contain.

Trailing punctuation is not part of a citation key. Email addresses and URLs containing `@` remain ordinary text.

ZotLit also ignores citation-like text inside code, math, `%%` comments, frontmatter, and URLs. These regions do not become Citation Occurrences.

### Resolution

ZotLit resolves literal citation keys against Zotero's native citation key field in the **Default library**. It does not read the `citekey` frontmatter field for resolution.

An item can render as a citation before it has a Literature Note. Opening that citation creates the Literature Note, then opens it. A key that matches no item shows unresolved styling and an error in the references sidebar.

Resolution refreshes when the Zotero database changes. A re-keyed item updates after the next refresh.

## Literal citations in the editor

**Citation key styling** controls the editor and reading-view treatment for literal citation keys. It is on by default and takes effect while **Citation key indexing** is on.

### Source mode

Source mode always shows the text you wrote. A plain click places the caret on a citation key.

Ctrl-click opens the Literature Note in the same tab. Use Cmd-click on macOS. Middle-click and Ctrl+Shift-click, or Cmd+Shift-click on macOS, open it in a new tab.

### Live Preview [#live-preview]

Live Preview replaces a citation with formatted text while your cursor is elsewhere. A Citation Cluster renders as one citation, including its prefixes, locators, and suffixes.

ZotLit uses the selected References Style when the Pandoc Engine is available. Otherwise each resolved key shows its `Creators (Year)` summary, while the surrounding source stays visible.

The raw source returns when your cursor or selection touches the citation. Cursor movement treats a concealed citation as one unit.

## Literal citations in reading view [#reading-mode]

Reading view shows the same formatted citation text as Live Preview. It uses the same References Style and `Creators (Year)` fallback.

Formatted citations also support Citekey Navigation. A citation with one work opens its Literature Note. A citation with several works opens a menu so you can choose a note.

## Citekey Navigation

Citekey Navigation gives recognized literal citation keys one opening flow across the editor and reading view. If the item has no Literature Note, ZotLit creates one before opening it.

In Live Preview and reading view, a plain click opens the note in place. Modifier clicks follow Obsidian's pane behavior. Source mode uses the modifier behavior described above.

Hover shows Obsidian's page preview only when one citation key resolves to exactly one existing Literature Note. Hover stays silent for unresolved keys, missing notes, and multi-work citations.

Obsidian controls hover modifier gating under **Settings → Core plugins → Page preview**. The ZotLit source appears there as **ZotLit citation key**.

Four command-palette commands open the citation key under the cursor:

- <Command inline>ZotLit: Open citation key under cursor</Command>
- <Command inline>ZotLit: Open citation key under cursor in new tab</Command>
- <Command inline>ZotLit: Open citation key under cursor to the right</Command>
- <Command inline>ZotLit: Open citation key under cursor in new window</Command>

These commands have no default hotkeys. They are available when **Citation key indexing** and **Citation key styling** are on. The cursor must be on a recognized citation key.

## Literature Note wikilinks

ZotLit can show a Literature Note wikilink as Citation Display Text instead of its path. This treatment works in Live Preview and reading view.

For a wikilink without a fragment, Citation Display Text is `@` followed by the item's native Zotero citation key. The Literature Note filename is the fallback when the item has no citation key.

A valid `#cite:` Citation Fragment produces the equivalent Pandoc citation source. The source includes its mode, prefix, locator, and suffix. For example, `[[Doe 2020#cite:locator=33]]` displays as `[@doe2020, p. 33]` when the item's citation key is `doe2020`.

Fragment-less links need both **Wikilink citations** and **Show wikilink citations as citation text**. A valid Citation Fragment displays as a citation regardless of those settings.

An explicit wikilink alias always wins. Heading and block subpaths, embeds, malformed Citation Fragments, ordinary links, and unresolved links keep Obsidian's display.

### Display and interaction

The wikilink treatment changes its display while preserving Obsidian's click, hover, drag, and reveal behavior. In Live Preview, the raw source returns when your cursor or selection touches the link. Source mode always shows the raw wikilink.

ZotLit uses the References Style when formatted citation text is available. In Live Preview, a decorated wikilink shows Citation Display Text while that result loads. A semicolon-separated run can render as one Citation Cluster and keeps the first link's navigation target.

In reading view, dragging a decorated wikilink out of the note carries its displayed text instead of its raw link path. The context menu's **Copy** action also copies the displayed text.

## References Style and Entry Markers

References Style is the formatting rule selected by **References style**. It controls formatted citations across Live Preview, reading view, and the references sidebar.

The references sidebar also keeps each Entry Marker produced by the style, such as a bibliography number. Citation Occurrences still keep their source positions for navigation.

## Theme hooks [#theme-hooks]

ZotLit adds public CSS classes to citation keys, rendered Citations, and Literature Note links in Source mode, Live Preview, and Reading view. Themes and CSS snippets can style these elements without depending on their DOM structure.

See [Theme hooks](/docs/reference/theme-hooks) for the selector contract and CSS examples.
