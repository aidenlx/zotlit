A literature note is an Obsidian Markdown file linked one-to-one with a Zotero item. ZotLit uses a marked region inside the note to keep Zotero-derived content up to date without overwriting anything you write yourself.

## What makes a file a literature note

ZotLit identifies a literature note by a single frontmatter field: `zotero-key`. Any Markdown file in your vault that contains this field is treated as a literature note, regardless of filename or folder location.

```yaml
---
zotero-key: ABC123XY
---
```

The update and overwrite commands only appear in the command palette and context menu when the active file has a resolvable `zotero-key`.

## The managed region

Every literature note is governed by one [profile](/docs/concepts/profiles). The profile supplies the note source, the text ZotLit renders into the note, and the note source marks the Zotero-derived part of it with a managed block, `{% managed %}` and `{% endmanaged %}`. See [Profile document](/docs/reference/templates/profile-document) for the document that carries the source, and [How templates work](/docs/concepts/how-templates-work) for how ZotLit finds it.

When ZotLit creates or overwrites a literature note, it renders the note source. Where the note source has a managed block, its output goes into the note body inside comment markers:

```markdown
%%zt-managed%%
...generated content...
%%/zt-managed%%
```

ZotLit owns everything between these two markers. Your own writing goes above or below the managed region.

### What the region contains

The managed region holds the output of the managed block in the profile that governs the note. In the Default profile, the block produces a **Notes** section linking the item's Zotero child notes, and an **Annotations** section with your PDF highlights as callouts.

Each callout comes from the profile's Annotation Section, the final part of the profile document, which sets how one annotation appears. Edit it to change the format of every annotation that profile renders.

The rest of the note source sits outside the managed block. In the Default profile, that places the title heading, the Zotero backlink, and the attachment file links above the managed region at creation time. The attachment links point to the original files and do not copy them into the vault. For a Zotero linked file, the original can be in an external folder. See [Zotero's guide to linked files](https://www.zotero.org/support/attaching_files#adding_linked_files). These lines sit outside the markers and are not touched by updates.

### How updates use the region

<Command inline name={m.command_update_note_name()} /> refreshes the frontmatter
with the current Zotero metadata and re-renders the managed block of the profile
that governs the note, replacing the managed region with the new output.
Everything outside the markers stays exactly as you left it. This is how ZotLit
can pull in new annotations or updated metadata without disturbing your own
notes, links, or tags.

A profile whose note source has no managed block updates the frontmatter only.
The note body has no region to replace.

<Command inline name={m.command_update_note_metadata_name()} /> is a lighter
operation. It refreshes frontmatter only and never touches the note body.

## Notes without a managed region

<Callout type="info" title="Notes created with ZotLit v1">
  Literature notes created with ZotLit v1 have a `zotero-key` and are recognized as literature notes, but they contain no managed region markers. Running <Command inline name={m.command_update_note_name()} /> on a v1 note refreshes its frontmatter and leaves the body untouched. ZotLit reports <UiLabel name={m.notice_updated_note_no_region()} />.

To recover the full update workflow on a v1 note, see [Keep notes up to date](/docs/how-to/keep-notes-updated).

</Callout>

## Overwrite versus update

<Command inline name={m.command_overwrite_note_name()} /> is a separate,
destructive command. It regenerates the entire note body from the note source of
the profile that governs the note, discarding everything below the frontmatter
block. Frontmatter keys managed by ZotLit are refreshed; other frontmatter keys
you added are kept. A confirmation dialog gates the action.

[Keep notes up to date](/docs/how-to/keep-notes-updated) covers both actions, and the batch update that ZotLit Companion starts from Zotero.
