配置方案（Profile）是决定由其生成的文献笔记所有细节的核心文档：包含笔记名称、存放文件夹、frontmatter 属性、正文内容以及标注格式。

## 什么是配置方案文档 [#document]

配置方案是一个单独的 Markdown 文件，命名规则为 `zotlit-profile.<slug>.md`，存放在由 <UiLabel name={m.settings_template_folder_name()} /> 所指定的文件夹中。ZotLit 会读取该文件夹下文件名以 `zotlit-profile.` 开头的所有直接子文件，其中的每一个文件都会作为一个独立的配置方案被加载。无需显式注册、安装或在设置中额外指定路径，只需将该文件放入模板文件夹中即可完成添加。

文件名本身并不是配置方案的唯一标识符，重命名该文件不会对功能产生任何影响。每个配置方案文档在其 manifest 元数据区中都包含一个 `id`，这才是文献笔记所记录的身份标识。视觉外观、属性字段和标注格式全部组织在这个单一文件内部。其所包含的详细格式请参阅[配置方案文档](/docs/reference/templates/profile-document)参考；它与其他两类模板文档的关系请参阅[模板工作原理](/docs/concepts/how-templates-work#kinds)。

## 默认配置方案 [#default]

每个仓库都内建一个默认配置方案（Default profile），它一开始无需任何文件实体。在您对其进行自定义之前，ZotLit 使用内置模板并将全库层面的默认值存储在插件设置中。自定义该配置方案时，会在模板文件夹中生成 `zotlit-profile.default.md` 文件，在此之后，默认配置方案便成为与其他配置方案毫无二致的独立文档。

默认配置方案同时也是所有配置方案的回退基准。未显式绑定特定配置方案的笔记均归属于默认配置方案；新添加的配置方案如果留空了某项设置，也会自动从默认配置方案继承该值。因此，一个自定义配置方案只需声明其特殊差异之处即可：例如专门存放图书的文件夹、针对特定期刊的引文格式、独特的标注 callout 样式等，无需重复声明其余通用项。

## ZotLit 如何选择配置方案 [#selection]

每篇笔记都严格由唯一一个配置方案负责写入。ZotLit 在写入时按照以下优先级顺序确定采用哪一个配置方案：

1. 您针对本次操作主动选定的配置方案。
2. 命令面板或 ZotLit Companion（Zotero 附加组件）链接中指明的配置方案。
3. 其匹配条件（Match conditions）符合当前条目的配置方案。
4. 默认配置方案。

步骤 1 和步骤 2 源于您在单次操作中的主动选择。步骤 3 为自动匹配：匹配条件是配置方案文档的一部分，未声明匹配条件的配置方案绝不会被自动选中。当恰好有一个配置方案符合条件时，ZotLit 会直接使用该方案而无需弹窗询问；当有多个配置方案同时匹配时，ZotLit 会中断流程并提示您进行选择。步骤 4 则是上述规则均未命中时的最终兜底方案。

关于匹配条件的语言语法，请参阅[配置方案匹配规则](/docs/reference/templates/profile-match)；在[针对不同笔记使用不同模板](/docs/how-to/use-different-templates)中，您可以看到如何添加配置方案并检查条目的匹配情况。

## 一篇笔记，绑定一个配置方案 [#stamp]

每篇文献笔记都会在其 `zotlit-profile` 属性字段中记录创建它的配置方案。该属性值包含配置方案的提示名称及其唯一 ID，形如 `Books (V1StGXR8Z5jd)`。在比较方案归属时，ZotLit 仅比对括号中的 ID。名称部分只是便于人类阅读的提示信息，在 ZotLit 下次写入该笔记时会自动刷新，因此无论修改配置方案的显示标签还是重命名其文件，都不会破坏笔记关联。

由默认配置方案写入的笔记不包含此属性字段。该属性的缺失即代表默认配置方案，绝不会被解释为“去查询其他笔记”。导入的笔记同样包含此标识印记，继承自发起导入的操作或生成它的文献笔记。

因为配置方案的身份严格以 ID 为准，如果有两份配置方案文档声明了完全相同的 ID，它们都将无法注册到系统中。在其中一份文档修改为唯一 ID 之前，该冲突配置方案将无法在任何地方使用。

## 笔记何时会更换配置方案 [#update]

对现有笔记执行更新操作不会重新触发自动匹配条件计算。ZotLit 会直接读取笔记上的印记，使用该印记所指明的配置方案渲染该笔记，绝不影响其他笔记。因此，修改现有配置方案的匹配条件或添加新的配置方案，只会影响未来新创建的笔记样式，绝不会篡改已存在的笔记。如果执行命令时传入的配置方案与笔记现有印记不符，操作将被拒绝并报错：<UiLabel name={m.notice_literature_note_profile_conflict()} />。

将一篇已有笔记迁移至不同的配置方案是一项需单独执行的主动操作，绝非编辑匹配条件所带来的隐式副作用。该操作在执行前会要求您确认，且会完整保留受管区域之外的原有手写文本；下一次更新时，笔记将按照新指定的配置方案进行重绘。[针对不同笔记使用不同模板](/docs/how-to/use-different-templates)提供了该迁移操作的具体步骤。

## 笔记本身不保存独立模板 [#customize]

由某个配置方案写入的所有笔记均依据该配置方案文档统一进行渲染。不存在针对单篇笔记的独立模板副本，因此编辑配置方案文档会同时影响使用它的所有笔记，每篇笔记在下一次更新时均会呈现出最新的改动。属于默认配置方案的笔记则依循默认配置方案文档进行渲染；在未对其进行自定义之前，均按内置模板呈现。

因此，编辑某篇笔记的模板实质上就是编辑该笔记所绑定的配置方案。[自定义模板](/docs/how-to/customize-a-template)详细介绍了此类编辑，以及引文文本和共享片段的修改。
