ZotLit 使用一个有序的引文集合来对当前活动笔记进行格式化、为其参考文献编号，并提供引文交互导航支持。

## 文档引文集（Document Citation Set）

文档引文集包含来自当前活动笔记的所有引文出现项（Citation Occurrences）。每个出现项都会保留其在源码中的位置和引文详细信息。

<SettingsPath page={m.settings_page_citations()} />
下的两项设置决定了哪些引文来源可以加入该集合：

| 设置项                                                           | 默认值 | 包含的引文来源                                      |
| ---------------------------------------------------------------- | ------ | --------------------------------------------------- |
| <UiLabel name={m.settings_citation_pandoc_citations_name()} />   | 开启   | 字面量 Pandoc 语法，例如 `@doe2024` 与 `[@doe2024]` |
| <UiLabel name={m.settings_citation_wikilink_citations_name()} /> | 关闭   | 指向文献笔记的合格双链（wikilink）                  |

您可以将两种来源均行关闭。此时，参考文献侧边栏、正文格式化引文、数字序号排版以及文献引用标识导航（Citekey Navigation）都将收到一个空集合。

合格的双链是指不带显示别名（unaliased）且直接指向文献笔记的链接。它可以不带链接片段，或者带有形如 `#cite:locator=33` 的有效引文片段。

带有别名的链接、嵌入块、无法解析的目标、标题片段以及块链接均不会纳入该集合。格式错误的引文片段同样会被排除。在 <UiLabel name={m.settings_citation_wikilink_citations_name()} /> 开启期间，参考文献侧边栏会将格式错误的片段报告为参考文献错误（Reference Error）。

该集合严格保持其在源码中的出现顺序。该顺序至关重要，因为数字编号样式需要根据整篇笔记的内容统一计算序号，而非依据当前可见的部分。

### 引文索引（Citation Index）

引文索引是 ZotLit 内部在整个仓库范围内维护的引文出现项记录。无论上述两项来源设置如何配置，该索引均会保持活跃并独立追踪这两类引文来源。

当某项引文功能查询当前活动笔记时，文档引文集会动态应用您的来源设置。更改任一设置都会立即重新计算文档引文集，无需重新扫描整个仓库。

引文插入与内置导出拥有各自独立的来源准入规则。关闭某种来源并不会禁用引文插入功能，也不会从导出中移除该来源。

## Pandoc 引文

Pandoc 引文可以引用单篇文献或多篇文献组合：

- `@key` 为作者置入正文形式（author-in-text）的单篇引文。
- `-@key` 会在输出中省略作者姓名。
- `[@key]` 与 `[@key, p. 3]` 为带括号的引文簇（Citation Cluster）。
- `[see @a, p. 3; @b]` 在一个引文簇中组合引用多篇文献。
- `@{https://example.com/paper}` 为带花括号的标识键，用于包含普通键所不支持的字符。

紧跟在后的尾部标点符号不属于文献引用标识的一部分。包含 `@` 的电子邮件地址和 URL 会被视为普通文本。

ZotLit 还会自动排除代码块、行内代码、数学公式、`%%` 注释、frontmatter 属性区以及 URL 中类似引文的文本。

### 解析机制

ZotLit 会对照您在 <UiLabel name={m.settings_library_scope_name()} /> 中涵盖的所有文献库，基于 Zotero 原生的文献引用标识字段来解析 Pandoc 引文键。它不会使用 frontmatter 中的 `citekey` 字段进行解析。

文献条目可以在创建对应的文献笔记之前就以引文形式出现在正文中。点击打开此类引文会先自动创建对应的文献笔记，随后将其打开。未能成功解析的标识键会保持原始字面量形式，并在侧边栏中显示为参考文献错误。

当 Zotero 数据库发生变动时，解析数据会及时刷新。重新更改标识键的条目会在下一次刷新后生效。

### 匹配多个条目的标识键（歧义键）[#ambiguous-key]

一个文献引用标识可能解析为单个 Zotero 条目、未找到任何条目，或者匹配到多个条目。匹配到多个条目即为歧义键（ambiguous key）。当同一个文献库中有两个条目拥有相同的文献引用标识，或者同时纳入作用域的两个不同文献库中各存在一个同名标识时，就会发生歧义。

ZotLit 绝不会擅自猜测选择其中任何一个候选条目。编辑器、阅读视图、引文悬停浮窗以及参考文献侧边栏均会一致报告歧义状态，并且该标识键保持独立：它不会关联任何候选条目，也不会向文末参考文献列表中添加任何条目。

如果一个引文簇中既包含歧义键又包含完全未找到的键，则引文簇会优先报告未找到的键。这是因为缺失属于更严重的故障状态，应当保持醒目可见。

有两种方式可以消除歧义：在 Zotero 中为其中一个条目修改分配不同的文献引用标识；或者缩小您的[文献库作用域](/docs/reference/settings#library-scope)，直到仅剩一个候选条目，从而使该标识键重新恢复唯一性。

## 双链引文

指向文献笔记的合格双链代表了与该笔记关联的 Zotero 条目。有效的引文片段（Citation Fragment）可以为其补充 Pandoc 的具体细节，例如前缀、定位符、后缀或作者省略模式。

例如，当条目的文献引用标识为 `doe2020` 时，`[[Doe 2020#cite:locator=33]]` 即代表了 Pandoc 源码 `[@doe2020, p. 33]` 的效果。

双链引文完整保留了 Obsidian 原生的链接目标、点击交互以及拖拽行为。在源码模式下，始终显示原始的双链文本。

## Formatted in-text citations

<UiLabel name={m.settings_citation_show_formatted_name()} /> is on by default.
It applies the selected
<UiLabel name={m.settings_citation_references_style_name()} /> in Live Preview
and reading view. Source mode always shows Markdown.

ZotLit asks the Pandoc engine to format the complete Document Citation Set. A complete render keeps numbering and style context consistent across the note. ZotLit swaps the whole document to formatted text only after that render finishes.

In Live Preview, the Markdown source returns only for the citation touched by your cursor or selection. Other citations remain formatted.

ZotLit leaves the native source visible when it cannot produce one complete formatted result.

A Citation Cluster with any unresolved item stays completely unchanged. Its resolved items still affect later numeric numbering and the References Sidebar.

Turning <UiLabel name={m.settings_citation_show_formatted_name()} /> off leaves every source in Obsidian's native presentation. It does not change set membership, Citekey Navigation, insertion, or export.

## References and errors

The References Sidebar presents one entry for each resolved item in the Document Citation Set. A formatted list follows the selected style's bibliography order and Entry Markers.

Without formatted output, the sidebar uses a minimal list in first-occurrence order. A Reference Error keeps its exact source occurrence and contributes no bibliography entry.

The [references how-to](/docs/how-to/review-copy-troubleshoot-references) covers navigation, item actions, bibliography copy, and error recovery.

## Citekey Navigation

<UiLabel name={m.settings_citation_open_as_links_name()} /> controls navigation
for both literal Pandoc citations and Literature Note wikilinks shown as
citations. It works independently of formatted display and hover behavior.

A single-item citation can open or create its Literature Note. A multi-item citation requires an item choice. An [ambiguous key](#ambiguous-key) requires a candidate choice because the key itself names no unique item.

The Citation Popover presents every cited item's full bibliography entry in citation order. An unresolved or ambiguous key remains visible as its own state instead of adopting an item.

The [references how-to](/docs/how-to/review-copy-troubleshoot-references) covers citation hover and the available navigation actions. The [commands reference](/docs/reference/commands) lists the open-under-cursor commands.

## Theme hooks [#theme-hooks]

ZotLit adds public CSS classes only to sources in the Document Citation Set where it supplies rendering or navigation. Excluded sources and sources with both applicable features inactive receive no public ZotLit class.

See [Theme hooks](/docs/reference/theme-hooks) for class names, state meanings, and activation rules.
