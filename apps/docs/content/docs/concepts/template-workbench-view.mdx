The Template Workbench View edits one template document and shows its output against data from your Zotero library.

## One view, three kinds of document [#kinds]

The view opens all three [kinds of template document](/docs/concepts/how-templates-work#kinds). The kind decides the tabs, the tab title, and what the preview renders.

| Document      | Tab title                                                | Tabs                                               | Preview                              |
| ------------- | -------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| Profile       | The profile's name, then `Profile`                       | Six                                                | A literature note for one paper      |
| Citation text | <UiLabel name={m.template_workbench_title_citation()} /> | One, <UiLabel name={m.workbench_tab_citation()} /> | One inserted citation                |
| Partial       | The partial's name, then `Partial`                       | One, <UiLabel name={m.workbench_tab_partial()} />  | The partial as one template calls it |

Everything you type is previewed, including bytes you have not saved yet. Editing uses Obsidian's automatic saving, with its Undo and Redo. A document with an error stays editable and saves with its diagnostics shown in the editor.

The native Markdown view keeps working on the same file. Select <UiLabel name={m.template_workbench_open_markdown()} /> to open the document as Markdown, and right-click a template document in the file explorer for <UiLabel name={m.template_workbench_open()} />.

## Side panels [#panels]

The view has two side panels beside the editor. The Fields panel, on the left, lists the template data for the chosen paper. The Preview panel, on the right, shows what the document produces for that paper.

The editor tabs and both panels use one chosen item and one chosen annotation. Choose an item in any of them, and the other two show the same item.

### Show or hide a panel [#show-panels]

Select **Show fields** or **Show preview** in the view header. The action looks pressed while its panel is shown, and you select it again to hide the panel. The same two entries are in the view's pane menu.

Hiding a panel keeps your chosen item and annotation. The panel shows them again when you bring it back.

### Resize a panel [#resize-panels]

Drag the edge between a panel and the editor to make the panel wider or narrower. The resize handle also works from the keyboard. In a narrow window, the editor keeps room for the template text.

### What the view remembers [#panel-state]

Obsidian saves which panels are shown, and how wide they are, with the view. After a restart, the view opens the way you left it.

A new view starts with no panels, for a quick edit. That is the case when you open a profile from the file explorer, or from <UiLabel name={m.template_workbench_open()} />. <UiLabel name={m.template_workbench_open_layout()} /> and <Command inline name={m.command_customize_note_template_name()} /> open the view in its own Workbench window with both panels shown.

### The Fields panel [#fields-panel]

The Fields panel is the [Template Data Explorer](/docs/how-to/explore-template-data) inside the view. It has the same filter, sections, roots, and copy actions. Its row menu adds <UiLabel name={m.workbench_fields_put_in_note()} />, which puts the field into the editor at your cursor.

### The Preview panel [#preview-panel]

While the Preview panel is shown, the view's pane menu has a Preview section with the choices that shape the preview:

- <UiLabel name={m.workbench_preview_as_new_note()} />,
  <UiLabel name={m.workbench_preview_as_updated_note()} />, or
  <UiLabel name={m.workbench_preview_updated_section()} />.
- <UiLabel name={m.workbench_preview_auto_refresh()} />. Turn it off to render
  only when you select <UiLabel name={m.workbench_preview_run()} />.
- <UiLabel name={m.workbench_show_markdown()} />, to read the note as Markdown
  source.

A problem that the preview finds appears in the editor's <UiLabel name={m.workbench_problems_heading()} /> area.

## A profile document [#profile]

A profile controls the name, folder, properties, and body of a literature note. It can also define how annotations appear and which Zotero items use the profile automatically.

The view groups these parts into six tabs:

- <UiLabel name={m.workbench_tab_note()} /> edits the literature note body.
- <UiLabel name={m.workbench_tab_properties()} /> edits the YAML properties that
  ZotLit manages.
- <UiLabel name={m.workbench_tab_annotation()} /> edits the format of one
  annotation.
- <UiLabel name={m.workbench_tab_name_and_folder()} /> edits the note path,
  citation style, imported note settings, and template language. Its
  <UiLabel name={m.workbench_name_path_heading()} /> group joins the literature
  note folder and the note name template, and previews the full path.
- <UiLabel name={m.workbench_tab_match()} /> selects the Zotero items that use
  an added profile automatically.
- <UiLabel name={m.workbench_tab_profile()} /> edits the profile's own name,
  description, and version.

<UiLabel name={m.workbench_advanced()} /> is a toggle in the view header. Select
it to show the whole profile document as Markdown source in place of the tabs,
and select it again to return to the tabs. A citation text or a partial shows
its source in its one tab, so the toggle is offered for a profile document only.

### Preview data [#preview-data]

The preview uses a Zotero item or built-in example. Opening the view from a literature note selects that note's item. The pane menu offers <UiLabel name={m.workbench_choose_item()} /> to change the preview data and <UiLabel name={m.template_workbench_open_layout()} /> to show both [side panels](#panels) in the Workbench window.

The preview changes as you edit. A database or citation-style warning can limit the preview, but you can continue editing the profile.

### Saving changes [#saving]

The built-in Default profile is read-only. You can read and select its values without creating a document. <UiLabel name={m.template_workbench_customize()} /> creates its document in the configured template folder before editing becomes available, or opens the existing custom document.

If creation fails, the built-in values remain readable and an inline error offers a retry. Closing an untouched customization keeps the created document.

Existing literature notes keep their current content. Run <Command name={m.command_update_note_name()} /> to apply the edited profile to the active note.

<Callout type="info" title="Edit the Markdown document">
  Select <UiLabel name={m.template_workbench_open_markdown()} /> to open an
  existing profile document as Markdown. Customizing the built-in Default
  creates its document before editing becomes available.
</Callout>

## The citation text [#citation]

The citation text opens on one <UiLabel name={m.workbench_tab_citation()} /> tab. Its tab title is the fixed <UiLabel name={m.template_workbench_title_citation()} />.

The preview, headed <UiLabel name={m.workbench_citation_result_heading()} />, renders one citation. Its caption names the variant being previewed, <UiLabel name={m.workbench_citation_variant_main()} /> or <UiLabel name={m.workbench_citation_variant_alt()} />. The view's pane menu picks that variant, and offers <UiLabel name={m.template_workbench_use_example()} /> for a set of built-in citation shapes or <UiLabel name={m.workbench_choose_item()} /> for one of your own Zotero items.

The Preview panel uses the variant and example you pick. See [Customize the citation text](/docs/how-to/customize-a-template#citation-text) for the steps.

## A partial [#partial]

A partial opens on one <UiLabel name={m.workbench_tab_partial()} /> tab. Its tab title is the partial's name, then `Partial`.

A partial has no data of its own: it renders with the data of whichever template calls it. So its preview, headed <UiLabel name={m.workbench_partial_result_heading()} />, asks you which caller to render as. The view's pane menu offers <UiLabel name={m.template_workbench_preview_as_note()} />, <UiLabel name={m.template_workbench_preview_as_annotation()} />, and <UiLabel name={m.template_workbench_preview_as_citation()} />. It opens on Note, and remembers your choice per file. ZotLit never guesses the caller from the templates that call the partial.

While your vault holds a profile besides Default, the pane menu also offers <UiLabel name={m.template_workbench_use_profile()} /> to preview against that profile's data. Saving a partial re-renders every open preview that uses it.

## The document's language [#language]

Above the editor of a citation text or a partial, a caption names the document's language, <UiLabel name={m.workbench_name_language_liquid()} /> or <UiLabel name={m.workbench_name_language_eta()} />. The caption reports; it does not switch.

The pane menu carries <UiLabel name={m.template_workbench_change_language()} />, the switch between the two languages. ZotLit rewrites the manifest key alone and translates no source. See [How templates work](/docs/concepts/how-templates-work#manifest).

A profile document sets its language on the <UiLabel name={m.workbench_tab_name_and_folder()} /> tab instead, under <UiLabel name={m.workbench_name_language_heading()} />.

## Open the view [#open]

A view edits one template document, and each kind opens from the place that holds it:

- A profile, from its row at <SettingsPath page={m.settings_page_profiles()} />, or from the <UiLabel name={m.settings_profile_document_name()} /> row at <SettingsPath />.
- The citation text, from the <UiLabel name={m.settings_citation_text_name()} /> row at <SettingsPath page={m.settings_page_citations()} />.
- A partial, from its row under <UiLabel name={m.settings_partials_heading()} /> at <SettingsPath page={m.settings_page_profiles()} />.

The profile a literature note already uses opens from that note.

Each of those rows carries its own control, and [Customize a template](/docs/how-to/customize-a-template) names it and walks the steps.
