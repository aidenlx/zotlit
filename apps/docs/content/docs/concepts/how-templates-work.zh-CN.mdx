模板是内嵌了动态表达式的 Markdown 文件，控制着您的文献笔记与引文的外观呈现。ZotLit 将它们统一存放在您仓库中的一个文件夹内，称之为**模板文档（template documents）**，并通过文件名来决定各自的用途。

<Callout type="info" title="智能体辅助编写模板">
  借助[模板工作台
  CLI](/docs/concepts/template-workbench)，智能体可以直接针对您的 Zotero
  文献库编辑并测试模板。您只需用自然语言描述想要的效果，无需亲自手写 Liquid 或
  Eta 代码。
</Callout>

## 三类模板文档 [#kinds]

每份模板文档都属于以下三类之一，由其文件名前缀明确区分：

| 类别                | 文件命名格式               | 所包含的内容                                                                                                 |
| ------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 文献笔记配置方案    | `zotlit-profile.<slug>.md` | 完整的配置方案：笔记名称、存放目录、frontmatter 属性、正文内容以及标注格式。例如 `zotlit-profile.books.md`。 |
| 引文文本            | `zotlit-citation.md`       | ZotLit 渲染的每条正文内引文的文本。整个仓库仅有一份，且必须严格以此命名。                                    |
| 共享片段（Partial） | `zotlit-partial.<name>.md` | 供任何其他模板按名称调用的可复用模板片段。例如 `zotlit-partial.authors.md`。                                 |

配置方案文档是文献笔记的唯一编写实体：笔记的文件名、frontmatter 属性、正文结构以及单条批注的渲染格式全部组织在这一份文件中。有关 ZotLit 如何对已有笔记进行更新的机制，请参阅[文献笔记与受管区域](/docs/concepts/literature-notes-and-the-managed-region)。

引文文本模板是所有正文内引文的唯一格式来源：包含从引文建议下拉框或命令面板插入的引文、标注自带的引文以及从 Zotero 导入笔记中的每条引文。它接收 [`zt.variant`](/docs/reference/templates/data#citation-variant) 变量（取值为 `main` 或 `alt` 字符串），用以区分触发引文的交互手势，模板根据该变量决定渲染的内容。`alt` 来源于 `Shift+Enter` 或查询词末尾的 `/`；批注中的引文与导入笔记中的引文则固定为 `main`。详见[各手势插入的内容说明](/docs/how-to/insert-citations#citation-text)。

共享片段（Partial）用于在不同模板间复用公共文本逻辑。多个配置方案以及引文文本模板均可通过名称直接渲染相同的片段。具体操作步骤请参阅[自定义模板](/docs/how-to/customize-a-template#share-a-partial)。

## ZotLit 如何发现模板 [#discovery]

ZotLit 会扫描模板文件夹中所有文件名以 `zotlit-` 开头的文件。该扫描是单层扁平化的：它仅读取该文件夹根目录下的直接子文件，不会递归扫描子文件夹。

没有 `zotlit-` 前缀的文件会被自动忽略，因此您可以将 Obsidian 自身的其他普通模板安全地保存在同一个文件夹中。

一个以 `zotlit-` 开头但既不属于上述三类、也不属于 [2.1 旧版模板文件](#convert-legacy)的文件将不会渲染任何内容。系统会在 <SettingsPath page={m.settings_page_advanced()} setting={m.settings_advanced_template_engine_heading()} /> 中生成一条 <UiLabel name={m.settings_template_unrecognized_name()} /> 提示，列出该文件名以及三种合法命名格式。例如 `zotlit-citation.liquid.md` 就是不合规的文件名：引文文本模板的文件名中不应带有语言后缀。

### 模板文件夹设置 [#template-folder]

模板文档统一保存在 <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} /> 所指定的文件夹中，默认为 `templates`。模板加载和文件变动监听均以此文件夹为准。ZotLit 会在文件发生更改时即时重新编译，无需重新加载插件即可让修改立即生效。

## Manifest 元数据区与模板语言 [#manifest]

引文文本模板与共享片段模板由一个可选的 YAML frontmatter manifest 以及后续的模板源码组成：

```text
---
language: eta
---
<模板源码>
```

`language` 是该 manifest 唯一接受的配置键，其有效取值仅为 `liquid` 或 `eta`。包含任何其他键均会被判定为错误。

A document with no frontmatter is Liquid. A Liquid partial or citation text needs no manifest, and the file ZotLit creates for you when you first open the citation text carries none.

To change the language for a citation text or a partial, use the switch in the [Template Workbench View](/docs/concepts/template-workbench-view). It rewrites the manifest key alone: your source is never translated between the two syntaxes.

A profile document always carries a manifest, because its manifest also holds the profile's name, folder, and citation style.

## Two template languages [#languages]

ZotLit supports two template languages: **Liquid** and **Eta**.

**Liquid** is the default. It is always active and requires no opt-in. Liquid templates can only combine data into text: they cannot read files, make network requests, or run system commands. That makes them safe to share, sync, and install from community sources.

**Eta** is a JavaScript-based engine. Eta templates can run arbitrary JavaScript with the same access as ZotLit itself. Because of the wider security surface, Eta is disabled by default and requires a per-device opt-in called the <UiLabel name={m.settings_template_js_enable_name()} /> gate. See [JavaScript templates](/docs/concepts/javascript-templates) for the full explanation.

An Eta document is inert while the gate is off. It is not compiled, and it does not fall back to the built-in default. ZotLit names the file it skipped and says why.

## Built-in defaults [#defaults]

The citation text works with no file in your vault: ZotLit renders a built-in Liquid default instead. Its settings row reads <UiLabel name={m.settings_template_using_default()} /> until a document exists. Opening the row creates the document from that built-in text, and resetting it moves your document to Obsidian's configured trash so the built-in text takes over again.

Literature notes work the same way through the built-in Default profile, which you customize into a document of your own.

## Converting 2.1 template files [#convert-legacy]

Template files from ZotLit 2.1 still load and still render, so you do not have to convert them to keep working. That covers `zotlit-note.liquid.md`, `zotlit-content.liquid.md`, `zotlit-annotation.liquid.md`, `zotlit-filename.liquid.md`, the two citation files, and any other `zotlit-<name>.(liquid|eta).md` that served as a partial.

ZotLit offers the conversion once in the Welcome view, as <UiLabel name={m.welcome_template_conversion_title()} />, and repeats it as a reminder row at the top of settings with a <UiLabel name={m.settings_template_conversion_reminder_action()} /> action. One pass folds the note, content, filename, and annotation files into one profile document, folds the two citation files into one citation text, and gives every remaining file its own partial document.

Before it writes anything, ZotLit renders both citation variants and the note, update, filename, and annotation output, and compares them byte for byte against what your old files produced. A mismatch converts nothing. The old files then go to Obsidian's configured trash, so you can recover them.

See [Migrate v1 Eta templates](/docs/how-to/migrate-v1-eta-templates) for the steps and the field mappings a v1 template also needs.

### When two 2.1 files share a name [#liquid-wins-shadowing]

A 2.1 name could carry both a `.liquid.md` and an `.eta.md` file. While both exist, the Liquid file wins and the Eta file is ignored, whether or not JavaScript templates are enabled. The conversion trashes both.
