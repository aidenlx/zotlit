如果您使用的是 ZotLit 2.1，模板目前依然正常运行，本篇指南将协助您了解升级带来的具体改动。

## 发生了哪些变化

在 2.1 版本中，一篇笔记的外观格式分散在模板文件夹中的多个独立文件内，每个组成部分对应一个文件。在 2.2 版本中，所有这些格式全部整合归纳到单一的[配置方案文档](/docs/reference/templates/profile-document)中。

| 2.1 旧版文件                                        | 2.2 归宿                                                    |
| --------------------------------------------------- | ----------------------------------------------------------- |
| `zotlit-note.<lang>.md`                             | `zotlit-profile.default.md` 中的笔记模板源码主体            |
| `zotlit-content.<lang>.md`                          | 位于该笔记源码内部的受管块（managed block）                 |
| `zotlit-filename.<lang>.md`                         | 配置方案文档 manifest 中的 `filename` 属性键                |
| `zotlit-annotation.<lang>.md`                       | 位于 `--- zotlit:annotation ---` 标题下方的标注格式区域     |
| `zotlit-cite.<lang>.md` 与 `zotlit-cite2.<lang>.md` | 单一引文文本文档 `zotlit-citation.md` 的两个分支            |
| 任何其他 `zotlit-<name>.<lang>.md`                  | 各自独立的 `zotlit-partial.<name>.md` 共享片段              |
| 设置中的 frontmatter 属性字段列表                   | manifest 中的 `frontmatter` 列表（受管 frontmatter 属性项） |

## 升级过程绝不破坏现有文件

在升级后，您的 2.1 文件会继续正常加载并执行渲染。ZotLit 绝不会擅自执行转换或移动您的文件，您已有的笔记丝毫不会受到影响。只有当您主动点击时，转换流程才会启动。

## 准备就绪后执行转换

<Steps>
  <Step>
    ### 打开模板转换入口

    在升级后首次启动 Obsidian 时，欢迎视图会自动打开一次。转换引导横幅位于快速入门时间线上方，标题为 <UiLabel name={m.welcome_template_conversion_title()} />。后续您也可以通过运行命令 <Command inline name={m.command_open_welcome_name()} /> 重新唤起该视图，或者使用 <SettingsPath /> 顶部的提醒横幅。

  </Step>
  <Step>
    ### 点击“转换模板”

    点击 <UiLabel name={m.welcome_template_conversion_action()} /> 并等待转换处理完毕。若直接关闭欢迎视图而不进行转换，所有内容都会保持原状，且提醒横幅会继续保留在 <SettingsPath /> 顶部，并提供 <UiLabel name={m.settings_template_conversion_reminder_action()} /> 操作入口。

  </Step>
</Steps>

## 转换过程中会执行什么

ZotLit 会先在内存中构建出全新的文档结构，并对照您 Zotero 文献库中的条目数据进行模拟渲染。它会将新文档生成的笔记、更新结果、笔记名称、标注格式以及两种引文输出，与您的 2.1 旧文件产出进行严格对比。只有当所有产出与旧版逐字节（byte-for-byte）完全吻合时，才会真正执行落盘写入。

当产出完全一致时，ZotLit 会写入 `zotlit-profile.default.md`、`zotlit-citation.md` 以及各个共享片段文件。随后，它会将您的 2.1 旧文件移动到 Obsidian 配置的废纸篓中。该废纸篓是唯一的安全备份：ZotLit 不会额外保留旧文件的副本。如果某些文件无法移动到废纸篓，转换依然成立且新转换的文档已经正常激活生效，系统会弹出通知列出遗留的文件：<UiLabel name={m.notice_literature_note_template_conversion_pending_cleanup({ files: "…" })} />。欢迎视图中也会展示相同的列表，标题为 <UiLabel name={m.welcome_template_cleanup_body()} />，点击 <UiLabel name={m.welcome_template_cleanup_retry()} /> 可再次尝试清理移动。

有一种特殊情况会保留原有文件：如果您的两个旧引文文件采用了不同的语言引擎，引文文本会转换为 Liquid，而 Eta 文件则会安全留在原地；ZotLit 会通过 <UiLabel name={m.notice_literature_note_template_conversion_kept({ files: "…" })} /> 提示保留的文件。

## 拒绝执行的情况与提示

任何阻断性校验均发生在首次物理写入之前，因此您的仓库文件和设置将安全保持原样。每次拒绝均会通过通知弹窗给出清晰说明。

- **A converted output that does not reproduce the old one.** <UiLabel name={m.notice_literature_note_template_conversion_mismatch({ difference: "…", files: "…" })} /> This is the refusal you are most likely to meet, because it is what the byte check reports. The notice lists only the files you need to edit, and names the output that differed: `create output`, `update output`, `filename output`, `annotation output`, `main citation output`, or `alternate citation output`. Edit the 2.1 file behind that output so the converted form reproduces it, then select the button again.

- **A layout ZotLit cannot convert automatically.** <UiLabel name={m.notice_literature_note_template_conversion_unsupported({ files: "…" })} /> The conversion handles only the shapes 2.1 shipped: one content insertion in the note file, and one language across the files. The notice lists only the files you need to edit. Edit them on disk to match, then select the button again. The notice also appears when an Eta file is involved and <UiLabel name={m.settings_template_js_enable_name()} /> is off; turn the gate on under <SettingsPath page={m.settings_page_advanced()} setting={m.settings_advanced_template_engine_heading()} /> and try again.

- **A frontmatter field written in JavaScript while the gate is off.** <UiLabel name={m.notice_literature_note_template_conversion_frontmatter_inert({ fields: "…" })} /> Turn on <UiLabel name={m.settings_template_js_enable_name()} /> under <SettingsPath page={m.settings_page_advanced()} setting={m.settings_advanced_template_engine_heading()} />, then select the button again. See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates).

- **A field that fails to evaluate against the item ZotLit picked.** <UiLabel name={m.notice_literature_note_template_conversion_frontmatter_evaluation({ fields: "…" })} /> This release has no editor for the legacy field list, and a profile's edit actions stay disabled while the conversion is pending. The list lives in the plugin's saved settings file, under `note.frontmatter-fields`; correct the named fields there, then select the button again. Writing a profile document by hand repairs nothing: the offer stands down as soon as `zotlit-profile.default.md` exists, whatever the file holds.

- **No item, or no annotation, to verify against.** <UiLabel name={m.notice_literature_note_template_conversion_no_item()} /> or <UiLabel name={m.notice_literature_note_template_conversion_no_annotation()} /> Connect a Zotero library that contains an item, then select the button again. The annotation notice appears only when an annotation file is among the files being converted.

- **A converted document already exists.** <UiLabel name={m.notice_literature_note_template_conversion_exists()} /> Rename or remove the file in the way, then select the button again. The notice says "profile document" even when the occupant is `zotlit-citation.md` or a partial.

- **No legacy templates left to convert.** <UiLabel name={m.notice_literature_note_template_conversion_none()} /> ZotLit found none of the files the conversion reads, so nothing is written and nothing changes. Keep using the built-in templates.

## While the conversion is pending

Until you convert, ZotLit refuses to create, update, or switch a note through any profile other than the Default profile. The notice reads <UiLabel name={m.notice_literature_note_template_conversion_required()} />. Notes on the Default profile are unaffected. Every profile document action stays locked until the conversion has run: the Profiles page shows no Add and no Import, and the actions on the rows it keeps, such as Edit, Duplicate, Share, and Delete, are disabled.

## Expected result

Your 2.1 files sit in Obsidian's configured trash, and the converted documents render the same output. A notice reads <UiLabel name={m.notice_literature_note_template_conversion_success()} /> Every profile works again.
