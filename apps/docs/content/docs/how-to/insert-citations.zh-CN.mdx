利用引文建议下拉框（Citation Suggester）或命令面板，从您的 Zotero 文献库中快速插入 Markdown 格式的学术引文。

两个入口均会统一检索您在[文献库作用域](/docs/reference/settings#library-scope)中指定的全部文献库，并按相关性排序输出。当有多个文献库参与检索时，每项建议结果都会清晰标明其来源文献库；如果仅有一个文献库在作用域内，该标签会自动省略。

引文插入机制完全独立于文档引文集（Document Citation Set）以及正文引文格式化渲染。即使同时关闭了这两类来源设置并禁用了 <UiLabel name={m.settings_citation_show_formatted_name()} />，引文插入功能依然能够正常使用。

## 打字输入时即时插入

在编辑器中键入 `[@`（或全角中文符号 `【@`）即可激活引文建议下拉框。光标下方将弹出一个包含您 Zotero 条目的下拉列表。

若按需启用了 <UiLabel name={m.settings_citation_at_trigger_name()} /> 设置项，在词边界处（行首、空格后，或前括号与前引号后）直接键入单个 `@` 符号同样能唤起建议菜单。

<Steps>
  <Step>
    ### 唤起引文菜单

    在编辑器中键入 `[@`。建议列表随即在光标下方展开。

    若开启了 <UiLabel name={m.settings_citation_at_trigger_name()} />，在词边界处键入单个 `@` 同样会触发建议。而在单词中间出现的 `@`（例如电子邮箱地址）则会被自动忽略。

  </Step>
  <Step>
    ### 搜索并选择条目

    继续输入关键词以过滤筛选列表。选中所需条目后按 `Enter` 即可完成插入。引文插入后会自动附带一个空格，方便您流畅继续后续书写。

    按 `Enter` 默认插入**主引文（main citation）**，内置的引文文本模板会将其渲染为 `[@citationKey]`。

    单个 `@` 查询会在遇到第一个空格时结束。如需包含空格，可用下划线 `_` 代替：例如输入 `@machine_learning` 即可搜索“machine learning”。而方括号触发词（`[@`）则原生支持直接输入常规空格。

  </Step>
  <Step>
    ### 插入备选引文格式（可选）

    若希望插入**备选引文（alternate citation）**（内置引文文本模板会将其渲染为作者置入正文的 `@citationKey` 形式），可通过以下任一方式实现：

    - 在按 `Enter` 之前，在查询词末尾追加一个斜杠 `/`。
    - 在选中的条目上直接按下 `Shift+Enter`。

    建议菜单底部的操作说明栏清晰提示了这些快捷键组合。

  </Step>
</Steps>

若选中的条目未生成文献引用标识，插入操作会被安全取消并弹出提示通知：“所选条目没有文献引用标识（citation key）：`{key}`。”。

### 建议菜单设置 [#suggester-settings]

- <UiLabel name={m.settings_citation_suggester_name()} />
  （默认开启）：启用或禁用行内建议菜单。位于
  <SettingsPath page={m.settings_page_citations()} />。
- <UiLabel name={m.settings_citation_at_trigger_name()} />
  （默认关闭）：允许在词边界处输入单个 `@` 来打开建议菜单。仅当
  <UiLabel name={m.settings_citation_suggester_name()} /> 开启时可见。位于
  <SettingsPath page={m.settings_page_citations()} />。
- <UiLabel name={m.settings_citation_show_citekey_name()} />
  （默认关闭）：在建议列表中，于条目标题旁显示其文献引用标识。位于
  <SettingsPath page={m.settings_page_citations()} />。

## 从命令面板插入 [#insert-from-the-command-palette]

<Steps>
  <Step>
    ### 打开引文选取器 [#open-the-citation-picker]

    打开命令面板（Windows/Linux 上为 `Ctrl+P`，macOS 上为 `Cmd+P`）并运行：

    <Command name={m.command_insert_citation_name()} />

    随后会出现展示 Zotero 文献库的选取器。

  </Step>
  <Step>
    ### 选择条目 [#select-an-item]

    搜索条目并按 `Enter` 插入主引文。

    按 `Shift+Enter` 则插入备选引文。此弹窗不支持查询词末尾的 `/` 快捷方式；在这里请求备选引文只能使用 `Shift+Enter`。

  </Step>
</Steps>

## 使用文献笔记链接引用 [#cite-with-a-literature-note-link]

如果引文还需要保留为通向对应文献笔记的 Obsidian 链接，请使用这种形式。

<Steps>
  <Step>
    ### 启用引文来源 [#enable-the-citation-source]

    打开 <SettingsPath page={m.settings_page_citations()} />，开启 <UiLabel name={m.settings_citation_wikilink_citations_name()} />。

  </Step>
  <Step>
    ### 插入不带别名的文献笔记链接 [#insert-an-unaliased-literature-note-link]

    在引用文献的笔记中输入 `[[`，选择该条目的文献笔记。不要给链接设置别名。

    例如：

    ```md
    This finding follows the earlier analysis [[Doe 2020]].
    ```

  </Step>
  <Step>
    ### 按需添加引文细节 [#add-citation-details-when-needed]

    在链接目标中添加引文片段。以下示例添加页码定位信息 `33`：

    ```md
    This finding follows the earlier analysis [[Doe 2020#cite:locator=33]].
    ```

    将 `Doe 2020` 替换为文献笔记的准确目标。

  </Step>
</Steps>

链接必须解析为 ZotLit 文献笔记。带别名的链接、嵌入、标题片段、块片段、无法解析的目标以及格式错误的引文片段，都不会进入文档引文集。

<Callout type="info">
  `[[@doe2024]]`
  这样的链接不会自动指向文献笔记，除非对应条目的文献笔记恰好就叫这个名字。
  要引用字面量文献引用标识，请使用 `[@doe2024]`。
</Callout>

## 同一文献引用标识匹配多个条目时 [#ambiguous-key]

同一文献引用标识可能属于多个 Zotero 条目，无论这些条目位于同一个文献库，还是作用域内的两个文献库。插入的文本只保存标识本身，因而无法继续唯一指向您选中的条目。

因此，无论从哪个入口插入，ZotLit 都会拒绝此次操作并提示：“文献引用标识（citation key）`@{key}` 对应多个 Zotero 条目。请先在 Zotero 中修改，再插入引用。”请在 Zotero 中为其中一个条目设置不同的标识，或将文献库作用域缩小到目标文献库，然后重新插入。

已经写入笔记的标识仍可读取。此类标识在编辑器、引文浮窗和参考文献侧边栏中的行为，请参阅[正文引文渲染与导航的工作原理](/docs/concepts/how-citekey-links-work)。

## 各种操作会插入什么 [#citation-text]

一个名为**引文文本**的模板文档负责渲染所有插入的引文。它接收 [`zt.variant`](/docs/reference/templates/data#citation-variant)，其值为字符串 `main` 或 `alt`，再决定各自渲染的内容。

- 在建议菜单或命令面板选取器中按 `Enter`，会传入 `main`。
- 在任一入口按 `Shift+Enter`，或在建议菜单查询词末尾添加 `/`，会传入 `alt`。末尾的 `/` 无需同时按 `Shift` 即可生效，且该 `/` 会从搜索词中移除。

内置引文文本会生成以下结果：

| 引用内容             | 主引文                  | 备选引文                               |
| -------------------- | ----------------------- | -------------------------------------- |
| 单个标识 `smith2024` | `[@smith2024]`          | `@smith2024`                           |
| 两个标识             | `[@a2020; @b2021]`      | 第一个条目放在正文中，其余放在方括号内 |
| 定位信息为 `62`      | `[@smith2024, {p. 62}]` | `@smith2024 [{p. 62}]`                 |
| 省略作者的条目       | `[-@smith2024]`         | `[-@smith2024]`                        |
| 带前缀的条目         | `[see @smith2024]`      | 回退为方括号内的引文簇                 |

备选分支会请求 Pandoc 优先把作者放在正文中。如果无法采用该形式（例如存在前缀或省略作者），Pandoc 会回退为方括号内的引文簇，因此两种变体可能生成相同文本。没有文献引用标识的条目会从输出中移除。

生成的引文会规范化为单行：去掉首尾空白，将包含换行的连续空白折叠为一个空格。每次插入都以一个空格结尾，并将光标放在其后；如果插入位置之后已有空格，则会复用它，不再重复添加。

如需修改这些行为，请编辑 <UiLabel name={m.settings_citation_text_name()} /> 文档。参阅[自定义引文文本](/docs/how-to/customize-a-template#citation-text)，或运行 <Command inline name={m.command_customize_citation_text_name()} />。模板可读取的字段列在[引文模板](/docs/reference/templates/data#citation-templates)中。

开启 <UiLabel name={m.settings_citation_pandoc_citations_name()} /> 和 <UiLabel name={m.settings_citation_show_formatted_name()} /> 后，两种变体都可以在实时预览与阅读视图中显示格式化文本。格式化需要 Pandoc 引擎与所选样式。

开启 <UiLabel name={m.settings_citation_pandoc_citations_name()} /> 和 <UiLabel name={m.settings_citation_open_as_links_name()} /> 后，您可以打开被引的文献笔记。在实时预览中直接选择，在源码模式中按住 Ctrl 或 Command 选择。请参阅[正文引文渲染与导航的工作原理](/docs/concepts/how-citekey-links-work)。
