利用引文建议下拉框（Citation Suggester）或命令面板，从您的 Zotero 文献库中快速插入 Markdown 格式的学术引文。

两个入口均会统一检索您在[文献库作用域](/docs/reference/settings#library-scope)中指定的全部文献库，并按相关性排序输出。当有多个文献库参与检索时，每项建议结果都会清晰标明其来源文献库；如果仅有一个文献库在作用域内，该标签会自动省略。

引文插入机制完全独立于文档引文集（Document Citation Set）以及正文引文格式化渲染。即使同时关闭了这两类来源设置并禁用了 <UiLabel name={m.settings_citation_show_formatted_name()} />，引文插入功能依然能够正常使用。

## 打字输入时即时插入

在编辑器中键入 `[@`（或全角中文符号 `【@`）即可激活引文建议下拉框。光标下方将弹出一个包含您 Zotero 条目的下拉列表。

若按需启用了 <UiLabel name={m.settings_citation_at_trigger_name()} /> 设置项，在词边界处（行首、空格后，或前括号与前引号后）直接键入单个 `@` 符号同样能唤起建议菜单。

<Steps>
  <Step>
    ### 唤起引文菜单

    在编辑器中键入 `[@`。建议列表随即在光标下方展开。

    若开启了 <UiLabel name={m.settings_citation_at_trigger_name()} />，在词边界处键入单个 `@` 同样会触发建议。而在单词中间出现的 `@`（例如电子邮箱地址）则会被自动忽略。

  </Step>
  <Step>
    ### 搜索并选择条目

    继续输入关键词以过滤筛选列表。选中所需条目后按 `Enter` 即可完成插入。引文插入后会自动附带一个空格，方便您流畅继续后续书写。

    按 `Enter` 默认插入**主引文（main citation）**，内置的引文文本模板会将其渲染为 `[@citationKey]`。

    单个 `@` 查询会在遇到第一个空格时结束。如需包含空格，可用下划线 `_` 代替：例如输入 `@machine_learning` 即可搜索“machine learning”。而方括号触发词（`[@`）则原生支持直接输入常规空格。

  </Step>
  <Step>
    ### 插入备选引文格式（可选）

    若希望插入**备选引文（alternate citation）**（内置引文文本模板会将其渲染为作者置入正文的 `@citationKey` 形式），可通过以下任一方式实现：

    - 在按 `Enter` 之前，在查询词末尾追加一个斜杠 `/`。
    - 在选中的条目上直接按下 `Shift+Enter`。

    建议菜单底部的操作说明栏清晰提示了这些快捷键组合。

  </Step>
</Steps>

若选中的条目未生成文献引用标识，插入操作会被安全取消并弹出提示通知：“所选条目没有文献引用标识：`{key}`”。

### Suggester settings

- <UiLabel name={m.settings_citation_suggester_name()} /> (default: on): enables
  or disables the inline suggester. Find it in
  <SettingsPath page={m.settings_page_citations()} />.
- <UiLabel name={m.settings_citation_at_trigger_name()} /> (default: off): also
  opens the suggester on a bare `@` at a word boundary. Visible only while
  <UiLabel name={m.settings_citation_suggester_name()} /> is on. Find it in
  <SettingsPath page={m.settings_page_citations()} />.
- <UiLabel name={m.settings_citation_show_citekey_name()} /> (default: off):
  shows each item's citation key beside its title in the suggester list. Find it
  in <SettingsPath page={m.settings_page_citations()} />.

## Insert from the command palette

<Steps>
  <Step>
    ### Open the citation picker

    Open the command palette (`Ctrl+P` on Windows/Linux, `Cmd+P` on macOS) and run:

    <Command name={m.command_insert_citation_name()} />

    A picker appears with your Zotero library.

  </Step>
  <Step>
    ### Select an item

    Search for an item and press `Enter` to insert the main citation.

    Press `Shift+Enter` to insert the alternate citation instead. The modal has no trailing-`/` shortcut; `Shift+Enter` is the only way to ask for the alternate citation here.

  </Step>
</Steps>

## Cite with a Literature Note link

Use this form when the citation must also remain an Obsidian link to its Literature Note.

<Steps>
  <Step>
    ### Enable the citation source

    Open <SettingsPath page={m.settings_page_citations()} /> and turn on <UiLabel name={m.settings_citation_wikilink_citations_name()} />.

  </Step>
  <Step>
    ### Insert an unaliased Literature Note link

    In the citing note, type `[[` and select the Literature Note for the item. Keep the link unaliased.

    For example:

    ```md
    This finding follows the earlier analysis [[Doe 2020]].
    ```

  </Step>
  <Step>
    ### Add citation details when needed

    Add a Citation Fragment to the link target. This example adds page locator `33`:

    ```md
    This finding follows the earlier analysis [[Doe 2020#cite:locator=33]].
    ```

    Replace `Doe 2020` with the exact target of your Literature Note.

  </Step>
</Steps>

The link must resolve to a ZotLit Literature Note. Aliases, embeds, heading fragments, block fragments, unresolved targets, and malformed Citation Fragments stay outside the Document Citation Set.

<Callout type="info">
  A link such as `[[@doe2024]]` does not name a Literature Note unless a note
  with that exact name is the Literature Note for the item. Use `[@doe2024]` for
  a literal citation key.
</Callout>

## When a citation key matches several items [#ambiguous-key]

A citation key can belong to more than one Zotero item, whether the twins sit in one library or in two libraries you have in scope. Inserted text carries the key alone, so it would no longer name the item you picked.

ZotLit therefore refuses the insert, from either entry point, and shows: "Citation key `@{key}` matches multiple Zotero items. Change it in Zotero before inserting a citation." Give one of the items a distinct citation key in Zotero, or narrow your library scope to the library you meant, then insert again.

Keys already written in your notes stay readable. See [How in-text citation rendering and navigation work](/docs/concepts/how-citekey-links-work) for what such a key does in the editor, the citation popover, and the References Sidebar.

## What each gesture inserts [#citation-text]

One template document, the **citation text**, renders every citation you insert. It receives [`zt.variant`](/docs/reference/templates/data#citation-variant), the string `main` or `alt`, and decides what each one renders.

- `main` comes from `Enter` in the suggester or in the command palette picker.
- `alt` comes from `Shift+Enter` in either, or from a trailing `/` in the suggester query. The trailing `/` wins without `Shift`, and the `/` is stripped from the search.

The built-in citation text renders these:

| What you cite                    | Main                    | Alternate                                    |
| -------------------------------- | ----------------------- | -------------------------------------------- |
| One key `smith2024`              | `[@smith2024]`          | `@smith2024`                                 |
| Two keys                         | `[@a2020; @b2021]`      | The first item in text, the rest in brackets |
| A locator of `62`                | `[@smith2024, {p. 62}]` | `@smith2024 [{p. 62}]`                       |
| An item with a suppressed author | `[-@smith2024]`         | `[-@smith2024]`                              |
| An item with a prefix            | `[see @smith2024]`      | A bracketed cluster, the fallback            |

The alternate branch asks Pandoc to prefer the author in text. Where that is not possible (a prefix, or a suppressed author), Pandoc falls back to a bracketed cluster, so the two variants can render the same text. An item with no citation key is dropped from the output.

The rendered citation is normalized to a single line: leading and trailing whitespace is trimmed, and any whitespace run containing a line break collapses to one space. Each insert ends with a trailing space and places the cursor after it; if a space already follows the insert position, it is reused rather than doubled.

To change any of this, edit the <UiLabel name={m.settings_citation_text_name()} /> document. See [Customize the citation text](/docs/how-to/customize-a-template#citation-text), or run <Command inline name={m.command_customize_citation_text_name()} />. The fields your template can read are in [Citation templates](/docs/reference/templates/data#citation-templates).

With <UiLabel name={m.settings_citation_pandoc_citations_name()} /> and <UiLabel name={m.settings_citation_show_formatted_name()} /> on, both variants can show formatted text in Live Preview and reading view. Formatting requires the Pandoc engine and selected style.

With <UiLabel name={m.settings_citation_pandoc_citations_name()} /> and <UiLabel name={m.settings_citation_open_as_links_name()} /> on, you can open the cited Literature Note. Use a click in Live Preview or Ctrl-click or Cmd-click in Source mode. See [How in-text citation rendering and navigation work](/docs/concepts/how-citekey-links-work).
