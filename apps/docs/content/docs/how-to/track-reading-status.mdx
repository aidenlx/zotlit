Keep a reading status, a rating, or another research mark on each paper's Literature Note, and work with it beside the paper's Zotero fields. This page uses a text property, `reading-status`, with the values `to-read`, `reading`, and `read`.

## Before you start

You need a view of items in a query file or a query block. To edit values, use the Table layout. See [Use the Table layout](/docs/how-to/use-query-files#table).

The values live in the properties of your Literature Notes, so Obsidian's Properties panel and Bases show the same values. [Properties from your Literature Notes](/docs/concepts/query-files-and-query-blocks#vault) explains how the view reads them.

## Add a reading status column [#add-column]

<Steps>
  <Step>
    ### Open the properties menu

    Select <UiLabel name={m.query_view_properties()} /> in the view's toolbar.

  </Step>
  <Step>
    ### Add the property

    Type `reading-status` in <UiLabel name={m.query_view_properties_search()} />, then select <UiLabel name={m.query_view_properties_add_vault({ name: "reading-status" })} />.

    When your notes already use the property, the list shows it as `vault.reading-status`. Select its checkbox instead.

  </Step>
</Steps>

The new column reads the `reading-status` property of each paper's Literature Note:

- A value shows as text.
- An empty cell means that the note has no value for the property.
- <UiLabel name={m.query_view_vault_no_note()} /> means that the paper has no
  Literature Note yet.

The List and Cards layouts show the column too. Copy and CSV export include it. To give the column a shorter name, such as "Status", see [Rename a property](/docs/how-to/use-query-files#display-names).

The menu does not offer Obsidian's `tags`, `aliases`, and `cssclasses`, or the keys that ZotLit uses to link a note to its paper. [Vault properties](/docs/reference/query-file-format#vault-reserved) lists them.

## Edit a value in the Table [#edit]

<Steps>
  <Step>
    ### Select the cell

    Select a cell in the column. A field opens in the cell.

  </Step>
  <Step>
    ### Type the value

    Type `reading`.

  </Step>
  <Step>
    ### Save or cancel

    Press `Enter`, or select anywhere outside the cell, to save. Press `Escape` to cancel.

  </Step>
</Steps>

ZotLit writes the value to that one property of the note and leaves the note's other properties as they are. When the note is open in an editor, the change shows there at once. A change that you make in the Properties panel or in the note shows in the cell too.

To clear a value, delete the text and save. The note keeps the property with an empty value. To remove the property from the note, use Obsidian's Properties panel.

The field follows the property type that Obsidian's Properties panel shows for the property:

- A checkbox property toggles when you select it.
- A list property shows its items as chips. Type an item and press `Enter` to add it. Select the cross on a chip to remove it.
- A number property saves only a number.
- A date property opens a date field.

To change the field, change the property type in Obsidian's Properties panel. [Values that an edit writes](/docs/reference/query-file-format#vault-values) lists every type.

A cell with a lock icon is read-only. Its tooltip reads <UiLabel name={m.query_view_vault_managed()} /> The note's [profile](/docs/concepts/profiles) writes this property on every update, such as `title` or `citekey`. To keep your own value, change its merge strategy in [Configure frontmatter properties](/docs/how-to/configure-frontmatter-properties).

## Start tracking a paper without a note [#create]

A cell that reads <UiLabel name={m.query_view_vault_no_note()} /> also takes a value. The first value creates the Literature Note.

<Steps>
  <Step>
    ### Type the value

    Select the cell, type `to-read`, and press `Enter`.

  </Step>
  <Step>
    ### Choose a profile, if asked

    ZotLit creates the note as <UiLabel name={m.query_view_table_create_note()} /> in the literature note column does. When more than one profile fits the paper, a picker opens. See [Choose the profile that creates the note](/docs/how-to/create-and-open-notes#choose-profile).

  </Step>
</Steps>

A notice names the new note, and the cell shows `to-read`. For a checkbox property, one click on the cell creates the note and checks the box.

Selecting the cell creates nothing. An empty value creates nothing either. When you dismiss the profile picker, ZotLit creates no note and shows <UiLabel name={m.query_view_vault_not_written({ name: "reading-status" })} />

### In a Literature Note [#in-note]

A query block or an embed inside a Literature Note can list that note's own paper. That row reads and writes the note that holds the view, even when the paper has a second Literature Note.

## Sort by reading status [#sort]

Select <UiLabel name={m.query_view_sort()} />, then <UiLabel name={m.query_view_sort_add()} />, and choose `vault.reading-status`. The menu lists a property once at least one of your Literature Notes has it.

Papers with no value, and papers without a note, sort last in both directions. Add a Zotero property, such as the date, to break ties.

The view sorts at most 5,000 matching papers. In a larger library, add a filter, such as a Collection, so that fewer papers match. After you edit a value, the rows keep their place until the view runs again.

## Filter by reading status [#filter]

<Steps>
  <Step>
    ### Add a condition

    Select <UiLabel name={m.query_view_filter()} />, then <UiLabel name={m.workbench_match_add_condition()} />, and choose `reading-status`.

  </Step>
  <Step>
    ### Choose the operator and the value

    Choose <UiLabel name={m.workbench_filter_op_is()} /> and type `read`. The condition reads `vault["reading-status"] == "read"` as an expression.

  </Step>
</Steps>

<UiLabel name={m.workbench_filter_op_is_not()} /> and
<UiLabel name={m.workbench_filter_op_is_empty()} /> also match papers that have
no Literature Note. For example, `reading-status`
<UiLabel name={m.workbench_filter_op_is_not()} /> `read` lists every paper that
you have not marked as read, including the ones you have not opened yet.

Keep each condition on a vault property as its own row, in a group of <UiLabel name={m.workbench_match_match_all()} />. The view cannot run when such a condition is:

- Inside a group of <UiLabel name={m.workbench_match_match_any()} /> or <UiLabel name={m.workbench_match_match_none()} />. The row shows <UiLabel name={m.query_view_vault_filter_nested()} />
- In one expression with a Zotero property that `||` or `!` joins, such as `vault.rating > 3 || date.year >= 2020`. The row shows <UiLabel name={m.query_view_vault_filter_mixed()} /> An expression of conditions joined by `&&`, such as `vault.rating > 3 && date.year >= 2020`, runs as separate rows would.

For a checkbox property, choose <UiLabel name={m.workbench_filter_op_is_true()} /> or <UiLabel name={m.workbench_filter_op_is_false()} />. The condition reads `vault["done"] == true` as an expression.

<UiLabel name={m.query_view_search()} /> in the Table does not search vault
properties. In the List and Cards layouts, it does.

## Use the same properties in Bases [#bases]

An Obsidian base reads the same properties of your Literature Notes. This base shows every Literature Note as a card in a Kanban board, with one column for each reading status. It needs Obsidian 1.14 or later.

Save this text as a file named `Reading list.base` in your vault, or paste it into a code block with the language `base` in any note:

```yaml
filters: file.hasProperty("zotero-key")
formulas:
  zotero: 'link("zotero://select/library/items/" + note["zotero-key"], "Open in Zotero")'
views:
  - type: kanban
    name: Reading progress
    groupBy:
      property: note.reading-status
      direction: ASC
    groupOrder:
      - to-read
      - reading
      - read
      - null
    order:
      - file.name
      - note.citekey
      - formula.zotero
```

`file.hasProperty("zotero-key")` keeps the Literature Notes, because ZotLit writes `zotero-key` on each one. A formula reads a name with a hyphen as `note["zotero-key"]`. Drag a card to another column to change its reading status. The Query View shows the change in its own cells.

The <UiLabel name={m.query_view_vault_no_note()} /> rows of the Query View have no card here: a base lists notes, so a paper without a Literature Note does not show.

<Callout type="warn" title="Group libraries">

The `zotero` formula opens papers from My Library only. For a paper in a group library, `zotero-key` holds the key followed by `g` and the group ID, such as `ABCD2345g4815`. Zotero opens that paper at `zotero://select/groups/4815/items/ABCD2345`, which the formula does not build.

</Callout>
