ZotLit can import Zotero child notes as standalone Markdown files in your vault and link to them from the parent literature note.

## How import is triggered

Import is link-driven. When a template or frontmatter expression references the `noteLink` property on a child note, ZotLit imports that note as a Markdown file. If `noteLink` is never referenced, no file is created for that child note.

In Liquid templates, a property access triggers import automatically:

```liquid
{{ note.noteLink }}
```

In frontmatter expressions, mapping over `noteLink` triggers import for each child note:

```liquid
zt.notes | map: "noteLink"
```

Accessing other properties (such as `title`) does not trigger import.

## Import a single child note

When you create, update, or overwrite a literature note whose template or frontmatter references `noteLink`, ZotLit imports the child notes during that operation. No separate command is needed.

<Callout type="info" title="Metadata-only update">
  A metadata-only update (
  <Command inline name={m.command_update_note_metadata_name()} />) re-evaluates
  frontmatter but does not re-render the note body. If a frontmatter expression
  references `noteLink`, child notes are still imported during that update. A
  `noteLink` reference that exists only in the body template has no effect
  during a metadata-only update because the body is not re-rendered.
</Callout>

## Import all child notes at once

<Steps>
  <Step>
    ### Open the parent literature note

    Open the literature note whose child notes you want to import.

  </Step>
  <Step>
    ### Run the import command

    Open the command palette and run:

    <Command name={m.command_import_child_notes_name()} />

    A modal titled <UiLabel name={m.batch_import_child_title()} /> appears. It shows how many child notes will be imported and lists any that are already imported.

    Click <UiLabel name={m.batch_import_confirm_button()} /> to proceed.

  </Step>
</Steps>

This command also appears in the right-click context menu on a literature note file.

## Create-once behavior

Imported notes are created once and not automatically updated. If an imported file already exists for a child note, `noteLink` links to the existing file without re-importing. Editing the Zotero note afterward does not change the imported file.

To bring an imported note up to date, use the re-import commands described below.

If an attachment was skipped because its folder was not approved, a notice lists the blocked source folder. This can happen with a Zotero linked file, which Zotero stores in an external folder instead of its data directory. See [Zotero's guide to linked files](https://www.zotero.org/support/attaching_files#adding_linked_files).

Select <UiLabel name={m.notice_attachment_sources_skipped_action()} />, open <SettingsPath page={m.settings_page_attachments()} setting={m.settings_attachment_approved_name()} />, and approve the folder if you trust it. Then re-import the note to copy the attachment. Approval applies to future imports and does not update earlier imports automatically.

## Re-import a single note

<Steps>
  <Step>
    ### Open an imported note

    Open a note that was previously imported from Zotero (one with a `zotero-note-key` frontmatter field).

  </Step>
  <Step>
    ### Run the update command

    Open the command palette and run:

    <Command name={m.command_reimport_note_name()} />

    A confirmation dialog appears: <UiLabel name={m.modal_reimport_note_title()} />: "Overwrite this file with the latest content from Zotero. Any local edits will be lost."

    Click <UiLabel name={m.modal_reimport_note_confirm()} /> to proceed.

  </Step>
</Steps>

## Import every note in a library or collection [#import-all]

This path imports both kinds of note in one action: the child notes attached to your regular items and the standalone notes filed alongside them.

For the whole library, open the command palette and run:

<Command name={m.command_import_all_notes_name()} />

For one collection, right-click it in the Zotero sidebar and choose <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_collection_import_all_notes.label"]()} />. Nested subcollections are included. The same entry on **My Library** or a group library covers that whole library.

Obsidian opens the <UiLabel name={m.batch_import_title()} /> modal described below, listing every note it found. Review the list, then confirm to start the batch.

The Obsidian command covers every library in your [library scope](/docs/reference/settings#library-scope) (set in <SettingsPath />). The Zotero entries cover the library or collection you right-clicked, whatever your library scope is.

If the collection no longer exists in your Zotero database, Obsidian reports "Collection not found in Zotero." If the library no longer exists, it reports "That Zotero library is not available."

While more than one library contributes notes, the <UiLabel name={m.batch_import_title()} /> modal names the library beside each heading. If a selected library is missing from your Zotero database, the import continues over the rest and states how many libraries it skipped. If none of your selected libraries is available, no modal opens and a notice reports "No library in the library scope is available."

## Re-import notes in batch

ZotLit Companion, the Zotero add-on, starts batch re-import from Zotero.

<Steps>
  <Step>
    ### Select notes in Zotero

    In Zotero, select the notes you want to re-import, child notes under an item, or standalone notes. Right-click to open the context menu, then choose <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_item_import_notes.label"]({ count: 2 })} />.

    (This menu entry appears when the selection contains note items. If you select regular items instead, the menu shows <UiLabel name={m["zotero.menu_item_import_child_notes.label"]()} />, which triggers a different import path.)

  </Step>
  <Step>
    ### Confirm import in Obsidian

    What happens next depends on how many notes you selected:

    **Single note:** If the note has not been imported before, it imports directly and a toast confirms success. If it already exists in the vault, Obsidian shows a confirmation: <UiLabel name={m.modal_import_overwrite_title()} />: "Overwrite `{title}` with the latest content from Zotero? Any local edits will be lost." Click <UiLabel name={m.modal_import_overwrite_confirm()} /> to proceed, or dismiss to cancel.

    **Two or more notes:** Obsidian opens a modal titled <UiLabel name={m.batch_import_title()} />. It groups notes by status:

    - **Import**: new notes that do not yet exist in the vault.
    - **Overwrite**: notes whose Zotero content has changed since the last import.
    - **Up to date**: notes that have not changed in Zotero and are skipped.

    The up-to-date check compares the `zotero-lastmod` frontmatter value in the existing file against the live `dateModified` timestamp in Zotero, rounded to whole seconds.

    Click <UiLabel name={m.batch_import_confirm_button()} /> to proceed.

  </Step>
</Steps>

<Callout type="info" title="Large selections">
  A selection too large to fit in a protocol link falls back to an HTTP
  connection to Obsidian. If the ZotLit server is not enabled in Obsidian,
  Zotero shows a notice asking you to enable it or select fewer items. See [Set
  up live updates](/docs/how-to/set-up-live-updates) for the server setting.
</Callout>

## Import folder

Imported notes are saved to the folder configured in <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_folder_name()} /> (default: `zotero_notes`). The folder is created automatically if it does not exist. Each filename includes a short random suffix to guarantee uniqueness.

## Citations in imported notes

The imported note's body is the Zotero note's HTML converted to Markdown. Citations within it render through your `cite` template.

Each cited reference resolves its citation key in this order:

1. The live Zotero item's own citation key.
2. The citation snapshot embedded in the Zotero note.
3. A visible sentinel: the Zotero item key with `?` appended (e.g. `-@ABC123?` in the default cite template). The trailing `?` makes unresolved citations greppable in your vault.

If every cited reference within a single citation is unresolvable (no citation key from any source), ZotLit keeps that citation's original HTML verbatim. Nothing is lost.

## Use colored highlight syntax

1. Turn on <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_colored_highlights_name()} />.
2. Open <UiLabel name={m.settings_note_import_highlight_mappings_name()} /> to set the output for each Zotero color.
3. Choose <UiLabel name={m.settings_note_import_highlight_mark()} />, a circle emoji (🔴 🟠 🟡 🟢 🔵 🟣), or <UiLabel name={m.settings_note_import_highlight_custom()} />.
4. For <UiLabel name={m.settings_note_import_highlight_custom()} />, enter one emoji in the field below. Combined emoji such as 👩‍🔬 are supported.
5. Import or re-import the note to apply your mappings.

By default, red, orange, yellow, green, blue, and purple use matching circle emoji. Magenta, gray, and plum use colored HTML marks. You can change any of these nine mappings.

An emoji mapping adds the selected emoji at the start of Colored Highlight Syntax:

```markdown
==🔵Highlighted text==
```

Your theme or another plugin must support the selected emoji to render its highlight color. Choosing a custom emoji does not add that rendering support.

The setting applies to highlights created in Zotero's note editor and inline Annotation Excerpts. Annotation Excerpts keep their Zotero backlinks:

```markdown
[==🔵Highlighted text==](zotero://...)
```

Highlights with unrecognized or missing source colors remain HTML. Empty or invalid custom emoji also use HTML marks. ZotLit keeps HTML when the text contains `==` because it conflicts with the Markdown delimiter.

The setting is off by default. Turning it off uses HTML marks and keeps your saved mappings.

Changes affect later imports and re-imports; existing files stay unchanged until re-imported. When <UiLabel name={m.settings_note_import_annotations_template_name()} /> is on, annotation-template output stays unchanged.

## Render annotations from template

By default, annotation paragraphs in imported notes keep the HTML that Zotero inserted: highlighted or underlined excerpts with a citation link.

Turn on <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_annotations_template_name()} /> to render those paragraphs through your `annotation` template instead, producing the same rich callouts used in literature notes.

<Callout type="warn" title="Replace on refresh">
  With this setting on, each annotation's text, comment, color, page, and image
  are taken fresh from Zotero. Edits you made to that paragraph inside the
  imported note are replaced. This is why the setting is off by default.
</Callout>

### What is rendered

Only paragraphs that still match the original Zotero structure are rendered from the template. A paragraph is left untouched when:

- You typed text before the excerpt.
- You added other elements to the paragraph (a second annotation, extra formatting).
- The paragraph is nested inside a list item, blockquote, or table cell.
- The annotation was deleted in Zotero and can no longer be fetched.

Highlight, underline, and image annotations are eligible for template rendering. Note and text annotations (which carry no excerpt) are kept as Zotero inserted them.

<Callout type="warn" title="Text after the citation">
  Text you add after the citation mark (the comment slot) is not protected.
  Zotero places the annotation's own comment in that position, so on refresh it
  is replaced along with the rest of the paragraph. Place notes you want to keep
  in a separate paragraph.
</Callout>
