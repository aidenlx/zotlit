当您的 Zotero 元数据或批注发生改动时，您可以随时刷新文献笔记以保持同步。ZotLit 仅更新由其托管的特定区域，从而完整保护您自己撰写的所有内容。

## 更新单篇笔记

这些命令可以通过 Obsidian 命令面板以及文献笔记文件的右键上下文菜单执行。它们仅在当前活动文件为文献笔记（即包含 `zotero-key` frontmatter 属性）时才会出现。

### 更新完整笔记

<Steps>
  <Step>
    ### 打开文献笔记

    在 Obsidian 中打开您需要更新的文献笔记。

  </Step>
  <Step>
    ### 运行更新命令

    打开命令面板（Windows/Linux 上为 `Ctrl+P`，macOS 上为 `Cmd+P`）并运行：

    <Command name={m.command_update_note_name()} />

    ZotLit 将刷新 frontmatter 属性，并重新渲染受管区域（位于 `%%zt-managed%%` 与 `%%/zt-managed%%` 之间）。您在受管区域之外书写的所有内容均保持完好如初。

    操作完成后弹出通知确认：<UiLabel name={m.notice_updated_note()} />

    图片和墨迹摘录会在笔记写入前准备完毕，期间无需打开任何 PDF 阅读器。发生变动的图片会生成新的文件名；其他笔记以及旧图片文件均会妥善保留现有版本。

    如果刷新失败，ZotLit 会优先保留笔记中已引用的有效旧图片。若无可用图片，则会写入说明文字和源链接。有关汇总统计的定义，请参阅[导入操作结果反馈](/docs/concepts/excerpt-images#import-outcomes)。

  </Step>
</Steps>

### 仅更新元数据

若只需刷新 frontmatter 属性而无需变动笔记正文，请运行：

<Command name={m.command_update_note_metadata_name()} />

随后弹出通知确认：<UiLabel name={m.notice_updated_note_metadata()} />。笔记正文不会受到任何触碰。

### 右键上下文菜单

您也可以在文件资源管理器中右键单击某个文献笔记文件。上下文菜单的 **ZotLit** 分组中提供了 <UiLabel name={m.command_update_note_name()} />、<UiLabel name={m.command_update_note_metadata_name()} />、<UiLabel name={m.command_overwrite_note_name()} /> 以及 <UiLabel name={m.command_copy_item_key_name()} /> 操作。

## 批量更新笔记 [#batch]

可以通过 Zotero 端的必备插件 ZotLit Companion 发起批量更新。

<Steps>
  <Step>
    ### Select items in Zotero

    In Zotero, select one or more items in your library. Right-click to open the context menu, then choose <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_item_update.label"]({ count: 2 })} /> (or <UiLabel name={m["zotero.menu_item_update_metadata.label"]()} /> for metadata only).

  </Step>
  <Step>
    ### Confirm in Obsidian

    Obsidian opens a confirmation dialog titled <UiLabel name={m.batch_update_title()} />. It shows how many notes will be created or updated, grouped by status: <UiLabel name={m.batch_update_group_update({ count: "…" })} />, <UiLabel name={m.batch_update_group_create({ count: "…" })} />, and <UiLabel name={m.batch_update_group_not_found({ count: "…" })} />.

    When your vault holds added profiles, the dialog also carries a profile control for the new notes. See [Choose the profile for new notes](/docs/how-to/create-and-open-notes#bulk-profiles).

    Select <UiLabel name={m.batch_update_confirm_button()} /> to proceed.

  </Step>
  <Step>
    ### Review the summary

    After the batch completes, a summary appears: <UiLabel name={m.batch_update_summary({ created: "…", updated: "…", failed: "…" })} /> With added profiles, the created and updated counts name the profile they ran under, as in <UiLabel name={m.batch_profile_created({ count: "…", label: "…" })} />.

  </Step>
</Steps>

To update every note at once, run <Command inline name={m.command_update_all_notes_name()} /> from the Obsidian command palette. This skips the Zotero selection step and covers every library in your [library scope](/docs/reference/settings#library-scope).

While more than one library contributes items, the confirmation names the library beside each status heading, so identical statuses stay apart. One contributing library keeps the plain headings.

If a selected library is missing from your Zotero database, the run continues over the rest and the confirmation states how many libraries it skipped. If none of your selected libraries is available, no dialog opens and a notice reports <UiLabel name={m.batch_all_no_library_in_scope()} />

<Callout type="info" title="Large selections">
  A selection too large to fit in a protocol link falls back to an HTTP
  connection to Obsidian. If the ZotLit server is not enabled in Obsidian,
  Zotero shows a notice asking you to enable it or select fewer items.
</Callout>

You can also open a single note from Zotero by right-clicking one item and choosing <UiLabel name={m["zotero.menu_item_open.label"]()} /> from the top-level context menu.

## Overwrite a note

<Command inline name={m.command_overwrite_note_name()} /> is a separate,
destructive command. It replaces the entire note body with a fresh render of the
note's [profile document](/docs/reference/templates/profile-document).
Frontmatter keys managed by ZotLit are refreshed; other frontmatter keys you
added are kept.

A confirmation dialog appears before the overwrite proceeds.

Overwrite uses the same [excerpt snapshot rules](/docs/concepts/excerpt-images#saved-snapshots) as a full update. A metadata-only update leaves the note body's image links unchanged.

<Callout type="warn" title="Notes created with ZotLit v1">
  Literature notes created with ZotLit v1 do not have a managed region. Running <UiLabel name={m.command_update_note_name()} /> on a v1 note refreshes its frontmatter but leaves the body untouched, showing the notice <UiLabel name={m.notice_updated_note_no_region()} />

To fully refresh a v1 note's body, use <Command inline name={m.command_overwrite_note_name()} />. It rebuilds the body from the note's profile document. A v1 note carries no `zotlit-profile` field, so the Default profile rebuilds it.

</Callout>
