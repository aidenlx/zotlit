Use the Profile Editor to change a literature note's name, folder, properties, body, or annotation format and preview the result.

## Edit a literature note profile

<Steps>
  <Step>
    ### Open the profile

    In Obsidian, open <SettingsPath />. On the <UiLabel name={m.settings_profile_document_name()} /> row, select <UiLabel name={m.settings_template_customize()} />.

    Customizing the built-in Default creates its document in the configured template folder before editing becomes available. If a custom document already exists, ZotLit opens it. If creation fails, use the retry action beside the error.

    To edit the profile used by an existing literature note, open that note and run <Command name={m.command_customize_note_template_name()} />. The same action is in the note's file menu. ZotLit opens the Profile Editor with that note's item selected.

    From a compact Profile Editor, open its pane menu and select <UiLabel name={m.profile_editor_open_workbench()} />. This opens the editor, Data Explorer, and preview together in a separate Obsidian window.

  </Step>
  <Step>
    ### Choose preview data

    If no item is selected, choose one in Data Explorer or select <UiLabel name={m.workbench_choose_item()} />. You can try a built-in journal article, conference paper, book, or thesis example.

    Choose a library item under <UiLabel name={m.workbench_recently_updated()} />, or select <UiLabel name={m.workbench_search_zotero()} /> to search your Zotero library. Selecting an item replaces the Explorer's list with its fields.

    For annotation formatting, select <UiLabel name={m.workbench_choose_annotation()} />. Search annotations from the selected item or try a highlight, underline, note, text, image, or ink example. Annotation examples keep their own parent item data; the note preview keeps its selected item.

    Choosing data in any linked pane updates the other linked panes. Separate workbenches keep their own selections. Full panels have selection actions in the header; sidebars have a small selection control. Right-click the pane header to access its menu in either layout.

    Data used for the preview updates automatically. To load it again, select <UiLabel name={m.workbench_refresh_item()} /> from the pane menu. In <UiLabel name={m.workbench_preview_on_demand()} /> mode, select <UiLabel name={m.workbench_preview_run()} /> to render the preview.

  </Step>
  <Step>
    ### Edit and preview

    Use the <UiLabel name={m.workbench_tab_note()} />, <UiLabel name={m.workbench_tab_properties()} />, <UiLabel name={m.workbench_tab_annotation()} />, <UiLabel name={m.workbench_tab_match()} />, and <UiLabel name={m.workbench_tab_name_and_folder()} /> tabs to edit the profile. The Default profile does not use <UiLabel name={m.workbench_tab_match()} /> conditions.

    Check the <UiLabel name={m.profile_preview_name()} /> as you edit. Select <UiLabel name={m.workbench_advanced()} /> to edit the complete profile document as Markdown.

    The note name result is labeled <UiLabel name={m.workbench_name_filename_result()} />. The <UiLabel name={m.workbench_tab_match()} /> tab reports <UiLabel name={m.workbench_match_result_yes()} /> or <UiLabel name={m.workbench_match_result_no()} /> for the selected item.

    If the preview fails, retry or choose another item. You can continue editing the profile.

  </Step>
  <Step>
    ### Apply the changes

    The Profile Editor uses Obsidian's automatic saving for edits, Undo, and Redo. A profile with an error remains editable and saves with its diagnostics shown in the editor.

    Existing notes keep their content until you update them. Open a literature note and run <Command name={m.command_update_note_name()} /> to apply its profile.

  </Step>
</Steps>

The Profile Editor supports Liquid, Eta, and JavaScript frontmatter fields. Eta and JavaScript fields require the <UiLabel name={m.settings_template_js_enable_name()} /> gate.

To return this template to its built-in form, select <UiLabel name={m.settings_profile_document_restore()} /> on the same row. ZotLit moves the file to Obsidian's configured trash. You can recover it from there; existing notes keep their content until updated.

## Customize a citation template

Citation templates have separate files. They control citations inserted into notes.

### Create an editable citation template file

<Steps>
  <Step>
    ### Open the citation template settings

    In Obsidian, open <SettingsPath page={m.settings_page_citations()} />. Under the <UiLabel name={m.settings_citation_templates_heading()} /> heading you see one row per citation template: <UiLabel name={m.settings_template_name_cite()} /> and <UiLabel name={m.settings_template_name_cite2()} />.

  </Step>
  <Step>
    ### Create the file

    On the row for the template you want to customize, click the <UiLabel name={m.settings_template_eject()} /> button (pencil-on-file icon). ZotLit copies the built-in default into your vault and opens it in the editor.

    A notice confirms the location: "Template saved to `{path}`."

    The file is created at `<template folder>/zotlit-<name>.liquid.md`, where `<template folder>` is the path configured in <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} /> (default: `templates`).

  </Step>
</Steps>

Each row is independent: create an editable file for one citation template and the other keeps its built-in default.

### Edit the citation template

Open the template file and change its content. Templates use Liquid syntax by default. The file is standard Markdown with embedded `{{ zt.field }}` expressions that pull data from the Zotero item.

To discover which fields are available and copy their paths, use the [Template Data Explorer](/docs/how-to/explore-template-data).

### See changes take effect

ZotLit watches the template folder and recompiles changed files immediately. No plugin reload is needed.

To apply your updated template to an existing literature note, run:

<Command name={m.command_update_note_name()} />

This re-renders the managed region using the current template. To update only frontmatter fields without touching the body, run:

<Command name={m.command_update_note_metadata_name()} />

### Restore a citation template

Two options return a template to its built-in default:

- <UiLabel name={m.settings_template_reset()} /> (rotate icon on the template
  row): replaces the file's contents with the built-in default while keeping the
  file in place. A confirm modal asks: "Replace '`{name}`' with the built-in
  default? Your changes will be lost."
- <UiLabel name={m.settings_template_delete()} /> (trash icon on the template
  row): moves the file to Obsidian's trash. With the file gone, ZotLit falls
  back to the built-in default automatically. The watcher picks up the deletion
  immediately.

### Switch a citation template to Eta (JavaScript)

After enabling the <UiLabel name={m.settings_template_js_enable_name()} /> gate, each template row shows a <UiLabel name={m.settings_template_language_tooltip()} /> dropdown with <UiLabel name={m.settings_template_language_liquid()} /> and <UiLabel name={m.settings_template_language_eta()} /> options. See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates) for the opt-in procedure.

Selecting <UiLabel name={m.settings_template_language_eta()} /> replaces the file. It does not convert syntax between Liquid and Eta.
