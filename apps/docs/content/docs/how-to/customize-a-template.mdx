To make a literature note before changing its template, start with <LessonLink slug="connect-zotero-to-obsidian" />.

1. Open <SettingsPath />. On the <UiLabel name={m.settings_profile_document_name()} /> row, select the pencil button, <UiLabel name={m.settings_profile_edit()} />.
2. Pick a paper to preview with <UiLabel name={m.workbench_choose_item()} />.
3. Edit in the tabs and watch the <UiLabel name={m.workbench_result_heading()} />.
4. Edits save by themselves and apply to new notes. Run <Command inline name={m.command_update_note_name()} /> on an existing note to bring its properties up to date.

What you edit is a **profile**: one file in your template folder (`templates` by default) that writes every literature note of its kind. The Default profile's file is `zotlit-profile.default.md`; ZotLit creates it the first time you select <UiLabel name={m.settings_profile_edit()} />. See [How templates work](/docs/reference/templates/how-templates-work).

## Edit a literature note profile

![The Template Workbench for Rougier et al. (2014), Ten Simple Rules for Better Figures: the Reading notes profile's note template in the editor on the left, the Note preview in the middle with the rendered properties, title, and annotations, and the Fields popover open at the right edge with the paper's fields in sections](/img/how-to/template-workbench-layout.webp)

1. **Open the profile.** In Obsidian, open <SettingsPath />. On the <UiLabel name={m.settings_profile_document_name()} /> row, select the pencil button, tooltip <UiLabel name={m.settings_profile_edit()} />.
   The Template Workbench View opens in its own window with the Preview panel shown, creating `zotlit-profile.default.md` in your template folder if it does not yet exist.
2. **Choose a paper for the preview.** Select <UiLabel name={m.workbench_choose_item()} /> in the row above the panels, then pick a paper under <UiLabel name={m.workbench_recently_updated()} />, choose <UiLabel name={m.workbench_search_zotero()} />, or select a built-in example.
   The editor tabs, Preview panel, and Fields panel show that paper.
3. **Edit a tab.** Select a tab to edit: <UiLabel name={m.workbench_tab_note()} /> (the note body), <UiLabel name={m.workbench_tab_properties()} />, <UiLabel name={m.workbench_tab_annotation()} /> (how one highlight is written), <UiLabel name={m.workbench_tab_name_and_folder()} />, or <UiLabel name={m.workbench_tab_match()} />.
   The <UiLabel name={m.workbench_result_heading()} /> in the Preview panel updates as you type.
4. **Add a field from the paper.** Place your cursor in the template. Select <UiLabel name={m.workbench_view_fields()} /> in the view header, then select the insert button on a field's row, or choose <UiLabel name={m.workbench_fields_put_in_note()} /> from the row menu.
   The field inserts at your cursor and the popover closes. (Hold Shift while selecting the insert button to keep the popover open.)
5. **Let it save.** Edits save automatically as you work, with Obsidian's Undo and Redo.
   New notes use your edited profile. Existing notes stay unchanged; running <Command inline name={m.command_update_note_name()} /> refreshes their properties, while <Command inline name={m.command_overwrite_note_name()} /> replaces the whole body after a confirmation.

For a full guide to every panel, pin, and setting in this view, see the [Template Workbench View reference](/docs/reference/template-workbench-view).

<Accordion title="Use one piece of text in several profiles" id="share-a-partial">

- A **partial** is a reusable template file (`zotlit-partial.<name>.md`) that any profile or citation template can call by name.
- To create one, open <SettingsPath page={m.settings_page_profiles()} setting={m.settings_partials_heading()} /> and select <UiLabel name={m.settings_partial_add()} />. Alternatively, select text inside the workbench editor, right-click it, and choose <UiLabel name={m.template_workbench_extract_partial()} />.
- Call the partial in Liquid using `{% render "authors" with zt as zt %}` (typing `{% render "` lists your partials and inserts the arguments automatically). In Eta, call `<%~ include("authors", zt) %>`.
- For details on naming and parameters, see [Calling a partial](/docs/reference/templates/syntax#calling-a-partial).

</Accordion>

## If you see something else

- **An error when ZotLit creates the document, the first time** → select the retry action beside the error message.
- **The preview is empty or shows no paper** → select <UiLabel name={m.workbench_choose_item()} /> and choose a paper from your library or a built-in example.
- **The preview fails** → retry the preview or pick another paper with <UiLabel name={m.workbench_choose_item()} />. You can keep editing.
- **A note did not change after you edited the body** → run <Command inline name={m.command_update_note_name()} /> to refresh properties. If your profile has no managed block, ZotLit shows <UiLabel name={m.notice_updated_note_no_managed_block()} /> Body edits automatically reach new notes; to rebuild an existing note's body, run <Command inline name={m.command_overwrite_note_name()} />, which replaces the body after a confirmation.
- **An Eta template does nothing** → Eta templates require the <UiLabel name={m.settings_template_js_enable_name()} /> setting to be enabled. Without it, Eta templates remain inert and do not fall back to built-in text. See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates).
- **A partial's call is marked** <UiLabel name={m.workbench_partial_missing()} /> → the partial was renamed or deleted. Edit the partial name in your template call or create the partial file again.
- **A partial's fields come out empty** → the Liquid call is missing its data argument; write `{% render "name" with zt as zt %}`.
