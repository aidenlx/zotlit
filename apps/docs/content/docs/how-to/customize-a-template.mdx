ZotLit ships built-in templates that control how citations are inserted. You can override one by creating an editable file in your vault.

<Callout type="info" title="Literature notes come from a template document">
  The filename, the properties, and the body of a literature note come from its
  Profile's template document, not from a template row in settings. Open it from
  the <UiLabel name={m.settings_profile_document_name()} /> row at{" "}
  <SettingsPath />, or from a Profile's row at{" "}
  <SettingsPath page={m.settings_page_profiles()} />. See
  [Settings](/docs/reference/settings#template-document).
</Callout>

<Callout type="info" title="Looking for a guided walkthrough?">
  The [Customize your annotations](/docs/tutorial/customize-template) tutorial
  walks through a full worked example with before/after results. This page
  covers the general procedure.
</Callout>

## Create an editable template file

<Steps>
  <Step>
    ### Open the citation template settings

    In Obsidian, open <SettingsPath page={m.settings_page_citations()} />. Under the <UiLabel name={m.settings_citation_templates_heading()} /> heading you see one row per citation template: <UiLabel name={m.settings_template_name_cite()} /> and <UiLabel name={m.settings_template_name_cite2()} />.

  </Step>
  <Step>
    ### Create the file

    On the row for the template you want to customize, click the <UiLabel name={m.settings_template_eject()} /> button (pencil-on-file icon). ZotLit copies the built-in default into your vault and opens it in the editor.

    A notice confirms the location: "Template saved to `{path}`."

    The file is created at `<template folder>/zotlit-<name>.liquid.md`, where `<template folder>` is the path configured in <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} /> (default: `templates`).

  </Step>
</Steps>

Each row is independent: create an editable file for one citation template and the other keeps its built-in default.

## Edit the template

Open the template file and change its content. Templates use Liquid syntax by default. The file is standard Markdown with embedded `{{ zt.field }}` expressions that pull data from the Zotero item.

To discover which fields are available and copy their paths, use the [Template Data Explorer](/docs/how-to/explore-template-data).

## See changes take effect

ZotLit watches the template folder and recompiles changed files immediately. No plugin reload is needed.

To apply your updated template to an existing literature note, run:

<Command name={m.command_update_note_name()} />

This re-renders the managed region using the current template. To update only frontmatter fields without touching the body, run:

<Command name={m.command_update_note_metadata_name()} />

## Restore the built-in default

Two options return a template to its built-in default:

- <UiLabel name={m.settings_template_reset()} /> (rotate icon on the template
  row): replaces the file's contents with the built-in default while keeping the
  file in place. A confirm modal asks: "Replace '`{name}`' with the built-in
  default? Your changes will be lost."
- <UiLabel name={m.settings_template_delete()} /> (trash icon on the template
  row): moves the file to Obsidian's trash. With the file gone, ZotLit falls
  back to the built-in default automatically. The watcher picks up the deletion
  immediately.

## Switch to Eta (JavaScript)

After enabling the <UiLabel name={m.settings_template_js_enable_name()} /> gate, each template row shows a <UiLabel name={m.settings_template_language_tooltip()} /> dropdown with <UiLabel name={m.settings_template_language_liquid()} /> and <UiLabel name={m.settings_template_language_eta()} /> options. See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates) for the opt-in procedure.

Selecting <UiLabel name={m.settings_template_language_eta()} /> replaces the file. It does not convert syntax between Liquid and Eta.
