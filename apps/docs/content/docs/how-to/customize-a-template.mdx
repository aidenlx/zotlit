Use the Template Workbench View to change a literature note's name, folder, properties, body, or annotation format, to change the text a citation inserts, or to share a piece of template text between profiles.

## Edit a literature note profile

<Steps>
  <Step>
    ### Open the profile

    In Obsidian, open <SettingsPath />. On the <UiLabel name={m.settings_profile_document_name()} /> row, select <UiLabel name={m.settings_template_customize()} />.

    Customizing the built-in Default creates its document in the configured template folder before editing becomes available. If a custom document already exists, ZotLit opens it. If creation fails, use the retry action beside the error.

    To edit the profile used by an existing literature note, open that note and run <Command name={m.command_customize_note_template_name()} />. The same action is in the note's file menu. ZotLit opens the Template Workbench View with that note's item selected.

    From a compact Template Workbench View, open its pane menu and select <UiLabel name={m.template_workbench_open_layout()} />. This opens the editor, Data Explorer, and preview together in a separate Obsidian window.

  </Step>
  <Step>
    ### Choose preview data

    If no item is selected, choose one in Data Explorer or select <UiLabel name={m.workbench_choose_item()} />. You can try a built-in journal article, conference paper, book, or thesis example.

    Choose a library item under <UiLabel name={m.workbench_recently_updated()} />, or select <UiLabel name={m.workbench_search_zotero()} /> to search your Zotero library. Selecting an item replaces the Explorer's list with its fields.

    For annotation formatting, select <UiLabel name={m.workbench_choose_annotation()} />. Search annotations from the selected item or try a highlight, underline, note, text, image, or ink example. Annotation examples keep their own parent item data; the note preview keeps its selected item.

    Choosing data in any linked pane updates the other linked panes. Separate workbenches keep their own selections. Full panels have selection actions in the header; sidebars have a small selection control. Right-click the pane header to access its menu in either layout.

    Data used for the preview updates automatically. To load it again, select <UiLabel name={m.workbench_refresh_item()} /> from the pane menu. In <UiLabel name={m.workbench_preview_on_demand()} /> mode, select <UiLabel name={m.workbench_preview_run()} /> to render the preview.

  </Step>
  <Step>
    ### Edit and preview

    Use the <UiLabel name={m.workbench_tab_note()} />, <UiLabel name={m.workbench_tab_properties()} />, <UiLabel name={m.workbench_tab_annotation()} />, <UiLabel name={m.workbench_tab_match()} />, and <UiLabel name={m.workbench_tab_name_and_folder()} /> tabs to edit the profile. The Default profile does not use <UiLabel name={m.workbench_tab_match()} /> conditions.

    Check the <UiLabel name={m.profile_preview_name()} /> as you edit. Select <UiLabel name={m.workbench_advanced()} /> to edit the complete profile document as Markdown.

    The note name result is labeled <UiLabel name={m.workbench_name_filename_result()} />. The <UiLabel name={m.workbench_tab_match()} /> tab reports <UiLabel name={m.workbench_match_result_yes()} /> or <UiLabel name={m.workbench_match_result_no()} /> for the selected item.

    If the preview fails, retry or choose another item. You can continue editing the profile.

  </Step>
  <Step>
    ### Apply the changes

    The Template Workbench View uses Obsidian's automatic saving for edits, Undo, and Redo. A profile with an error remains editable and saves with its diagnostics shown in the editor.

    Existing notes keep their content until you update them. Open a literature note and run <Command name={m.command_update_note_name()} /> to apply its profile.

  </Step>
</Steps>

The Template Workbench View supports Liquid, Eta, and JavaScript frontmatter fields. Eta and JavaScript fields require the <UiLabel name={m.settings_template_js_enable_name()} /> gate.

To return this template to its built-in form, select <UiLabel name={m.settings_profile_document_restore()} /> on the same row. ZotLit moves the file to Obsidian's configured trash. You can recover it from there; existing notes keep their content until updated.

## Customize the citation text [#citation-text]

The **citation text** is one template document, `zotlit-citation.md`, that renders every citation you insert. It renders both the main and the alternate citation from one source: [`zt.variant`](/docs/reference/templates/data#citation-variant) tells it which gesture asked for the citation.

<Steps>
  <Step>
    ### Open the citation text

    Open <SettingsPath page={m.settings_page_citations()} />. Find the <UiLabel name={m.settings_citation_text_name()} /> row and select its pencil button, tooltipped <UiLabel name={m.settings_citation_text_open()} />.

    The row's second line shows the document's vault path, or <UiLabel name={m.settings_template_using_default()} /> while your vault holds no file. With no file, that button writes `zotlit-citation.md` from the built-in text first, then opens it.

    Two other entry points open the same document: the command <Command inline name={m.command_customize_citation_text_name()} />, and <UiLabel name={m.template_workbench_open_citation()} /> in the Template Workbench View's pane menu.

  </Step>
  <Step>
    ### Edit the source

    The document opens in the Template Workbench View on one <UiLabel name={m.workbench_tab_citation()} /> tab. There are no <UiLabel name={m.workbench_basic()} /> and <UiLabel name={m.workbench_advanced()} /> modes here: the tab is the source. A caption above the editor names the document's language.

    The template receives `zt.variant`, `zt.citations`, and `zt.items`. See [Citation templates](/docs/reference/templates/data#citation-templates) for the fields on each cited item.

  </Step>
  <Step>
    ### Check the preview

    <UiLabel name={m.workbench_citation_result_heading()} /> renders what you have typed, including bytes you have not saved.

    Its pane menu offers <UiLabel name={m.template_workbench_use_example()} /> with six built-in citation shapes: <UiLabel name={m.workbench_citation_example_one_item()} />, <UiLabel name={m.workbench_citation_example_two_items()} />, <UiLabel name={m.workbench_citation_example_item_with_page()} />, <UiLabel name={m.workbench_citation_example_suppressed_author()} />, <UiLabel name={m.workbench_citation_example_prefix_and_suffix()} />, and <UiLabel name={m.workbench_citation_example_annotation_citation()} />. It opens on <UiLabel name={m.workbench_citation_example_one_item()} />.

    Select <UiLabel name={m.workbench_choose_item()} /> instead to preview one of your own Zotero items, by citation key alone. That clears the example.

    Switch between <UiLabel name={m.template_workbench_preview_main_citation()} /> and <UiLabel name={m.template_workbench_preview_alt_citation()} /> from the same menu to check both branches of your template. The preview caption names the variant on show.

  </Step>
</Steps>

Edits take effect on the next citation you insert. Existing citations in your notes are plain text and stay as written.

### Restore the built-in citation text [#reset-citation-text]

Once the document exists, the <UiLabel name={m.settings_citation_text_name()} /> row also carries a rotate button, tooltipped <UiLabel name={m.settings_template_reset()} />. It asks <UiLabel name={m.settings_citation_text_reset_confirm_title()} /> and then moves your document to Obsidian's configured trash, where you can recover it. New citations use the built-in text again.

## Share a piece of template text between profiles [#share-a-partial]

A **partial** is a template document that any other template renders by name. Write a line once, in `zotlit-partial.<name>.md`, and call it from every profile and from the citation text.

### Create a partial [#create-a-partial]

Three ways, all of which name the file for you:

- Open <SettingsPath page={m.settings_page_profiles()} setting={m.settings_partials_heading()} /> and select <UiLabel name={m.settings_partial_add()} />.
- Type `{% render "` or `{% include "` in a Liquid template, or `include("` in an Eta one. The completion lists every partial in your vault and ends with <UiLabel name={m.workbench_partial_new()} />. The new document opens in a split beside what you were editing.
- Select some template text, right-click it, and choose <UiLabel name={m.template_workbench_extract_partial()} />. ZotLit moves the selection into the new document, leaves the matching call behind, and opens the new document in a split. In the template you extracted from, that is one undo step.

Name a partial with letters, digits, and hyphens. ZotLit trims the name, turns each run of spaces into a hyphen, and lowercases it, so `Journal line` becomes `journal-line`. Names are one flat list for your whole vault, and two partials cannot share a name regardless of case.

Five names belong to other ZotLit templates and are refused: `filename`, `note`, `annotation`, `content`, and `citation`. A file that takes one anyway registers nothing and gets a <UiLabel name={m.settings_partial_reserved_name()} /> row in settings.

### Call a partial [#call-a-partial]

In Liquid:

```liquid
{% render "authors" with zt as zt %}
```

In Eta:

```eta
<%~ include("authors", zt) %>
```

In Liquid, the `with zt as zt` clause is not optional. The `render` tag opens an isolated scope, so a bare `{% render "authors" %}` cannot see the caller's `zt`: every `zt` output in the partial comes out empty, and only its literal text survives. Accepting a name from the completion list writes the clause for you.

Liquid's `{% include %}` tag renders a partial with access to the caller's variables, and needs no `with` clause. Use `render` when you want the partial's scope kept separate. See [Calling a partial](/docs/reference/templates/syntax#calling-a-partial) for the complete rule, and [the Eta form](/docs/reference/templates/eta-syntax#calling-a-partial) for an Eta document.

### Preview and edit a partial [#preview-a-partial]

In a profile's <UiLabel name={m.workbench_basic()} /> mode, a call with a plain quoted name — Liquid `render` or `include`, Eta `include(...)` — is drawn as a **Partial Placeholder**: a compact control carrying the partial's name, the rest of the arguments as written, <UiLabel name={m.workbench_partial_preview()} />, and <UiLabel name={m.workbench_partial_edit()} />. The preview arrow opens a read-only render of that partial below the line, using the data of the slice the call sits in. Put your cursor in the call and the placeholder turns back into plain source, so you can edit the arguments.

The five reserved names are never partial names, so none of them draws one: `{% render "annotation" %}` draws the annotation placeholder for the profile's annotation section, and a call on `filename`, `note`, `content`, or `citation` draws nothing. A call inside a fenced code block is prose about a call, and draws nothing either.

A partial has no data of its own, so its own editor asks you which caller to render as: <UiLabel name={m.template_workbench_preview_as_note()} />, <UiLabel name={m.template_workbench_preview_as_annotation()} />, or <UiLabel name={m.template_workbench_preview_as_citation()} />, from the preview pane menu. It opens on Note and remembers your choice for that file.

### Rename or delete a partial [#rename-a-partial]

Renaming is an ordinary Obsidian file rename. ZotLit has no rename action and rewrites no calls, so every template that called the old name then reports a missing partial on its placeholder, with <UiLabel name={m.workbench_partial_create()} /> and <UiLabel name={m.workbench_partial_pick()} /> to fix that one call.

To delete, open the partial's row at <SettingsPath page={m.settings_page_profiles()} setting={m.settings_partials_heading()} />, open its <UiLabel name={m.workbench_more_actions()} /> menu, and select <UiLabel name={m.settings_partial_delete()} />. ZotLit moves the file to Obsidian's configured trash and rewrites no callers.

A note that ZotLit writes through a template calling a partial your vault no longer holds is not written at all. ZotLit says which partial is missing and offers <UiLabel name={m.template_workbench_open_layout()} /> to open the document holding the failing call.
