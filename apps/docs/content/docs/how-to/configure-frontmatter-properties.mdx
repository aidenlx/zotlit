You can map Zotero data into YAML frontmatter properties that appear at the top of every literature note. ZotLit ships four default fields: `title`, `related`, `collections`, and `citekey`.

<Callout type="info" title="Properties belong to a profile">
  Each profile stores its property rules in its template document. The Profile
  Editor changes those rules and saves the document automatically.
</Callout>

## Add a frontmatter field

<Steps>
  <Step>
    ### Open the Profile Editor

    In Obsidian, open <SettingsPath />. On the <UiLabel name={m.settings_profile_properties_name()} /> row, select <UiLabel name={m.template_workbench_customize()} />.

    The Profile Editor opens on the Default profile. Select the <UiLabel name={m.workbench_tab_properties()} /> tab.

  </Step>
  <Step>
    ### Add a new field

    Select <UiLabel name={m.workbench_properties_add()} />. Each property has these controls:

    - <UiLabel name={m.workbench_properties_name()} /> is the YAML property name written to frontmatter.
    - <UiLabel name={m.workbench_properties_format()} /> selects a Zotero field, fixed text, or a rule.
    - <UiLabel name={m.workbench_properties_expression()} /> is the field value or rule. Use `zt.` paths such as `zt.title` or `zt.DOI` for Zotero data.
    - <UiLabel name={m.workbench_properties_merge()} /> controls how ZotLit applies the value when it updates a note.

  </Step>
  <Step>
    ### Choose a merge strategy

    Three strategies are available:

    | Strategy                                                   | Behavior on update                                                 |
    | ---------------------------------------------------------- | ------------------------------------------------------------------ |
    | <UiLabel name={m.workbench_properties_merge_replace()} /> | Overwrites the field with the new value every time.                |
    | <UiLabel name={m.workbench_properties_merge_append()} />  | Adds new array items without removing existing ones.               |
    | <UiLabel name={m.workbench_properties_merge_keep()} />    | Writes the field only if it does not already exist in frontmatter. |

  </Step>
  <Step>
    ### Check the result

    The Profile Editor saves the property automatically. Check the preview to see the value for the selected paper.

  </Step>
</Steps>

## Add Zotero tags to note frontmatter [#zotero-tags]

Create a managed `tags` field with the `obsidian_tag` filter. The filter reads
Zotero tag objects from `zt.tags` and returns an array of Obsidian tag values.

<Steps>
  <Step>
    ### Add the `tags` field

    In the <UiLabel name={m.workbench_tab_properties()} /> tab, select <UiLabel name={m.workbench_properties_add()} /> and enter these values:

    | Input | Value |
    | ----- | ----- |
    | <UiLabel name={m.workbench_properties_name()} /> | `tags` |
    | <UiLabel name={m.workbench_properties_format()} /> | <UiLabel name={m.workbench_properties_format_value()} /> |
    | <UiLabel name={m.workbench_properties_expression()} /> | `zt.tags \| obsidian_tag` |
    | <UiLabel name={m.workbench_properties_merge()} /> | <UiLabel name={m.workbench_properties_merge_replace()} /> |

    The <UiLabel name={m.workbench_properties_merge_replace()} /> strategy keeps the note's Zotero tags in sync. Choose
    <UiLabel name={m.workbench_properties_merge_append()} /> when you want to keep manual Obsidian tags too.

  </Step>
  <Step>
    ### Update the note

    Run <Command inline name={m.command_update_note_metadata_name()} /> on an
    existing literature note. ZotLit evaluates the field and writes the result
    to its frontmatter.

  </Step>
</Steps>

For example, Zotero tags named `Methodology` and `Open Access` become:

```yaml
tags:
  - Methodology
  - Open_Access
```

The filter normalizes spaces and other characters according to Obsidian's tag
rules. Frontmatter tag values do not need a leading `#`. See the [`obsidian_tag`
filter reference](/docs/reference/templates/syntax#obsidian-tag) for all
normalization rules.

For agent-assisted setup, install the [ZotLit skill](/docs/install-skill) and
ask the agent to add a managed `tags` field with the expression
`zt.tags | obsidian_tag`. The [Template Workbench
CLI](/docs/concepts/template-workbench) lets the agent configure
the field and test the rendered result.

## Edit or remove a field

Select a property row to edit it. Use <UiLabel name={m.workbench_properties_remove()} /> to remove it.

## Reorder fields

The order of the properties in the Profile Editor determines the order of frontmatter keys when ZotLit creates a new literature note. On a new note, the system identity field `zotero-key` follows the configured properties.

Use <UiLabel name={m.workbench_properties_move_up()} /> or <UiLabel name={m.workbench_properties_move_down()} /> to move a property.

### Existing notes

Reordering the fields does not change property order in notes that already exist. When ZotLit updates an existing note, a key already present in that note's YAML keeps its current position.

To reorder properties within a single note, use Obsidian's properties panel: drag the property type icon to the left of a property name to move that row. Obsidian writes the new key order back into the note's YAML. The note must have two or more properties for this to work.

## Validation rules

ZotLit rejects invalid configurations:

- Empty key: "Enter a key."
- Reserved key: "'`{key}`' is managed by ZotLit and can't be used." Reserved keys are `zotero-key`, `zotero-note-key`, and `zotero-lastmod`.
- Duplicate key: "'`{key}`' is already mapped."
- Empty expression: "Enter an expression."
- Syntax error: surfaced on save when the expression fails to compile.

## Apply updated fields to existing notes

After changing frontmatter configuration, run:

<Command name={m.command_update_note_metadata_name()} />

This re-evaluates all field expressions and writes the results to the active note's frontmatter according to each field's merge strategy.

The default `citekey` field uses `zt.citationKey`, Liquid, and <UiLabel name={m.settings_frontmatter_merge_replace()} />. It writes `null` when the Zotero item has no citation key. You can edit or remove this field because it is not reserved.

## Agent-based configuration

An agent with the ZotLit skill can configure managed frontmatter field templates through the [Template Workbench CLI](/docs/concepts/template-workbench).
