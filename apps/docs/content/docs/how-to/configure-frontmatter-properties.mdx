You can map Zotero data into YAML frontmatter properties that appear at the top of every literature note. ZotLit ships four default fields: `title`, `related`, `collections`, and `citekey`.

## Add a frontmatter field

<Steps>
  <Step>
    ### Open the Frontmatter sub-page

    In Obsidian, open **Settings > ZotLit > {m.settings_page_templates()} > {m.settings_page_frontmatter()}**. This sub-page lists all configured user fields.

  </Step>
  <Step>
    ### Add a new field

    Click the add button. A modal opens with four inputs:

    - **{m.settings_frontmatter_key_name()}**: the YAML property name written to frontmatter.
    - **{m.settings_frontmatter_language_name()}**: **{m.settings_frontmatter_language_liquid()}** or **{m.settings_frontmatter_language_javascript()}**. The JavaScript option appears only when the [JavaScript Templates gate](/docs/how-to/enable-javascript-templates) is enabled on that device.
    - **{m.settings_frontmatter_expr_name()}**: the template expression whose output becomes the field value. Use `zt.` paths (e.g. `zt.title`, `zt.DOI`). Browse available paths with the [Template Data Explorer](/docs/how-to/explore-template-data).
    - **{m.settings_frontmatter_merge_name()}**: controls how the value is applied on note update.

  </Step>
  <Step>
    ### Choose a merge strategy

    Three strategies are available:

    | Strategy | Behavior on update |
    |----------|-------------------|
    | **{m.settings_frontmatter_merge_replace()}** | Overwrites the field with the new value every time. |
    | **{m.settings_frontmatter_merge_append()}** | Adds new array items without removing existing ones. |
    | **{m.settings_frontmatter_merge_keep()}** | Writes the field only if it does not already exist in frontmatter. |

  </Step>
  <Step>
    ### Save

    Click **{m.settings_frontmatter_save()}**. If validation passes, the field is added to the list.

  </Step>
</Steps>

## Add Zotero tags to note frontmatter [#zotero-tags]

Create a managed `tags` field with the `obsidian_tag` filter. The filter reads
Zotero tag objects from `zt.tags` and returns an array of Obsidian tag values.

<Steps>
  <Step>
    ### Add the `tags` field

    In **Settings > ZotLit > {m.settings_page_templates()} > {m.settings_page_frontmatter()}**, add a field with these values:

    | Input | Value |
    | ----- | ----- |
    | **{m.settings_frontmatter_key_name()}** | `tags` |
    | **{m.settings_frontmatter_language_name()}** | **{m.settings_frontmatter_language_liquid()}** |
    | **{m.settings_frontmatter_expr_name()}** | `zt.tags \| obsidian_tag` |
    | **{m.settings_frontmatter_merge_name()}** | **{m.settings_frontmatter_merge_replace()}** |

    The <code>{m.settings_frontmatter_merge_replace()}</code> strategy keeps the note's Zotero tags in sync. Choose
    **{m.settings_frontmatter_merge_append()}** when you want to keep manual Obsidian tags too.

  </Step>
  <Step>
    ### Update the note

    Run <Command inline name={m.command_update_note_metadata_name()} /> on an
    existing literature note. ZotLit evaluates the field and writes the result
    to its frontmatter.

  </Step>
</Steps>

For example, Zotero tags named `Methodology` and `Open Access` become:

```yaml
tags:
  - Methodology
  - Open_Access
```

The filter normalizes spaces and other characters according to Obsidian's tag
rules. Frontmatter tag values do not need a leading `#`. See the [`obsidian_tag`
filter reference](/docs/reference/templates/syntax#obsidian-tag) for all
normalization rules.

For agent-assisted setup, install the [ZotLit skill](/docs/install-skill) and
ask the agent to add a managed `tags` field with the expression
`zt.tags | obsidian_tag`. The [Template Workbench](/docs/concepts/template-workbench)
lets the agent configure the field and test the rendered result.

## Edit or remove a field

Click a field's row to reopen the edit modal and change its settings. To remove a field, use the delete control on its row in the Frontmatter list.

## Reorder fields

The order of fields in the Frontmatter list determines the order of frontmatter keys when ZotLit creates a new literature note. On a new note, the system identity field `zotero-key` follows the user-configured fields.

To change the order, drag a field by the handle on its row in **Settings > ZotLit > {m.settings_page_templates()} > {m.settings_page_frontmatter()}**.

### Existing notes

Reordering the list does not change property order in notes that already exist. When ZotLit updates an existing note, a key already present in that note's YAML keeps its current position.

To reorder properties within a single note, use Obsidian's properties panel: drag the property type icon to the left of a property name to move that row. Obsidian writes the new key order back into the note's YAML. The note must have two or more properties for this to work.

## Validation rules

The modal rejects invalid configurations:

- Empty key: "Enter a key."
- Reserved key: "'`{key}`' is managed by ZotLit and can't be used." Reserved keys are `zotero-key`, `zotero-note-key`, and `zotero-lastmod`.
- Duplicate key: "'`{key}`' is already mapped."
- Empty expression: "Enter an expression."
- Syntax error: surfaced on save when the expression fails to compile.

## Apply updated fields to existing notes

After changing frontmatter configuration, run:

<Command name={m.command_update_note_metadata_name()} />

This re-evaluates all field expressions and writes the results to the active note's frontmatter according to each field's merge strategy.

The default `citekey` field uses `zt.citationKey`, Liquid, and **{m.settings_frontmatter_merge_replace()}**. It writes `null` when the Zotero item has no citation key. You can edit or remove this field because it is not reserved.

## Agent-based configuration

An agent with the ZotLit skill can configure managed frontmatter field templates through the Template Workbench CLI. See [Template Workbench](/docs/concepts/template-workbench) for details.

  A frontmatter field with {m.settings_frontmatter_language_name()} set to{" "}
  {m.settings_frontmatter_language_javascript()} is inert when the JavaScript
  Templates gate is off on that device. The settings page shows: "This field is
  inactive because JavaScript templates are disabled on this device." See
  [Enable JavaScript templates](/docs/how-to/enable-javascript-templates).
</Callout>
