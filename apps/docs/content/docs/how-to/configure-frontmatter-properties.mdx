You can map Zotero data into YAML frontmatter properties that appear at the top of every literature note. ZotLit ships four default fields: `title`, `related`, `collections`, and `citekey`.

<Callout type="info" title="The template document is the editor">
  ZotLit 2.1 removed the field list from the settings tab. A Profile's
  properties are defined in its template document, and the{" "}
  <UiLabel name={m.settings_profile_properties_name()} />
  row in settings points at it. The parts of a field described below are
  unchanged.
</Callout>

## Add a frontmatter field

<Steps>
  <Step>
    ### Open the template document

    In Obsidian, open <SettingsPath />. On the <UiLabel name={m.settings_profile_properties_name()} /> row, select <UiLabel name={m.settings_template_eject()} />. ZotLit writes the Profile's template document into your template folder, with the fields it already writes, and opens it.

    On a Profile that already has a template document, the same row offers <UiLabel name={m.settings_template_open()} /> instead.

  </Step>
  <Step>
    ### Add a new field

    Each field has four parts:

    - <UiLabel name={m.settings_frontmatter_key_name()} />: the YAML property name written to frontmatter.
    - <UiLabel name={m.settings_frontmatter_language_name()} />: <UiLabel name={m.settings_frontmatter_language_liquid()} /> or <UiLabel name={m.settings_frontmatter_language_javascript()} />. The JavaScript option appears only when the [JavaScript Templates gate](/docs/how-to/enable-javascript-templates) is enabled on that device.
    - <UiLabel name={m.settings_frontmatter_expr_name()} />: the template expression whose output becomes the field value. Use `zt.` paths (e.g. `zt.title`, `zt.DOI`). Browse available paths with the [Template Data Explorer](/docs/how-to/explore-template-data).
    - <UiLabel name={m.settings_frontmatter_merge_name()} />: controls how the value is applied on note update.

  </Step>
  <Step>
    ### Choose a merge strategy

    Three strategies are available:

    | Strategy                                                  | Behavior on update                                                 |
    | --------------------------------------------------------- | ------------------------------------------------------------------ |
    | <UiLabel name={m.settings_frontmatter_merge_replace()} /> | Overwrites the field with the new value every time.                |
    | <UiLabel name={m.settings_frontmatter_merge_append()} />  | Adds new array items without removing existing ones.               |
    | <UiLabel name={m.settings_frontmatter_merge_keep()} />    | Writes the field only if it does not already exist in frontmatter. |

  </Step>
  <Step>
    ### Save

    Save the template document. If validation passes, the field is written to every literature note the Profile creates or updates.

  </Step>
</Steps>

## Add Zotero tags to note frontmatter [#zotero-tags]

Create a managed `tags` field with the `obsidian_tag` filter. The filter reads
Zotero tag objects from `zt.tags` and returns an array of Obsidian tag values.

<Steps>
  <Step>
    ### Add the `tags` field

    In the template document, add a field with these values:

    | Input | Value |
    | ----- | ----- |
    | <UiLabel name={m.settings_frontmatter_key_name()} /> | `tags` |
    | <UiLabel name={m.settings_frontmatter_language_name()} /> | <UiLabel name={m.settings_frontmatter_language_liquid()} /> |
    | <UiLabel name={m.settings_frontmatter_expr_name()} /> | `zt.tags \| obsidian_tag` |
    | <UiLabel name={m.settings_frontmatter_merge_name()} /> | <UiLabel name={m.settings_frontmatter_merge_replace()} /> |

    The <UiLabel name={m.settings_frontmatter_merge_replace()} /> strategy keeps the note's Zotero tags in sync. Choose
    <UiLabel name={m.settings_frontmatter_merge_append()} /> when you want to keep manual Obsidian tags too.

  </Step>
  <Step>
    ### Update the note

    Run <Command inline name={m.command_update_note_metadata_name()} /> on an
    existing literature note. ZotLit evaluates the field and writes the result
    to its frontmatter.

  </Step>
</Steps>

For example, Zotero tags named `Methodology` and `Open Access` become:

```yaml
tags:
  - Methodology
  - Open_Access
```

The filter normalizes spaces and other characters according to Obsidian's tag
rules. Frontmatter tag values do not need a leading `#`. See the [`obsidian_tag`
filter reference](/docs/reference/templates/syntax#obsidian-tag) for all
normalization rules.

For agent-assisted setup, install the [ZotLit skill](/docs/install-skill) and
ask the agent to add a managed `tags` field with the expression
`zt.tags | obsidian_tag`. The [Template Workbench](/docs/concepts/template-workbench)
lets the agent configure the field and test the rendered result.

## Edit or remove a field

Edit a field in the template document to change its settings. To remove a field, delete it from the document.

## Reorder fields

The order of the fields in the template document determines the order of frontmatter keys when ZotLit creates a new literature note. On a new note, the system identity field `zotero-key` follows the user-configured fields.

To change the order, move the field in the template document.

### Existing notes

Reordering the fields does not change property order in notes that already exist. When ZotLit updates an existing note, a key already present in that note's YAML keeps its current position.

To reorder properties within a single note, use Obsidian's properties panel: drag the property type icon to the left of a property name to move that row. Obsidian writes the new key order back into the note's YAML. The note must have two or more properties for this to work.

## Validation rules

ZotLit rejects invalid configurations:

- Empty key: "Enter a key."
- Reserved key: "'`{key}`' is managed by ZotLit and can't be used." Reserved keys are `zotero-key`, `zotero-note-key`, and `zotero-lastmod`.
- Duplicate key: "'`{key}`' is already mapped."
- Empty expression: "Enter an expression."
- Syntax error: surfaced on save when the expression fails to compile.

## Apply updated fields to existing notes

After changing frontmatter configuration, run:

<Command name={m.command_update_note_metadata_name()} />

This re-evaluates all field expressions and writes the results to the active note's frontmatter according to each field's merge strategy.

The default `citekey` field uses `zt.citationKey`, Liquid, and <UiLabel name={m.settings_frontmatter_merge_replace()} />. It writes `null` when the Zotero item has no citation key. You can edit or remove this field because it is not reserved.

## Agent-based configuration

An agent with the ZotLit skill can configure managed frontmatter field templates through the Template Workbench CLI. See [Template Workbench](/docs/concepts/template-workbench) for details.
