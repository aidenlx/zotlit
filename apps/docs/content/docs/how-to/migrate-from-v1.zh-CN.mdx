ZotLit v2 会在原位置直接替换 v1。基础设置会在首次加载时自动迁移；但如果您自定义过 Eta 模板，在您重命名文件、更新数据变量名并开启 <UiLabel name={m.settings_template_js_enable_name()} /> 权限开关之前，它们将不会被加载。您在 v1 中创建的笔记依然会被系统索引正常识别；当您需要增量式正文更新支持时，对其执行覆盖操作即可。

<Callout type="info" title="需要您留意的关键事项">

- **恢复自定义笔记生成效果的必备操作：** 将模板文件重命名为 v2 规范格式，将代码中的 `it.*` 全面替换为 `zt.*`，并[开启 <UiLabel name={m.settings_template_js_enable_name()} /> 权限开关](/docs/how-to/enable-javascript-templates)。若未完成这些步骤，v2 将回退到内置的默认模板，无法体现您先前的自定义效果。
- **自动迁移（无需任何手动操作）：** 插件基础设置，包括文件夹路径以及自定义 frontmatter 属性。它们会在首次加载时自动完成转换迁移。
- **可选操作：** 对旧的 v1 笔记执行 <Command inline name={m.command_overwrite_note_name()} />，以注入受管区域标记，从而享受后续的增量式正文更新。

</Callout>

## 安装 v2

<Steps>
  <Step>
    ### 安装 v2 插件

    ZotLit v2 使用与 v1 完全相同的插件 ID（`zotlit`）。当您安装 v2 时，Obsidian 会直接就地覆盖替换 v1。没有独立的次级插件条目，也无需手动预先卸载。该插件仅限桌面端运行。

  </Step>
  <Step>
    ### 在 Obsidian 中确认

    升级完成后，打开**设置 → ZotLit**。设置面板将加载显示迁移后的配置。如果您能看到之前的文献笔记文件夹路径以及模板文件夹路径，则说明自动迁移已经成功完成。

  </Step>
</Steps>

升级完成后，v1 的代码即被完全取代。如果您在过渡期间需要查阅原有的老版使用文档，<a href={zotlitLegacyUrl} target="_blank" rel="noreferrer noopener">ZotLit v1 文档</a>依然保持在线可用。

## 设置项迁移（全自动）

在升级后的首次启动期间，ZotLit 会自动侦测到您的 v1 设置并立即执行迁移。针对基础设置项您无需进行任何手动操作。该迁移仅运行一次并将结果持久化落盘；即使发生写入异常也只会记录到日志中，绝不会阻断插件的正常加载。

具体迁移内容包括：

- 您的文献笔记保存目录以及模板存放文件夹路径。
- 自定义 frontmatter 属性字段，将保留为 JavaScript 语言字段。您从未自定义过的字段（即沿用 v1 默认值的字段）会自动转换为现代的 Liquid 语法。
- 内嵌的模板源码（例如笔记文件名模板的正文）不会直接迁移，因为 v2 采用了全新的数据体系规范（由 v1 的 `it.*` 全面升级为 `zt.*`）。v2 改为直接从仓库中的模板文件读取配置。

<Callout type="info" title="JavaScript 语言字段需要开启权限开关">
  迁移为 JavaScript 语言的自定义 frontmatter 字段需要开启{" "}
  <UiLabel name={m.settings_template_js_enable_name()} />{" "}
  开关才能执行计算。在您开启之前，笔记更新时会暂时跳过这些字段，并弹出通知列出跳过的字段项。有关开启授权的步骤，请参阅[启用
  JavaScript 模板](/docs/how-to/enable-javascript-templates)。
</Callout>

## Migrate templates

V2 reads template files whose name starts with `zotlit-`. V1 files used the `zt-` prefix (for example, `zt-note.eta.md`), which v2 does not read. Until you rename them, v2 does not load your custom templates and falls back to the built-in defaults.

V1 templates were written in Eta (JavaScript). In v2, Eta templates require the <UiLabel name={m.settings_template_js_enable_name()} /> gate: a per-device opt-in stored outside synced settings, disabled by default. Until the gate is on:

- Eta template files (`.eta.md`) that v2 reads are inert. A notice names the file and explains that JavaScript templates are disabled.
- JavaScript-language frontmatter fields are also inert. A notice lists the skipped fields when you update a note.

If you customized your Eta templates, these three steps are required to restore note generation:

1. **Rename** your template files to the v2 pattern (`zt-` to `zotlit-`, `annots` to `content`).
2. **Replace `it.*` with `zt.*`** throughout your templates.
3. **Enable** the <UiLabel name={m.settings_template_js_enable_name()} /> gate on each device where you use ZotLit.

Your renamed note, content, and annotation files then render as the pieces of one literature note profile, and your two citation files render the text a citation inserts. ZotLit offers to fold them into v2's template documents in one verified pass, from the Welcome view or from a reminder row at the top of settings.

Follow [Migrate v1 Eta templates](/docs/how-to/migrate-v1-eta-templates) for the full procedure, including field-by-field mappings, [the conversion pass](/docs/how-to/migrate-v1-eta-templates#convert), and an optional Liquid conversion path.

<Callout type="info" title="Never customized your templates?">
  If you used only the v1 defaults, no action is needed. V2 ships updated
  defaults in Liquid that work without the{" "}
  <UiLabel name={m.settings_template_js_enable_name()} />
  gate.
</Callout>

## Annotations in imported notes

When you import a Zotero note into your vault, v2 converts the annotation content already in the note directly. Highlights and underlines become inline marks with a `zotero://` backlink, image excerpts become embeds, and your typed comments are kept as written. If you edited an annotation paragraph inside Zotero before importing, those edits are preserved. V1 re-rendered every annotation through the annotation template instead, which discarded in-place edits.

To restore v1-style rendering, enable <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_annotations_template_name()} />. The toggle is off by default. When on, annotation paragraphs are re-rendered through your annotation template with data pulled fresh from Zotero.

<Callout
  type="warn"
  title="Edits in Zotero are discarded when this setting is on"
>
  This is the same behavior v1 had: annotations are re-rendered from Zotero's
  stored data, so any edits you made to annotation paragraphs inside the Zotero
  note are not preserved. Paragraphs you restructured or added prose to fall
  back to the direct conversion.
</Callout>

## Refresh v1 notes [#refresh-v1-notes]

V2 recognizes your existing literature notes by their `zotero-key` frontmatter value. They appear in the note index, and <Command inline name={m.command_update_note_metadata_name()} /> refreshes their frontmatter. However, v1 notes lack a managed region (the `%%zt-managed%%` markers that v2 uses to separate generated content from your writing), so incremental body updates cannot target them.

Adding the managed region is optional. You do not need to do it immediately or for every note. When you are ready:

<Steps>
  <Step>
    ### Open a v1 literature note

    Open any note that was created by ZotLit v1.

  </Step>
  <Step>
    ### Run the overwrite command

    Open the command palette and run:

    <Command name={m.command_overwrite_note_name()} />

    A confirmation modal appears. Select <UiLabel name={m.modal_overwrite_note_confirm()} /> to proceed. ZotLit regenerates the entire note body from the current note template. Managed frontmatter keys are refreshed; other frontmatter keys you added are kept.

  </Step>
  <Step>
    ### Verify the managed region

    After overwriting, the note contains `%%zt-managed%%` markers. It now responds to <Command inline name={m.command_update_note_name()} /> for incremental updates.

  </Step>
</Steps>

<Callout type="info" title="Why overwrite instead of update?">
  The managed region is what lets ZotLit replace generated content while
  preserving your writing. V1 notes lack these markers, so there is no boundary
  for an incremental update to target. See [Literature notes and the managed
  region](/docs/concepts/literature-notes-and-the-managed-region) for more
  detail.
</Callout>

## Retired features

Two v1 workflows are not carried forward into v2.

**Annotation merging.** V1 could merge annotations from multiple PDF attachments or deduplicate them across updates. V2 does not include this workflow. Annotations are rendered per-attachment as they appear in Zotero.

**Topic-based imports.** V1 let you subscribe a note to a Zotero tag (`#zt-topic/<name>`) so that new items with that tag were automatically imported as literature notes. V2 does not include this workflow.
