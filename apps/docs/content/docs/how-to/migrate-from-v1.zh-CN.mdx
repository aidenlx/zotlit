ZotLit v2 会就地替换 v1。设置会在首次加载时自动迁移，但如果你自定义了 Eta 模板，则必须先重命名模板、更新数据词汇并启用 <UiLabel name={m.settings_template_js_enable_name()} /> 开关后，模板才会被加载。使用 v1 创建的笔记仍会显示在索引中。当你需要增量更新正文时，覆盖这些笔记即可。

<Callout type="info" title="需要你注意的事项">

- **恢复笔记生成所需操作：** 将模板文件重命名为 v2 规范命名，将 `it.*` 替换为 `zt.*`，并[启用 <UiLabel name={m.settings_template_js_enable_name()} /> 开关](/docs/how-to/enable-javascript-templates)。若缺少这些步骤，v2 将回退到内置默认模板，不会体现你的自定义内容。
- **自动完成（无需操作**）： 设置（包括文件夹路径和自定义属性字段）会在首次加载时自动迁移。
- **可选操作：** 对 v1 笔记运行 <Command inline name={m.command_overwrite_note_name()} />，以添加用于增量更新正文的托管区域。这需要包含托管块的模板，例如重命名后的 `zotlit-content` 文件；内置默认模板不包含托管块。

</Callout>

## 安装 v2 [#install-v2]

<Steps>
  <Step>
    ### 安装 v2 插件 [#install-the-v2-plugin]

    ZotLit v2 使用与 v1 相同的插件 ID（`zotlit`）。安装 v2 时，Obsidian 会直接替换 v1。没有独立的插件条目，也无需手动卸载。该插件仅支持桌面端。

  </Step>
  <Step>
    ### 在 Obsidian 中确认 [#confirm-in-obsidian]

    升级完成后，打开**设置 > ZotLit**（Settings > ZotLit）。设置面板将加载已迁移的配置。如果你看到了文献笔记文件夹路径和模板文件夹路径，则说明迁移成功。

  </Step>
</Steps>

升级完成后，v1 将被完全替换。如果你在过渡期间需要查阅原有文档，[ZotLit v1 文档](https://zotlit-v1.aidenlx.site)仍然可供访问。

## 设置（自动迁移） [#settings-automatic]

升级后的首次加载时，ZotLit 会检测到你的 v1 设置并自动完成迁移。设置方面无需任何手动操作。迁移仅运行一次并持久保存结果；写入失败会记录到日志中，但绝不会阻止插件加载。

迁移保留的内容：

- 你的文献笔记文件夹和模板文件夹路径。
- 自定义属性字段，保留为 JavaScript 语言字段。从未自定义的字段（仍使用 v1 默认值）会转换为 Liquid。
- 内嵌的模板源码（例如文件名模板正文）不会被迁移，因为 v2 使用了不同的数据词汇（使用 `zt.*` 替代了 v1 的 `it.*`）。V2 会从仓库文件中读取模板。

<Callout type="info" title="JavaScript 语言字段需要开启安全开关">
  作为 JavaScript 迁移过来的自定义属性字段需要开启
  <UiLabel name={m.settings_template_js_enable_name()} /> 开关才能执行求值。
  在启用之前，更新笔记时会跳过这些字段，并弹出提示列出被跳过的字段。有关启用步骤，请参阅[启用
  JavaScript 模板](/docs/how-to/enable-javascript-templates)。
</Callout>

## 迁移模板 [#migrate-templates]

V2 会读取名称以 `zotlit-` 开头的模板文件。V1 文件使用的是 `zt-` 前缀（例如 `zt-note.eta.md`），v2 不会读取它们。在重命名之前，v2 不会加载你的自定义模板，而是回退到内置默认值。

V1 模板是用 Eta（JavaScript）编写的。在 v2 中，Eta 模板需要通过 <UiLabel name={m.settings_template_js_enable_name()} /> 开关授权：这是一项按设备保存且独立于同步设置的选项，默认处于关闭状态。在该开关开启之前：

- v2 读取的 Eta 模板文件（`.eta.md`）不会执行。系统会提示文件名并说明 JavaScript 模板已禁用。
- JavaScript 语言的属性字段也不会执行。更新笔记时，系统会弹出提示列出被跳过的字段。

如果你自定义了 Eta 模板，需要完成以下三个步骤才能恢复笔记生成：

1. **重命名**模板文件为 v2 命名规范（将 `zt-` 改为 `zotlit-`，将 `annots` 改为 `content`）。
2. 在所有模板中**将 `it.*` 替换为 `zt.*`**。
3. 在使用 ZotLit 的每台设备上**启用** <UiLabel name={m.settings_template_js_enable_name()} /> 开关。

重命名后的笔记、内容和标注文件随后会作为单个文献笔记配置方案的各个组成部分进行渲染，而两个引文文件则用于渲染插入的引文文本。ZotLit 支持在文库视图上方的设置横幅中，或设置顶部的提醒栏中，通过一次校验流程将它们整合进 v2 的模板文档中。

完整流程请参阅[迁移 v1 Eta 模板](/docs/how-to/migrate-v1-eta-templates)，其中包含[转换流程](/docs/how-to/migrate-v1-eta-templates#convert)以及可选的 Liquid 转换路径。逐字段的对应关系请参阅[与 v1 的差异](/docs/reference/templates/eta-syntax#v1-changes)。

<Callout type="info" title="从未自定义过模板？">
  如果你只使用过 v1 的默认模板，则无需执行任何操作。V2 附带了更新后的 Liquid
  默认模板，无需开启 <UiLabel name={m.settings_template_js_enable_name()} />
  开关即可直接使用。
</Callout>

## 导入笔记中的标注 [#annotations-in-imported-notes]

当将 Zotero 笔记导入仓库时，v2 会直接转换笔记中已有的标注内容。高亮和下划线会变为带有 `zotero://` 反向链接的行内标记，图片摘录会变为嵌入内容，你输入的评论也会原样保留。如果在导入前已在 Zotero 内编辑过标注段落，这些编辑同样会得到保留。而在 v1 中，系统会通过标注模板重新渲染每个标注，从而丢失就地编辑的内容。

若要恢复 v1 风格的渲染方式，请启用 <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_annotations_template_name()} />。该开关默认处于关闭状态。开启后，标注段落将使用从 Zotero 最新提取的数据，通过标注模板重新渲染。

<Callout type="warn" title="开启此设置后在 Zotero 中的编辑将被丢弃">
  这与 v1 的行为一致：标注会从 Zotero 存储的数据中重新渲染，因此你在 Zotero
  笔记内对标注段落所做的任何编辑都不会保留。重构过或添加了正文的段落将回退到直接转换。
</Callout>

## 刷新 v1 笔记 [#refresh-v1-notes]

V2 通过 `zotero-key` 属性值识别你现有的文献笔记。它们会显示在笔记索引中，且 <Command inline name={m.command_update_note_metadata_name()} /> 可以刷新它们的属性。但是，v1 笔记缺少托管区域（v2 用于区分生成内容与个人撰写内容的 `%%zt-managed%%` 标记），因此无法对其进行正文增量更新。

添加托管区域是可选的。你无需立即处理，也无需处理所有笔记。准备好后：

<Steps>
  <Step>
    ### 打开一篇 v1 文献笔记 [#open-a-v1-literature-note]

    打开由 ZotLit v1 创建的任意笔记。

  </Step>
  <Step>
    ### 运行覆盖命令 [#run-the-overwrite-command]

    打开命令面板（Command palette）并运行：

    <Command name={m.command_overwrite_note_name()} />

    此时会出现确认弹窗。选择 <UiLabel name={m.modal_overwrite_note_confirm()} /> 继续。ZotLit 将根据当前笔记模板重新生成整篇笔记正文。受托管的属性键会被刷新；你自行添加的其他属性键则会保留。

  </Step>
  <Step>
    ### 验证托管区域 [#verify-the-managed-region]

    当你的模板包含托管块时，覆盖后的笔记将包含 `%%zt-managed%%` 标记。此时它即可响应 <Command inline name={m.command_update_note_name()} /> 命令进行增量更新。内置默认模板不包含托管块，因此其正文只渲染一次，后续更新仅刷新属性。

  </Step>
</Steps>

<Callout type="info" title="为什么是覆盖而不是更新？">
  托管区域是 ZotLit 在替换生成内容的同时保留你撰写文字的关键。V1
  笔记缺少这些标记，因此增量更新没有明确的作用边界。详细信息请参阅[文献笔记与托管区域](/docs/reference/literature-notes)。
</Callout>

## 已弃用的功能 [#retired-features]

v1 中的两项工作流未延续到 v2 中。

**标注合并**。 v1 可以合并来自多个 PDF 附件的标注，或在更新时对其去重。v2 不再包含此工作流。标注将按照其在 Zotero 中的呈现方式按附件分别渲染。

**基于主题的导入。** v1 允许将笔记订阅到某个 Zotero 标签（`#zt-topic/<name>`），从而带有该标签的新条目会自动作为文献笔记导入。v2 不再包含此工作流。
