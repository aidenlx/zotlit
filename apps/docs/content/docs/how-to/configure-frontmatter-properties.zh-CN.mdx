您可以将 Zotero 数据映射为呈现于每篇文献笔记顶部的 YAML frontmatter 属性。ZotLit 预设了四个默认字段：`title`、`related`、`collections` 以及 `citekey`。

<Callout type="info" title="属性规则归属于特定配置方案">
  每个配置方案都会在其配置方案文档的 manifest
  中保存自己的属性规则。模板工作台视图能够直接修改这些规则并自动保存文档。有关
  manifest
  的格式，请参阅[配置方案文档](/docs/reference/templates/profile-document)；有关字段机制、合并策略以及系统保留键，请参阅[Frontmatter
  属性](/docs/reference/templates/frontmatter)。
</Callout>

## 添加 frontmatter 字段

<Steps>
  <Step>
    ### 打开模板工作台视图

    在 Obsidian 中，打开 <SettingsPath />。在 <UiLabel name={m.settings_profile_document_name()} /> 所在行，点击其铅笔图标按钮（提示文本为 <UiLabel name={m.settings_profile_edit()} />）。

    模板工作台视图将打开并加载默认配置方案。切换到 <UiLabel name={m.workbench_tab_properties()} /> 标签页。

  </Step>
  <Step>
    ### 添加新字段

    点击 <UiLabel name={m.workbench_properties_add()} />。每个属性包含以下控制项：

    - <UiLabel name={m.workbench_properties_name()} />：写入 frontmatter 的 YAML 属性键名。
    - <UiLabel name={m.workbench_properties_format()} />：选择 <UiLabel name={m.workbench_properties_format_value()} />、<UiLabel name={m.workbench_properties_format_text()} /> 或 <UiLabel name={m.workbench_properties_format_rule()} />。
    - <UiLabel name={m.workbench_properties_expression()} />：字段值或计算规则。使用形如 `zt.title` 或 `zt.DOI` 的 `zt.` 路径读取 Zotero 数据。
    - <UiLabel name={m.workbench_properties_merge()} />：控制 ZotLit 在更新笔记时如何处理现有值。

  </Step>
  <Step>
    ### 选择合并策略

    使用 <UiLabel name={m.workbench_properties_merge_replace()} /> 在每次更新时无条件覆盖该字段；使用 <UiLabel name={m.workbench_properties_merge_append()} /> 追加新的数组元素并保留笔记中已有的项；使用 <UiLabel name={m.workbench_properties_merge_keep()} /> 仅在笔记中该属性为空时才写入。关于各策略的详细行为说明，请参阅[合并策略](/docs/reference/templates/frontmatter#merge-strategies)。

  </Step>
  <Step>
    ### 检查预览结果

    模板工作台视图会自动保存新属性。在右侧预览中直接查看当前选定论文所生成的属性取值。

  </Step>
</Steps>

## Add Zotero tags to note frontmatter [#zotero-tags]

Create a managed `tags` field with the `obsidian_tag` filter. The filter reads
Zotero tag objects from `zt.tags` and returns an array of Obsidian tag values.

<Steps>
  <Step>
    ### Add the `tags` field

    In the <UiLabel name={m.workbench_tab_properties()} /> tab, select <UiLabel name={m.workbench_properties_add()} /> and enter these values:

    | Input | Value |
    | ----- | ----- |
    | <UiLabel name={m.workbench_properties_name()} /> | `tags` |
    | <UiLabel name={m.workbench_properties_format()} /> | <UiLabel name={m.workbench_properties_format_value()} /> |
    | <UiLabel name={m.workbench_properties_expression()} /> | `zt.tags \| obsidian_tag` |
    | <UiLabel name={m.workbench_properties_merge()} /> | <UiLabel name={m.workbench_properties_merge_replace()} /> |

    The <UiLabel name={m.workbench_properties_merge_replace()} /> strategy keeps the note's Zotero tags in sync. Choose
    <UiLabel name={m.workbench_properties_merge_append()} /> when you want to keep manual Obsidian tags too.

  </Step>
  <Step>
    ### Update the note

    Run <Command inline name={m.command_update_note_metadata_name()} /> on an
    existing literature note. ZotLit evaluates the field and writes the result
    to its frontmatter.

  </Step>
</Steps>

For example, Zotero tags named `Methodology` and `Open Access` become:

```yaml
tags:
  - Methodology
  - Open_Access
```

The filter normalizes spaces and other characters according to Obsidian's tag
rules. Frontmatter tag values do not need a leading `#`. See the [`obsidian_tag`
filter reference](/docs/reference/templates/syntax#obsidian-tag) for all
normalization rules.

For agent-assisted setup, install the [ZotLit skill](/docs/install-skill) and
ask the agent to add a managed `tags` field with the expression
`zt.tags | obsidian_tag`. The [Template Workbench
CLI](/docs/concepts/template-workbench) lets the agent configure
the field and test the rendered result.

## Edit or remove a field

Select a property row to edit it. Use <UiLabel name={m.workbench_properties_remove()} /> to remove it.

## Reorder fields

The order of the properties in the Template Workbench View determines the order of frontmatter keys when ZotLit creates a new literature note.

Use <UiLabel name={m.workbench_properties_move_up()} /> or <UiLabel name={m.workbench_properties_move_down()} /> to move a property.

### Existing notes

Reordering the fields does not change property order in notes that already exist. When ZotLit updates an existing note, a key already present in that note's YAML keeps its current position.

To reorder properties within a single note, use Obsidian's properties panel: drag the property type icon to the left of a property name to move that row. Obsidian writes the new key order back into the note's YAML. The note must have two or more properties for this to work.

## Validation rules

The <UiLabel name={m.workbench_tab_properties()} /> tab marks a row it cannot use with <UiLabel name={m.workbench_properties_row_problem()} />, and the <UiLabel name={m.workbench_problems_heading()} /> area names what went wrong and offers <UiLabel name={m.workbench_problems_where_entry()} /> to open the row.

See [Validation](/docs/reference/templates/frontmatter#validation) for the rules ZotLit applies, and [Edit a profile as Markdown](/docs/how-to/edit-a-profile-as-markdown#problems) for the area that reports them.

## Apply updated fields to existing notes

After changing frontmatter configuration, run:

<Command name={m.command_update_note_metadata_name()} />

This re-evaluates all field expressions and writes the results to the active note's frontmatter according to each field's merge strategy.

The shipped fields are ordinary entries, so you can edit or remove `citekey` here. See [Default fields](/docs/reference/templates/frontmatter#default-fields) for what the Default profile declares.

## Agent-based configuration

An agent with the ZotLit skill can configure managed frontmatter field templates through the [Template Workbench CLI](/docs/concepts/template-workbench).

<Callout type="info" title="JavaScript fields and the gate">
  A property declares its value with one member. `expr` holds one Liquid
  expression, `value` holds one JSON-e rule (fixed text is a rule that is a
  plain string), and `js` holds one JavaScript expression. A `js` property is
  inert while <UiLabel name={m.settings_template_js_enable_name()} /> are off on
  that device, and ZotLit reports the affected fields:{" "}
  <UiLabel name={m.notice_frontmatter_js_inert({ fields: "…" })} /> See [Enable
  JavaScript templates](/docs/how-to/enable-javascript-templates).
</Callout>
