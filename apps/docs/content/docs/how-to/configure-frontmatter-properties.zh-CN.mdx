您可以将 Zotero 数据映射为呈现于每篇文献笔记顶部的 YAML frontmatter 属性。ZotLit 预设了四个默认字段：`title`、`related`、`collections` 以及 `citekey`。

<Callout type="info" title="属性规则归属于特定配置方案">
  每个配置方案都会在其配置方案文档的 manifest
  中保存自己的属性规则。模板工作台视图能够直接修改这些规则并自动保存文档。有关
  manifest
  的格式，请参阅[配置方案文档](/docs/reference/templates/profile-document)；有关字段机制、合并策略以及系统保留键，请参阅[Frontmatter
  属性](/docs/reference/templates/frontmatter)。
</Callout>

## 添加 frontmatter 字段

<Steps>
  <Step>
    ### 打开模板工作台视图

    在 Obsidian 中，打开 <SettingsPath />。在 <UiLabel name={m.settings_profile_document_name()} /> 所在行，点击其铅笔图标按钮（提示文本为 <UiLabel name={m.settings_profile_edit()} />）。

    模板工作台视图将打开并加载默认配置方案。切换到 <UiLabel name={m.workbench_tab_properties()} /> 标签页。

  </Step>
  <Step>
    ### 添加新字段

    点击 <UiLabel name={m.workbench_properties_add()} />。每个属性包含以下控制项：

    - <UiLabel name={m.workbench_properties_name()} />：写入 frontmatter 的 YAML 属性键名。
    - <UiLabel name={m.workbench_properties_format()} />：选择 <UiLabel name={m.workbench_properties_format_value()} />、<UiLabel name={m.workbench_properties_format_text()} /> 或 <UiLabel name={m.workbench_properties_format_rule()} />。
    - <UiLabel name={m.workbench_properties_expression()} />：字段值或计算规则。使用形如 `zt.title` 或 `zt.DOI` 的 `zt.` 路径读取 Zotero 数据。
    - <UiLabel name={m.workbench_properties_merge()} />：控制 ZotLit 在更新笔记时如何处理现有值。

  </Step>
  <Step>
    ### 选择合并策略

    使用 <UiLabel name={m.workbench_properties_merge_replace()} /> 在每次更新时无条件覆盖该字段；使用 <UiLabel name={m.workbench_properties_merge_append()} /> 追加新的数组元素并保留笔记中已有的项；使用 <UiLabel name={m.workbench_properties_merge_keep()} /> 仅在笔记中该属性为空时才写入。关于各策略的详细行为说明，请参阅[合并策略](/docs/reference/templates/frontmatter#merge-strategies)。

  </Step>
  <Step>
    ### 检查预览结果

    模板工作台视图会自动保存新属性。在右侧预览中直接查看当前选定论文所生成的属性取值。

  </Step>
</Steps>

## 将 Zotero 标签添加到笔记 frontmatter [#zotero-tags]

使用 `obsidian_tag` 过滤器创建受管的 `tags` 字段。该过滤器读取
`zt.tags` 中的 Zotero 标签对象，返回 Obsidian 标签值组成的数组。

<Steps>
  <Step>
    ### 添加 `tags` 字段 [#add-the-tags-field]

    在 <UiLabel name={m.workbench_tab_properties()} /> 标签页中选择 <UiLabel name={m.workbench_properties_add()} />，填入以下值：

    | 输入项 | 值 |
    | ----- | ----- |
    | <UiLabel name={m.workbench_properties_name()} /> | `tags` |
    | <UiLabel name={m.workbench_properties_format()} /> | <UiLabel name={m.workbench_properties_format_value()} /> |
    | <UiLabel name={m.workbench_properties_expression()} /> | `zt.tags \| obsidian_tag` |
    | <UiLabel name={m.workbench_properties_merge()} /> | <UiLabel name={m.workbench_properties_merge_replace()} /> |

    <UiLabel name={m.workbench_properties_merge_replace()} /> 策略会让笔记中的 Zotero 标签保持同步。
    如果还希望保留手动添加的 Obsidian 标签，请选择 <UiLabel name={m.workbench_properties_merge_append()} />。

  </Step>
  <Step>
    ### 更新笔记 [#update-the-note]

    在已有的文献笔记上运行 <Command inline name={m.command_update_note_metadata_name()} />。
    ZotLit 会计算字段值，并将结果写入笔记的 frontmatter。

  </Step>
</Steps>

例如，名为 `Methodology` 和 `Open Access` 的 Zotero 标签会转换为：

```yaml
tags:
  - Methodology
  - Open_Access
```

过滤器会按 Obsidian 的标签规则规范化空格和其他字符。
Frontmatter 中的标签值不需要以 `#` 开头。完整的规范化规则请参阅
[`obsidian_tag` 过滤器参考](/docs/reference/templates/syntax#obsidian-tag)。

如需智能体协助设置，请安装 [ZotLit 技能](/docs/install-skill)，
让智能体添加表达式为 `zt.tags | obsidian_tag` 的受管 `tags` 字段。
智能体可通过[模板工作台 CLI](/docs/concepts/template-workbench)
配置字段并测试渲染结果。

## 编辑或删除字段 [#edit-or-remove-a-field]

选择属性行即可编辑。使用 <UiLabel name={m.workbench_properties_remove()} /> 删除该属性。

## 调整字段顺序 [#reorder-fields]

创建新的文献笔记时，frontmatter 键的排列顺序取决于模板工作台视图中的属性顺序。

使用 <UiLabel name={m.workbench_properties_move_up()} /> 或 <UiLabel name={m.workbench_properties_move_down()} /> 移动属性。

### 已有笔记 [#existing-notes]

调整字段顺序不会改变已有笔记中的属性顺序。ZotLit 更新已有笔记时，已经存在于该笔记 YAML 中的键会保留当前位置。

要调整某篇笔记中的属性顺序，请在 Obsidian 属性面板中拖动属性名称左侧的类型图标。Obsidian 会将新顺序写回笔记的 YAML。笔记至少需要有两个属性才能使用此操作。

## 校验规则 [#validation-rules]

<UiLabel name={m.workbench_tab_properties()} /> 标签页会用
<UiLabel name={m.workbench_properties_row_problem()} /> 标记无法使用的行。
<UiLabel name={m.workbench_problems_heading()} /> 区域会说明问题，并提供
<UiLabel name={m.workbench_problems_where_entry()} /> 以打开对应行。

ZotLit 使用的规则请参阅[校验](/docs/reference/templates/frontmatter#validation)；报告这些问题的区域请参阅[以 Markdown 编辑配置方案](/docs/how-to/edit-a-profile-as-markdown#problems)。

## 将更新后的字段应用到已有笔记 [#apply-updated-fields-to-existing-notes]

修改 frontmatter 配置后，运行：

<Command name={m.command_update_note_metadata_name()} />

此命令会重新计算所有字段表达式，并根据每个字段的合并策略，将结果写入当前笔记的 frontmatter。

内置字段也是普通配置项，因此您可以在此编辑或删除 `citekey`。默认配置方案声明的字段请参阅[默认字段](/docs/reference/templates/frontmatter#default-fields)。

## 通过智能体配置 [#agent-based-configuration]

安装 ZotLit 技能的智能体可以通过[模板工作台 CLI](/docs/concepts/template-workbench)配置受管 frontmatter 字段模板。

<Callout type="info" title="JavaScript 字段与权限开关">
  每个属性使用一个成员声明其值：`expr` 存放一个 Liquid 表达式，`value` 存放一个
  JSON-e 规则 （固定文本就是内容为普通字符串的规则），`js` 存放一个 JavaScript
  表达式。 如果当前设备关闭了{" "}
  <UiLabel name={m.settings_template_js_enable_name()} />
  ，`js` 属性不会求值。 ZotLit 会报告受影响的字段：{" "}
  <UiLabel name={m.notice_frontmatter_js_inert({ fields: "…" })} />
  请参阅[启用 JavaScript 模板](/docs/how-to/enable-javascript-templates)。
</Callout>
