自定义的 v1 Eta 模板需要重命名文件并更新变量名方可在 v2 中顺利运行。如果您从未自定义过模板（即完全使用默认模板），则无需进行任何操作，v2 会自动提供升级后的全新默认模板。

<Callout type="info" title="从 ZotLit 2.1 升级？">
  本篇专注于从 v1 Eta 模板的迁移。如果您是从 2.1 版本升级（其模板分散在形如
  `zotlit-note.liquid.md` 的独立文件中），请参阅[从 2.1
  模板迁移](/docs/how-to/migrate-from-2.1-templates)。
</Callout>

您有两条迁移路径可选：继续沿用 Eta 语法（重命名文件、替换数据变量，并开启 [<UiLabel name={m.settings_template_js_enable_name()} /> 权限开关](/docs/how-to/enable-javascript-templates)，本指南主要围绕此展开）；或者直接转换为 Liquid（使用 v2 默认且无需任何授权的 Liquid 引擎重写模板，文末附有 [Eta 到 Liquid 的转换对照表](#eta-to-liquid-translations)）。

<Callout type="info" title="运行 Eta 模板需要开启 JavaScript 权限开关">
  Eta 模板依赖 <UiLabel name={m.settings_template_js_enable_name()} />{" "}
  权限开关。关于授权操作流程，请参阅[启用 JavaScript
  模板](/docs/how-to/enable-javascript-templates)。
</Callout>

<Steps>
  <Step>
    ### 重命名模板文件

    v2 通过 `zotlit-` 前缀（取代了旧的 `zt-`）来读取模板，且原先的 `annots` 模板现已重命名为 `content`。请先将您的旧模板文件按此规则重命名。ZotLit 会以这些新名称加载并渲染它们，随后您可以通过下文所述的[一次性合并转换](#convert)将其整合到 v2 的现代模板文档中。

    | v1 原文件名 | 重命名为 | 内容最终归宿 |
    | ------------------ | -------------------------- | ------------------------------------------------------------- |
    | `zt-note.eta.md` | `zotlit-note.eta.md` | 默认配置方案文档中的笔记正文主体部分 |
    | `zt-annots.eta.md` | `zotlit-content.eta.md` | 位于同一笔记正文内部的受管块（managed block） |
    | `zt-annot.eta.md` | `zotlit-annotation.eta.md` | 位于该配置方案文档末尾的标注格式区域（annotation section） |

    您的两个 v1 引文文件 `zt-cite*.eta.md` 同样将前缀从 `zt-` 改为 `zotlit-`。它们最终会通过基于 `zt.variant` 的 `if`/`else` 分支统一整合到单个引文文本文档 `zotlit-citation.md` 中。

    如果存在以下旧文件，请直接将其删除（v2 中已无对应概念）：

    - `zt-field.eta.md`：现已被基于设置的 [frontmatter 系统](/docs/reference/templates/frontmatter)全面取代。
    - `zt-colored.eta.md`：高亮颜色样式现已在笔记导入时自动处理。

  </Step>
  <Step>
    ### 将 `it` 全面替换为 `zt`

    模板的核心数据变量名已由 `it` 改为 `zt`。在模板标签内部，将 `it.` 批量查找替换为 `zt.` 即可解决绝大多数引用：

    ```
    it.title       →  zt.title
    it.creators    →  zt.creators
    it.backlink    →  zt.backlink
    it.pageLabel   →  zt.pageLabel
    ```

    下方有变更语义的字段（`comment`、`tags`、`collections`、`date`、`notes`）除外，请按后续步骤逐个处理，不要进行盲目全局替换。

  </Step>
  <Step>
    ### 更新已重命名与重构的字段

    以下字段的名称或数据类型发生了变化：

    | v1 属性字段 | v2 属性字段 | 说明 |
    | --------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
    | `it.citekey` | `zt.citationKey` | `zt.citekey` 同样作为别名可用 |
    | `it.abstractNote`     | `zt.abstract`       | `zt.abstractNote` also works                                                                                                |
    | `it.publicationTitle` | `zt.containerTitle` | `zt.publicationTitle` also works                                                                                            |
    | `it.color`            | `zt.colorHex`       | Hex string, e.g. `#ffd400`                                                                                                  |
    | —                     | `zt.colorName`      | New: palette name (`"yellow"`, `"red"`, etc.)                                                                               |
    | `it.imgExcerpt`       | `embed(zt.imgLink)` | `zt.imgLink` is a [link helper](/docs/reference/templates/eta-syntax#link-helpers) or `null`; `embed()` adds the `!` prefix |
    | `it.imgPath`          | _(removed)_         | Use `zt.imgLink()` instead                                                                                                  |
    | `it.imgUrl`           | _(removed)_         | Use `zt.imgLink()` instead                                                                                                  |
    | `it.textExcerpt`      | `zt.text`           | Renamed                                                                                                                     |
    | `it.commentMd`        | `zt.comment`        | Markdown comment is now the default                                                                                         |
    | `it.comment`          | `zt.commentHtml`    | Raw HTML (only `<i>/<b>/<sub>/<sup>`)                                                                                       |

    Direct Zotero fields that are plain strings (`title`, `DOI`, `url`, `volume`, `issue`, `pages`, `publisher`, etc.) carry over unchanged after the `it` → `zt` rename.

  </Step>
  <Step>
    ### Update tag access

    v1 exposed tags as formatted strings. v2 exposes them as objects with `name` and `type` properties. Tags coerce to their `name` in string contexts, so `join` still works:

    ```eta
    <%/* Tags coerce to their name */%>
    <%= zt.tags.join(", ") %>

    <%/* Explicit property access */%>
    <%= zt.tags.map(t => t.name).join(", ") %>

    <%/* Filter to manual tags only */%>
    <%= zt.tags.filter(t => t.type === "manual").join(", ") %>
    ```

  </Step>
  <Step>
    ### Update collection access

    v2 reshapes collection objects. Key differences:

    | Aspect           | v1                          | v2                                         |
    | ---------------- | --------------------------- | ------------------------------------------ |
    | `path` order     | leaf → root                 | root → leaf                                |
    | `path` rendering | auto-rendered `"A > B > C"` | plain `string[]`; use `c.path.join(" > ")` |
    | Singular alias   | `it.collection`             | removed; use the `zt.collections` array    |

    ```eta
    <%/* Collections coerce to their name in string contexts */%>
    <%= zt.collections.join(", ") %>

    <%/* Render each collection's full hierarchy */%>
    <%= zt.collections.map(c => c.path.join(" > ")).join("; ") %>
    ```

  </Step>
  <Step>
    ### Update date fields

    | v1 property                        | v2 property                        | Type change                                                                                                                        |
    | ---------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
    | `it.date`                          | `zt.date`                          | Was a year-only string; now a parsed `ItemDate` object. `<%= zt.date %>` renders ISO; `zt.date?.year` gets the numeric year.       |
    | `it.dateAdded` / `it.dateModified` | `zt.dateAdded` / `zt.dateModified` | Were raw SQL strings (`"YYYY-MM-DD HH:MM:SS"`); now `Temporal.Instant`. Render as local date in `<%= %>` tags (e.g. `2026-06-21`). |

    If your v1 template used `it.date` as a year string, replace with `zt.date?.year`:

    ```eta
    <%/* v1 */%>
    year: "<%= it.date %>"

    <%/* v2 */%>
    year: "<%= zt.date?.year %>"
    ```

  </Step>
  <Step>
    ### Update child note access

    v1 inlined child-note content as Markdown on `it.notes`. v2 writes each child note to a separate file and provides link-only entries:

    | v1                                      | v2                                                   |
    | --------------------------------------- | ---------------------------------------------------- |
    | `it.notes`: array of `{title, content}` | `zt.notes`: array of `{key, title, noteLink()}`      |
    | Note content inlined                    | Content in a separate file; `noteLink()` links to it |

    The default content template renders child notes as a bulleted list of links:

    ```eta
    <% if (zt.notes.length) { %>
    ## Notes

    <% for (const note of zt.notes) { -%>
    - <%~ note.noteLink() %>
    <% } %>
    <% } %>
    ```

  </Step>
  <Step>
    ### Rewrite the annotation template with `bq()`

    v1 relied on external blockquote handling. v2 uses the [`bq()` helper](/docs/reference/templates/eta-syntax#bq-blockquote-helper) inside the annotation template:

    ```eta
    <% bq(() => { %>
    [!note] Page <%= zt.pageLabel %>

    <%= embed(zt.imgLink) %><%= zt.text %>
    <% if (zt.comment) { %>

    <%= zt.comment %>
    <% } %>
    <% }) %>
    ```

    `bq()` wraps all content in a Markdown blockquote (`> ` per line), trims the result, and collapses consecutive empty blockquote lines. It must appear in a `<% %>` execute tag.

  </Step>
  <Step>
    ### Update the content template

    The template is renamed from `annots` to `content`. It now receives the full context object instead of a raw annotation array:

    ```eta
    <%/* v1: received a raw array as `it` */%>
    <% for (const annotation of it) { %>

    <%/* v2: receives full context, access annotations via zt.annotations */%>
    <% for (const annotation of zt.annotations) { %>
    ```

    Update the `include` call in your note template:

    ```eta
    <%/* v1 */%>
    <%~ include("annots", it.annotations) %>

    <%/* v2 */%>
    <%~ include("content", zt) %>
    ```

    The content template now has access to all `zt.*` properties (attachments, tags, notes, etc.), not annotations alone.

  </Step>
  <Step>
    ### Update the citation source

    v1 passed `it` as a raw array. v2 wraps items in an object:

    ```eta
    <%/* v1 */%>
    [<%= it.filter(lit => !!lit.citekey).map(lit => `@${lit.citekey}`).join("; ") %>]

    <%/* v2 */%>
    [<%= zt.citations.filter(c => c.item.citationKey).map(c =>
      `${c.suppressAuthor ? "-" : ""}@${c.item.citationKey}`
    ).join("; ") %>]
    ```

    Key changes:

    - `it` (array) becomes `zt.citations` (array inside an object). `zt.items` exposes the same items without citation metadata.
    - `lit.citekey` becomes `c.item.citationKey` (or `c.item.citekey`).
    - Both of your v1 citation files render from one v2 document. The conversion below writes them as the two branches of an `if`/`else` on `zt.variant`, which is `"main"` or `"alt"`. See [Citation templates](/docs/reference/templates/data#citation-templates).

  </Step>
  <Step>
    ### Update attachment access

    v1 selected one attachment and exposed it as `it.fileLink` (a string). v2 provides all attachments as an array, and `fileLink` is a [link helper](/docs/reference/templates/eta-syntax#link-helpers) you call:

    ```eta
    <%= zt.attachments.map(a => a.fileLink()).filter(Boolean).join(" ") %>
    ```

    Each attachment object has: `key`, `filename`, `contentType`, `linkMode`, `filePath`, `fileLink`.

  </Step>
  <Step>
    ### Update creator access

    v2 uses a flat array with explicit properties. Creators coerce to their full name in string contexts:

    ```eta
    <%/* All authors (coerces to fullName) */%>
    <%= zt.authors.join(", ") %>

    <%/* Explicit property access */%>
    <%= zt.authors.map(c => c.fullName).join(", ") %>

    <%/* Filter by role */%>
    <%= zt.creators.filter(c => c.role === "editor").join(", ") %>
    ```

    Creator properties: `family`, `given`, `literal` (institutional names), `role`, `fullName`.

    Convenience properties on the item context: `zt.authors` (the first populated role: primary creator, editor, director, then contributor) and `zt.authorsShort` (formatted short string, e.g. "Smith et al.").

  </Step>
  <Step>
    ### Update the filename template

    The filename template is a template file (`zotlit-filename.eta.md`), not a setting string. The [one-pass conversion](#convert) later folds it into the `filename` key of your profile document's manifest. The v2 default adds `suffix()` for collision avoidance:

    ```eta
    <%= zt.citationKey ?? zt.DOI ?? zt.title ?? zt.key %><%= suffix() %>
    ```

    - `it.citekey` becomes `zt.citationKey` (canonical name; `zt.citekey` also works).
    - The `.md` extension is no longer included. ZotLit appends it automatically.
    - [`suffix()`](/docs/reference/templates/eta-syntax#suffix-filename-collision-guard) appends a random string only when the name collides with an existing note.

  </Step>
  <Step>
    ### Migrate frontmatter fields

    If you customized `zt-field.eta.md`, delete it and rebuild its fields as managed frontmatter entries in your profile document. Open the document from the <UiLabel name={m.settings_profile_document_name()} /> row at <SettingsPath /> with <UiLabel name={m.settings_profile_edit()} />, then select the <UiLabel name={m.workbench_tab_properties()} /> tab.

    For each field, select <UiLabel name={m.workbench_properties_add()} /> and fill in:

    - <UiLabel name={m.workbench_properties_name()} />: the YAML property name.
    - <UiLabel name={m.workbench_properties_format()} />: <UiLabel name={m.workbench_properties_format_value()} /> for a Zotero field, <UiLabel name={m.workbench_properties_format_text()} /> for fixed text, or <UiLabel name={m.workbench_properties_format_rule()} /> for a JSON-e rule.
    - <UiLabel name={m.workbench_properties_expression()} />: the value. A Zotero field uses a `zt.` path, such as `zt.title`.
    - <UiLabel name={m.workbench_properties_merge()} />: <UiLabel name={m.workbench_properties_merge_replace()} />, <UiLabel name={m.workbench_properties_merge_append()} />, or <UiLabel name={m.workbench_properties_merge_keep()} />.

    | v1 template line           | <UiLabel name={m.workbench_properties_name()} /> | <UiLabel name={m.workbench_properties_expression()} /> | <UiLabel name={m.workbench_properties_merge()} />              |
    | -------------------------- | ------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------------------- |
    | `title: "<%= it.title %>"` | `title`                                          | `zt.title`                                             | <UiLabel name={m.workbench_properties_merge_replace()} />       |
    | `authors: ...`             | `authors`                                        | `zt.authors \| map: "fullName" \| join: ", "`           | <UiLabel name={m.workbench_properties_merge_replace()} />       |
    | `year: "<%= it.date %>"`   | `year`                                           | `zt.date \| date: "%Y"`                                | <UiLabel name={m.workbench_properties_merge_replace()} />       |
    | `tags: ...`                | `tags`                                           | `zt.tags \| map: "name" \| join: ", "`                 | <UiLabel name={m.workbench_properties_merge_append()} />        |

    YAML escaping is handled automatically.

    The Properties tab writes each property as one entry in the `frontmatter` list of the profile document manifest. An entry carries a `key` and one value member, and the member name declares the language: `expr` holds a Liquid value, which is what <UiLabel name={m.workbench_properties_format_value()} /> writes; `value` holds fixed text or a JSON-e rule, which is what <UiLabel name={m.workbench_properties_format_text()} /> and <UiLabel name={m.workbench_properties_format_rule()} /> write; and `js` holds a JavaScript value, which you write in <UiLabel name={m.workbench_advanced()} />.

    ZotLit manages reserved frontmatter keys that you cannot target from a user field, such as `zotero-key`, `zotlit-profile`, `zotero-note-key`, and `zotero-lastmod`. The default `citekey` entry is an ordinary managed frontmatter field. See [Frontmatter reference](/docs/reference/templates/frontmatter) for details.

    <Callout type="info" title="JavaScript values">
      A `js` entry runs only while <UiLabel name={m.settings_template_js_enable_name()} /> is on. See [Enable JavaScript templates](/docs/how-to/enable-javascript-templates).
    </Callout>

  </Step>
  <Step>
    ### Overwrite v1 notes to add the managed region

    v1 notes lack the `%%zt-managed%%` / `%%/zt-managed%%` markers that v2 uses to isolate generated content. Incremental update cannot target their body. Running <Command inline name={m.command_update_note_name()} /> on a v1 note refreshes frontmatter only.

    To add the managed region, run the overwrite command on each note you want refreshed:

    <Command name={m.command_overwrite_note_name()} />

    A confirmation modal appears. Click <UiLabel name={m.modal_overwrite_note_confirm()} /> to proceed. ZotLit regenerates the entire note body from the current templates, inserting the managed-region markers.

    After overwriting, the note responds to <Command inline name={m.command_update_note_name()} /> for incremental updates. You do not need to overwrite every note at once. Leave notes untouched until you are ready.

    See [Refresh v1 notes](/docs/how-to/migrate-from-v1#refresh-v1-notes) for the full procedure.

  </Step>
</Steps>

<Callout type="info" title="Whitespace change from v1">
  v1 defaulted `autoTrim` to `[false, "nl"]` (trim one newline after tags). v2 defaults to `[false, false]` (preserve all whitespace). Migrated templates may produce extra blank lines where `%>` previously consumed a trailing newline. Add `-%>` to the closing side of tags that need the old trim behavior. See [Whitespace control](/docs/reference/templates/eta-syntax#whitespace-control).
</Callout>

## Expected result

After completing these steps, your custom Eta templates render with v2 field names and helpers. Notes that have been overwritten contain the `%%zt-managed%%` markers and respond to incremental updates. Notes you have not overwritten continue to work for frontmatter-only refreshes.

## Convert to template documents [#convert]

Renamed files load and render as they are, so you can stop here. ZotLit also offers to fold them into v2's template documents in one pass, from the Welcome view or from a reminder row at the top of settings, and it verifies the output before it writes anything.

[Migrate from 2.1 templates](/docs/how-to/migrate-from-2.1-templates) covers that conversion: what each file becomes, what the pass checks, and what it refuses.

## Eta to Liquid translations

v2's default engine is Liquid. Converting your templates to Liquid removes the need for the <UiLabel name={m.settings_template_js_enable_name()} /> gate entirely. For each construct, the table below shows the Liquid equivalent and links to the relevant syntax reference section.

| Eta construct                                         | Liquid equivalent                                 | Reference                                                                      |
| ----------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------ |
| `<%= zt.title %>`                                     | `{{ zt.title }}`                                  | [Outputs and tags](/docs/reference/templates/syntax#outputs-and-tags)          |
| `<% if (zt.abstract) { %> ... <% } %>`                | `{% if zt.abstract %} ... {% endif %}`            | [Control flow](/docs/reference/templates/syntax#if-elsif-else-endif)           |
| `<% for (const a of zt.annotations) { %> ... <% } %>` | `{% for a in zt.annotations %} ... {% endfor %}`  | [for / endfor](/docs/reference/templates/syntax#for-endfor)                    |
| `<%~ include("content", zt) %>`                       | `{% render "content" with zt as zt %}`            | [Includes with render](/docs/reference/templates/syntax#includes-with-render)  |
| `<% bq(() => { %> ... <% }) %>`                       | `{% bq %} ... {% endbq %}`                        | [bq: blockquote block](/docs/reference/templates/syntax#bq-blockquote-block)   |
| `embed(zt.imgLink)`                                   | `{{ zt.imgLink \| embed }}`                       | [embed filter](/docs/reference/templates/syntax#embed-embed-filter)            |
| `<%= suffix() %>`                                     | `{% suffix %}`                                    | [suffix tag](/docs/reference/templates/syntax#suffix-filename-collision-guard) |
| `zt.attachments[0].fileLink()`                        | `{{ zt.attachments[0] \| file_link }}`            | [Link filters](/docs/reference/templates/syntax#link-filters)                  |
| `zt.collections.map(c => c.path.join(" > "))`         | `{{ zt.collections \| collection_paths: " > " }}` | [collection_paths](/docs/reference/templates/syntax#collection-paths)          |
| `zt.tags.map(t => t.name).join(", ")`                 | `{{ zt.tags \| map: "name" \| join: ", " }}`      | [Array filters](/docs/reference/templates/syntax#array-filters)                |
| `zt.dateAdded` (Temporal.Instant formatting)          | `{{ zt.dateAdded \| date: "%Y-%m-%d" }}`          | [date filter](/docs/reference/templates/syntax#date-formatting-filter)         |
| `-%>` (trim one newline after tag)                    | `-%}` / `-}}`                                     | [Whitespace control](/docs/reference/templates/syntax#whitespace-control)      |

A renamed 2.1 Liquid file uses the `.liquid.md` extension (e.g. `zotlit-note.liquid.md`); a converted template document carries no language in its name. The data variable is still `zt` and the property names are identical to the Eta equivalents documented above.
