Create highlights, underlines, note annotations, text annotations (text typed on the page), image annotations, and ink annotations (freehand strokes), change annotation colors and comments, adjust annotation positions, or delete annotations from Obsidian.

## Before you edit

Keep Zotero running while you edit. ZotLit sends each change to Zotero and cannot edit annotations while Zotero is closed.

Open the item's PDF in Obsidian. See [Open an item's PDF in Obsidian](/docs/how-to/open-pdf-in-obsidian) for the available entry points.

Before the first edit, give ZotLit permission to change annotations in Zotero. <UiLabel name={m.capability_enable_editing()} /> is in two places:

- In the annotation view, select the mode button at the start of the view's toolbar, then select <UiLabel name={m.capability_enable_editing()} />.
- In <SettingsPath page={m.settings_page_zotero()} setting={m.settings_zotero_connection_heading()} />, on the <UiLabel name={m.settings_zotero_editing_name()} /> row, select <UiLabel name={m.settings_zotero_editing_enable()} />.

Zotero opens its permission dialog at once. In the dialog, choose **Always Allow**. ZotLit edits only with a permission that Zotero remembers, so **Allow** leaves editing off. To decline, choose **Deny**.

While Zotero waits for your answer, the PDF reader toolbar shows <UiLabel name={m.capability_authorizing()} />.

<Callout type="warn" title="Edit one annotation in one application at a time">
  Zotero has a [known defect](https://github.com/aidenlx/zotlit/issues/1165) when edits to the same annotation overlap in Zotero and Obsidian. One comment can silently overwrite the other even when both applications report a successful save. A deletion in Obsidian can also remove an annotation that Zotero just updated.

You can keep both applications open. Make changes in one application at a time, wait for each change to save, then switch. This reduces the risk but does not guarantee that overlapping edits cannot occur.

</Callout>

## Create a highlight or underline

1. Select text in the PDF.
2. In the popup, select <UiLabel name={m.pdf_toolbar_highlight()} /> or <UiLabel name={m.pdf_toolbar_underline()} />.
3. Wait for the new mark to appear before you continue editing it or switch to Zotero.

The toolbar at the right of the PDF reader provides the same two tools. Select a tool to keep it active, then select text to create marks without using the popup each time. Use the arrow beside a tool to select its color.

To create one highlight in another color, select the text and select a color from the popup. When neither tool is active, a color creates a highlight.

## Create a note annotation

Use the note tool to pin a comment to a spot on the page.

1. In the toolbar at the right of the PDF reader, select <UiLabel name={m.pdf_toolbar_note()} />.
2. Click the page where the note belongs. The note appears centered on the click, and its popup opens with the comment editor ready.
3. Type the comment. It saves as any comment does; see [Add or edit a comment](#add-or-edit-a-comment).

The tool turns off after each note, as in Zotero. A click on an annotation mark selects that mark instead of creating a note, and a drag creates nothing.

## Create a text annotation

Use the text tool to type text onto the page itself.

1. In the toolbar at the right of the PDF reader, select <UiLabel name={m.pdf_toolbar_text()} />. The tool turns off when the text box opens.
2. Click the page where the text starts. A text box opens at the click.
3. Type the text. Press `Enter` to start a new line. The box grows to one line of up to 300 pt, then wraps, as in Zotero.
4. Press `Escape` or click outside the box. The text becomes a text annotation in Zotero, and stays on the page while it saves.

A box that you leave empty creates nothing. A click on an annotation mark selects that mark instead of opening a box. Zotero shows the annotation only when you finish typing, because ZotLit creates it once with its text.

### Choose the text color and font size

Select the arrow beside <UiLabel name={m.pdf_toolbar_text()} />. The menu lists the colors, then the sizes under <UiLabel name={m.pdf_toolbar_text_font_size()} />: 10, 12, 14, 18, 24, and 36 pt. A check mark shows the current color and size. The default size is 14 pt.

ZotLit remembers your color and font size for other PDFs.

## Create an image annotation

Use the image tool to capture a figure, a table, or another area without text.

1. In the toolbar at the right of the PDF reader, select <UiLabel name={m.pdf_toolbar_image()} />.
2. Drag a rectangle around the area. The rectangle stays faint until it is large enough to save.
3. Release the pointer. The new mark appears, and its card shows the captured area.

The tool turns off after each capture. To cancel a drag, press `Escape`. Press `Escape` again to turn off the tool. A press on an annotation mark selects that mark instead of starting a rectangle.

## Create an ink annotation

Use the ink tool to draw on the page by hand.

1. In the toolbar at the right of the PDF reader, select <UiLabel name={m.pdf_toolbar_ink()} />. The tool starts on blue, Zotero's default ink color.
2. Press on the page and drag. The stroke follows the pointer.
3. Release the pointer. The stroke becomes an ink annotation in Zotero, and stays on the page while it saves.

Each stroke is its own annotation. The tool stays active after each stroke, so you can start the next stroke at once. A tap without movement saves a dot. To combine several strokes into one annotation, merge them in Zotero.

The ink tool works with a mouse, a pen tablet, a trackpad, or a finger on a touchscreen. While the tool is active, a touch drag draws instead of scrolling the page. A stroke draws over text and over other annotation marks, so a press on a mark starts a stroke instead of selecting the mark.

A stroke stays on the page where it started, even if the pointer leaves the page. Zotero limits the size of one annotation. When a long stroke reaches that limit, ZotLit saves the part drawn so far and continues the stroke as a new annotation. You do not need to lift the pointer.

To cancel a stroke, press `Escape` before you release the pointer. The tool stays active. Press `Escape` again to turn off the tool. A second finger on the screen during a stroke, as at the start of a pinch zoom, also cancels the stroke.

### Choose the ink color and width

Select the arrow beside <UiLabel name={m.pdf_toolbar_ink()} />. The menu lists the colors, then the widths under <UiLabel name={m.pdf_toolbar_ink_width()} />: 0.4, 1, 2, 3, 5, 8, and 12 pt. A check mark shows the current color and width. The default width is 2 pt.

ZotLit remembers your color and width for other PDFs. A stroke keeps the color and width it started with.

## Add or edit a comment

1. Select the annotation mark in the PDF.
2. In the popup, select <UiLabel name={m.annot_view_card_add_comment()} /> or <UiLabel name={m.annot_view_card_edit_comment()} />. The comment editor opens in the popup.
3. Enter the comment.
4. Wait for the comment to save before you edit the annotation in Zotero.

Comments request an automatic save after one second without typing. During continuous typing, ZotLit requests a save after ten seconds from the first unsaved change. Press `Ctrl+Enter` (Windows) or `Command+Enter` (macOS) to request a save and keep the editor open. Press `Escape` or move focus out of the editor to request a save and close it.

You can also select an annotation card, then select <UiLabel name={m.annot_view_card_add_comment()} /> or <UiLabel name={m.annot_view_card_edit_comment()} />, the pencil beside the comment. The popup and card editors share one draft, so text entered in either editor appears in the other.

If ZotLit detects that the comment changed in Zotero, it shows <UiLabel name={m.annot_view_conflict_title()} /> with both versions. Select <UiLabel name={m.annot_view_conflict_use_comment()} /> to save your draft over the Zotero comment, or <UiLabel name={m.annot_view_conflict_keep_zotero_comment()} /> to discard your draft.

## Change a color

1. Select the annotation mark in the PDF.
2. Select <UiLabel name={m.annot_view_card_color()} /> in the popup.
3. Select one of Zotero's annotation colors.

The palette button on an annotation card provides the same colors.

## Adjust an annotation's position

You can move or resize image, ink, and text annotations, move note annotations, and move either end of a highlight or underline. Editing must be enabled. When it is not, a selected mark shows no handles and the keys below do nothing.

1. Select the annotation mark in the PDF. Handles appear on the mark.
2. Drag a handle, or drag the mark itself. The mark follows the pointer.
3. Release the pointer. ZotLit sends the new position to Zotero.

Press `Escape` during a drag to put the mark back without saving. A drag that ends where it started saves nothing. The popup hides during the drag and returns after it.

### Handles for each annotation type

| Annotation type        | Handles                                                                            | Drag                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Image                  | Eight squares, on the four corners and the four edge midpoints.                    | A corner moves two edges. An edge handle moves one edge. The inside of the image moves the whole rectangle.                                  |
| Ink                    | Four corners, on a box slightly larger than the strokes.                           | A corner scales the drawing. Its proportions stay the same, and the pen width scales with it. The inside of the box moves the drawing.       |
| Highlight or underline | Two narrow strips, at the start of the first line and at the end of the last line. | A strip moves that end of the range one character at a time. The quoted text follows the new range.                                          |
| Text                   | Six squares, on the four corners and the middle of the left and right sides.       | A side handle changes the width and keeps the font size. A corner scales the box and the font size together. The inside of the box moves it. |
| Note                   | None.                                                                              | The note icon moves the note.                                                                                                                |

An image rectangle stays on its page and keeps at least 10 points on each side. A text box keeps at least 10 points of width, and its height follows its text after a side handle moves. When you release a side handle on a box of one line, the box fits the width of its text. On a rotated text box, the handles rotate with the box. A highlight or underline range keeps at least one character. Its start stays on the annotation's page, and its end can move onto the next page but no further. A drag on the body of a highlight selects text as usual.

### Adjust from the keyboard

Select the annotation mark first. Each key press is one step.

| Annotation type           | Keys                                            | Result                                                                                    |
| ------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Highlight or underline    | `Shift+Left arrow`, `Shift+Right arrow`         | Moves the end back or forward by one character.                                           |
| Highlight or underline    | `Shift+Up arrow`, `Shift+Down arrow`            | Moves the end to the nearest character on the line above or below.                        |
| Image                     | `Shift+Right arrow`, `Shift+Left arrow`         | Moves the right edge 5 points out or in.                                                  |
| Image                     | `Shift+Down arrow`, `Shift+Up arrow`            | Moves the bottom edge 5 points down or up.                                                |
| Ink                       | `Shift+Right arrow`, `Shift+Down arrow`         | Enlarges the drawing by 5 points. The proportions and the top-left corner stay.           |
| Ink                       | `Shift+Left arrow`, `Shift+Up arrow`            | Shrinks the drawing by 5 points. The proportions and the top-left corner stay.            |
| Text                      | `Shift+Right arrow`, `Shift+Left arrow`         | Moves the right edge 5 points out or in. The height follows the text.                     |
| Text                      | `Shift+Down arrow`, `Shift+Up arrow`            | Enlarges or shrinks the box and its font by 5 points of width. The top-left corner stays. |
| Image, ink, note, or text | `Alt+arrow` (Windows) or `Option+arrow` (macOS) | Moves the mark 5 points in the arrow's direction.                                         |

For a highlight or underline, add `Ctrl` (Windows) or `Command` (macOS) to the `Shift` keys to move the start instead of the end. A key that would leave the range with no characters does nothing. The `Shift` keys for images and text work as in Zotero's reader, with one difference: `Shift+Up arrow` does not make a text box narrower than 10 points. To move a mark, Zotero's reader uses an arrow key without a modifier. ZotLit uses `Alt+arrow` or `Option+arrow`.

`Alt+arrow` or `Option+arrow` does not move a mark that is within 10 points of the page edge on that side. `Up arrow` and `Down arrow` without a modifier still select the previous or next annotation in reading order.

### How the change saves

Each drag release and each key press is one change. ZotLit sends it to Zotero at once. ZotLit also updates the annotation's place in the annotation list order, and for a highlight or underline, its quoted text. Zotero's reader and sidebar show the new position, and the image in the annotation view refreshes. To put the mark back where it was, see [Undo and redo a change](#undo-and-redo-a-change).

If the annotation changed in Zotero while you adjusted it, the annotation card shows <UiLabel name={m.annot_view_conflict_title()} /> and says that the position changed in Zotero. For a highlight or underline, the card also shows the Zotero quote beside yours. Select <UiLabel name={m.annot_view_conflict_apply_again()} /> to save your position over the Zotero one, or <UiLabel name={m.annot_view_conflict_discard()} /> to keep the Zotero position. Until you select one, the mark shows the Zotero position.

If Zotero refuses the change, the mark returns to its saved position, and a notice says that the annotation was not adjusted and why.

## Delete an annotation

1. Reveal the annotation in the annotation view.
2. Open its <UiLabel name={m.annot_view_more_tooltip()} /> menu.
3. Select <UiLabel name={m.annot_view_menu_delete()} />.
4. In the confirmation dialog, select <UiLabel name={m.annot_view_delete_confirm_action()} />.

The annotation is deleted from Zotero. You can undo the deletion while the PDF is still open in Obsidian, but the restored annotation comes back under a new Zotero key. See [Undo and redo a change](#undo-and-redo-a-change).

## Undo and redo a change

While a PDF is open in Obsidian, ZotLit remembers the annotation changes it saved to Zotero for that PDF: creations, deletions, colors, comments, and positions. Undo asks Zotero for the previous value, and redo asks for the change again. Both are ordinary edits, so Zotero must be running and editing must be enabled.

| Platform          | Undo        | Redo                       |
| ----------------- | ----------- | -------------------------- |
| macOS             | `Command+Z` | `Command+Shift+Z`          |
| Windows and Linux | `Ctrl+Z`    | `Ctrl+Y` or `Ctrl+Shift+Z` |

The keys work anywhere in the PDF view, and in the annotation view on a card you selected, as long as the PDF is open. Inside a comment editor or a text box you are typing in, the same keys undo your typing instead. A held key steps once.

The command palette carries <Command inline name={m.command_undo_annotation_change_name()} /> and <Command inline name={m.command_redo_annotation_change_name()} />. Neither has a shortcut of its own, so you can assign one. The PDF view's More options menu carries the same two entries, shown dimmed when there is nothing to step that way.

### What counts as one step

Each creation, deletion, color change, and drag is one step. One ink stroke is one step, even where ZotLit saved a long stroke as more than one annotation.

The comment text you save on one annotation is also one step, however many times it saved while you typed, and undo takes it back to the comment you started from. A change to anything else ends that step, and so does a change to that comment in Zotero, so the next comment you type on the same annotation starts a new one. A comment you leave as you found it records no step.

A run of keyboard nudges on one mark is one step while the presses are less than half a second apart. A pause longer than that, or a change of any other kind, starts a new step.

### What the history covers

The history belongs to the PDF, not to the window. Two views of the same PDF, and the annotation view beside them, share one history in the order you made the changes. A change to another PDF is never in it.

ZotLit records a change only while a view of that PDF is open, and the history ends when you close the last one. Reopening the PDF starts an empty history, so an earlier session can never revert today's work. Refreshing the data, reloading the annotations, and changes made in Zotero all leave the history standing. A new change after an undo discards the steps you could have redone. The history holds the last 100 steps and is never written to disk.

After each step, the PDF view selects the annotation that changed and scrolls to it. When the step removed an annotation, the view clears the selection and returns to the page the annotation was on.

### When undo stops

Before it writes, ZotLit checks that Zotero still holds what your change left there. If that annotation changed in Zotero since — by hand, by sync, or from another device — ZotLit writes nothing, drops that step, and shows <UiLabel name={m.annot_history_changed_in_zotero()} />. Press undo again to try the step before it. A Zotero change to a different field of the same annotation does not stop the undo, and neither does a Zotero value that already equals the one the undo would write.

Undo and redo do nothing while a change is still saving, or while you have unsaved comment text on an annotation the step would change. When editing is not enabled, they show the same notice as any other blocked edit.

### A restored annotation gets a new key

Zotero cannot bring a deleted annotation back under its old key. When you undo a deletion, or redo a creation you undid, Zotero creates the annotation again with its color, comment, text, and position, but under a new Zotero key.

Links in your notes, excerpt images, and `obsidian://` URIs that name the old key no longer resolve. ZotLit shows no notice for this. Pull the restored annotation into the note again, or update the key by hand.
