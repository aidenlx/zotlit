ZotLit 能够将 Zotero 子笔记作为独立的 Markdown 文件导入您的仓库中，并在父级文献笔记中建立指向它们的双链链接。

## 导入是如何触发的

笔记导入完全由链接引用驱动。当模板或 frontmatter 表达式引用了子笔记的 `noteLink` 属性时，ZotLit 就会自动将该笔记作为 Markdown 文件导入仓库。如果从未引用过 `noteLink`，则不会为该子笔记创建任何落地文件。

在 Liquid 模板中，访问该属性即可自动触发导入：

```liquid
{{ note.noteLink }}
```

在 frontmatter 表达式中，对 `noteLink` 进行映射计算即可为每个子笔记触发导入：

```liquid
zt.notes | map: "noteLink"
```

仅访问其他属性（例如 `title`）不会触发落地文件导入。

## 导入单篇文献下的子笔记

当您创建、更新或覆盖一篇文献笔记，且其模板或 frontmatter 中引用了 `noteLink` 时，ZotLit 会在该操作期间自动导入所有子笔记，无需额外运行单独的命令。

<Callout type="info" title="仅更新元数据操作">
  仅更新元数据（
  <Command inline name={m.command_update_note_metadata_name()} />
  ）会重新计算 frontmatter，但不会重绘笔记正文。如果 frontmatter 表达式引用了
  `noteLink`，子笔记依然会在该更新期间正常导入。若 `noteLink`
  仅存在于正文模板中，则在仅更新元数据时不会生效，因为正文没有重新渲染。
</Callout>

<Steps>
  <Step>

## Create-once behavior

Imported notes are created once and not automatically updated. If an imported file already exists for a child note, `noteLink` links to the existing file without re-importing. Editing the Zotero note afterward does not change the imported file.

To bring an imported note up to date, use the re-import commands described below.

If an attachment was skipped because its folder was not approved, a notice lists the blocked source folder. This can happen with a Zotero linked file, which Zotero stores in an external folder instead of its data directory. See [Zotero's guide to linked files](https://www.zotero.org/support/attaching_files#adding_linked_files).

Select <UiLabel name={m.notice_attachment_sources_skipped_action()} />, open <SettingsPath page={m.settings_page_attachments()} setting={m.settings_attachment_approved_name()} />, and approve the folder if you trust it. Then re-import the note to copy the attachment. Approval applies to future imports and does not update earlier imports automatically.

## Import every note in a library or collection [#import-all]

This path imports both kinds of note in one action: the child notes attached to your regular items and the standalone notes filed alongside them.

For the whole library, open the command palette and run:

<Command name={m.command_import_all_notes_name()} />

For one collection, right-click it in the Zotero sidebar and choose <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_collection_import_all_notes.label"]()} />. Nested subcollections are included. The same entry on **My Library** or a group library covers that whole library.

Obsidian opens the <UiLabel name={m.batch_import_title()} /> modal described below, listing every note it found. Review the list, then confirm to start the batch.

A note with no parent literature note is listed under <UiLabel name={m.batch_import_group_orphan({ count: "…" })} /> rather than under <UiLabel name={m.batch_import_group_import({ count: "…" })} />. That group states the profile its notes import through and lets you pick another one: the choice governs the new notes in the group.

The Obsidian command covers every library in your [library scope](/docs/reference/settings#library-scope) (set in <SettingsPath />). The Zotero entries cover the library or collection you right-clicked, whatever your library scope is.

If the collection no longer exists in your Zotero database, Obsidian reports <UiLabel name={m.notice_collection_not_found()} />. If the library no longer exists, it reports <UiLabel name={m.batch_all_library_unavailable()} />.

While more than one library contributes notes, the <UiLabel name={m.batch_import_title()} /> modal names the library beside each heading. If a selected library is missing from your Zotero database, the import continues over the rest and states how many libraries it skipped. If none of your selected libraries is available, no modal opens and a notice reports <UiLabel name={m.batch_all_no_library_in_scope()} />.

## Re-import notes in batch

ZotLit Companion, the Zotero add-on, starts batch re-import from Zotero.

<Steps>
  <Step>
    ### Select notes in Zotero

    In Zotero, select the notes you want to re-import, child notes under an item, or standalone notes. Right-click to open the context menu, then choose <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_item_import_notes.label"]({ count: 2 })} />.

    (This menu entry appears when the selection contains note items. If you select regular items instead, the menu shows <UiLabel name={m["zotero.menu_item_import_child_notes.label"]()} />, which triggers a different import path.)

  </Step>
  <Step>
    ### Confirm import in Obsidian

    What happens next depends on how many notes you selected:

    **Single note:** If the note has not been imported before, it imports directly and a toast confirms success. If it already exists in the vault, Obsidian shows a confirmation: <UiLabel name={m.modal_import_overwrite_title()} /> with the body <UiLabel name={m.modal_import_overwrite_desc({ title: "…" })} /> Select <UiLabel name={m.modal_import_overwrite_confirm()} /> to proceed, or dismiss to cancel.

    **Two or more notes:** Obsidian opens a modal titled <UiLabel name={m.batch_import_title()} />. It groups notes by status:

    - <UiLabel name={m.batch_import_group_import({ count: "…" })} />: new notes that do not yet exist in the vault.
    - <UiLabel name={m.batch_import_group_orphan({ count: "…" })} />: new notes with no parent literature note. The group names the profile they import through, and you can change it. See [Import every note in a library or collection](#import-all).
    - <UiLabel name={m.batch_import_group_overwrite({ count: "…" })} />: notes whose Zotero content has changed since the last import.
    - <UiLabel name={m.batch_import_group_up_to_date({ count: "…" })} />: notes that have not changed in Zotero and are skipped.

    The up-to-date check compares the `zotero-lastmod` frontmatter value in the existing file against the live `dateModified` timestamp in Zotero, in whole seconds.

    Select <UiLabel name={m.batch_import_confirm_button()} /> to proceed.

  </Step>
</Steps>

<Callout type="info" title="Large selections">
  A selection too large to fit in a protocol link falls back to an HTTP
  connection to Obsidian. If the ZotLit server is not enabled in Obsidian,
  Zotero shows a notice asking you to enable it or select fewer items. See [Set
  up live updates](/docs/how-to/set-up-live-updates) for the server setting.
</Callout>

## Profile of an imported note

An imported note records the profile that imported it in its `zotlit-profile` frontmatter field. ZotLit writes the field only when that profile is not the Default profile, so a note without it was imported under Default.

A re-import reads the field back, so the note keeps rendering through the profile that created it. When that profile no longer exists, ZotLit reports <UiLabel name={m.notice_imported_note_profile_unknown({ stamp: "…", target: "…" })} /> and offers <UiLabel name={m.profile_switch_recovery()} />.

## Import folder

Imported notes use their profile's <UiLabel name={m.settings_note_import_folder_name()} /> (default: `zotero_notes`). The Default profile's binding sits at <SettingsPath />, and another profile sets `importFolder` in its own document. The folder is created automatically if it does not exist. Each filename includes a short random suffix to guarantee uniqueness.

## Citations in imported notes

The imported note's body is the Zotero note's HTML converted to Markdown. Citations within it render through [the citation text](/docs/how-to/customize-a-template#citation-text), always as the `main` variant.

Each cited reference resolves its citation key in this order:

1. The live Zotero item's own citation key.
2. The citation snapshot embedded in the Zotero note.
3. A visible sentinel: the Zotero item key with `?` appended (e.g. `-@ABC123?` in the built-in citation text). The trailing `?` makes unresolved citations greppable in your vault.

If every cited reference within a single citation is unresolvable (no citation key from any source), ZotLit keeps that citation's original HTML verbatim. Nothing is lost.

## Use colored highlight syntax

1. Turn on <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_colored_highlights_name()} />. A profile other than Default sets it in its own profile document.
2. Open <UiLabel name={m.settings_note_import_highlight_mappings_name()} /> to set the output for each Zotero color. These mappings apply to all profiles.
3. Choose <UiLabel name={m.settings_note_import_highlight_mark()} />, a circle emoji (🔴 🟠 🟡 🟢 🔵 🟣), or <UiLabel name={m.settings_note_import_highlight_custom()} />.
4. For <UiLabel name={m.settings_note_import_highlight_custom()} />, enter one emoji in the field below. Combined emoji such as 👩‍🔬 are supported.
5. Import or re-import the note to apply your mappings.

By default, red, orange, yellow, green, blue, and purple use matching circle emoji. Magenta, gray, and plum use colored HTML marks. You can change any of these nine mappings.

An emoji mapping adds the selected emoji at the start of Colored Highlight Syntax:

```markdown
==🔵Highlighted text==
```

Your theme or another plugin must support the selected emoji to render its highlight color. Choosing a custom emoji does not add that rendering support.

The setting applies to highlights created in Zotero's note editor and inline annotation excerpts. Annotation excerpts keep their Zotero backlinks:

```markdown
[==🔵Highlighted text==](zotero://...)
```

Highlights with unrecognized or missing source colors remain HTML. Empty or invalid custom emoji also use HTML marks. ZotLit keeps HTML when the text contains `==` because it conflicts with the Markdown delimiter.

The setting is off by default. Turning it off uses HTML marks and keeps your saved mappings.

Changes affect later imports and re-imports; existing files stay unchanged until re-imported. When <UiLabel name={m.settings_note_import_annotations_template_name()} /> is on, annotation-template output stays unchanged.

## Render annotations from template

By default, annotation paragraphs in imported notes keep the HTML that Zotero inserted: highlighted or underlined excerpts with a citation link.

Turn on <SettingsPath page={m.settings_page_note_import()} setting={m.settings_note_import_annotations_template_name()} /> for the Default profile, or set `importAnnotationsAsTemplate` in a profile document. ZotLit renders those paragraphs through the Annotation Section of that profile, producing the same rich callouts used in literature notes.

<Callout type="warn" title="Replace on refresh">
  With this setting on, each annotation's text, comment, color, and page come
  from its saved Zotero data. Image and ink excerpts are prepared during import.
  Edits you made to that paragraph inside the imported note are replaced. This
  is why the setting is off by default.
</Callout>

### What is rendered

Only paragraphs that still match the original Zotero structure are rendered from the template. A paragraph is left untouched when:

- You typed text before the excerpt.
- You added other elements to the paragraph (a second annotation, extra formatting).
- The paragraph is nested inside a list item, blockquote, or table cell.
- The annotation was deleted in Zotero and can no longer be fetched.

Highlight, underline, image, and ink annotations are eligible for template rendering. Note and text annotations (which carry no excerpt) are kept as Zotero inserted them.

Image and ink paragraphs use [live excerpt images](/docs/concepts/excerpt-images) with both PDF readers closed. Ordinary embedded images keep the snapshots stored in the Child Note. A paragraph converted through the annotation template does not also copy its stored snapshot.

Re-import selects a new image version only for that Imported Note. Other notes and older image files stay unchanged. A failed refresh keeps a verified previous image when available; otherwise it writes an explanation and source link. Other content and notes can still import if an image fails.

With <UiLabel name={m.settings_attachment_import_name()} /> off, live excerpts create no new image files. The import summary counts only images requested by the template and combines the results for a batch.

The existing re-import rules still apply. Batch import skips notes whose Zotero modification time has not changed, even if a live annotation changed. Use the single-note re-import command to refresh such a note. With a missing annotation or blank annotation template, ZotLit converts the stored paragraph as ordinary note content.

<Callout type="warn" title="Text after the citation">
  Text you add after the citation mark (the comment slot) is not protected.
  Zotero places the annotation's own comment in that position, so on refresh it
  is replaced along with the rest of the paragraph. Place notes you want to keep
  in a separate paragraph.
</Callout>
