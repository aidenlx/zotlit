当您需要使用本机安装的独立 Pandoc 程序、自有参考文献库文件、自定义 CSL 编译参数或自动化命令行脚本工作流时，请参阅本指南。

若希望通过一篇实例文献笔记直观比对内置导出与原生 Pandoc 导出的差异，请参阅[搭建 Pandoc 引文工作流](/docs/tutorial/pandoc-citation-workflow)。

## 环境要求 [#requirements]

您需要：

- Pandoc 3.1.1 或更高版本。
- Obsidian 1.14.2 或更高版本。
- Obsidian 安装包版本 1.13.4 或更高版本，且开启了**命令行界面（CLI）**功能。
- Zotero 9 或更高版本。
- 保持 Obsidian 处于运行状态，且输入笔记所在的仓库已打开并正常加载了 ZotLit。
- 确保系统环境 PATH 中可调用 `obsidian` 命令行工具。

该工作流直接调用您本地安装的 Pandoc CLI，独立于 ZotLit 自带的受管 Pandoc 引擎与内置导出命令。

## 配置原生工作流

<Steps>
  <Step>
    ### 保存 ZotLit 集成文件对

    打开 <SettingsPath page={m.settings_page_citations()} setting={m.settings_citation_native_pandoc_heading()} />。在对应选项组中，找到 <UiLabel name={m.settings_citation_pandoc_files_name()} /> 并点击 <UiLabel name={m.settings_citation_pandoc_files_save()} />。

    选择一个专门存放工作流文件的本地目录。ZotLit 会在其中保存 `zotlit-cite.lua` 与 `zotlit.yaml`。

    请将这两个文件妥善放在一起并保持原名。在每次更新 ZotLit 插件后，均需重新保存一对最新文件。低于 ZotLit 2.2.0 版本保存的文件无法与 2.2.0 及更高版本协同工作。

  </Step>
  <Step>
    ### 生成参考文献库文件

    推荐使用 [Better BibTeX](https://retorque.re/zotero-better-bibtex/installation/) 来管理文献引用标识并实现参考文献库的自动实时更新。

    在 Zotero 中，右键单击包含被引条目的个人文库、群组文献库或分类。选择**导出文献库…**，格式选择 **Better CSL JSON**。勾选**保持更新**，然后保存为 `references.json`。

    当源文献库或分类发生变动时，导出的文件会自动刷新。详见 [Better BibTeX 自动导出指南](https://retorque.re/zotero-better-bibtex/exporting/auto/)。

    若未安装 Better BibTeX，可直接右键单击文献库或分类，选择**导出文献库…**，格式选择 **CSL JSON** 并保存为 `references.json`。后续若引用数据发生更改需手动重新导出。

    BibLaTeX 与 BibTeX 格式同样受支持。下文的命令以 CSL JSON 为例。

  </Step>
  <Step>
    ### 准备文献笔记引文

    Confirm that the cited Zotero item has a citation key and a ZotLit Literature Note. In your input note, add an unaliased link to that Literature Note with a Citation Fragment:

    ```md
    This result follows the earlier analysis [[Doe 2020#cite:locator=33]].
    ```

    Replace `Doe 2020` with the exact link target of your Literature Note. The locator fragment becomes a page locator in the Pandoc citation.

  </Step>
  <Step>
    ### Set the document style and language

    Without a style property, the note cites with the style ZotLit selects for it in Obsidian. For an Imported Note, that is its profile's style. For every other note, it is your <UiLabel name={m.settings_citation_references_style_name()} />. Set a style here only when this note needs a different one.

    Open the input note and run:

    <Command name={m.command_set_citation_presentation_name()} />

    Select a CSL style installed in Zotero, or select <UiLabel name={m.citation_presentation_style_inherited({ style: "…" })} />. Enter the complete document's language, then select <UiLabel name={m.citation_presentation_confirm()} />.

    When you select a named style, the note frontmatter contains its Zotero style ID and a Pandoc language tag:

    ```yaml
    ---
    zotlit-csl: http://www.zotero.org/styles/nature
    lang: en-US
    ---
    ```

    The note must not also contain `csl` or `citation-style` for this path. <UiLabel name={m.citation_presentation_style_inherited({ style: "…" })} /> removes `zotlit-csl`, and the note returns to the vault or profile style.

    <Callout type="info" title="Use a Pandoc-owned style instead">
      A document can keep a sole standard `csl` or `citation-style` input, and
      you can pass `--csl` on the command line. Remove `zotlit-csl` for that
      path. The ZotLit filter reports `csl-ambiguous` when a document contains
      both `csl` and `zotlit-csl`.
    </Callout>

  </Step>
  <Step>
    ### Run Pandoc with absolute paths

    Keep Obsidian open with the input vault and ZotLit loaded. Run the canonical command with absolute paths:

    ```sh
    pandoc "/absolute/path/to/input.md" --defaults "/absolute/path/to/workflow/zotlit.yaml" --bibliography "/absolute/path/to/references.json" --fail-if-warnings --output "/absolute/path/to/output.docx"
    ```

    Replace each example path. Keep `--fail-if-warnings` so a warning stops the run instead of producing an unchecked document.

  </Step>
  <Step>
    ### Verify the result

    Confirm that the output `.docx` exists and opens.

    Pandoc prints one ZotLit line in the terminal that names the style and where it comes from:

    ```text
    ZotLit: citations use APA Style 7th edition (from your vault settings).
    ```

    Check that the line names the style you expect. The source reads `from this note`, `from the Research profile`, `from your vault settings`, or `from the csl field or the --csl option`. When your vault selection is Default, the line names the Pandoc default style, Chicago author-date. This line is not a warning, so `--fail-if-warnings` does not stop the run.

    Check that `[[Doe 2020#cite:locator=33]]` became a formatted citation with locator `33`. Confirm that the document contains the corresponding formatted bibliography entry.

  </Step>
</Steps>

## Fix a failed run

Open <UiLabel name={m.settings_citation_pandoc_guide_name()} /> under <SettingsPath page={m.settings_page_citations()} setting={m.settings_citation_native_pandoc_heading()} /> for the full error reference.

| Error code                   | Recovery                                                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `file-not-found`             | Use the absolute path of a Markdown file inside the open vault.                                                                   |
| `database-unavailable`       | Repair the Zotero database connection in ZotLit.                                                                                  |
| `item-not-found`             | Correct the Literature Note's `zotero-key`, or restore the item.                                                                  |
| `citation-key-missing`       | Assign a citation key to the resolved Zotero item.                                                                                |
| `duplicate-citation-key`     | Give the cited items distinct citation keys.                                                                                      |
| `unresolved-citation-intent` | Point the `#cite:` link to a valid Literature Note.                                                                               |
| `style-missing`              | Install the named style in Zotero, or change the style where it is set: `zotlit-csl`, the ZotLit settings, or the profile.        |
| `style-property-invalid`     | Set `zotlit-csl` to the ID of a style installed in Zotero, or remove it.                                                          |
| `language-property-invalid`  | Set `lang` to a language tag such as `en-US`, or remove it. ZotLit checks `lang` only when the note has no `zotlit-csl` or `csl`. |
| `profile-unavailable`        | Switch the note to an available profile in Obsidian.                                                                              |
| `parent-missing`             | Install the dependent style's independent parent in Zotero.                                                                       |
| `csl-ambiguous`              | Keep only standard `csl` or `zotlit-csl`.                                                                                         |

Refresh both integration files when the saved pair came from an earlier ZotLit version. A pair saved before ZotLit 2.2.0 does not work with 2.2.0 or later. Keep the pair together when you move the workflow folder.
