如果您更喜欢直接手写 Markdown 文本而非使用工作台的各个标签页，可直接编辑配置方案文档自身。配置方案本质上就是您仓库中的一篇普通笔记，即使其中包含格式错误，ZotLit 也会允许您继续自由编辑。

## 直接以 Markdown 打开文档 [#open]

<Steps>
  <Step>
    ### 在 Obsidian 的 Markdown 编辑器中打开文档

    在文件列表中，您可以像对待其他普通笔记一样直接打开配置方案文档。如果当前正在工作台视图中，可点击标题栏的 <UiLabel name={m.workbench_advanced()} /> 在单窗口内编辑完整源码；或者打开面板菜单选择 <UiLabel name={m.template_workbench_open_markdown()} />，这会先保存当前内容并将面板切换至 Obsidian 原生的 Markdown 编辑器。

  </Step>
  <Step>
    ### 编辑并保存文档

    直接修改文本并保存文件。ZotLit 始终保持文档处于可编辑状态，任何语法错误都绝不会导致您的文本丢失。

  </Step>
  <Step>
    ### 返回工作台视图

    视图标题栏中提供了 <UiLabel name={m.template_workbench_open()} /> 按钮，点击即可重新在模板工作台中打开该文档，附带其预览渲染与问题诊断。

  </Step>
</Steps>

## ZotLit 强制要求的文档内部结构 [#shape]

配置方案文档按严格顺序由四个部分构成：manifest 元数据区、笔记模板源码、可选的受管块，以及标注格式区域。[配置方案文档](/docs/reference/templates/profile-document#document-structure)详细介绍了各部分的边界定义以及完整的示例文件。

在执行保存之前，必须满足以下所有结构要求：

- 文件的第一行必须严格是 `---`，且后续必须有一行独立的 `---` 闭合 manifest 区。
- `id` 必须是 12 位的字母或数字组合，且模板文件夹中不得有其他配置方案声明了相同的 ID。声明了重复 ID 的配置方案均会被排除在 ZotLit 之外。
- 笔记模板源码中最多只能包含一个受管块，由 `{% managed %}` 起始并由 `{% endmanaged %}` 闭合。在更新笔记时，ZotLit 仅重新渲染该块内的内容，正文其余部分完好保留。详见[文献笔记与受管区域](/docs/concepts/literature-notes-and-the-managed-region)。
- 在笔记源码之后，必须有且仅有一行 `--- zotlit:annotation ---` 分隔标记。
- 对于 `id: default` 的默认配置方案文档，不得包含 Match 匹配条件或特定绑定项。
- 由 ZotLit 管理的属性必须在 manifest 中声明，而非写在笔记模板正文中。详见 [Frontmatter 属性](/docs/reference/templates/frontmatter)。

## 问题面板（Problems）报告的内容 [#problems]

违反上述规则的文档绝不会被强制拒绝或丢弃。您可以在当前编辑处就地修正：ZotLit 会保持文档可编辑，并在工作台底部的 <UiLabel name={m.workbench_problems_heading()} /> 区域列出每一处故障以及推荐的修复建议。随着您的编辑修改，问题面板会自动动态重算，一旦文档恢复合规，对应的错误项就会自动消除。

| 违反的规则                                   | 问题面板报告的提示                                                    |
| -------------------------------------------- | --------------------------------------------------------------------- |
| 文件开头缺少 manifest 元数据区               | <UiLabel name={m.workbench_problem_invalid_document()} />             |
| manifest 不是有效的 YAML，或某属性键校验失败 | <UiLabel name={m.workbench_problem_invalid_manifest()} />             |
| manifest 中的片段被命名为了 `annotation`     | <UiLabel name={m.workbench_problem_reserved_annotation_partial()} />  |
| 笔记源码中包含了多个受管块                   | <UiLabel name={m.workbench_problem_duplicate_managed_block()} />      |
| 受管块未正确开始或闭合                       | <UiLabel name={m.workbench_problem_invalid_managed_block()} />        |
| 出现了除标注行之外的其他未知分隔标题         | <UiLabel name={m.workbench_problem_unknown_section_header()} />       |
| 缺少标注格式区域                             | <UiLabel name={m.workbench_problem_missing_annotation_section()} />   |
| 标注格式区域出现多次                         | <UiLabel name={m.workbench_problem_duplicate_annotation_section()} /> |

问题面板还提供 <UiLabel name={m.workbench_problems_copy()} />，可将完整报告粘贴到问题反馈中。有关报告的其他内容，请参阅[收集调试日志](/docs/how-to/collect-debug-logs)。
