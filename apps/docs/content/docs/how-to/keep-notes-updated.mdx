## Update with Update notes [#update-notes]

1. Open the literature note you want to update. (For <UiLabel name={m.modal_update_notes_all()} />, any note can be open.)
   The note is the active tab.
2. Open the command palette (`Ctrl+P` on Windows/Linux, `Cmd+P` on macOS) and run <Command inline name={m.command_update_notes_name()} />.
   A dialog titled <UiLabel name={m.modal_update_notes_title()} /> opens, with the checkbox <UiLabel name={m.modal_update_notes_create()} /> turned off by default.
3. Select <UiLabel name={m.modal_update_notes_active()} />.
   For a note made with the current default template, the notice <UiLabel name={m.notice_updated_note_no_region()} /> appears. The properties are refreshed, your body text stays as you wrote it, and the **Annotations** section is a live view that was already current. For a note with a managed region, the notice reads <UiLabel name={m.notice_updated_note()} />
   An update refreshes the properties ZotLit manages; your own writing and any properties you added stay as they are.
   - Or select <UiLabel name={m.modal_update_notes_all()} />: this updates every existing literature note in your [library scope](/docs/reference/settings#library-scope). A confirmation asks <UiLabel name={m.batch_update_existing_confirm_intro({ count: "…" })} />; papers with no note are listed under <UiLabel name={m.batch_update_group_no_note({ count: "…" })} /> and left alone.

## If you see something else

- **<UiLabel name={m.notice_updated_note_no_region()} />** This is the normal result for a note made with the current default template: the **Annotations** section is a live view and stays current by itself. If the note was created with ZotLit v1, the body was not rebuilt because v1 notes have no managed region; run <Command inline name={m.command_overwrite_note_name()} /> to rebuild the body using the Default profile, which discards the old body text.
- **Lines `%%zt-managed%%` and `%%/zt-managed%%` in the note.** An earlier default template or a profile with a managed block created this note. <Command inline name={m.command_update_note_name()} /> rewrites only what sits between those lines; text outside them stays as it is, and query views inside keep the settings saved in their toolbar. To stop ZotLit from updating that section, delete both comment lines.
- **The update commands are not in the palette, or <Command inline name={m.command_update_notes_name()} /> has no <UiLabel name={m.modal_update_notes_active()} /> button.** The active file is not a literature note because it lacks a `zotero-key` property. Open the literature note first.
- **An image in the note reads <UiLabel name={m.excerpt_image_unavailable()} /> with a link to the source.** The image could not be generated and the note had no earlier snapshot to keep, though the rest of the note updated. See [Excerpt images import outcomes](/docs/reference/excerpt-images#import-outcomes).
- **A notice starting "Excerpt images: …"** This counts images that were not generated fresh. "Kept from the note and not refreshed" means ZotLit kept the snapshot already in the note. See [Excerpt images import outcomes](/docs/reference/excerpt-images#import-outcomes).
- **An image reads <UiLabel name={m.excerpt_image_import_disabled()} />** Turn on <UiLabel name={m.settings_attachment_import_name()} /> under <SettingsPath page={m.settings_page_attachments()} />, then update the note again.
- **A notice: <UiLabel name={m.batch_all_no_library_in_scope()} />** None of the selected Zotero libraries are in the database ZotLit reads, so no dialog opens. Check your [Library scope settings](/docs/reference/settings#library-scope). If only some libraries are missing, the update continues and the confirmation lists how many were skipped.
- **Zotero says the selection is too large, or asks to enable a server.** Large selections are sent to Obsidian over a local server. Turn on the server in Obsidian, or select fewer papers in Zotero. See [Set up live updates](/docs/how-to/set-up-live-updates).
- **Zotero asks for confirmation each time it opens Obsidian.** This is Zotero's built-in prompt for `obsidian://` links. See [Suppress the Zotero security prompt](/docs/how-to/suppress-zotero-security-prompt).
