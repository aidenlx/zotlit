本篇指南将协助您将引文工作流迁移至 ZotLit。

完成迁移后，可参阅[搭建 Pandoc 引文工作流](/docs/tutorial/pandoc-citation-workflow)，通过单篇笔记实操比对内置导出与原生 Pandoc 导出。

[Pandoc Reference List 代码仓库](https://github.com/community-archive/obsidian-pandoc-reference-list)由 [Obsidian Community Archive](https://github.com/community-archive/.github) 组织归档维护。

## 梳理各项功能的迁移归宿

| 分类判定                 | 原有功能行为                                                                                            | ZotLit 中的对应处理方式                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 保持原样直接可用         | 字面量引文语法，如 `@doe2024`、`[@doe2024]` 及 `[@doe2024, p. 33]`                                      | 完整保留 Markdown 源码不变。开启 <UiLabel name={m.settings_citation_pandoc_citations_name()} /> 即可。 |
| 需调整设置或语法         | Zotero 文献库选择、实时格式化渲染、建议弹窗、提示工具条、CSL 样式选择、引文语言以及 `[[@citekey]]` 链接 | 配置 ZotLit 对应项，并对受影响的属性字段及链接进行核对。                                               |
| 继续通过原生 Pandoc 使用 | `bibliography`、参考文献库文件、多源文献库输入以及标准的 `csl` 或 `citation-style` 路径/URL             | 在[原生 Pandoc 工作流](/docs/how-to/export-with-native-pandoc)中继续保留这些参数输入。                 |
| ZotLit 中无直接等价物    | 应用内直接基于独立参考文献文件驱动、浮窗延迟控制、参考文献中的隐藏链接以及点击单条复制                  | 改用下文介绍的由 Zotero 数据库原生支撑的 ZotLit 控制方案。                                             |

ZotLit 的应用内引文功能直接读取 Zotero 文献条目。导出的参考文献库文件在原生 Pandoc 中依然十分重要，但它不再作为应用内<UiLabel name={m.references_view_name()} />侧边栏的数据源。

## 工作流迁移步骤

<Steps>
  <Step>
    ### 记录当前的配置

    记录现有的参考文献文件来源、选定的文献库、CSL 引文样式、语言以及渲染设置。

    在整个仓库中检索以下笔记属性与引文书写形式：

    - `bibliography`
    - `csl` 或 `citation-style`
    - `lang` 或 `citation-language`
    - `[[@`

    在完成全部验证步骤之前，请妥善保留原始笔记。

  </Step>
  <Step>
    ### 在 Zotero 中确认文献引用标识

    确认每篇被引用的 Zotero 条目均已设置文献引用标识。ZotLit 会依据 Zotero 原生的 **Citation Key** 字段解析字面量引文键。

    推荐安装 [Better BibTeX](https://retorque.re/zotero-better-bibtex/installation/) 来生成并维护稳定的文献引用标识。如果原生字段中已具备合规的标识键，ZotLit 并不强制依赖 Better BibTeX。

    在批量迁移笔记之前，请先确定您理想的标识命名格式，避免在迁移完成后频繁改动现有标识。

  </Step>
  <Step>
    ### 连接 Zotero 数据库

    Open <SettingsPath page={m.settings_page_zotero()} />. Confirm that <UiLabel name={m.settings_db_file_name()} /> points to the profile that contains your cited items.

    On the same page, under <UiLabel name={m.settings_zotero_libraries_heading()} />, set <UiLabel name={m.settings_library_scope_name()} /> to <UiLabel name={m.settings_library_scope_all()} />, or choose <UiLabel name={m.settings_library_scope_selected()} /> and add the same personal and group libraries you used before.

    ZotLit searches the complete scope at once. When one citation key matches several items, ZotLit reports an Ambiguous Citation Key. It does not choose an item by library order.

  </Step>
  <Step>
    ### Configure in-app formatting

    Open <SettingsPath page={m.settings_page_citations()} />.

    1. Keep <UiLabel name={m.settings_citation_pandoc_citations_name()} /> on.
    2. Keep <UiLabel name={m.settings_citation_show_formatted_name()} /> on.
    3. Under <UiLabel name={m.settings_citation_references_heading()} />, install the <UiLabel name={m.settings_citation_engine_name()} />.
    4. Install your former CSL style in Zotero.
    5. Select that style under <UiLabel name={m.settings_citation_references_style_name()} />.
    6. Set <UiLabel name={m.settings_citation_locale_name()} />, or leave it at <UiLabel name={m.settings_citation_locale_default()} />.

    Set <UiLabel name={m.settings_citation_hover_action_name()} /> to <UiLabel name={m.settings_citation_hover_action_popover()} /> when you previously used citekey tooltips. ZotLit has modifier-key controls for each editing mode, but no tooltip-delay setting.

  </Step>
  <Step>
    ### Migrate note metadata

    Apply these rules to each affected note:

    | Property                  | Migration rule                                                                                                                                                                    |
    | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `bibliography`            | Keep it only for native Pandoc. ZotLit's in-app features and built-in export get bibliography data from Zotero.                                                                   |
    | `csl` or `citation-style` | Keep one of these for a Pandoc-owned style. Do not add `zotlit-csl` to the same note.                                                                                             |
    | `zotlit-csl`              | Use this instead when ZotLit should resolve a style installed in Zotero. Remove `csl` and `citation-style` first.                                                                 |
    | `lang`                    | Keep it when it is a valid document language, such as `en-US`, `de`, or `zh-CN`. ZotLit also uses it for that note's citations.                                                   |
    | `citation-language`       | Convert it to `lang` only when the value describes the complete document. Otherwise, set the vault <UiLabel name={m.settings_citation_locale_name()} /> and remove this property. |

    To set a Zotero-installed style and document language together, run:

    <Command name={m.command_set_citation_presentation_name()} />

    The same action appears in the active note's **More options** menu. Its <UiLabel name={m.citation_presentation_language_name()} /> value becomes Pandoc `lang` for the complete exported document.

    <Callout type="warn" title="Choose one style owner">
      A native Pandoc document can use standard `csl` or `citation-style`, or
      ZotLit can resolve `zotlit-csl`. Keep only one family. The ZotLit filter
      reports `csl-ambiguous` when a document contains both `csl` and
      `zotlit-csl`.
    </Callout>

  </Step>
  <Step>
    ### Audit citekey links one at a time

    Pandoc Reference List can treat `[[@doe2024]]` as a citation. ZotLit's <UiLabel name={m.settings_citation_wikilink_citations_name()} /> setting has a different contract.

    Review every `[[@citekey]]` occurrence and choose its intended result:

    - Replace it with `[@citekey]` when it is only a citation.
    - Replace it with an unaliased link to the correct ZotLit Literature Note when it must cite and open that note.

    For example, use `[[Doe 2020]]` only when `Doe 2020.md` is the Literature Note for that item. Add `#cite:locator=33` when the link cites a locator: `[[Doe 2020#cite:locator=33]]`.

    Enable <UiLabel name={m.settings_citation_wikilink_citations_name()} /> after the Literature Note links are valid. Do not use a bulk replacement because link intent and note names differ by occurrence.

  </Step>
  <Step>
    ### Disable Pandoc Reference List for the test

    Keep your recorded settings, then disable Pandoc Reference List in **Settings > Community plugins**.

    Test rendered citations with only ZotLit active. This keeps both plugins from changing the same citation display.

  </Step>
  <Step>
    ### Verify one representative note

    Open a note that contains the syntax and metadata you migrated.

    1. Confirm that its literal citations format in Live Preview.
    2. Run <Command inline name={m.command_open_references_view_name()} />.
    3. Hover a citation and inspect the <UiLabel name={m.settings_citation_hover_action_popover()} />.
    4. Open its Literature Note, Zotero item, and attachment where available.
    5. Select <UiLabel name={m.references_copy_bibliography()} /> in the <UiLabel name={m.references_view_name()} /> Sidebar.

    Resolve every Reference Error before you continue. In particular, change duplicate citation keys or narrow <UiLabel name={m.settings_library_scope_name()} /> when a key is ambiguous.

  </Step>
  <Step>
    ### Choose an export workflow

    Use <Command inline name={m.command_pandoc_export_name()} /> for ZotLit's built-in DOCX or HTML export.

    Continue with [native Pandoc](/docs/how-to/export-with-native-pandoc) when you need bibliography files, multiple inputs, standard CSL paths or URLs, or other Pandoc options.

  </Step>
</Steps>

## Behaviors without a direct equivalent

- **Bibliography file for in-app references:** connect ZotLit to the matching Zotero database instead.
- **Arbitrary CSL path or URL in Obsidian:** install the style in Zotero. Keep the path or URL for native Pandoc when required.
- **Tooltip delay:** choose <UiLabel name={m.settings_citation_hover_action_popover()} />, <UiLabel name={m.settings_citation_hover_action_page_preview()} />, or <UiLabel name={m.settings_citation_hover_action_off()} />. Configure modifier-key requirements by editing mode.
- **Hide links in references:** ZotLit has no matching citation setting.
- **Click one reference to copy it:** select the entry text and use your normal copy shortcut. The row click targets citation navigation and item actions.
