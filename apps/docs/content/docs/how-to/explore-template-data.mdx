The Template Data Explorer shows the full data tree that templates receive for a Zotero item. Use it to discover field paths, inspect values, and copy ready-to-use snippets into your templates.

## Open the explorer

The explorer opens in the right sidebar. You can reach it from several entry points.

### From the command palette

<Steps>
  <Step>
    ### Run the command

    Open the command palette and run:

    <Command name={m.command_open_template_data_explorer_name()} />

    If a literature note is active in the editor, the explorer seeds from that note's Zotero item. Otherwise it opens with an item picker.

  </Step>
</Steps>

### From a literature note

Right-click (or click the three-dot menu) on a literature note in the file explorer or tab, then select **{m.template_data_explorer_menu_explore()}**. The explorer opens seeded with that note's item.

### From the annotation view

In the annotation sidebar, open the more-options menu on any annotation row and select **{m.template_data_explorer_menu_explore()}**. The explorer opens anchored at that annotation.

### From Zotero (item)

ZotLit Companion, the Zotero add-on, adds these entry points in Zotero. Right-click a single item, open the **ZotLit** submenu, and select **{m.template_data_explorer_menu_explore()}**. Zotero opens the explorer in Obsidian via a protocol link.

### From Zotero (annotation)

In Zotero's PDF reader, right-click an annotation and select **Explore Annotation in Obsidian**, added by the Companion. The explorer opens in Obsidian anchored at that annotation.

## Copy a Zotero key [#indexed-key]

A Zotero key identifies one object: an item, an attachment, an annotation, or a note. Copy one when a tool asks you which object to work on.

In Obsidian:

- For the active literature note, run <Command inline name={m.command_copy_item_key_name()} />, or select **{m.command_copy_item_key_name()}** from the file menu.
- On an annotation row, open the more-options menu and select **{m.indexed_key_menu_copy_annotation()}**.
- In the explorer, open the more-options menu on the tab and select **{m.command_copy_item_key_name()}** or **{m.indexed_key_menu_copy_annotation()}**. The label follows the current root.

If a literature note is already open, you can also copy its `zotero-key` frontmatter value by hand.

In Zotero, the Companion adds two more entry points:

- Right-click one or more library rows and open the **ZotLit** submenu. The entry names the kind you selected, such as **Copy Item Key** or **Copy Attachment Key**. Multiple rows copy one key per line.
- In the PDF reader, right-click an annotation and select **Copy Annotation Key**.

One key is always enough. The [root you choose](#roots) — note or annotation — selects the view on that object.

## Browse the data tree

The explorer displays a collapsible tree of every property available under the `zt` root object. Expand nodes to drill into nested objects and arrays. Primitive values (strings, numbers, booleans) display inline next to their key.

### Filter properties

Type in the filter box (placeholder: "Filter properties...") to narrow the tree. Filtering matches key names and stringified primitive values by case-insensitive substring. Matching nodes and their ancestor chains auto-expand.

### Switch between note root and annotation root [#roots]

By default the tree shows the full `zt` object (note root). To view the data available inside annotation templates, open the more-options menu on an annotation node in the tree and select **{m.template_data_explorer_menu_explore_annotation()}**. The tree re-anchors to that annotation's data shape.

To return, click **{m.template_data_explorer_back_to_note_root()}** in the breadcrumb.

## Copy paths and snippets

Each row in the tree offers actions to copy data into your templates.

### Copy path

Click **{m.template_data_explorer_menu_copy_path()}** in a row's more-options menu to copy the engine-neutral property path (e.g. `zt.creators[0].lastName`). The notice "Path copied" confirms the action.

### Copy value

Click the **{m.template_data_explorer_menu_copy_value()}** button on a row to copy its current value. Primitives copy verbatim; objects and arrays copy as JSON. The notice "Value copied" confirms the action.

### Copy template snippets

Below **{m.template_data_explorer_menu_copy_path()}**, the menu offers ready-to-use template snippets wrapped in the correct syntax:

- **{m.template_data_explorer_menu_copy_output()}**: renders the value (e.g. `{{ zt.title }}`).
- **{m.template_data_explorer_menu_copy_if_present()}**: wraps the value in a conditional block.
- **{m.template_data_explorer_menu_copy_loop()}**: iterates over an array node.
- **{m.template_data_explorer_menu_copy_joined()}**: joins an array into a delimiter-separated string.

Array nodes show **{m.template_data_explorer_menu_copy_loop()}** and **{m.template_data_explorer_menu_copy_joined()}**. Non-array nodes show **{m.template_data_explorer_menu_copy_output()}** and **{m.template_data_explorer_menu_copy_if_present()}**.

When {m.settings_template_js_enable_name()} is enabled, these snippet items split into **{m.template_data_explorer_submenu_liquid()}** and **{m.template_data_explorer_submenu_eta()}** submenus so you can pick the syntax matching your template. When disabled, Liquid snippets appear inline with no submenu.

A successful copy shows the notice "Snippet copied."
