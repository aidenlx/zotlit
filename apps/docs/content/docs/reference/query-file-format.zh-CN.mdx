本参考列出了查询文件（`.zotquery`）和查询块（` ```zotquery `）的键名。两者包含相同的 YAML 文本，格式采用 Obsidian `.base` 文件的形式。

工具栏会自动为你写入这些键。当你手动编写查询块，或将某个视图从一个文件复制到另一个文件时，可以手动编辑它们。

## 示例 [#example]

```yaml
filters: collections.within("Thesis")
views:
  - type: table
    name: Reading list
    from: items
    sort:
      - property: title
        direction: ASC
    order:
      - title
      - firstAuthor
      - date
      - vault.literatureNote
      - vault.reading-status
    limit: 100
  - type: annotations
    name: Figures
    from: annotations
    filters: tags.contains("figure")
    groupBy:
      property: item.indexedKey
      direction: ASC
    limit: 100
```

## 顶层键 [#top-level]

| 键           | 取值                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `filters`    | 适用于所有视图的筛选器。它们会应用于与首个视图具有相同 `from` 的每个视图。参见[筛选器](#filters)。 |
| `formulas`   | 文件中的公式，按名称索引。参见[公式](#formulas)。                                                  |
| `properties` | 每个属性的显示名称，按属性路径索引。参见[显示名称](#properties)。                                  |
| `views`      | 视图列表。必填。首个视图为默认视图，不带 `#View name` 的嵌入将显示该视图。                         |

ZotLit 在保存时会保留文件中的所有其他键。

## 视图键 [#view]

| 键           | 取值                                                                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`       | 布局方式：`annotations`、`table`、`list` 或 `cards`。必填。                                                                                                                                                                 |
| `name`       | 视图名称。必填，且不能与文件中的其他视图同名。当两个视图同名时，文件将在对应行位置显示错误提示。                                                                                                                            |
| `from`       | 每行对应的记录类型：`annotations`、`attachments` 或 `items`。必填。                                                                                                                                                         |
| `filters`    | 该视图专属的筛选器。参见[筛选器](#filters)。                                                                                                                                                                                |
| `sort`       | `property` 与 `direction` 对的列表。排在前面的键优先排序。`direction` 为 `ASC` 或 `DESC`；默认为 `ASC`。条目视图还可以按[仓库属性](#vault-sort)排序。                                                                       |
| `groupBy`    | 一个 `property` 与 `direction` 对。各行将按该属性的每个值归类到对应标题下。                                                                                                                                                 |
| `groupOrder` | 用于“手动”（Manual）分组顺序的分组值列表。仅显示列出的分组，并按此顺序排列。`null` 代表无值记录所在的分组。                                                                                                                 |
| `limit`      | 正整数：视图显示的最大行数。不设置 `limit` 时，视图将显示所有匹配项。在按[仓库属性](#vault)排序或筛选后，`limit` 依然按视图实际显示的行数计算。                                                                             |
| `order`      | 每行显示的属性路径列表，按显示顺序排列。复制与导出 CSV 时将以其作为列。若未设置 `order`，布局将显示记录的默认属性。对于条目表格，还可以加入 `vault.literatureNote` 以显示文献笔记列。条目视图还可以显示[仓库属性](#vault)。 |
| `columnSize` | 你调整过宽度的每个表格列的像素宽度，按属性路径索引。未记录的列采用自适应宽度。                                                                                                                                              |

`property` 的值为视图记录的属性路径，与 [ZotLit Query](/docs/reference/commands#query-cli) 中的命名一致。例如，在条目视图中 `title` 为文献标题，而在标注视图中 `item.title` 为文献标题。

`order` 还支持 `vault.literatureNote`（在条目表格中）、表示[仓库属性](#vault)的 `vault.<name>`（在条目视图中），以及表示[公式](#formulas)的 `formula.<name>`。`sort` 和 `groupBy` 目前暂不支持公式：按公式排序或分组的视图将在行位置显示错误。`groupBy` 同样不支持仓库属性。

### 布局与记录 [#layouts]

| `type`        | 允许的 `from`                           |
| ------------- | --------------------------------------- |
| `annotations` | `annotations`                           |
| `table`       | `items`                                 |
| `list`        | `annotations`、`attachments` 或 `items` |
| `cards`       | `annotations`、`attachments` 或 `items` |

若视图的 `type` 与 `from` 不匹配，将在行位置显示提示信息。

### 布局选项 [#layout-options]

| 布局          | 键                 | 取值                                      | 默认值   |
| ------------- | ------------------ | ----------------------------------------- | -------- |
| `annotations` | `cardWidth`        | 卡片最小宽度（像素），取值范围 200 到 800 | `320`    |
| `annotations` | `showComment`      | `true` 或 `false`                         | `true`   |
| `annotations` | `showTags`         | `true` 或 `false`                         | `true`   |
| `annotations` | `showPage`         | `true` 或 `false`                         | `true`   |
| `list`        | `markers`          | `bullet`、`number` 或 `none`              | `bullet` |
| `list`        | `indentProperties` | `true` 或 `false`                         | `false`  |
| `list`        | `separator`        | 一行中两个属性之间的分隔文本              | `, `     |
| `cards`       | `cardSize`         | 卡片最小宽度（像素），取值范围 50 到 800  | `200`    |

## 筛选器 [#filters]

筛选器可以是一个[筛选表达式](/docs/reference/how-queries-work#steps)，也可以是置于 `and`、`or` 或 `not` 下的分组筛选条件：

```yaml
filters:
  and:
    - colorName == "yellow"
    - or:
        - tags.contains("method")
        - tags.contains("result")
```

`and` 匹配符合所有条目的记录。`or` 匹配符合至少一项的记录。筛选器编辑器会将 `not` 分组作为单个表达式条件打开。

筛选器可以通过 `this.item` 和 `this.attachment` 引用查询上下文（Query Context）：

| `from`        | 筛选当前笔记所属文献的记录           | 筛选单个附件的记录                         |
| ------------- | ------------------------------------ | ------------------------------------------ |
| `annotations` | `item == this.item`                  | `attachment == this.attachment`            |
| `attachments` | `item == this.item`                  | `indexedKey == this.attachment.indexedKey` |
| `items`       | `indexedKey == this.item.indexedKey` |                                            |

在嵌入视图或查询块中，`this.item` 指代笔记的 `zotero-key` 属性所指定的条目。在查询文件自己的标签页中，`this` 没有值。参见 [`this`：笔记所属文献](/docs/reference/how-queries-work#this)。

## 公式 [#formulas]

`formulas` 将每个公式名称映射到一个[筛选表达式](/docs/reference/how-queries-work#steps)。视图将计算结果显示为属性 `formula.<name>`：

```yaml
formulas:
  year: date.year
  authors: creators.length
views:
  - type: table
    name: Reading list
    from: items
    filters: formula.year >= 2020
    order:
      - title
      - formula.year
      - formula.authors
```

| 规则     | 取值                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 名称     | 字母、数字和 `_`，以字母或 `_` 开头。区分大小写。                                               |
| 表达式   | 与筛选器使用相同的语法。它可以读取视图记录的属性、`this.item`、`this.attachment` 以及其他公式。 |
| 结果     | `true` 或 `false`、数字、文本、日期或列表。                                                     |
| 使用位置 | 任何视图的 `order` 与 `filters`，以及其他公式中。                                               |

视图仅计算其 `order` 和 `filters` 所使用的公式。通过其他公式间接引用自身的公式属于错误配置。

无法在视图记录上运行的公式仅会在该视图中对该属性标错。例如，表达式为 `colorName` 的公式 `colour` 可以在标注视图中正常运行。如果同一文件中的条目视图显示 `formula.colour`，该属性会被标记异常，而其他属性仍正常显示。若某条记录无法计算公式结果，该单元格将显示[错误值](/docs/reference/how-queries-work#error-values)。

## 仓库属性 [#vault]

仓库属性 `vault.<name>` 是指文献对应文献笔记中属性（frontmatter）键 `<name>` 的值。`vault.` 后面的文本就是笔记中写入的键名，包含其大小写和连字符。例如，`vault.reading-status` 会读取每篇文献对应笔记中的 `reading-status` 属性。

仓库属性适用于 `from: items` 的视图。[来自文献笔记的属性](/docs/reference/how-queries-work#vault)详细说明了 ZotLit 如何读取它们。

| 键           | 是否支持仓库属性                                          |
| ------------ | --------------------------------------------------------- |
| `order`      | 是。表格、列表和卡片布局均可显示。表格还支持直接编辑。    |
| `sort`       | 是。参见[排序](#vault-sort)。                             |
| `filters`    | 是，作为每行都必须匹配的条件。参见[筛选](#vault-filter)。 |
| `properties` | 是。键名为 `vault.<name>`，如 `vault.reading-status`。    |
| `columnSize` | 是。                                                      |
| `groupBy`    | 否。                                                      |

每个单元格会显示以下三种状态之一：

| 文献状态                     | 单元格显示                                                   |
| ---------------------------- | ------------------------------------------------------------ |
| 无文献笔记                   | 浅色文字显示 <UiLabel name={m.query_view_vault_no_note()} /> |
| 有笔记但未包含该键，或值为空 | 空白                                                         |
| 有笔记且包含有效值           | 该值                                                         |

当一篇文献关联多个文献笔记时，视图将读取最后修改的笔记。在文献笔记内部的嵌入视图或查询块中，该笔记所属文献对应的行将直接读取该笔记。复制与 CSV 导出均会写入每个仓库属性的值。当笔记的属性发生变化时，视图会自动刷新单元格。

### 仓库属性不能使用的名称 [#vault-reserved]

<UiLabel name={m.query_view_properties()} />
菜单中不会列出这些键，也不会添加它们：

| 键                | 归属     |
| ----------------- | -------- |
| `tags`            | Obsidian |
| `aliases`         | Obsidian |
| `cssclasses`      | Obsidian |
| `zotero-key`      | ZotLit   |
| `zotlit-profile`  | ZotLit   |
| `zotero-note-key` | ZotLit   |
| `zotero-lastmod`  | ZotLit   |
| `zotlit-csl`      | ZotLit   |

手动输入到 `order` 中的键（如 `vault.tags`）仍会作为一列显示。

若笔记对应的[配置方案](/docs/reference/templates/how-templates-work#profiles)以 `replace` [合并策略](/docs/reference/templates/frontmatter#merge-strategies)写入某个键，该键在表格中将为只读，因为下一次更新笔记时会将其覆盖。鼠标悬停在单元格上时会显示锁定图标。默认配置方案自带的 `title`、`related`、`collections` 和 `citekey` 即采用此方式。采用 `keep` 或 `append` 策略的键保持可编辑状态。

### 编辑写入的值 [#vault-values]

表格根据 Obsidian 属性面板赋予该属性的类型来编辑仓库属性。当属性在面板中未指定类型时，表格将使用笔记中现有值的类型，否则默认为文本。

| 类型             | 编辑方式                                  | 写入的值                                 |
| ---------------- | ----------------------------------------- | ---------------------------------------- |
| 文本             | 文本框                                    | 文本                                     |
| 列表、标签或别名 | 一行中的多项。按 `Enter` 将文本添加为一项 | 文本列表                                 |
| 数字             | 文本框                                    | 数字                                     |
| 复选框           | 点击切换勾选状态                          | `true` 或 `false`                        |
| 日期             | 日期选择框                                | 日期，格式为 `YYYY-MM-DD`                |
| 日期与时间       | 日期时间选择框                            | 日期与时间，格式为 `YYYY-MM-DDTHH:mm:ss` |

每次编辑仅会写入自身对应的键。清空单元格将保留该键并将值设为空。向数字属性输入非数字文本不会写入任何内容。

### 排序 [#vault-sort]

```yaml
sort:
  - property: vault.reading-status
    direction: ASC
  - property: date
    direction: DESC
```

空值在升序和降序中均排在最后。排序可以混用仓库属性和 Zotero 属性。

按仓库属性排序时，视图最多读取 5,000 篇匹配文献进行排序，随后在分组视图的每个分组中保留 `limit` 行。当匹配文献超过该数量时，仅对这 5,000 篇进行排序，结果计数中会同时显示这两个数字。修改值之后，各行会保持原有位置，直到视图重新运行。

### 筛选 [#vault-filter]

筛选条件按 `vault.<name>` 读取仓库属性；若名称中包含连字符或空格，则按 `vault["<name>"]` 读取：

```yaml
filters:
  and:
    - collections.within("Thesis")
    - vault["reading-status"] == "read"
```

没有文献笔记的文献视为没有值。因此 `vault["reading-status"] != "read"` 和 `vault["reading-status"] == null` 均会匹配没有笔记的文献。

仓库条件必须作为独立的条件项，且每一行都必须匹配该条件：

- 整个筛选器仅由一个仓库条件构成。
- 或者该条件直接作为文件或视图 `filters` 顶层 `and` 下的直接条目。

以下条件会导致视图中止运行，筛选器编辑器中的条件行会显示原因：

| 条件                                                                            | 原因                                                  |
| ------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 位于 `or` 或 `not` 分组内的仓库条件                                             | <UiLabel name={m.query_view_vault_filter_nested()} /> |
| 同时读取仓库属性和 Zotero 属性的条件，如 `vault.rating > 3 && date.year > 2020` | <UiLabel name={m.query_view_vault_filter_mixed()} />  |

请将混合条件拆分为 `and` 下的两个独立条目。读取 `this` 或通过表达式指定属性（如 `vault[name]`）的条件也会显示第二种原因。

## 显示名称 [#properties]

`properties` 用于为属性指定显示名称。每个键名与 `order` 中的条目文本一致：属性路径、`vault.literatureNote`、表示[仓库属性](#vault)的 `vault.<name>`，或表示公式的 `formula.<name>`。

```yaml
properties:
  title:
    displayName: Work
  formula.year:
    displayName: Year of source
```

显示名称会出现在文件的所有视图中：表格表头、卡片标签、<UiLabel name={m.query_view_properties()} />菜单，以及复制和导出 CSV 的表头行。ZotLit 会保留每个属性下的其他键。带有 Obsidian Bases 前缀 `note.` 的键（如 `note.date`）不代表任何属性。

## 新建查询文件 [#new-file]

通过[命令面板或文件列表新建](/docs/how-to/use-query-files#create)的查询文件包含以下文本：

```yaml
views:
  - type: table
    name: Items
    from: items
    sort:
      - property: dateModified
        direction: DESC
    limit: 100
    order:
      - title
      - creators
      - date.year
      - vault.literatureNote
  - type: annotations
    name: Annotations
    from: annotations
    groupBy:
      property: item.indexedKey
      direction: ASC
    limit: 100
```

ZotLit 会以当前应用的语言写入视图名称。
