本页介绍 ZotLit 中配置的 Liquid 模板语言：输出表达式、标签、过滤器、空白控制、ZotLit 专有词汇、输出类型转换、引入机制以及模板文档的命名规则。

所有模板数据都可以通过单个变量 `zt` 访问。`zt` 的具体结构取决于模板类型：完整属性列表请参阅[数据参考](/docs/reference/templates/data)。

## 输出与标签 [#outputs-and-tags]

Liquid 使用两种分隔符：

| 语法               | 用途                         |
| ------------------ | ---------------------------- |
| `{{ expression }}` | 将值渲染输出到笔记中         |
| `{% tag %}`        | 执行逻辑操作，不产生直接输出 |

```liquid
{{ zt.title }}
{% if zt.comment %}
{{ zt.comment }}
{% endif %}
```

使用 `{% comment %}...{% endcomment %}` 可完全注释掉某个部分：

```liquid
{% comment %}
Draft: revisit multi-author rendering
{% endcomment %}
```

## 真值判断 [#truthiness]

在 Liquid 中，只有 `nil`（null 或缺失）和 `false` 被视为假值（falsy）。`0`、`""` 和空数组均为真值（truthy）。

ZotLit 在渲染前会将空字符串字段值规格化为 `null`。这意味着当没有评论时 `{% if zt.comment %}` 为假，有评论时为真，无需书写 `!= ""` 进行判断。

## 空白控制 [#whitespace-control]

Liquid 会完全按照书写的内容渲染空白字符，不会自动清除任何空格或换行。

在分隔符内侧添加 `-` 可清除对应侧的空白：

| 标记          | 作用                                                                 |
| ------------- | -------------------------------------------------------------------- |
| `{%-` / `{{-` | 清除标签前同行的缩进空白。绝不会清除独立的换行符。                   |
| `-%}` / `-}}` | 清除行内空格以及紧随其后的**恰好一个**换行符。其后的空行依然会保留。 |

```liquid
{% for note in zt.notes -%}
- {{ note.noteLink }}
{% endfor %}
```

`for` 标签末尾的 `-%}` 会消除紧随其后的换行符，因此每次循环迭代都会以 `- ` 开头。置于 `-%}` 标记之后的空行仍会保留。该标记始终只会移除一个换行符。

Liquid 没有仓库层级的全局空白设置。空白清除必须在每个标签上显式指定，以保证模板在不同仓库间具有良好的可移植性。

<Callout type="info" title="Eta 具有单独的 autoTrim 设置">
  Eta 引擎拥有自己独立的前后空白自动清除设置（autoTrim）。这些设置不适用于
  Liquid 模板。详见 [Eta 语法](/docs/reference/templates/eta-syntax)。
</Callout>

## `{% liquid %}` 语句块 [#the--liquid--statement-block]

对于多行逻辑且不想产生多余空白的情况，`{% liquid %}` 允许每行书写一条语句而无需重复添加定界符。除了显式 `echo` 的内容外，不会产生任何输出：

```liquid
{% liquid
  assign names = "" | split: ","
  for creator in zt.creators
    assign names = names | push: creator.lastName
  endfor
  echo names | join: ", "
%}
```

该语句块内部的缩进会被忽略。

<Callout type="warn" title="echo 会绕过输出类型强制转换">
  `{% liquid %}` 语句块内部的 `{% echo %}` 不会应用 `{{ }}` 具有的输出类型强制转换。当你需要 null 转空字符串及日期规格化功能时，请使用 `{{ }}` 输出。
</Callout>

## 控制流 [#control-flow]

### if / elsif / else / endif [#if-elsif-else-endif]

```liquid
{% if zt.abstract %}
> {{ zt.abstract }}
{% elsif zt.comment %}
> {{ zt.comment }}
{% else %}
> (no abstract)
{% endif %}
```

### unless / endunless [#unless--endunless]

```liquid
{% unless zt.notes.size > 0 %}
No child notes.
{% endunless %}
```

### for / endfor [#for-endfor]

```liquid
{% for c in zt.creators limit: 3 offset: 1 reversed %}
- {{ c.fullName }}
{% endfor %}
```

`for` 支持 `limit:`、`offset:` 和 `reversed` 修饰符。

### case / when / endcase [#case--when--endcase]

```liquid
{% case zt.itemType %}
{% when "journalArticle" %}
Journal article
{% when "book", "bookSection" %}
Book
{% else %}
Other
{% endcase %}
```

### assign 与 capture [#assign-and-capture]

```liquid
{% assign year = zt.dateAdded | date: "%Y" %}
{% capture heading %}Notes from {{ year }}{% endcapture %}
## {{ heading }}
```

## 标准过滤器 [#standard-filters]

过滤器通过 `|` 对值进行转换，并在 `:` 后接收参数。

### 数组过滤器 [#array-filters]

`map`、`where`、`compact`、`join`、`sort`、`first`、`last`、`size`、`push`、`uniq`、`group_by`

```liquid
{{ zt.attachments | map: "fileLink" | compact | join: " " }}
{{ zt.creators | map: "lastName" | join: ", " }}
```

### 字符串过滤器 [#string-filters]

`append`、`prepend`、`split`、`strip`、`upcase`、`downcase`、`replace`、`truncate`、`default`

```liquid
{{ zt.citationKey | default: zt.DOI | default: zt.title | default: zt.key }}
{{ zt.title | truncate: 60 }}
```

当输入为 nil、false 或空字符串时，`default` 会返回指定的默认参数值。

## ZotLit 专用词汇 [#zotlit-vocabulary]

ZotLit 注册了一小组专用于文献笔记任务的标签和过滤器。

### `{% render_annotation %}`：渲染标注 [#render-annotation]

渲染单个标注，在标注模板内部可通过 `zt` 访问该标注对象。

```liquid
{% render_annotation annotation %}
```

annotation 参数是必填的。缺失或为 null 时会抛出错误。

对于标注值，等效的原生 Liquid 语法为：

```liquid
{% render "annotation" with annotation as zt %}
```

命名参数形式 `{% render "annotation", zt: annotation %}` 同样等效。

在文献笔记配置方案中，快捷调用和原生调用 `annotation` 都会使用该配置方案的“标注分节”。这个必选的末尾分节始于独立的 `--- zotlit:annotation ---` 行，一直持续到文档末尾。它使用当前配置方案的语言，内容可以为空。

从共享片段发起的调用会使用发起调用所在配置方案的标注分节，且标注数据彼此隔离。直接插入标注以及导入笔记在遇到匹配的配置方案时也会使用该分节。在配置方案渲染之外，快捷调用会继续使用原有的同名模板查找机制。

### `{% bq %}`：块引用块 [#bq-blockquote-block]

将其内容包装为 Markdown 块引用（blockquote）。每一行都会加上 `> ` 前缀。内容会先被去除首尾空白。块内部连续的空行会合并为一个独立的 `>`。

```liquid
{% bq %}
[!note] Page {{ zt.pageLabel }}

{{ zt.imgLink | embed }}{{ zt.text }}
{% if zt.comment %}

{{ zt.comment }}
{% endif %}
{% endbq %}
```

渲染输出：

```markdown
> [!note] Page 42
>
> ![[excerpt.png]]The highlighted passage
>
> My thoughts on this
```

### `embed`：嵌入过滤器 [#embed-embed-filter]

为非空字符串添加 `!` 前缀，生成 Obsidian 嵌入语法。null、undefined、空字符串或非字符串值会转为空字符串 `""`。

```liquid
{{ zt.imgLink | embed }}
```

| 输入                | 输出                 |
| ------------------- | -------------------- |
| `"[[excerpt.png]]"` | `"![[excerpt.png]]"` |
| `null`              | `""`                 |
| `""`                | `""`                 |

对于 `zt.imgLink`，该过滤器会使用已生成的摘录图片。如果没有可用图片，它会返回说明和来源链接，而不会添加 `!`。有关已保存快照和导入结果的说明，请参阅[摘录图片](/docs/reference/excerpt-images)。

### 链接过滤器 [#link-filters]

三个用于生成 Obsidian 双链（wiki-link）的过滤器，支持可选的别名（alias）和子路径（subpath）：

| 过滤器      | 生成内容     |
| ----------- | ------------ |
| `file_link` | 附件文件链接 |
| `note_link` | 笔记链接     |
| `img_link`  | 摘录图片链接 |

每个过滤器都接受两个可选的位置参数：`alias` 和 `subpath`。

```liquid
{{ zt.attachments[0] | file_link: "Open the PDF" }}
{{ zt | note_link: "See notes", "#Summary" }}
{{ zt | img_link: "alt text" }}
```

<Callout type="warn">
  在标注上使用 `file_link`
  已被弃用。它保存的是渲染笔记的那台电脑上的本地文件路径，在另一台电脑上或
  Zotero
  存储目录移动后将无法打开任何文件。请像[默认标注模板](/docs/reference/templates/defaults#annotation-template)那样，使用持久链接
  `zt.backlink` 链接到标注。`zt.backlink` 是普通 URL，不是过滤器。附件上的
  `file_link` 没有被弃用，标注上的用法在当前主版本周期内仍然可用。
</Callout>

当文件或笔记链接无法解析时，过滤器会返回 `null`（`compact` 会将其从数组中移除，输出转换会将其渲染为 `""`）。对于图片和手绘标注，若图片不可用，`img_link` 会返回后备提示内容。对于其他标注类型，它会返回 `null`。

### `note_links`：批量笔记链接 [#note_links-batch-note-links]

将条目数组映射为其笔记链接。无法解析链接的条目会渲染为包含该对象 key 的 `zt-error:` 标记，而不会被静默丢弃。

```liquid
{{ zt.relatedItems | note_links | join: ", " }}
```

### `pandoc_cite`：Pandoc 引用源码 [#pandoc-cite]

将引用条目（Citation Item）数组格式化为 Pandoc 引用源码。将 `zt.citations` 直接传给该过滤器即可。

```liquid
{{ zt.citations | pandoc_cite }}
{{ zt.citations | pandoc_cite: "prefer-author-in-text" }}
```

可选参数默认为 `"normal"`。

| 形式                      | 单个条目的输出 | 说明                                                                                                            |
| ------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------- |
| `"normal"`                | `[@smith2024]` | 生成带方括号的引用组（Citation Cluster）。                                                                      |
| `"prefer-author-in-text"` | `@smith2024`   | 当首个保留条目无前缀且未隐藏作者时，生成正文内作者引用（Author-in-text Citation）。否则，生成标准的括号引用组。 |

该过滤器支持 Pandoc 源码中使用的所有引用条目属性：

| 输入                                        | 输出                       |
| ------------------------------------------- | -------------------------- |
| 定位符 `"3"`，`labelShort` 为 `"p."`        | `[@smith2024, {p. 3}]`     |
| 前缀 `"see "`，后缀 `", note 4"`            | `[see @smith2024, note 4]` |
| `suppressAuthor` 设为 `true`                | `[-@smith2024]`            |
| 文献引用标识 `"KX67D9YM?"`                  | `[@{KX67D9YM?}]`           |
| `"prefer-author-in-text"` 搭配定位符 `"3"`  | `@smith2024 [{p. 3}]`      |
| `"prefer-author-in-text"` 搭配前缀 `"see "` | `[see @smith2024]`         |
| 空数组，或所有条目的文献引用标识均为 null   | `""`                       |

文献引用标识为 null 的条目会被忽略。过滤器会保留其余条目的顺序，并在 Pandoc 要求时为复杂的文献引用标识添加花括号包裹。

如果输入内容无法在不改变引用结构的前提下呈现，则会抛出渲染错误。

### `tex_cite`：LaTeX 引用命令 [#tex-cite]

将引用条目数组格式化为一个 LaTeX 引用命令。将 `zt.citations` 直接传给该过滤器即可。

```liquid
{{ zt.citations | tex_cite }}
{{ zt.citations | tex_cite: "autocite" }}
```

可选命令参数默认为 `"cite"`。书写时不要带反斜杠。支持带星号的命令形式，例如 `"autocite*"`。

| 命令         | 单个条目的输出         | 参考文献宏包            |
| ------------ | ---------------------- | ----------------------- |
| `"cite"`     | `\cite{smith2024}`     | LaTeX, natbib, BibLaTeX |
| `"autocite"` | `\autocite{smith2024}` | BibLaTeX                |

所有保留的条目会合并到一个标识符列表中。生成的命令包含一个前注（prenote）和一个后注（postnote），两者均来自首个保留条目：

| 输入                                      | 输出                             |
| ----------------------------------------- | -------------------------------- |
| 两个条目                                  | `\cite{smith2024,doe2023}`       |
| 定位符 `"3"`，`labelShort` 为 `"p."`      | `\cite[p. 3]{smith2024}`         |
| 前缀 `"see "`                             | `\cite[see][]{smith2024}`        |
| 前缀 `"see "` 搭配定位符 `"3"`            | `\cite[see][p. 3]{smith2024}`    |
| 定位符 `"3"`，后缀 `", note 4"`           | `\cite[p. 3, note 4]{smith2024}` |
| 空数组，或所有条目的文献引用标识均为 null | `""`                             |

文献引用标识为 null 的条目会被忽略，其余条目保持原顺序。

<Callout type="warn" title="包含前注的形式需要 natbib 或 BibLaTeX">
  LaTeX 内核自带的 `\cite` 只接收一个可选参数。上述双参数形式 `\cite[see][p. 3]
  {smith2024}` 必须在 natbib 或 BibLaTeX 环境下编译，这两个宏包重定义了 `\cite`
  以同时接收两个参数。无前缀的引用最多输出一个可选参数，可在原生 LaTeX
  文档中直接工作。
</Callout>

词缀内容会原样作为 LaTeX 源码传递，因此前缀 `\emph{see}` 会被渲染为斜体强调。以下输入则会引发渲染错误：

- `suppressAuthor` 设为 `true`（LaTeX 没有通用的对应形式）。
- 第一个条目之后的任何条目包含前缀、后缀或定位符（无对应参数位置）。
- 文献引用标识为空，或包含空格、逗号及 TeX 特殊字符。
- 前缀、后缀或定位符的花括号不匹配，或者包含未转义的 `%`。

### `collection_paths`：分类路径字符串 [#collection-paths]

将分类数组映射为其连接后的路径字符串。默认分隔符为 `/`。

```liquid
{{ zt.collections | collection_paths }}
{{ zt.collections | collection_paths: " > " }}
```

### `arr_prefix`：为每个元素添加前缀 [#arr-prefix]

为数组的每个元素添加前缀字符串。非数组输入会抛出渲染错误。

```liquid
{{ zt.creators | map: "lastName" | arr_prefix: "@" }}
```

省略前缀参数时，默认为空字符串。

### `arr_suffix`：为每个元素添加后缀 [#arr-suffix]

为数组的每个元素添加后缀字符串。非数组输入会抛出渲染错误。

```liquid
{{ zt.creators | map: "lastName" | arr_suffix: "!" }}
```

省略后缀参数时，默认为空字符串。

### `arr_replace`：替换每个元素中的内容 [#arr-replace]

替换数组每个元素中出现的所有指定字面量子字符串。

```liquid
{{ zt.collections | collection_paths | arr_replace: "/", " > " }}
```

| 参数          | 必填 | 默认值 | 说明                                   |
| ------------- | ---- | ------ | -------------------------------------- |
| `search`      | 是   | —      | 要查找的字面量子字符串。不能为空       |
| `replacement` | 否   | `""`   | 替换文本。省略时表示删除查找到的字符串 |

非数组输入会抛出渲染错误。查找字符串为空或缺失也会引发渲染错误（空的查找项会导致在每个字符之间插入替换内容）。

### `obsidian_tag`：转换为 Obsidian 标签 [#obsidian-tag]

将任意文本转换为合法的 [Obsidian 标签](https://obsidian.md/help/tags#Tag+format)，支持可选前缀。

```liquid
{{ zt.tags | obsidian_tag: "#" }}
{{ zt.tags | obsidian_tag: "zotero/" }}
```

支持数组（逐个元素映射）或单值（返回单个值）。它会自动读取 Zotero 标签对象的 `name` 属性，因此可以直接传入 `zt.tags`，无需预先执行 `map: "name"`。

**规格化规则**：

- 连续的 Obsidian 不支持字符会被替换为一个下划线。
- 连续的 `/` 会合并为一个 `/`。首尾的 `_` 和 `/` 会被去除。
- 全由数字组成的名称会被添加前缀下划线（`1984` 变为 `_1984`），因为 Obsidian 不允许纯数字标签。
- 规格化后若无任何有效字符保留，在数组中会被丢弃，若为单值则返回空字符串。
- 可选前缀会在规格化之后添加并原样保留。笔记正文内的标签可使用 `"#"`，嵌套标签可使用 `"zotero/"`。由于输入中开头的 `#` 会在规格化过程中被去除，因此重复应用 `obsidian_tag: "#"` 是安全的。
- 保留字母大小写。Obsidian 匹配标签时不区分大小写，但会显示该标签首次创建时的大小写形式。

**字符处理机制：** Obsidian 采用“黑名单”而非“白名单”来定义合法标签字符。黑名单之外的所有字符均原样保留。这包括中日韩（CJK）文字、CJK 标点符号、全角字符、`©` 等符号以及 Emoji 表情。包含零宽连字符的 Emoji（如 `👩‍💻`）会变成 `👩_💻`，因为零宽连字符属于 Obsidian 拒绝的字符。

| 输入（name）        | 输出               | 说明                                |
| ------------------- | ------------------ | ----------------------------------- |
| `Machine Learning`  | `Machine_Learning` | 空格被替换                          |
| `(draft) papers`    | `draft_papers`     | 括号和空格被合并                    |
| `R & D`             | `R_D`              | 连续标点符号被合并                  |
| `文献、综述`        | `文献、综述`       | 保留 CJK 文字与标点符号             |
| `/Reading/`         | `Reading`          | 两端的斜杠被去除                    |
| `a//b`              | `a/b`              | 连续斜杠合并                        |
| `1984`              | `_1984`            | 纯数字名称添加下划线前缀            |
| `a/1984`            | `a/1984`           | 包含非数字字符，无需添加前缀        |
| `#todo`（前缀 `#`） | `#todo`            | 开头的 `#` 被去除，随后重新添加前缀 |
| `!!!`               | _（丢弃）_         | 规格化后无保留字符                  |

`obsidian_tag` 专门针对 Obsidian 的标签规则进行规格化。如果只是进行通用的数组文本替换而无需针对标签规则处理，请使用 `arr_replace`。
有关受管的 `tags` 属性字段配置，请参阅[将 Zotero 标签添加到笔记属性](/docs/how-to/configure-frontmatter-properties#zotero-tags)。

### `{% suffix %}`：文件名冲突防范 [#suffix-filename-collision-guard]

仅在 `filename` 模板中有意义。当生成的文件名唯一时，不输出任何内容；当与现有笔记名称冲突时，追加一个随机字符串。

```liquid
{{ zt.citationKey | default: zt.DOI | default: zt.title | default: zt.key }}{% suffix %}
```

- 首篇名为 `Smith2020` 的笔记生成 `Smith2020.md`（无后缀）。
- 第二篇同样会渲染为 `Smith2020` 的笔记生成 `Smith2020_a1b2c3.md`。

参数按位置传递：`length`、`prepend`、`append`（均为可选）。

| 参数      | 默认值 | 约束限制            |
| --------- | ------ | ------------------- |
| `length`  | `6`    | 整数，1–64          |
| `prepend` | `"_"`  | 不能包含 `:` 或 `%` |
| `append`  | `""`   | 不能包含 `:` 或 `%` |

```liquid
{% suffix 10 %}
{% suffix 6, "(", ")" %}
```

suffix 是在创建笔记时解析的占位标记。发生冲突时解析为 `prepend + <random> + append`，文件名可用时解析为 `""`。

### `date`：日期格式化过滤器 [#date-formatting-filter]

接受 strftime 风格的格式化字符串。支持规格化 ZotLit 提供的所有日期格式：

| 输入类型                                                         | 行为                                 |
| ---------------------------------------------------------------- | ------------------------------------ |
| `Temporal.Instant`                                               | 格式化前转换为本地时间日期           |
| `Temporal.PlainDate` / `PlainYearMonth`                          | 格式化前转换为本地时间日期           |
| Zotero `ItemDate`（kind 为 `"date"` / `"yearMonth"` / `"year"`） | 格式化前转换为本地时间日期           |
| Zotero `ItemDate`（kind 为 `"text"`）                            | 忽略格式化字符串，原样输出其原始文本 |

```liquid
{{ zt.dateAdded | date: "%Y-%m-%d" }}
{{ zt.date | date: "%B %Y" }}
```

kind 为 `"text"` 的 `ItemDate` 表示 Zotero 无法解析的日期（例如 `"submitted"`）。`date` 过滤器会原样返回。

## 输出类型强制转换 [#output-coercion]

通过 `{{ }}` 渲染的值会被强制转换为文本：

| 值                   | 渲染结果                                      |
| -------------------- | --------------------------------------------- |
| `null` / `undefined` | `""`（空字符串，绝不会输出字面量文本 "null"） |
| `Date`               | ISO 8601 字符串（`toISOString()`）            |
| `Temporal.Instant`   | 本地普通日期，例如 `2026-06-21`               |
| 其他所有值           | `String()`（调用值自身的 `toString()`）       |

此转换仅适用于 `{{ }}` 输出。`{% liquid %}` 块内的 `{% echo %}` 会绕过该转换。

## 使用 `{% render %}` 引入模板 [#includes-with-render]

`{% render %}` 按名称组合模板，并提供独立的作用域：

```liquid
{% render "content" with zt as zt %}
{% render "annotation" with annotation as zt %}
```

`with <value> as zt` 将该值绑定到子模板内部的 `zt`。子模板只能访问你显式传入的内容，不会继承父模板的变量。

名称解析为已注册的模板，而非文件路径。在配置方案渲染期间，`"annotation"` 指向该配置方案的标注分节。

### 调用片段 [#calling-a-partial]

片段通过其名称调用，所需的数据通过调用语句传递：

```liquid
{% render "authors" with zt as zt %}
```

`{% render %}` 会创建独立的作用域，因此只有在调用时按名称传递 `zt`，片段内部才能访问到它。<UiLabel name={m.workbench_tag_render()} />

不带参数的裸调用传递给片段的 `zt` 为空，因此其中的所有 `zt` 输出都会为空，只保留其字面量文本：

```liquid
{% render "authors" %}
```

`{% include %}` 渲染同一片段时会继承调用者的作用域变量，因此无需 `with` 子句。<UiLabel name={m.workbench_tag_include()} />

```liquid
{% include "authors" %}
```

在 `{% render "` 和 `{% include "` 中进行自动补全时会列出仓库中的所有片段。选中名称后会自动补全整个调用语法：`render` 会附带 `with zt as zt` 子句，而 `include` 则不需要。如果你已经为调用填写了参数，则会保留这些参数，只替换名称。

## 模板文档命名 [#template-document-naming]

模板文档直接存放在 <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} /> 所指定的文件夹中。扫描为单层扁平结构，绝不会读取子文件夹中的文件，没有 `zotlit-` 前缀的文件会被忽略。

仅凭文件名中的前缀即可区分文档类型：

| 文件名                     | 文档类型                                             |
| -------------------------- | ---------------------------------------------------- |
| `zotlit-profile.<slug>.md` | 文献笔记配置方案：笔记名称、文件夹、属性、正文及标注 |
| `zotlit-citation.md`       | 引文文本，每个仓库仅一份，必须为此确切文件名         |
| `zotlit-partial.<name>.md` | 单个片段，以 `<name>` 注册                           |

不符合上述任何模式的 `zotlit-` 文件将不会注册为任何模板，并在 <SettingsPath page={m.settings_page_advanced()} /> 的 <UiLabel name={m.settings_advanced_template_engine_heading()} /> 分组中报错提示。详见[无法识别的 ZotLit 文件](/docs/reference/settings#unrecognized-files)。

### 语言 [#document-language]

引文文档或片段默认使用 Liquid 语言，除非其清单另有声明。清单是位于文件顶部的可选 YAML 块，`language` 是其唯一合法的键：

```md
---
language: eta
---

<%= zt.title %>
```

合法的值为 `liquid` 和 `eta`。没有清单的文档默认为 Liquid。可以在模板工作台视图的窗格菜单中通过 <UiLabel name={m.template_workbench_change_language()} /> 在两者之间切换；这会重写清单中的键，而模板源码保持原样。

### 片段名称 [#partial-names]

片段名称由一个或多个字母、数字和连字符组成。<UiLabel name={m.settings_partial_add()} /> 提示框会自动去除首尾空格、将连续空格转换为连字符并将结果转为小写，因此 `Journal line` 会变为 `journal-line`。名称匹配不区分大小写，两个文件不能以不同的大小写占用同一个名称。

有五个保留名称已被其他 ZotLit 模板占用：`filename`、`note`、`annotation`、`content` 和 `citation`。使用这些名称的片段文件将无法注册，并会在 <SettingsPath page={m.settings_page_profiles()} setting={m.settings_partials_heading()} /> 中报错。详见[片段](/docs/reference/settings#partials)。

## 从 Eta 迁移到 Liquid [#eta-to-liquid]

v2 的默认引擎是 Liquid。将模板转换为 Liquid 后，完全无需开启 <UiLabel name={m.settings_template_js_enable_name()} />。下表列出了各种构造对应的 Liquid 等效写法，并链接到了相关语法参考小节。

| Eta 语法                                              | Liquid 等效写法                                   | 参考章节                                                                        |
| ----------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------- |
| `<%= zt.title %>`                                     | `{{ zt.title }}`                                  | [输出与标签](/docs/reference/templates/syntax#outputs-and-tags)                 |
| `<% if (zt.abstract) { %> ... <% } %>`                | `{% if zt.abstract %} ... {% endif %}`            | [控制流](/docs/reference/templates/syntax#if-elsif-else-endif)                  |
| `<% for (const a of zt.annotations) { %> ... <% } %>` | `{% for a in zt.annotations %} ... {% endfor %}`  | [for / endfor](/docs/reference/templates/syntax#for-endfor)                     |
| `<%~ include("content", zt) %>`                       | `{% render "content" with zt as zt %}`            | [使用 render 引入](/docs/reference/templates/syntax#includes-with-render)       |
| `<% bq(() => { %> ... <% }) %>`                       | `{% bq %} ... {% endbq %}`                        | [bq：块引用块](/docs/reference/templates/syntax#bq-blockquote-block)            |
| `embed(zt.imgLink)`                                   | `{{ zt.imgLink \| embed }}`                       | [embed 过滤器](/docs/reference/templates/syntax#embed-embed-filter)             |
| `<%= suffix() %>`                                     | `{% suffix %}`                                    | [suffix 标签](/docs/reference/templates/syntax#suffix-filename-collision-guard) |
| `zt.attachments[0].fileLink()`                        | `{{ zt.attachments[0] \| file_link }}`            | [链接过滤器](/docs/reference/templates/syntax#link-filters)                     |
| `zt.collections.map(c => c.path.join(" > "))`         | `{{ zt.collections \| collection_paths: " > " }}` | [collection_paths](/docs/reference/templates/syntax#collection-paths)           |
| `zt.tags.map(t => t.name).join(", ")`                 | `{{ zt.tags \| map: "name" \| join: ", " }}`      | [数组过滤器](/docs/reference/templates/syntax#array-filters)                    |
| `zt.dateAdded`（Temporal.Instant 格式化）             | `{{ zt.dateAdded \| date: "%Y-%m-%d" }}`          | [date 过滤器](/docs/reference/templates/syntax#date-formatting-filter)          |
| `-%>`（清除标签后一个换行符）                         | `-%}` / `-}}`                                     | [空白控制](/docs/reference/templates/syntax#whitespace-control)                 |

重命名后的 2.1 Liquid 文件使用 `.liquid.md` 扩展名（例如 `zotlit-note.liquid.md`）；转换后的模板文档名称中无需包含语言标识。数据变量依然是 `zt`，属性名称与 [Eta 模板语法](/docs/reference/templates/eta-syntax) 中的 Eta 等效属性完全一致。
