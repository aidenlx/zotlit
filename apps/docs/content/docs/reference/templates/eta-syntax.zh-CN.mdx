本页介绍了在 ZotLit 中配置的 Eta 模板语言。运行 Eta 模板需要先开启 [<UiLabel name={m.settings_template_js_enable_name()} /> 开关](/docs/how-to/enable-javascript-templates)。有关默认的 Liquid 引擎语法，请参阅[模板语法](/docs/reference/templates/syntax)。

所有模板数据均可通过全局变量 `zt` 统一访问。`zt` 的具体数据结构取决于模板类型：查阅[数据参考](/docs/reference/templates/data)获取完整的字段属性列表。

## 定界符

| 定界符      | 用途                                 |
| ----------- | ------------------------------------ |
| `<% %>`     | 执行 JavaScript 代码逻辑（无输出）   |
| `<%= %>`    | 输出表达式求值结果（经过自动过滤器） |
| `<%~ %>`    | 输出表达式求值结果（经过自动过滤器） |
| `<%/* */%>` | 注释（从最终输出中剥离）             |

在 ZotLit 中，`<%= %>` 与 `<%~ %>` 在功能上完全相同，两者的结果都会经过自动过滤器。两者均可用于输出；常规推荐使用 `<%= %>`。

```eta
<%= zt.title %>
<% if (zt.abstract) { %>
<%= zt.abstract %>
<% } %>
```

使用 `<%/* */%>` 编写不会出现在渲染笔记中的内部注释：

```eta
<%/* 草稿：后续重新审视多作者渲染逻辑 */%>
```

<Callout type="warn" title="不支持井号前缀注释">
  Eta 不支持 `<%# %>` 语法，该语法会导致模板编译错误。所有注释请统一使用 `<%/* */%>`。
</Callout>

## 空白控制 [#whitespace-control]

在默认情况下，ZotLit 将 `autoTrim` 设置为 `[false, false]`：标签周围的空白字符会严格按照原样完整保留。`%>` 之后的换行符以及 `<%` 之前的缩进都会忠实呈现在渲染后的笔记中。

通过在定界符边缘添加修饰符，可以在单侧覆盖这一默认行为：

| 修饰符 | 位置              | 效果                           |
| ------ | ----------------- | ------------------------------ |
| `-`    | 起始标签（`<%-`） | 消除标签前方紧邻的一个换行符   |
| `-`    | 结束标签（`-%>`） | 消除标签后方紧邻的一个换行符   |
| `_`    | 起始标签（`<%_`） | 消除标签前方所有的连续空白字符 |
| `_`    | 结束标签（`_%>`） | 消除标签后方所有的连续空白字符 |

```eta
<% for (const annotation of zt.annotations) { -%>
- <%= annotation.text %>
<% } %>
```

末尾的 `-%>` 会移除起始标签之后紧邻的换行符，使每次循环都从 `- ` 所在行开始。

### 全局 autoTrim 设置 [#global-autotrim-setting]

开启 <UiLabel name={m.settings_template_js_enable_name()} /> 后，以下两个设置控制默认的空白裁剪行为：

- <UiLabel name={m.settings_template_trim_leading_name()} />
  ：应用于每个标签的起始侧。
- <UiLabel name={m.settings_template_trim_trailing_name()} />
  ：应用于每个标签的结束侧。

每项均有三个选项：<UiLabel name={m.settings_template_trim_disable()} />（不裁剪）、<UiLabel name={m.settings_template_trim_nl()} /> 和 <UiLabel name={m.settings_template_trim_slurp()} />。单个标签中的修饰符始终优先于该标签对应的全局设置。

<Callout type="info" title="Markdown 对空白敏感">
  默认设置保留所有空白，避免意外破坏 Markdown
  格式。需要精确控制时，请使用单个标签中的修饰符。
</Callout>

## 自动过滤器（输出类型转换） [#auto-filter-output-coercion]

每个 `<%= %>` 和 `<%~ %>` 表达式在渲染前都会经过过滤函数，将值转换为可安全用于 Markdown 的文本：

| 值                   | 渲染结果                           |
| -------------------- | ---------------------------------- |
| `null` / `undefined` | `""`（空字符串）                   |
| `Date`               | ISO 8601 字符串（`toISOString()`） |
| `Temporal.Instant`   | 本地日期，例如 `2026-06-21`        |
| 其他值               | `String(value)`                    |

因此，`<%= zt.someFieldThatIsNull %>` 不输出内容，而不是输出字面文本“null”。创作者对象和日期通过 `toString()` 方法渲染：创作者输出全名，日期输出 ISO 字符串。

## `zt` 变量 [#the-zt-variable]

所有模板数据均位于 `zt` 变量下。所有模板类型都使用此变量名：

```eta
<%= zt.title %>
<%= zt.creators[0].family %>
<%= zt.citationKey %>
```

在 `<%= %>` 标签内选择插值提示时，编辑器自动补全会插入 `= zt. `。

`zt` 取代了 v1 的 `it` 变量。完整的属性映射见[迁移 v1 Eta 模板](/docs/how-to/migrate-v1-eta-templates)。

## `renderAnnotation()`：标注渲染 [#render-annotation]

渲染一条标注，在标注模板内通过 `zt` 访问它。

```eta
<%~ renderAnnotation(annotation) %>
```

标注参数为必填项。缺失或为 null 时会报错。

对于标注值，等效的原生 Eta 语法为：

```eta
<%~ include("annotation", annotation) %>
```

在文献笔记配置方案中，此快捷函数和对 `annotation` 的原生调用均使用该配置方案的标注区域。此必需的末尾区域从独占一行的 `--- zotlit:annotation ---` 之后开始，一直延伸至文档末尾。它使用配置方案的语言，内容可以为空。

从共享模板片段发起的调用使用调用方配置方案的标注区域，并隔离标注数据。直接插入标注和导入笔记也使用适用配置方案中的同一区域。在配置方案渲染之外，此快捷函数仍使用原有的命名模板查找方式。

## `include()`：组合模板 [#include-composing-templates]

`include()` 在当前位置渲染另一个模板。传入模板名称和可选的数据参数：

```eta
<%~ include("annotation", annotation) %>
<%~ include("content", zt) %>
```

数据参数直接成为子模板的 `zt` 变量，不会与父模板数据合并。省略此参数时，子模板继承父模板的 `zt`。

名称用于查找已注册的模板，而非文件路径。渲染配置方案时，`"annotation"` 指向该配置方案的标注区域。

### 调用模板片段 [#calling-a-partial]

通过名称调用模板片段，并将其所需的数据作为第二个参数传入：

```eta
<%~ include("authors", zt) %>
```

此参数成为模板片段的 `zt`。省略时，片段继承调用方的 `zt`。在 `include("` 内使用自动补全会列出仓库中的所有模板片段，选择名称后会插入完整调用，包括 `zt` 参数。若调用已有参数，则保留参数，仅替换名称。

### 引入 `content` 模板 [#the-content-include]

从笔记模板调用 `include("content", zt)` 时，ZotLit 会自动在输出外包裹受管区域标记（`%%zt-managed%%` / `%%/zt-managed%%`）。这些标记在渲染时注入，不出现在模板文档中。

## `bq()`：引用块辅助函数 [#bq-blockquote-helper]

将内容包裹为 Markdown 引用块，每行添加 `> ` 前缀，并裁剪内容首尾空白。块内的连续空行合并为仅含一个 `>` 的行。

```eta
<% bq(() => { %>
[!note] Page <%= zt.pageLabel %>

<%= embed(zt.imgLink) %><%= zt.text %>
<% if (zt.comment) { %>

<%= zt.comment %>
<% } %>
<% }) %>
```

渲染结果：

```markdown
> [!note] Page 42
>
> ![[excerpt.png]]The highlighted passage
>
> My thoughts on this
```

`bq()` 必须放在 `<% %>` 执行标签中。它捕获回调内生成的所有输出，裁剪结果首尾空白，为每行添加 `> ` 前缀（空行仅保留 `>`），将连续的纯 `>` 行合并为一行，然后输出结果。

捕获内容为空时，`bq()` 输出一个 `>`。

## `embed()`：嵌入辅助函数 [#embed-embed-helper]

通过添加 `!` 前缀，将链接辅助函数的结果转换为 Markdown 嵌入。链接为 `null`、`undefined` 或渲染结果为空时，返回 `""`。

```eta
<%= embed(zt.imgLink) %>
<%= embed(zt.imgLink, "alt text") %>
```

函数签名： `embed(link, alias?, subpath?)`

| 输入                                    | 输出                 |
| --------------------------------------- | -------------------- |
| `zt.imgLink` 渲染为 `"[[excerpt.png]]"` | `"![[excerpt.png]]"` |
| `zt.imgLink` 为 `null`                  | `""`                 |

对于图片和手写标注，`embed(zt.imgLink)` 使用已准备好的笔记图片，或返回图片不可用的说明及来源链接。它会保留这类回退文本，不添加 `!`。图片准备在模板运行前完成，因此每次渲染只执行一次模板。预览渲染不会在仓库中创建图片文件。

## `pandocCite()`：Pandoc 引文源码 [#pandoc-cite]

将引文条目数组格式化为 Pandoc 引文源码。将 `zt.citations` 直接传入此辅助函数即可。

```eta
<%= pandocCite(zt.citations) %>
<%= pandocCite(zt.citations, "prefer-author-in-text") %>
```

函数签名： `pandocCite(citations, form?)`

可选的形式参数默认为 `"normal"`。

| 形式                      | 单个条目的输出 | 说明                                                                               |
| ------------------------- | -------------- | ---------------------------------------------------------------------------------- |
| `"normal"`                | `[@smith2024]` | 生成方括号包裹的引文组。                                                           |
| `"prefer-author-in-text"` | `@smith2024`   | 保留的第一个条目无前缀且未隐藏作者时，生成作者融入正文的引文；否则生成普通引文组。 |

此辅助函数处理 Pandoc 源码使用的所有引文条目属性：

| 输入                                        | 输出                       |
| ------------------------------------------- | -------------------------- |
| 定位信息 `"3"`，`labelShort` 为 `"p."`      | `[@smith2024, {p. 3}]`     |
| 前缀 `"see "` 与后缀 `", note 4"`           | `[see @smith2024, note 4]` |
| `suppressAuthor` 设为 `true`                | `[-@smith2024]`            |
| 文献引用标识（citation key） `"KX67D9YM?"`  | `[@{KX67D9YM?}]`           |
| `"prefer-author-in-text"`，定位信息为 `"3"` | `@smith2024 [{p. 3}]`      |
| `"prefer-author-in-text"`，前缀为 `"see "`  | `[see @smith2024]`         |
| 数组为空或所有条目的文献引用标识均为 null   | `""`                       |

文献引用标识为 null 的条目会被省略。此辅助函数保留其余条目的顺序，并在 Pandoc 要求时为复杂文献引用标识添加花括号。

若输入只能通过改变引文结构才能表示，则会报告渲染错误。

## `texCite()`：LaTeX 引文命令 [#tex-cite]

将引文条目数组格式化为一条 LaTeX 引文命令。将 `zt.citations` 直接传入此辅助函数即可。

```eta
<%= texCite(zt.citations) %>
<%= texCite(zt.citations, "autocite") %>
```

函数签名： `texCite(citations, command?)`

可选的命令参数默认为 `"cite"`。填写时省略反斜杠。支持 `"autocite*"` 等带星号的命令。

| 命令         | 单个条目的输出         | 参考文献宏包            |
| ------------ | ---------------------- | ----------------------- |
| `"cite"`     | `\cite{smith2024}`     | LaTeX, natbib, BibLaTeX |
| `"autocite"` | `\autocite{smith2024}` | BibLaTeX                |

所有保留条目的文献引用标识组成一个列表。命令包含一个前注和一个后注，两者均来自保留的第一个条目：

| 输入                                      | 输出                             |
| ----------------------------------------- | -------------------------------- |
| 两个条目                                  | `\cite{smith2024,doe2023}`       |
| 定位信息 `"3"`，`labelShort` 为 `"p."`    | `\cite[p. 3]{smith2024}`         |
| 前缀 `"see "`                             | `\cite[see][]{smith2024}`        |
| 前缀 `"see "`，定位信息为 `"3"`           | `\cite[see][p. 3]{smith2024}`    |
| 定位信息 `"3"`，后缀为 `", note 4"`       | `\cite[p. 3, note 4]{smith2024}` |
| 数组为空或所有条目的文献引用标识均为 null | `""`                             |

文献引用标识为 null 的条目会被省略，其余条目保持原有顺序。

<Callout type="warn" title="前注形式需要 natbib 或 BibLaTeX">
  LaTeX 内核自带的 `\cite` 只接受一个可选参数。

上述形式 `\cite[see][p. 3]{smith2024}` 含两个可选参数，需要使用 natbib 或 BibLaTeX 编译。这些宏包会重新定义 `\cite`，使其接受两个参数。不含前缀的引文至多生成一个可选参数，可用于普通 LaTeX 文档。

</Callout>

前后缀会作为源码传入 LaTeX，因此前缀 `\emph{see}` 会渲染为强调文本。以下输入会导致渲染错误：

- `suppressAuthor` 设为 `true`，因为 LaTeX 没有通用的对应形式。
- 第一个条目之后的任意条目带有前缀、后缀或定位信息，因为命令中没有对应位置。
- 文献引用标识为空，或包含空白、逗号或 TeX 特殊字符。
- 前缀、后缀或定位信息中的花括号不匹配，或包含未转义的 `%`。

## `suffix()`：避免文件名冲突 [#suffix-filename-collision-guard]

仅适用于 `filename` 模板。生成的文件名与现有笔记冲突时，追加随机字符串。文件名可用时，不输出内容。

```eta
<%= zt.citationKey ?? zt.DOI ?? zt.title ?? zt.key %><%= suffix() %>
```

- 第一篇名为 `Smith2020` 的笔记生成 `Smith2020.md`。
- 第二篇同样渲染为 `Smith2020` 的笔记生成 `Smith2020_a1b2c3.md`。

### 函数签名 [#signature]

```
suffix(length?, prepend?, append?)
```

| 参数      | 默认值 | 约束                |
| --------- | ------ | ------------------- |
| `length`  | `6`    | 1–64 的整数         |
| `prepend` | `"_"`  | 不得包含 `:` 或 `%` |
| `append`  | `""`   | 不得包含 `:` 或 `%` |

前后缀仅在冲突时出现。文件名可用时，整个表达式（包括前后缀）不输出内容。

```eta
<%= zt.title %><%= suffix(10) %>
<%= zt.title %><%= suffix(6, "(", ")") %>
<%= zt.citationKey %><%= suffix(4, "-") %>
```

随机字符串由字母和数字组成。发生冲突时，ZotLit 会使用新的随机字符串重试，最多 5 次。

## 链接辅助函数 [#link-helpers]

`zt` 上下文中的链接是函数，而非预先计算的字符串。调用这些函数即可渲染链接。每个函数均接受可选的覆盖参数：

```
linkHelper(alias?, subpath?)
```

- `alias`：链接的显示文本。省略时使用默认值（文件名或笔记标题）。
- `subpath`：追加到目标后的 `#` 片段，例如 `"#heading"` 或 `"#page=3"`。

| 辅助函数          | 适用位置                     | 默认子路径                    | 返回值                                              |
| ----------------- | ---------------------------- | ----------------------------- | --------------------------------------------------- |
| `zt.noteLink()`   | 条目上下文                   | 无                            | 指向条目文献笔记的 Markdown 链接，或 `null`         |
| `note.noteLink()` | 每个 `zt.notes[]` 元素       | 无                            | 指向子笔记的链接                                    |
| `a.fileLink()`    | 每个 `zt.attachments[]` 元素 | 无                            | 附件文件链接                                        |
| `zt.fileLink()`   | 标注上下文                   | `#page=N&zt-annotation=<key>` | 定位到标注所在页面及标注本身的附件链接              |
| `zt.imgLink()`    | 标注上下文                   | 无                            | 摘录图片链接、图片不可用的说明及来源链接，或 `null` |

```eta
<%= zt.attachments[0].fileLink() %>
<%= zt.attachments[0].fileLink("Open the PDF") %>
<%= zt.noteLink("See notes", "#Summary") %>
```

文献笔记路径无法解析时（冲突、递归解析或模板错误），`zt.noteLink()` 返回 `null`。对于 `image` 和 `ink` 以外的标注类型，`zt.imgLink` 为 `null`。图片不可用时采用[摘录回退处理](/docs/concepts/excerpt-images#import-outcomes)。

启用 <SettingsPath page={m.settings_page_reader()} setting={m.settings_reader_open_file_links_name()} /> 时（默认开启），指向 Zotero 文献库中 PDF 的文件链接会[在 Obsidian 中打开](/docs/how-to/open-pdf-in-obsidian)。`zt.fileLink()` 链接会打开标注所在页面，并选中该标注。

## 模板文档命名 [#template-document-naming]

模板文档直接放在 <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} /> 指定的文件夹中。扫描仅限一层，文档类型完全由文件名前缀决定：`zotlit-profile.<slug>.md` 表示配置方案，`zotlit-citation.md` 表示引文文本，`zotlit-partial.<name>.md` 表示一个模板片段。完整规则和片段保留名称见[模板文档命名](/docs/reference/templates/syntax#template-document-naming)。

Eta 文档在文件顶部、源码之前的 YAML manifest 中声明语言：

```md
---
language: eta
---

<%= zt.title %>
```

此 manifest 唯一允许的键是 `language`，其值为 `liquid` 或 `eta`。不含 manifest 的文档按 Liquid 处理，因此每份 Eta 引文文档和 Eta 模板片段都需要此块。在模板工作台视图的窗格菜单中选择 <UiLabel name={m.template_workbench_change_language()} />，可在两种语言之间切换；此操作重写 manifest 键，保留源码原文。

配置方案文档通过自身 manifest 的 `language` 键声明语言。

## 同步渲染 [#no-async]

ZotLit 同步渲染模板。Eta 模板内无法使用 `async`/`await`。
