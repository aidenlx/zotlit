本页介绍了 ZotLit 中配置的 Eta 模板语言。使用 Eta 模板需要开启 [<UiLabel name={m.settings_template_js_enable_name()} /> 开关](/docs/how-to/enable-javascript-templates)。关于默认的 Liquid 引擎，请参阅[模板语法](/docs/reference/templates/syntax)。

所有模板数据均可通过单一变量 `zt` 访问。`zt` 的结构取决于模板类型：完整属性列表请参阅[数据参考](/docs/reference/templates/data)。

## 定界符 [#delimiters]

| 定界符      | 用途                      |
| ----------- | ------------------------- |
| `<% %>`     | 执行 JavaScript（无输出） |
| `<%= %>`    | 输出表达式（自动过滤）    |
| `<%~ %>`    | 输出表达式（自动过滤）    |
| `<%/* */%>` | 注释（从输出中移除）      |

在 ZotLit 中，`<%= %>` 与 `<%~ %>` 功能完全相同。两者都会将其结果传递给自动过滤器。两者均可用于输出；通常习惯使用 `<%= %>`。

```eta
<%= zt.title %>
<% if (zt.abstract) { %>
<%= zt.abstract %>
<% } %>
```

使用 `<%/* */%>` 编写不会出现在渲染后笔记中的注释：

```eta
<%/* Draft: revisit multi-author rendering */%>
```

<Callout type="warn" title="不支持井号前缀注释">
  Eta 不支持 `<%# %>`。该语法会导致编译错误。所有注释请使用 `<%/* */%>`。
</Callout>

## 空白控制 [#whitespace-control]

默认情况下，ZotLit 将 `autoTrim` 设置为 `[false, false]`：标签周围的空白会完全按原样保留。`%>` 之后的换行符和 `<%` 之前的缩进都会出现在渲染后的笔记中。

单个标签的标记可以覆盖标签单侧的这一默认行为：

| 标记 | 位置            | 效果                   |
| ---- | --------------- | ---------------------- |
| `-`  | 开标签（`<%-`） | 去掉标签前的一个换行符 |
| `-`  | 闭标签（`-%>`） | 去掉标签后的一个换行符 |
| `_`  | 开标签（`<%_`） | 去掉标签前的所有空白   |
| `_`  | 闭标签（`_%>`） | 去掉标签后的所有空白   |

```eta
<% for (const annotation of zt.annotations) { -%>
- <%= annotation.text %>
<% } %>
```

尾随的 `-%>` 会吞掉紧随开标签后面的换行符，因此每次迭代都会直接从 `- ` 行开始。

### 全局 autoTrim 设置 [#global-autotrim-setting]

当开启 <UiLabel name={m.settings_template_js_enable_name()} /> 时，由两项设置控制默认的空白去除行为：

- <UiLabel name={m.settings_template_trim_leading_name()} />
  ：应用于每个标签的开标签侧。
- <UiLabel name={m.settings_template_trim_trailing_name()} />
  ：应用于每个标签的闭标签侧。

每项设置均接受三个值：<UiLabel name={m.settings_template_trim_disable()} />（不修剪）、<UiLabel name={m.settings_template_trim_nl()} /> 或 <UiLabel name={m.settings_template_trim_slurp()} />。针对单个标签的标记始终会覆盖该标签的全局设置。

<Callout type="info" title="Markdown 对空白敏感">
  默认设置（保留所有空白）可避免悄悄破坏 Markdown
  格式。建议使用标签标记进行精确控制。
</Callout>

## 自动过滤（输出强制类型转换） [#auto-filter-output-coercion]

每个 `<%= %>` 和 `<%~ %>` 表达式在渲染前都会通过一个过滤函数。该过滤器将值强制转换为对 Markdown 安全的文本：

| 值                   | 渲染结果                           |
| -------------------- | ---------------------------------- |
| `null` / `undefined` | `""`（空字符串）                   |
| `Date`               | ISO 8601 字符串（`toISOString()`） |
| `Temporal.Instant`   | 本地纯日期，例如 `2026-06-21`      |
| 其他所有值           | `String(value)`                    |

这意味着 `<%= zt.someFieldThatIsNull %>` 不会输出任何内容，而不是字面文本 “null”。创作者对象和日期通过其 `toString()` 方法进行渲染：创作者会生成其全名，日期会生成 ISO 字符串。

## `zt` 变量 [#the-zt-variable]

所有模板数据都存放在 `zt` 变量下。该变量名适用于所有模板类型：

```eta
<%= zt.title %>
<%= zt.creators[0].family %>
<%= zt.citationKey %>
```

在 `<%= %>` 标签内选择插值提示时，编辑器自动补全会插入 `= zt. `。

`zt` 取代了 v1 中的 `it` 变量。完整属性映射请参阅[从 v1 变更](#v1-changes)。

## 从 v1 变更 [#v1-changes]

### 模板文件名 [#v1-file-names]

| v1 文件名          | 重命名为                   | 内容最终归属               |
| ------------------ | -------------------------- | -------------------------- |
| `zt-note.eta.md`   | `zotlit-note.eta.md`       | 默认配置方案文档的笔记正文 |
| `zt-annots.eta.md` | `zotlit-content.eta.md`    | 同一笔记正文中的托管区块   |
| `zt-annot.eta.md`  | `zotlit-annotation.eta.md` | 同一配置方案文档的标注分节 |

两个 v1 引文文件 `zt-cite*.eta.md` 采用相同的由 `zt-` 到 `zotlit-` 的重命名规则。两者合并为一个引文文本文档 `zotlit-citation.md`，基于 `zt.variant` 使用 `if`/`else` 进行分支。

### 重命名和结构重构的字段 [#v1-fields]

以下字段更改了名称或类型：

| v1 属性               | v2 属性             | 说明                                                                                                                 |
| --------------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `it.citekey`          | `zt.citationKey`    | `zt.citekey` 也可作为别名使用                                                                                        |
| `it.abstractNote`     | `zt.abstract`       | `zt.abstractNote` 同样有效                                                                                           |
| `it.publicationTitle` | `zt.containerTitle` | `zt.publicationTitle` 同样有效                                                                                       |
| `it.color`            | `zt.colorHex`       | 十六进制字符串，例如 `#ffd400`                                                                                       |
| —                     | `zt.colorName`      | 新增：调色板名称（`"yellow"`、`"red"` 等）                                                                           |
| `it.imgExcerpt`       | `embed(zt.imgLink)` | `zt.imgLink` 是[链接辅助函数](/docs/reference/templates/eta-syntax#link-helpers)或 `null`；`embed()` 会添加 `!` 前缀 |
| `it.imgPath`          | _（已移除）_        | 改用 `zt.imgLink()`                                                                                                  |
| `it.imgUrl`           | _（已移除）_        | 改用 `zt.imgLink()`                                                                                                  |
| `it.textExcerpt`      | `zt.text`           | 已重命名                                                                                                             |
| `it.commentMd`        | `zt.comment`        | Markdown 评论现为默认                                                                                                |
| `it.comment`          | `zt.commentHtml`    | 原始 HTML（仅限 `<i>/<b>/<sub>/<sup>`）                                                                              |

属于纯字符串的直接 Zotero 字段（`title`、`DOI`、`url`、`volume`、`issue`、`pages`、`publisher` 等）在由 `it` 重命名为 `zt` 后保持不变。

### 标签 [#v1-tags]

v1 将标签公开为格式化字符串。v2 将其公开为具有 `name` 和 `type` 属性的对象。标签在字符串上下文中会强制转换为其 `name`，因此 `join` 依然有效：

```eta
<%/* Tags coerce to their name */%>
<%= zt.tags.join(", ") %>

<%/* Explicit property access */%>
<%= zt.tags.map(t => t.name).join(", ") %>

<%/* Filter to manual tags only */%>
<%= zt.tags.filter(t => t.type === "manual").join(", ") %>
```

### 分类 [#v1-collections]

v2 重构了分类对象。主要区别：

| 方面        | v1                     | v2                                       |
| ----------- | ---------------------- | ---------------------------------------- |
| `path` 顺序 | 叶节点 → 根节点        | 根节点 → 叶节点                          |
| `path` 渲染 | 自动渲染 `"A > B > C"` | 纯 `string[]`；使用 `c.path.join(" > ")` |
| 单数别名    | `it.collection`        | 已移除；请使用 `zt.collections` 数组     |

```eta
<%/* Collections coerce to their name in string contexts */%>
<%= zt.collections.join(", ") %>

<%/* Render each collection's full hierarchy */%>
<%= zt.collections.map(c => c.path.join(" > ")).join("; ") %>
```

### 日期 [#v1-dates]

| v1 属性                            | v2 属性                            | 类型变化                                                                                                                         |
| ---------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `it.date`                          | `zt.date`                          | 原为仅包含年份的字符串；现为解析后的 `ItemDate` 对象。`<%= zt.date %>` 渲染 ISO；`zt.date?.year` 获取数字年份。                  |
| `it.dateAdded` / `it.dateModified` | `zt.dateAdded` / `zt.dateModified` | 原为原始 SQL 字符串（`"YYYY-MM-DD HH:MM:SS"`）；现为 `Temporal.Instant`。在 `<%= %>` 标签中渲染为本地日期（例如 `2026-06-21`）。 |

如果你的 v1 模板将 `it.date` 用作年份字符串，请替换为 `zt.date?.year`：

```eta
<%/* v1 */%>
year: "<%= it.date %>"

<%/* v2 */%>
year: "<%= zt.date?.year %>"
```

### 子笔记 [#v1-child-notes]

v1 在 `it.notes` 上将子笔记内容内联为 Markdown。v2 仅提供纯链接条目。只有当你[导入子笔记](/docs/how-to/import-zotero-notes)时，子笔记才会成为单独的文件：

| v1                                    | v2                                                        |
| ------------------------------------- | --------------------------------------------------------- |
| `it.notes`：`{title, content}` 的数组 | `zt.notes`：`{key, title, noteLink()}` 的数组             |
| 笔记内容内联                          | `noteLink()` 链接到导入的文件，否则在 Zotero 中打开该笔记 |

默认模板不再列出子笔记。要将它们作为链接列出，请在模板中添加如下循环：

```eta
<% if (zt.notes.length) { %>
## Notes

<% for (const note of zt.notes) { -%>
- <%~ note.noteLink() %>
<% } %>
<% } %>
```

### 标注模板与 `bq()` [#v1-annotation]

v1 依赖外部块引用处理。v2 在标注模板内部使用 [`bq()` 辅助函数](/docs/reference/templates/eta-syntax#bq-blockquote-helper)：

```eta
<% bq(() => { %>
[!note] Page <%= zt.pageLabel %>

<%= embed(zt.imgLink) %><%= zt.text %>
<% if (zt.comment) { %>

<%= zt.comment %>
<% } %>
<% }) %>
```

`bq()` 将所有内容包装在 Markdown 块引用中（每行以 `> ` 为前缀），去除多余空白，并将连续的空白块引用行折叠。它必须出现在 `<% %>` 执行标签中。

### 内容模板 [#v1-content]

该模板已从 `annots` 重命名为 `content`。它现在接收完整的上下文对象，而不是原始标注数组：

```eta
<%/* v1: received a raw array as `it` */%>
<% for (const annotation of it) { %>

<%/* v2: receives full context, access annotations via zt.annotations */%>
<% for (const annotation of zt.annotations) { %>
```

更新文献笔记模板中的 `include` 调用：

```eta
<%/* v1 */%>
<%~ include("annots", it.annotations) %>

<%/* v2 */%>
<%~ include("content", zt) %>
```

内容模板现在可以访问所有 `zt.*` 属性（附件、标签、笔记等），而不仅仅是标注。

### 引文源 [#v1-citation]

v1 将 `it` 作为原始数组传递。v2 将条目包装在对象中：

```eta
<%/* v1 */%>
[<%= it.filter(lit => !!lit.citekey).map(lit => `@${lit.citekey}`).join("; ") %>]

<%/* v2 */%>
[<%= zt.citations.filter(c => c.item.citationKey).map(c =>
  `${c.suppressAuthor ? "-" : ""}@${c.item.citationKey}`
).join("; ") %>]
```

主要变化：

- `it`（数组）变为 `zt.citations`（对象内的数组）。`zt.items` 公开不含引用元数据的相同条目。
- `lit.citekey` 变为 `c.item.citationKey`（或 `c.item.citekey`）。
- 你的两个 v1 引文文件现在都从一个 v2 文档渲染。[转换流程](/docs/how-to/migrate-v1-eta-templates#convert)会将它们编写为基于 `zt.variant`（取值为 `"main"` 或 `"alt"`）的 `if`/`else` 两个分支。请参阅[引文模板](/docs/reference/templates/data#citation-templates)。

### 附件 [#v1-attachments]

v1 选择一个附件并将其公开为 `it.fileLink`（字符串）。v2 将所有附件作为数组提供，而 `fileLink` 是由你调用的[链接辅助函数](/docs/reference/templates/eta-syntax#link-helpers)：

```eta
<%= zt.attachments.map(a => a.fileLink()).filter(Boolean).join(" ") %>
```

每个附件对象包含：`key`、`filename`、`contentType`、`linkMode`、`filePath`、`fileLink`。

### 创作者 [#v1-creators]

v2 使用具有显式属性的扁平数组。创作者在字符串上下文中会强制转换为其全名：

```eta
<%/* All authors (coerces to fullName) */%>
<%= zt.authors.join(", ") %>

<%/* Explicit property access */%>
<%= zt.authors.map(c => c.fullName).join(", ") %>

<%/* Filter by role */%>
<%= zt.creators.filter(c => c.role === "editor").join(", ") %>
```

创作者属性：`family`、`given`、`literal`（机构名称）、`role`、`fullName`。

条目上下文中的便捷属性：`zt.authors`（首个有值的角色：主要创作者、编者、导演，随后是贡献者）和 `zt.authorsShort`（格式化的简写字符串，例如 “Smith et al.”）。

### 文件名模板 [#v1-filename]

文件名模板是一个模板文件（`zotlit-filename.eta.md`），而不是设置字符串。[单步转换](/docs/how-to/migrate-v1-eta-templates#convert)随后会将其合并到配置方案文档清单的 `filename` 键中。v2 默认添加了 `suffix()` 以避免重名冲突：

```eta
<%= zt.citationKey ?? zt.DOI ?? zt.title ?? zt.key %><%= suffix() %>
```

- `it.citekey` 变为 `zt.citationKey`（规范名称；`zt.citekey` 同样可用）。
- 不再包含 `.md` 扩展名。ZotLit 会自动追加该扩展名。
- [`suffix()`](/docs/reference/templates/eta-syntax#suffix-filename-collision-guard) 仅在名称与现有笔记发生冲突时追加随机字符串。

### 来自 `zt-field.eta.md` 的属性 [#v1-frontmatter]

| v1 模板行                  | <UiLabel name={m.workbench_properties_name()} /> | <UiLabel name={m.workbench_properties_expression()} /> | <UiLabel name={m.workbench_properties_merge()} />         |
| -------------------------- | ------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------------- |
| `title: "<%= it.title %>"` | `title`                                          | `zt.title`                                             | <UiLabel name={m.workbench_properties_merge_replace()} /> |
| `authors: ...`             | `authors`                                        | `zt.authors \| map: "fullName" \| join: ", "`          | <UiLabel name={m.workbench_properties_merge_replace()} /> |
| `year: "<%= it.date %>"`   | `year`                                           | `zt.date \| date: "%Y"`                                | <UiLabel name={m.workbench_properties_merge_replace()} /> |
| `tags: ...`                | `tags`                                           | `zt.tags \| map: "name" \| join: ", "`                 | <UiLabel name={m.workbench_properties_merge_append()} />  |

YAML 转义由系统自动处理。

### 空白 [#v1-whitespace]

<Callout type="info" title="从 v1 的空白变更">
  v1 默认将 `autoTrim` 设置为 `[false, "nl"]`（去除标签后的一个换行符）。v2 默认设置为 `[false, false]`（保留所有空白）。迁移后的模板如果在以前由 `%>` 吞掉尾随换行符的地方，可能会产生额外的空行。对于需要沿用旧去除行为的标签，请在其闭标签侧添加 `-%>`。请参阅[空白控制](/docs/reference/templates/eta-syntax#whitespace-control)。
</Callout>

## `renderAnnotation()`：标注渲染 [#render-annotation]

渲染单个标注，该标注在标注模板内部作为 `zt` 提供。

```eta
<%~ renderAnnotation(annotation) %>
```

annotation 参数为必填项。缺失或为 null 时会抛出错误。

对于标注值，等效的原生 Eta 语法为：

```eta
<%~ include("annotation", annotation) %>
```

在文献笔记配置方案中，对 `annotation` 的快捷调用和原生调用均使用该配置方案的标注分节。这一必需的最终分节始于完全匹配的独立行 `--- zotlit:annotation ---` 之后，并一直持续到文档末尾。它使用该配置方案的语言，且可以为空。

来自共享片段的调用会使用发起调用的配置方案分节，并具有独立的标注数据。直接标注插入和导入笔记则在其适用的配置方案中使用相同的分节。在配置方案渲染之外，该快捷方式保持现有的命名模板查找逻辑。

## `include()`：组合模板 [#include-composing-templates]

`include()` 内联渲染另一个模板。传入模板名称和可选的数据参数：

```eta
<%~ include("annotation", annotation) %>
<%~ include("content", zt) %>
```

数据参数会成为子模板的 `zt` 变量，直接透传而不与父级数据合并。如果省略，子模板将继承父级的 `zt`。

该名称解析为已注册的模板，而非文件路径。在配置方案渲染期间，`"annotation"` 会选中该配置方案的标注分节。

### 调用片段 [#calling-a-partial]

片段通过其名称调用，所需数据作为第二个参数传入：

```eta
<%~ include("authors", zt) %>
```

该参数成为片段的 `zt`。如果省略，片段将继承调用者的 `zt`。在 `include("` 内部补全时会列出仓库中的所有片段，选中名称后会写入包含 `zt` 参数在内的完整调用。若已提供了参数，则参数会保留，仅替换名称。

### `content` 包含 [#the-content-include]

当从笔记模板调用 `include("content", zt)` 且仓库中存在支持它的 `content` 模板文件时，ZotLit 会用托管区域标记（`%%zt-managed%%` / `%%/zt-managed%%`）包裹输出。这些标记绝不会出现在模板文档中，它们是在渲染时注入的。内置的 `content` 模板在渲染时不带标记。

## `bq()`：块引用辅助函数 [#bq-blockquote-helper]

将其内容包装在 Markdown 块引用中。每行均以 `> ` 为前缀。内容会被去除多余空白。块内连续的空行会折叠为单独的 `>`。

```eta
<% bq(() => { %>
[!note] Page <%= zt.pageLabel %>

<%= embed(zt.imgLink) %><%= zt.text %>
<% if (zt.comment) { %>

<%= zt.comment %>
<% } %>
<% }) %>
```

渲染输出：

```markdown
> [!note] Page 42
>
> ![[excerpt.png]]The highlighted passage
>
> My thoughts on this
```

`bq()` 必须出现在 `<% %>` 执行标签中。它会捕获回调内部生成的所有输出，修剪结果，为每行添加 `> ` 前缀（空行变为单独的 `>`），将连续的单独 `>` 行折叠为一行，并将结果写入输出。

当捕获的内容为空时，`bq()` 渲染单独的 `>`。

## `embed()`：嵌入辅助函数 [#embed-embed-helper]

通过添加 `!` 前缀将链接辅助函数转换为 Markdown 嵌入语法。当链接为 `null`、`undefined` 或渲染为空时返回 `""`。

```eta
<%= embed(zt.imgLink) %>
<%= embed(zt.imgLink, "alt text") %>
```

签名：`embed(link, alias?, subpath?)`

| 输入                                    | 输出                 |
| --------------------------------------- | -------------------- |
| `zt.imgLink` 渲染为 `"[[excerpt.png]]"` | `"![[excerpt.png]]"` |
| `zt.imgLink` 为 `null`                  | `""`                 |

对于图片和手绘标注，`embed(zt.imgLink)` 使用准备好的笔记图片，或者返回图像不可用的说明及源链接。它会保留该后备文本而不添加 `!`。图片准备工作在模板之前运行，因此模板每次渲染仅执行一次。预览渲染不会创建仓库图片文件。

## `pandocCite()`：Pandoc 引文源 [#pandoc-cite]

将引文条目数组格式化为 Pandoc 引文源。直接将 `zt.citations` 传递给该辅助函数。

```eta
<%= pandocCite(zt.citations) %>
<%= pandocCite(zt.citations, "prefer-author-in-text") %>
```

签名：`pandocCite(citations, form?)`

可选参数 form 默认为 `"normal"`。

| 形式                      | 单个条目的输出 | 描述                                                                                                        |
| ------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `"normal"`                | `[@smith2024]` | 生成带方括号的引用组（Citation Cluster）。                                                                  |
| `"prefer-author-in-text"` | `@smith2024`   | 当第一个保留条目没有前缀且不隐藏作者时，生成正文作者引文（Author-in-text Citation）；否则生成普通的引用组。 |

该辅助函数可处理 Pandoc 源中使用的所有引文条目属性：

| 输入                                        | 输出                       |
| ------------------------------------------- | -------------------------- |
| 定位符 `"3"` 带有 `labelShort` `"p."`       | `[@smith2024, {p. 3}]`     |
| 前缀 `"see "` 与后缀 `", note 4"`           | `[see @smith2024, note 4]` |
| `suppressAuthor` 设为 `true`                | `[-@smith2024]`            |
| 文献引用标识 `"KX67D9YM?"`                  | `[@{KX67D9YM?}]`           |
| `"prefer-author-in-text"` 带有定位符 `"3"`  | `@smith2024 [{p. 3}]`      |
| `"prefer-author-in-text"` 带有前缀 `"see "` | `[see @smith2024]`         |
| 空数组或仅包含文献引用标识为 null 的条目    | `""`                       |

文献引用标识为 null 的条目会被忽略。辅助函数会保留剩余条目的顺序，并在 Pandoc 需要时为复杂的文献引用标识添加大括号。

如果输入的内容在不改变引用结构的情况下无法表示，则会抛出渲染错误。

## `texCite()`：LaTeX 引用命令 [#tex-cite]

将引文条目数组格式化为一个 LaTeX 引用命令。直接将 `zt.citations` 传递给该辅助函数。

```eta
<%= texCite(zt.citations) %>
<%= texCite(zt.citations, "autocite") %>
```

签名：`texCite(citations, command?)`

可选参数 command 默认为 `"cite"`。编写时无需反斜杠。亦支持带星号的命令，例如 `"autocite*"`。

| 命令         | 单个条目的输出         | 参考文献包              |
| ------------ | ---------------------- | ----------------------- |
| `"cite"`     | `\cite{smith2024}`     | LaTeX、natbib、BibLaTeX |
| `"autocite"` | `\autocite{smith2024}` | BibLaTeX                |

所有保留的条目会合并为一个标识符列表。该命令包含一个前注（prenote）和一个后注（postnote），两者均来自第一个保留的条目：

| 输入                                     | 输出                             |
| ---------------------------------------- | -------------------------------- |
| 两个条目                                 | `\cite{smith2024,doe2023}`       |
| 定位符 `"3"` 带有 `labelShort` `"p."`    | `\cite[p. 3]{smith2024}`         |
| 前缀 `"see "`                            | `\cite[see][]{smith2024}`        |
| 前缀 `"see "` 带有定位符 `"3"`           | `\cite[see][p. 3]{smith2024}`    |
| 定位符 `"3"` 带有后缀 `", note 4"`       | `\cite[p. 3, note 4]{smith2024}` |
| 空数组或仅包含文献引用标识为 null 的条目 | `""`                             |

文献引用标识为 null 的条目会被忽略，剩余条目保留其顺序。

<Callout type="warn" title="前注形式需要 natbib 或 BibLaTeX">
  LaTeX 内核本身的 `\cite` 仅接受一个可选参数。上述双参数形式 `\cite[see][p. 3]
  {smith2024}` 可在 natbib 或 BibLaTeX 下编译，它们重新定义了 `\cite`
  以同时接受两个参数。不带前缀的引用最多输出一个可选参数，可在普通 LaTeX
  文档中正常工作。
</Callout>

词缀以源码形式传递给 LaTeX，因此前缀 `\emph{see}` 会渲染为斜体强调。以下输入则会引发渲染错误：

- `suppressAuthor` 设为 `true`，LaTeX 没有通用的对应形式。
- 第一个条目之后的任何条目包含前缀、后缀或定位符，因为没有位置可容纳它们。
- 文献引用标识为空，或包含空格、逗号或 TeX 特殊字符。
- 前缀、后缀或定位符中的大括号不配对，或包含未转义的 `%`。

## `suffix()`：文件名冲突保护 [#suffix-filename-collision-guard]

仅适用于 `filename` 模板。当生成的文件名与现有笔记冲突时追加随机字符串。当名称无冲突时，不渲染任何内容。

```eta
<%= zt.citationKey ?? zt.DOI ?? zt.title ?? zt.key %><%= suffix() %>
```

- 首篇名为 `Smith2020` 的笔记会生成 `Smith2020.md`。
- 第二篇同样会渲染为 `Smith2020` 的笔记则会生成 `Smith2020_a1b2c3.md`。

### 签名 [#signature]

```
suffix(length?, prepend?, append?)
```

| 参数      | 默认值 | 约束                |
| --------- | ------ | ------------------- |
| `length`  | `6`    | 整数，1–64          |
| `prepend` | `"_"`  | 不能包含 `:` 或 `%` |
| `append`  | `""`   | 不能包含 `:` 或 `%` |

词缀仅在发生冲突时出现。当名称无冲突时，整个表达式（包括词缀）不渲染任何内容。

```eta
<%= zt.title %><%= suffix(10) %>
<%= zt.title %><%= suffix(6, "(", ")") %>
<%= zt.citationKey %><%= suffix(4, "-") %>
```

随机字符串使用字母和数字。发生冲突时，ZotLit 最多会使用新的随机字符串重试 5 次。

## 链接辅助函数 [#link-helpers]

`zt` 上下文中的链接是函数，而非预先计算的字符串。调用它们即可进行渲染。每个函数均接受可选的覆盖参数：

```
linkHelper(alias?, subpath?)
```

- `alias`：链接的显示文本。省略时使用默认值（文件名或笔记标题）。
- `subpath`：追加到目标后面的 `#` 片段，例如 `"#heading"` 或 `"#page=3"`。

| 辅助函数          | 适用对象                     | 默认 subpath                  | 返回值                                                          |
| ----------------- | ---------------------------- | ----------------------------- | --------------------------------------------------------------- |
| `zt.noteLink()`   | 条目上下文                   | 无                            | 该条目文献笔记的 Markdown 链接，或者 `null`                     |
| `note.noteLink()` | 每个 `zt.notes[]` 条目       | 无                            | 导入笔记的链接，否则为在 Zotero 中打开该笔记的 `zotero://` 链接 |
| `a.fileLink()`    | 每个 `zt.attachments[]` 条目 | 无                            | 附件文件链接                                                    |
| `zt.fileLink()`   | 标注上下文                   | `#page=N&zt-annotation=<key>` | 已弃用。锚定到标注所在页及标注本身的附件链接                    |
| `zt.imgLink()`    | 标注上下文                   | 无                            | 摘录图片链接、图像不可用的说明及源链接，或者 `null`             |

```eta
<%= zt.attachments[0].fileLink() %>
<%= zt.attachments[0].fileLink("Open the PDF") %>
<%= zt.noteLink("See notes", "#Summary") %>
```

当文献笔记路径无法解析时（冲突、递归解析或模板错误），`zt.noteLink()` 返回 `null`。对于除 `image` 和 `ink` 以外的标注类型，`zt.imgLink` 为 `null`。不可用的图片将使用[摘录回退机制](/docs/reference/excerpt-images#import-outcomes)。

### 持久标注链接 [#annotation-backlink]

标注上下文中的 `zt.backlink` 是指向标注的持久链接。它是 Zotero 原生的打开链接，并通过 Zotero 标识符指明附件和标注：

```
zotero://open/library/items/<attachmentKey>?annotation=<annotationKey>&page=<pageLabel>
```

群组文库使用 `groups/<groupID>` 代替 `library`。`page` 为打印页码标签，若标注没有页码，则链接会省略该参数。

`zt.backlink` 是纯 URL 字符串，而不是辅助函数。不要调用它；应自行将其包装在 Markdown 链接中，就像[默认标注模板](/docs/reference/templates/defaults#annotation-template)所做的那样：

```eta
<%= zt.pageLabel ? `Page [${zt.pageLabel}](${zt.backlink})` : `[Zotero](${zt.backlink})` %>
```

<Callout type="warn">
  标注的 `zt.fileLink()`
  已弃用。它保存的是渲染笔记时所在电脑的文件路径，因此在另一台电脑上或 Zotero
  存储文件夹移动后将无法打开任何内容。请改用 `zt.backlink`。`zt.fileLink()`
  在当前发布版本系列中仍可用。附件的 `a.fileLink()` 未被弃用。
</Callout>

当开启 <SettingsPath page={m.settings_page_reader()} setting={m.settings_reader_open_file_links_name()} /> 时（此为默认设置），点击持久标注链接会在 [Obsidian 中打开 PDF](/docs/how-to/open-pdf-in-obsidian)，并选中该标注。当此电脑未存放该 PDF 时，则由 Zotero 打开该链接。各种情况请参阅 [Zotero 打开链接](/docs/reference/protocol-links#zotero-open-links)。指向 Zotero 文库中 PDF 的文件链接也会在 Obsidian 中打开，而旧的 `zt.fileLink()` 链接仍会定位并打开在标注所在的页面。

## 模板文档命名 [#template-document-naming]

模板文档直接存放在通过 <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} /> 设置的文件夹内。扫描为扁平结构，仅凭文件名即可识别文档类型：配置方案为 `zotlit-profile.<slug>.md`，引文文本为 `zotlit-citation.md`，单个片段为 `zotlit-partial.<name>.md`。完整规则及保留的片段名称请参阅[模板文档命名](/docs/reference/templates/syntax#template-document-naming)。

Eta 文档在文件顶部的 YAML 清单中声明其语言，位于源码之前：

```md
---
language: eta
---

<%= zt.title %>
```

`language` 是清单中唯一合法的键，其值为 `liquid` 和 `eta`。没有清单的文档默认为 Liquid，因此每个 Eta 引文文档和 Eta 片段都需要此代码块。可通过模板工作台视图的窗格菜单，使用 <UiLabel name={m.template_workbench_change_language()} /> 在两者之间切换文档；它会重写清单键并保留源码不变。

配置方案文档通过其自身清单中的 `language` 键声明其语言。

## 不支持异步 [#no-async]

ZotLit 以同步方式渲染模板。在 Eta 模板内无法使用 `async`/`await`。
