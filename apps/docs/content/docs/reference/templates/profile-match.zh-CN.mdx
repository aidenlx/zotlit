本参考手册介绍了配置方案匹配规则（Profile Match）语言：配置方案文档在其 `match` 配置键中所承载的表达式与条件树。

一条匹配条件用于对单篇 Zotero 条目进行断言判断。ZotLit 在创建文献笔记时会执行该匹配逻辑。这套规则语法与模板工作台视图中 <UiLabel name={m.workbench_tab_match()} /> 标签页写入配置方案文档的格式完全一致，也是分享配置方案时在其 manifest 中所包含的内容。

## 匹配规则存放在何处 [#where]

匹配规则位于[配置方案文档](/docs/reference/templates/profile-document) manifest 中的 `match` 键下。`match` 键可以承载单条表达式或一棵复合条件树。

系统内置的默认配置方案不含 `match`，缺少 `match` 键的配置方案绝不会被自动选中。但您依然可以通过手动方式选择使用该配置方案。具体操作步骤请参阅[针对不同笔记使用不同模板](/docs/how-to/use-different-templates)，其中介绍了如何在模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 标签页中配置匹配规则。

## 支持的字段 [#fields]

匹配条件可针对以下四个字段进行判断：

| 字段          | 允许的取值                      | 支持的测试方式 | 语法示例                               |
| ------------- | ------------------------------- | -------------- | -------------------------------------- |
| `library`     | `personal` 或 `group:<groupID>` | `==` 或 `!=`   | `library == "group:118"`               |
| `itemType`    | 条目类型规范名称                | `==` 或 `!=`   | `itemType == "journalArticle"`         |
| `tags`        | 标签名称列表                    | 列表函数       | `tags.contains("Read")`                |
| `collections` | 分类路径列表                    | 列表函数       | `collections.within("Project/Drafts")` |

### 文献库取值说明

`library` 的取值为 `"personal"` 或 `"group:<groupID>"`，其中 `<groupID>` 为正整数。该取值通过群组唯一数字 ID（而非本地数据库临时自增 ID）来指明群组文献库，因此即使重建 Zotero 本地数据库也不会发生错位失效。

ZotLit 会拒绝任何既非 `personal` 也非以正整数结尾的 `group:` 的取值。在已连接文献库的情况下，如果指定的群组不存在于当前库中，也会被判定为非法。

### 条目类型取值说明

条目类型名称来自于 ZotLit 基于 Zotero 规范生成的闭集：涵盖所有顶级条目类型，自动排除子项类型（`attachment`、`note` 与 `annotation`）。[按条目类型划分的字段](/docs/reference/templates/data#common-fields)列出了集合中的全部名称。使用不在集合中的名称会被拒绝。

### 标签取值说明

标签名称为任意自由文本，匹配过程严格区分大小写。您手动添加的标签与 Zotero 自动附加的抓取标签具有同等效力。

### 分类路径说明

分类路径（Collection path）从根分类开始，逐级延伸至包含条目的直接父分类，层级名称之间以 `/` 连接。例如，`Project/Drafts/Review` 表示位于 `Project` 下的 `Drafts` 分类之中的 `Review` 分类。

路径不提供转义语法，因此名称中包含 `/` 的分类可能存在歧义。ZotLit 会对照条目所属的文献库来计算路径，且允许声明当前文献库中尚不存在的路径：对不存在路径的正向归属判断仅会简单返回 false，而不会导致系统报错。

## 相等性断言 [#equality]

标量字段 `library` 与 `itemType` 支持相等性断言。

| 语法形式           | 适用字段              | 成立条件                                   | 示例                     |
| ------------------ | --------------------- | ------------------------------------------ | ------------------------ |
| `field == "value"` | `library`, `itemType` | 条目的对应字段值等于右侧被引用的字符串。   | `itemType == "book"`     |
| `field != "value"` | `library`, `itemType` | 条目的对应字段值不等于右侧被引用的字符串。 | `library != "group:118"` |

字段名必须置于左侧，带引号的目标值置于右侧。目标值使用双引号或单引号均可。ZotLit 会拒绝两侧颠倒的书写方式，以及该字段无法接受的目标值。

## List functions [#list-functions]

The list fields `tags` and `collections` take a function call. Every argument is a string literal.

| Function            | Fields                | Arguments   | Holds when                                                                    |
| ------------------- | --------------------- | ----------- | ----------------------------------------------------------------------------- |
| `contains(value)`   | `tags`, `collections` | Exactly one | The list holds that value.                                                    |
| `containsAny(a, b)` | `tags`, `collections` | One or more | The list holds at least one of the values.                                    |
| `containsAll(a, b)` | `tags`, `collections` | One or more | The list holds every value.                                                   |
| `isEmpty()`         | `tags`, `collections` | None        | The list holds no values.                                                     |
| `within(path)`      | `collections`         | Exactly one | The item is filed in that Collection or in one of its descendant Collections. |

On `collections`, `contains` tests direct filing: `collections.contains("Project/Drafts")` holds only when the item is filed directly in that exact path. `within` accepts any descendant. On `tags`, the value is one Tag name, not a path.

ZotLit rejects `within` on `tags`, a list function on `library` or `itemType`, a call with the wrong number of arguments, and a non-string argument.

## Operators [#operators]

| Operator | Meaning                                         |
| -------- | ----------------------------------------------- |
| `!`      | Negates one test or a parenthesized expression. |
| `&&`     | Holds when both sides hold.                     |
| `\|\|`   | Holds when at least one side holds.             |
| `( )`    | Groups tests.                                   |

`!` binds tightest, then `&&`, then `||`:

```
!tags.contains("Read")
!(itemType == "book" || itemType == "thesis")
itemType == "book" && tags.contains("Read")
```

`true` matches every item. `false` is rejected as unsupported: it describes no item set that a profile can use.

## Tree form [#tree]

The `match` key holds either one expression string or one tree node. A tree node is a mapping with a single key, `and` or `or`, whose value is a list of entries. Each entry is an expression string or another tree node.

```yaml
match: 'itemType == "book" && tags.contains("Read")'
```

```yaml
match:
  and:
    - 'itemType == "book"'
    - or:
        - 'tags.contains("Read")'
        - 'collections.within("Project/Drafts")'
```

`and` holds when every entry holds. `or` holds when at least one entry holds.

An empty list is legal. An empty `and` matches every item. An empty `or` matches no item.

An entry that is an empty expression string is rejected, because a leaf has to test something.

## Rejected forms [#rejected]

| Form                                  | Why it is rejected                                                 |
| ------------------------------------- | ------------------------------------------------------------------ |
| `hasTag("Read")`                      | Legacy name. Use `tags.contains("Read")`.                          |
| `inCollection("Project")`             | Legacy name. Use `collections.contains` or `collections.within`.   |
| `inCollectionDirectly("Project")`     | Legacy name. Use `collections.contains` or `collections.within`.   |
| `title == "x"`                        | A match tests only the four fields in [Fields](#fields).           |
| `tags == "Read"`                      | A list field takes a list function, not an equality test.          |
| `itemType.contains("book")`           | A scalar field takes an equality test, not a list function.        |
| `false`                               | Describes no item set. Use `true` to match every item.             |
| `library == "group:0"`                | A group ID is a positive integer, and the group must be connected. |
| `itemType == "novel"`                 | An item type outside the closed set.                               |
| An empty expression, or broken syntax | The condition does not name a test.                                |

The three legacy names also take a Library argument. The current language has no equal, because a Collection path is evaluated against the item's own Library.

## Selection with a Profile Match [#selection]

ZotLit treats a Profile Match it cannot evaluate as a non-match, not as a refusal. It reports the problem as a diagnostic, keeps the profile out of automatic selection, and continues with the other profiles. Causes include invalid syntax, an unsupported construct, an unknown Library, and an unknown item type. A profile's row in [Settings](/docs/reference/settings#profile-match) shows the status of its Profile Match, and the <UiLabel name={m.workbench_tab_match()} /> tab of the Template Workbench View shows the diagnostic.

A profile with no `match` key never takes part in automatic selection. A profile whose `match` holds is used for the new note. When several profiles match, the profile picker opens with the matching candidates. [Settings](/docs/reference/settings#profile-match) describes the statuses, the condition summary, and the picker. A Match is edited in the profile document, on the <UiLabel name={m.workbench_tab_match()} /> tab of the Template Workbench View; [Use a different template for different notes](/docs/how-to/use-different-templates) gives the procedure.
