本参考手册介绍了配置方案匹配规则（Profile Match）语言：配置方案文档在其 `match` 配置键中所承载的表达式与条件树。

一条匹配条件用于对单篇 Zotero 条目进行断言判断。ZotLit 在创建文献笔记时会执行该匹配逻辑。这套规则语法与模板工作台视图中 <UiLabel name={m.workbench_tab_match()} /> 标签页写入配置方案文档的格式完全一致，也是分享配置方案时在其 manifest 中所包含的内容。

## 匹配规则存放在何处 [#where]

匹配规则位于[配置方案文档](/docs/reference/templates/profile-document) manifest 中的 `match` 键下。`match` 键可以承载单条表达式或一棵复合条件树。

系统内置的默认配置方案不含 `match`，缺少 `match` 键的配置方案绝不会被自动选中。但您依然可以通过手动方式选择使用该配置方案。具体操作步骤请参阅[针对不同笔记使用不同模板](/docs/how-to/use-different-templates)，其中介绍了如何在模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 标签页中配置匹配规则。

## 支持的字段 [#fields]

匹配条件可针对以下四个字段进行判断：

| 字段          | 允许的取值                      | 支持的测试方式 | 语法示例                               |
| ------------- | ------------------------------- | -------------- | -------------------------------------- |
| `library`     | `personal` 或 `group:<groupID>` | `==` 或 `!=`   | `library == "group:118"`               |
| `itemType`    | 条目类型规范名称                | `==` 或 `!=`   | `itemType == "journalArticle"`         |
| `tags`        | 标签名称列表                    | 列表函数       | `tags.contains("Read")`                |
| `collections` | 分类路径列表                    | 列表函数       | `collections.within("Project/Drafts")` |

### 文献库取值说明

`library` 的取值为 `"personal"` 或 `"group:<groupID>"`，其中 `<groupID>` 为正整数。该取值通过群组唯一数字 ID（而非本地数据库临时自增 ID）来指明群组文献库，因此即使重建 Zotero 本地数据库也不会发生错位失效。

ZotLit 会拒绝任何既非 `personal` 也非以正整数结尾的 `group:` 的取值。在已连接文献库的情况下，如果指定的群组不存在于当前库中，也会被判定为非法。

### 条目类型取值说明

条目类型名称来自于 ZotLit 基于 Zotero 规范生成的闭集：涵盖所有顶级条目类型，自动排除子项类型（`attachment`、`note` 与 `annotation`）。[按条目类型划分的字段](/docs/reference/templates/data#common-fields)列出了集合中的全部名称。使用不在集合中的名称会被拒绝。

### 标签取值说明

标签名称为任意自由文本，匹配过程严格区分大小写。您手动添加的标签与 Zotero 自动附加的抓取标签具有同等效力。

### 分类路径说明

分类路径（Collection path）从根分类开始，逐级延伸至包含条目的直接父分类，层级名称之间以 `/` 连接。例如，`Project/Drafts/Review` 表示位于 `Project` 下的 `Drafts` 分类之中的 `Review` 分类。

路径不提供转义语法，因此名称中包含 `/` 的分类可能存在歧义。ZotLit 会对照条目所属的文献库来计算路径，且允许声明当前文献库中尚不存在的路径：对不存在路径的正向归属判断仅会简单返回 false，而不会导致系统报错。

## 相等性断言 [#equality]

标量字段 `library` 与 `itemType` 支持相等性断言。

| 语法形式           | 适用字段              | 成立条件                                   | 示例                     |
| ------------------ | --------------------- | ------------------------------------------ | ------------------------ |
| `field == "value"` | `library`, `itemType` | 条目的对应字段值等于右侧被引用的字符串。   | `itemType == "book"`     |
| `field != "value"` | `library`, `itemType` | 条目的对应字段值不等于右侧被引用的字符串。 | `library != "group:118"` |

字段名必须置于左侧，带引号的目标值置于右侧。目标值使用双引号或单引号均可。ZotLit 会拒绝两侧颠倒的书写方式，以及该字段无法接受的目标值。

## 列表函数 [#list-functions]

列表字段 `tags` 和 `collections` 使用函数调用进行判断。所有参数都必须是字符串字面量。

| 函数                | 字段                  | 参数       | 成立条件                         |
| ------------------- | --------------------- | ---------- | -------------------------------- |
| `contains(value)`   | `tags`, `collections` | 恰好一个   | 列表包含该值。                   |
| `containsAny(a, b)` | `tags`, `collections` | 一个或多个 | 列表包含所给值中的至少一个。     |
| `containsAll(a, b)` | `tags`, `collections` | 一个或多个 | 列表包含所有给定值。             |
| `isEmpty()`         | `tags`, `collections` | 无         | 列表为空。                       |
| `within(path)`      | `collections`         | 恰好一个   | 条目属于该分类或其任意下级分类。 |

对于 `collections`，`contains` 判断直接归属：只有条目直接属于指定路径的分类时，`collections.contains("Project/Drafts")` 才成立。`within` 则包括任意下级分类。对于 `tags`，参数值是标签名称，而非路径。

ZotLit 会拒绝以下写法：对 `tags` 使用 `within`、对 `library` 或 `itemType` 使用列表函数、参数数量错误，或使用非字符串参数。

## 运算符 [#operators]

| 运算符 | 含义                             |
| ------ | -------------------------------- |
| `!`    | 对单个判断或括号内的表达式取反。 |
| `&&`   | 两侧都成立时为真。               |
| `\|\|` | 至少一侧成立时为真。             |
| `( )`  | 对判断进行分组。                 |

`!` 的优先级最高，其次是 `&&`，最后是 `||`：

```
!tags.contains("Read")
!(itemType == "book" || itemType == "thesis")
itemType == "book" && tags.contains("Read")
```

`true` 匹配所有条目。`false` 不受支持，会被拒绝，因为它无法指定配置方案可使用的任何条目集合。

## 条件树形式 [#tree]

`match` 键接受一个表达式字符串或一个树节点。树节点是仅含 `and` 或 `or` 一个键的映射，其值为配置项列表。每个配置项可以是表达式字符串，也可以是另一个树节点。

```yaml
match: 'itemType == "book" && tags.contains("Read")'
```

```yaml
match:
  and:
    - 'itemType == "book"'
    - or:
        - 'tags.contains("Read")'
        - 'collections.within("Project/Drafts")'
```

所有配置项都成立时，`and` 成立。至少一个配置项成立时，`or` 成立。

允许空列表。空的 `and` 匹配所有条目，空的 `or` 不匹配任何条目。

表达式字符串为空的配置项会被拒绝，因为叶节点必须包含具体判断。

## 不接受的写法 [#rejected]

| 写法                              | 拒绝原因                                                          |
| --------------------------------- | ----------------------------------------------------------------- |
| `hasTag("Read")`                  | 旧版名称。请使用 `tags.contains("Read")`。                        |
| `inCollection("Project")`         | 旧版名称。请使用 `collections.contains` 或 `collections.within`。 |
| `inCollectionDirectly("Project")` | 旧版名称。请使用 `collections.contains` 或 `collections.within`。 |
| `title == "x"`                    | 匹配规则仅支持[支持的字段](#fields)中列出的四个字段。             |
| `tags == "Read"`                  | 列表字段需使用列表函数，不支持相等性断言。                        |
| `itemType.contains("book")`       | 标量字段需使用相等性断言，不支持列表函数。                        |
| `false`                           | 未指定任何条目集合。使用 `true` 可匹配所有条目。                  |
| `library == "group:0"`            | 群组 ID 必须是正整数，且该群组必须已连接。                        |
| `itemType == "novel"`             | 条目类型不在允许的集合中。                                        |
| 空表达式或语法错误                | 条件未指定有效判断。                                              |

这三个旧版函数名还接受文献库参数。当前语法没有对应参数，因为分类路径始终在条目所属的文献库中计算。

## 根据匹配规则选择配置方案 [#selection]

对于无法求值的配置方案匹配规则，ZotLit 将其视为不匹配，并继续检查其他配置方案。系统会报告诊断信息，将该配置方案排除在自动选择之外。可能的原因包括语法错误、不支持的结构、未知文献库或未知条目类型。[设置](/docs/reference/settings#profile-match)中的配置方案行会显示匹配规则状态；模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 标签页会显示诊断信息。

不含 `match` 键的配置方案不参与自动选择。`match` 条件成立的配置方案会用于新笔记。多个配置方案同时匹配时，系统会打开配置方案选择器并列出候选项。[设置](/docs/reference/settings#profile-match)介绍了各类状态、条件摘要和选择器。您可以在模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 标签页中编辑配置方案文档的匹配规则；具体步骤见[针对不同笔记使用不同模板](/docs/how-to/use-different-templates)。
