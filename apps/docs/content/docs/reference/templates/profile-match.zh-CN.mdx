本参考文档介绍配置方案匹配（Profile Match）：配置方案文档在其 `match` 键中包含的筛选表达式或树结构。

配置方案匹配针对单个 Zotero 条目进行测试。ZotLit 在创建文献笔记时对其进行求值。它使用条目查询过滤器的[筛选表达式](/docs/reference/how-queries-work#steps)语言。模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 选项卡将其写入配置方案文档，而分享的配置方案则在其清单中携带它。

## 配置方案匹配的位置 [#where]

配置方案匹配是[配置方案文档](/docs/reference/templates/profile-document)清单中的 `match` 键。`match` 键保存一个表达式或一个树节点。

内置的默认（Default）配置方案不包含 `match`，缺少 `match` 键的配置方案永远不会被自动选择。你仍然可以手动选择该配置方案。具体操作步骤请参阅[为不同笔记使用不同模板](/docs/how-to/use-different-templates)，该指南介绍了在模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 选项卡上设置匹配条件。

## 字段 [#fields]

配置方案匹配可以读取条目查询过滤器能够读取的任何条目字段。`zotlit:query-schema` [命令](/docs/reference/commands#query-cli)列出了所有可用字段。以下四个是常用字段。

| 字段          | 取值                            | 测试方式     | 示例                                   |
| ------------- | ------------------------------- | ------------ | -------------------------------------- |
| `library`     | `personal` 或 `group:<groupID>` | `==` 或 `!=` | `library == "group:118"`               |
| `itemType`    | 单个条目类型名称                | `==` 或 `!=` | `itemType == "journalArticle"`         |
| `tags`        | 标签名称列表                    | 列表方法     | `tags.contains("Read")`                |
| `collections` | 分类路径列表                    | 列表方法     | `collections.within("Project/Drafts")` |

### 文库取值 [#library-values]

`library` 的取值为 `"personal"` 或 `"group:<groupID>"`，其中 `<groupID>` 为正整数。该值通过群组 ID 而非本地数据库 ID 来指定群组文库，因此在重建 Zotero 数据库后仍然有效。

既不符合这两种形式的值，或者未连接的群组，均不会匹配任何条目。

### 条目类型取值 [#item-type-values]

条目类型名称来自 ZotLit 基于 Zotero 架构构建的封闭集合：顶级条目类型，不包括子类型 `attachment`、`note` 和 `annotation`。[按条目类型划分的字段](/docs/reference/templates/data#common-fields)列出了集合中的所有名称。集合之外的名称不会匹配任何条目。

### 标签取值 [#tag-values]

标签名称为自由文本，匹配规则为精确匹配且区分大小写。你手动添加的标签和 Zotero 自动添加的标签均一视同仁。

### 分类路径 [#collection-paths]

分类路径从根分类开始，一直到该条目的直接父分类，各级名称用 `/` 连接。例如，`Project/Drafts/Review` 表示 `Project` 分类下 `Drafts` 中的 `Review` 分类。

路径没有转义语法，因此名称中包含 `/` 的分类会产生歧义。ZotLit 会针对条目所属的文库对路径进行求值，且接受任何文库中均不存在的路径：对不存在路径的正向包含测试仅直接返回假（false）。

## 文本条件 [#text-conditions]

匹配编辑器中的文本条件默认忽略大小写。例如，`title.icontains("Nature")` 同时匹配 `Nature` 和 `NATURE`。

| 行                                                                     | 表达式                       |
| ---------------------------------------------------------------------- | ---------------------------- |
| <UiLabel name={m.workbench_filter_op_contains()} />                    | `title.icontains("Nature")`  |
| <UiLabel name={m.workbench_filter_op_does_not_contain()} />            | `!title.icontains("Nature")` |
| <UiLabel name={m.workbench_filter_op_contains_match_case()} />         | `title.contains("Nature")`   |
| <UiLabel name={m.workbench_filter_op_does_not_contain_match_case()} /> | `!title.contains("Nature")`  |

已保存的 `title.contains("Nature")` 表达式会作为 <UiLabel name={m.workbench_filter_op_contains_match_case()} /> 行打开并保留其结果。每行都会保留你输入的原始文本。标签和分类条件使用精确、区分大小写的包含测试。

## 等值测试 [#equality]

文本字段 `library` 和 `itemType` 支持等值测试。

| 形式               | 字段                  | 成立条件                   | 示例                     |
| ------------------ | --------------------- | -------------------------- | ------------------------ |
| `field == "value"` | `library`、`itemType` | 条目的值等于带引号的值。   | `itemType == "book"`     |
| `field != "value"` | `library`、`itemType` | 条目的值不等于带引号的值。 | `library != "group:118"` |

取值可以使用双引号或单引号，字段可以位于任意一侧。列表字段与文本之间的等值测试（例如 `tags == "Read"`）不会匹配任何条目。

## 列表方法 [#list-functions]

列表字段 `tags` 和 `collections` 支持列表方法。

| 方法          | 字段                  | 参数个数 |
| ------------- | --------------------- | -------- |
| `contains`    | `tags`、`collections` | 恰好一个 |
| `containsAny` | `tags`、`collections` | 任意数量 |
| `containsAll` | `tags`、`collections` | 任意数量 |
| `isEmpty`     | `tags`、`collections` | 无       |
| `within`      | `collections`         | 恰好一个 |

`containsAny` 和 `containsAll` 也接受一个值列表，例如 `tags.containsAny(["Read", "Cited"])`。[列表方法](/docs/reference/functions-and-methods#list-methods)提供了每个方法的签名和返回结果。

在 `collections` 上，`contains` 测试直接归档：`collections.contains("Project/Drafts")` 仅在该条目直接归档于该确切路径下时才成立。`within` 则接受任何子孙路径。在 `tags` 上，取值是单个标签名称，而不是路径。

参数数量错误或 `within` 路径非文本的调用会被 ZotLit 拒绝。文本字段有其自身的方法，因此 `itemType.contains("book")` 会测试条目类型名称中是否包含 `book`。

## 运算符 [#operators]

| 运算符 | 含义                             |
| ------ | -------------------------------- |
| `!`    | 对单个测试或括号中的表达式取反。 |
| `&&`   | 当两侧均成立时成立。             |
| `\|\|` | 当至少一侧成立时成立。           |
| `( )`  | 为测试分组。                     |

`!` 优先级最高，其次是 `&&`，最后是 `||`：

```
!tags.contains("Read")
!(itemType == "book" || itemType == "thesis")
itemType == "book" && tags.contains("Read")
```

`true` 匹配所有条目，`false` 不匹配任何条目。

## 树形结构 [#tree]

`match` 键可以保存一个表达式字符串或一个树节点。树节点是仅包含单个键（`and`、`or` 或 `not`）的映射，其值为条目列表。每个条目可以是一个表达式字符串或另一个树节点。

```yaml
match: 'itemType == "book" && tags.contains("Read")'
```

```yaml
match:
  and:
    - 'itemType == "book"'
    - or:
        - 'tags.contains("Read")'
        - 'collections.within("Project/Drafts")'
```

当所有条目均成立时 `and` 成立。当至少一个条目成立时 `or` 成立。当没有条目成立时 `not` 成立。

空列表是合法的。空的 `and` 或 `not` 会匹配所有条目。空的 `or` 不匹配任何条目。

作为空表达式字符串的条目属于错误，因为叶节点必须测试某些内容。

## 拒绝的形式 [#rejected]

| 形式                              | 被拒绝的原因                                                       |
| --------------------------------- | ------------------------------------------------------------------ |
| `hasTag("Read")`                  | 旧版名称。请改用 `tags.contains("Read")`。                         |
| `inCollection("Project")`         | 旧版名称。请改用 `collections.contains` 或 `collections.within`。  |
| `inCollectionDirectly("Project")` | 旧版名称。请改用 `collections.contains` 或 `collections.within`。  |
| `tags.contains("Read", "Cited")`  | `contains` 仅接受一个参数。请改用 `containsAny` 或 `containsAll`。 |
| `collections.within(3)`           | 分类路径必须是文本。                                               |
| 空表达式或语法错误                | 条件未指定测试内容。                                               |

这三个旧版名称还接受一个文库参数。目前的语言中没有对应项，因为分类路径会直接针对条目自身的文库进行求值。

## 使用配置方案匹配进行选择 [#selection]

ZotLit 将无法求值的配置方案匹配视为不匹配，而非直接拒绝执行。它会将问题作为诊断信息报告，不让该配置方案参与自动选择，并继续处理其他配置方案。原因包括语法无效、未知函数以及参数错误的调用。[设置](/docs/reference/settings#profile-match)中配置方案对应的行会显示其配置方案匹配的状态，模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 选项卡则会显示诊断信息。

没有 `match` 键的配置方案永远不会参与自动选择。`match` 成立的配置方案将用于新笔记。当有多个配置方案匹配时，会打开配置方案选择器并列出匹配的候选方案。[设置](/docs/reference/settings#profile-match)详细介绍了各项状态、条件摘要和选择器。可以在配置方案文档中、在模板工作台视图的 <UiLabel name={m.workbench_tab_match()} /> 选项卡上编辑匹配条件；[为不同笔记使用不同模板](/docs/how-to/use-different-templates)给出了具体操作步骤。
