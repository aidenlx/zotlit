This page documents the Eta template language as configured in ZotLit. Eta templates require the [<UiLabel name={m.settings_template_js_enable_name()} /> gate](/docs/how-to/enable-javascript-templates) to be enabled. For the default Liquid engine, see [Template syntax](/docs/reference/templates/syntax).

All template data is accessible through a single variable, `zt`. The shape of `zt` depends on the template type: see the [Data reference](/docs/reference/templates/data) for the full property list.

## Delimiters

| Delimiter   | Purpose                              |
| ----------- | ------------------------------------ |
| `<% %>`     | Execute JavaScript (no output)       |
| `<%= %>`    | Output an expression (auto-filtered) |
| `<%~ %>`    | Output an expression (auto-filtered) |
| `<%/* */%>` | Comment (stripped from output)       |

`<%= %>` and `<%~ %>` are functionally identical in ZotLit. Both pass their result through the auto-filter. Use either for output; `<%= %>` is conventional.

```eta
<%= zt.title %>
<% if (zt.abstract) { %>
<%= zt.abstract %>
<% } %>
```

Use `<%/* */%>` for comments that do not appear in the rendered note:

```eta
<%/* Draft: revisit multi-author rendering */%>
```

<Callout type="warn" title="No hash-prefix comments">
  Eta does not support `<%# %>`. That syntax causes a compile error. Use `<%/* */%>` for all comments.
</Callout>

## Whitespace control [#whitespace-control]

By default, ZotLit sets `autoTrim` to `[false, false]`: whitespace around tags is preserved exactly as written. Newlines after `%>` and indentation before `<%` appear in the rendered note.

Per-tag markers override this default on one side of the tag:

| Marker | Position        | Effect                              |
| ------ | --------------- | ----------------------------------- |
| `-`    | Opening (`<%-`) | Trims one newline before the tag    |
| `-`    | Closing (`-%>`) | Trims one newline after the tag     |
| `_`    | Opening (`<%_`) | Trims all whitespace before the tag |
| `_`    | Closing (`_%>`) | Trims all whitespace after the tag  |

```eta
<% for (const annotation of zt.annotations) { -%>
- <%= annotation.text %>
<% } %>
```

The trailing `-%>` consumes the newline immediately after the opening tag, so each iteration begins on the `- ` line.

### Global autoTrim setting

Two settings control default trim behavior when the <UiLabel name={m.settings_template_js_enable_name()} /> gate is on:

- <UiLabel name={m.settings_template_trim_leading_name()} />: applies to the
  opening side of every tag.
- <UiLabel name={m.settings_template_trim_trailing_name()} />: applies to the
  closing side of every tag.

Each accepts three values: <UiLabel name={m.settings_template_trim_disable()} /> (no trim), <UiLabel name={m.settings_template_trim_nl()} />, or <UiLabel name={m.settings_template_trim_slurp()} />. Per-tag markers always override the global setting for that tag.

<Callout type="info" title="Markdown is whitespace-sensitive">
  The default (keep all whitespace) avoids silently breaking Markdown
  formatting. Use per-tag markers for precise control.
</Callout>

## Auto-filter (output coercion)

Every `<%= %>` and `<%~ %>` expression passes through a filter function before rendering. The filter coerces values to Markdown-safe text:

| Value                | Rendered as                         |
| -------------------- | ----------------------------------- |
| `null` / `undefined` | `""` (empty string)                 |
| `Date`               | ISO 8601 string (`toISOString()`)   |
| `Temporal.Instant`   | Local plain date, e.g. `2026-06-21` |
| Everything else      | `String(value)`                     |

This means `<%= zt.someFieldThatIsNull %>` outputs nothing rather than the literal text "null". Creator objects and dates render through their `toString()` method: creators produce their full name, dates produce ISO strings.

## The `zt` variable

All template data lives under the `zt` variable. The variable name applies across all template types:

```eta
<%= zt.title %>
<%= zt.creators[0].family %>
<%= zt.citationKey %>
```

The editor autocomplete inserts `= zt. ` when you select the interpolation hint inside `<%= %>` tags.

`zt` replaces v1's `it` variable. See [Changes from v1](#v1-changes) for the full property mapping.

## Changes from v1 [#v1-changes]

### Template file names [#v1-file-names]

| v1 filename        | Rename to                  | Where its content ends up                            |
| ------------------ | -------------------------- | ---------------------------------------------------- |
| `zt-note.eta.md`   | `zotlit-note.eta.md`       | The note body of the default profile document        |
| `zt-annots.eta.md` | `zotlit-content.eta.md`    | The managed block inside that same note body         |
| `zt-annot.eta.md`  | `zotlit-annotation.eta.md` | The annotation section of that same profile document |

Your two v1 citation files, `zt-cite*.eta.md`, take the same `zt-` to `zotlit-` rename. Both of them fold into one citation text document, `zotlit-citation.md`, as an `if`/`else` on `zt.variant`.

### Renamed and reshaped fields [#v1-fields]

These fields changed name or type:

| v1 property           | v2 property         | Notes                                                                                                                       |
| --------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `it.citekey`          | `zt.citationKey`    | `zt.citekey` also works as an alias                                                                                         |
| `it.abstractNote`     | `zt.abstract`       | `zt.abstractNote` also works                                                                                                |
| `it.publicationTitle` | `zt.containerTitle` | `zt.publicationTitle` also works                                                                                            |
| `it.color`            | `zt.colorHex`       | Hex string, e.g. `#ffd400`                                                                                                  |
| —                     | `zt.colorName`      | New: palette name (`"yellow"`, `"red"`, etc.)                                                                               |
| `it.imgExcerpt`       | `embed(zt.imgLink)` | `zt.imgLink` is a [link helper](/docs/reference/templates/eta-syntax#link-helpers) or `null`; `embed()` adds the `!` prefix |
| `it.imgPath`          | _(removed)_         | Use `zt.imgLink()` instead                                                                                                  |
| `it.imgUrl`           | _(removed)_         | Use `zt.imgLink()` instead                                                                                                  |
| `it.textExcerpt`      | `zt.text`           | Renamed                                                                                                                     |
| `it.commentMd`        | `zt.comment`        | Markdown comment is now the default                                                                                         |
| `it.comment`          | `zt.commentHtml`    | Raw HTML (only `<i>/<b>/<sub>/<sup>`)                                                                                       |

Direct Zotero fields that are plain strings (`title`, `DOI`, `url`, `volume`, `issue`, `pages`, `publisher`, etc.) carry over unchanged after the `it` → `zt` rename.

### Tags [#v1-tags]

v1 exposed tags as formatted strings. v2 exposes them as objects with `name` and `type` properties. Tags coerce to their `name` in string contexts, so `join` still works:

```eta
<%/* Tags coerce to their name */%>
<%= zt.tags.join(", ") %>

<%/* Explicit property access */%>
<%= zt.tags.map(t => t.name).join(", ") %>

<%/* Filter to manual tags only */%>
<%= zt.tags.filter(t => t.type === "manual").join(", ") %>
```

### Collections [#v1-collections]

v2 reshapes collection objects. Key differences:

| Aspect           | v1                          | v2                                         |
| ---------------- | --------------------------- | ------------------------------------------ |
| `path` order     | leaf → root                 | root → leaf                                |
| `path` rendering | auto-rendered `"A > B > C"` | plain `string[]`; use `c.path.join(" > ")` |
| Singular alias   | `it.collection`             | removed; use the `zt.collections` array    |

```eta
<%/* Collections coerce to their name in string contexts */%>
<%= zt.collections.join(", ") %>

<%/* Render each collection's full hierarchy */%>
<%= zt.collections.map(c => c.path.join(" > ")).join("; ") %>
```

### Dates [#v1-dates]

| v1 property                        | v2 property                        | Type change                                                                                                                        |
| ---------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `it.date`                          | `zt.date`                          | Was a year-only string; now a parsed `ItemDate` object. `<%= zt.date %>` renders ISO; `zt.date?.year` gets the numeric year.       |
| `it.dateAdded` / `it.dateModified` | `zt.dateAdded` / `zt.dateModified` | Were raw SQL strings (`"YYYY-MM-DD HH:MM:SS"`); now `Temporal.Instant`. Render as local date in `<%= %>` tags (e.g. `2026-06-21`). |

If your v1 template used `it.date` as a year string, replace with `zt.date?.year`:

```eta
<%/* v1 */%>
year: "<%= it.date %>"

<%/* v2 */%>
year: "<%= zt.date?.year %>"
```

### Child notes [#v1-child-notes]

v1 inlined child-note content as Markdown on `it.notes`. v2 provides link-only entries. A child note becomes a separate file only when you [import it](/docs/how-to/import-zotero-notes):

| v1                                      | v2                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------- |
| `it.notes`: array of `{title, content}` | `zt.notes`: array of `{key, title, noteLink()}`                           |
| Note content inlined                    | `noteLink()` links to the imported file, or else opens the note in Zotero |

The default template no longer lists child notes. To list them as links, add a loop like this to your template:

```eta
<% if (zt.notes.length) { %>
## Notes

<% for (const note of zt.notes) { -%>
- <%~ note.noteLink() %>
<% } %>
<% } %>
```

### The annotation template and `bq()` [#v1-annotation]

v1 relied on external blockquote handling. v2 uses the [`bq()` helper](/docs/reference/templates/eta-syntax#bq-blockquote-helper) inside the annotation template:

```eta
<% bq(() => { %>
[!note] Page <%= zt.pageLabel %>

<%= embed(zt.imgLink) %><%= zt.text %>
<% if (zt.comment) { %>

<%= zt.comment %>
<% } %>
<% }) %>
```

`bq()` wraps all content in a Markdown blockquote (`> ` per line), trims the result, and collapses consecutive empty blockquote lines. It must appear in a `<% %>` execute tag.

### The content template [#v1-content]

The template is renamed from `annots` to `content`. It now receives the full context object instead of a raw annotation array:

```eta
<%/* v1: received a raw array as `it` */%>
<% for (const annotation of it) { %>

<%/* v2: receives full context, access annotations via zt.annotations */%>
<% for (const annotation of zt.annotations) { %>
```

Update the `include` call in your note template:

```eta
<%/* v1 */%>
<%~ include("annots", it.annotations) %>

<%/* v2 */%>
<%~ include("content", zt) %>
```

The content template now has access to all `zt.*` properties (attachments, tags, notes, etc.), not annotations alone.

### The citation source [#v1-citation]

v1 passed `it` as a raw array. v2 wraps items in an object:

```eta
<%/* v1 */%>
[<%= it.filter(lit => !!lit.citekey).map(lit => `@${lit.citekey}`).join("; ") %>]

<%/* v2 */%>
[<%= zt.citations.filter(c => c.item.citationKey).map(c =>
  `${c.suppressAuthor ? "-" : ""}@${c.item.citationKey}`
).join("; ") %>]
```

Key changes:

- `it` (array) becomes `zt.citations` (array inside an object). `zt.items` exposes the same items without citation metadata.
- `lit.citekey` becomes `c.item.citationKey` (or `c.item.citekey`).
- Both of your v1 citation files render from one v2 document. The [conversion](/docs/how-to/migrate-v1-eta-templates#convert) writes them as the two branches of an `if`/`else` on `zt.variant`, which is `"main"` or `"alt"`. See [Citation templates](/docs/reference/templates/data#citation-templates).

### Attachments [#v1-attachments]

v1 selected one attachment and exposed it as `it.fileLink` (a string). v2 provides all attachments as an array, and `fileLink` is a [link helper](/docs/reference/templates/eta-syntax#link-helpers) you call:

```eta
<%= zt.attachments.map(a => a.fileLink()).filter(Boolean).join(" ") %>
```

Each attachment object has: `key`, `filename`, `contentType`, `linkMode`, `filePath`, `fileLink`.

### Creators [#v1-creators]

v2 uses a flat array with explicit properties. Creators coerce to their full name in string contexts:

```eta
<%/* All authors (coerces to fullName) */%>
<%= zt.authors.join(", ") %>

<%/* Explicit property access */%>
<%= zt.authors.map(c => c.fullName).join(", ") %>

<%/* Filter by role */%>
<%= zt.creators.filter(c => c.role === "editor").join(", ") %>
```

Creator properties: `family`, `given`, `literal` (institutional names), `role`, `fullName`.

Convenience properties on the item context: `zt.authors` (the first populated role: primary creator, editor, director, then contributor) and `zt.authorsShort` (formatted short string, e.g. "Smith et al.").

### The filename template [#v1-filename]

The filename template is a template file (`zotlit-filename.eta.md`), not a setting string. The [one-pass conversion](/docs/how-to/migrate-v1-eta-templates#convert) later folds it into the `filename` key of your profile document's manifest. The v2 default adds `suffix()` for collision avoidance:

```eta
<%= zt.citationKey ?? zt.DOI ?? zt.title ?? zt.key %><%= suffix() %>
```

- `it.citekey` becomes `zt.citationKey` (canonical name; `zt.citekey` also works).
- The `.md` extension is no longer included. ZotLit appends it automatically.
- [`suffix()`](/docs/reference/templates/eta-syntax#suffix-filename-collision-guard) appends a random string only when the name collides with an existing note.

### Properties from `zt-field.eta.md` [#v1-frontmatter]

| v1 template line           | <UiLabel name={m.workbench_properties_name()} /> | <UiLabel name={m.workbench_properties_expression()} /> | <UiLabel name={m.workbench_properties_merge()} />         |
| -------------------------- | ------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------------- |
| `title: "<%= it.title %>"` | `title`                                          | `zt.title`                                             | <UiLabel name={m.workbench_properties_merge_replace()} /> |
| `authors: ...`             | `authors`                                        | `zt.authors \| map: "fullName" \| join: ", "`          | <UiLabel name={m.workbench_properties_merge_replace()} /> |
| `year: "<%= it.date %>"`   | `year`                                           | `zt.date \| date: "%Y"`                                | <UiLabel name={m.workbench_properties_merge_replace()} /> |
| `tags: ...`                | `tags`                                           | `zt.tags \| map: "name" \| join: ", "`                 | <UiLabel name={m.workbench_properties_merge_append()} />  |

YAML escaping is handled automatically.

### Whitespace [#v1-whitespace]

<Callout type="info" title="Whitespace change from v1">
  v1 defaulted `autoTrim` to `[false, "nl"]` (trim one newline after tags). v2 defaults to `[false, false]` (preserve all whitespace). Migrated templates may produce extra blank lines where `%>` previously consumed a trailing newline. Add `-%>` to the closing side of tags that need the old trim behavior. See [Whitespace control](/docs/reference/templates/eta-syntax#whitespace-control).
</Callout>

## `renderAnnotation()`: annotation rendering [#render-annotation]

Renders one annotation, available as `zt` inside the annotation template.

```eta
<%~ renderAnnotation(annotation) %>
```

The annotation argument is required. A missing or null value raises an error.

For an annotation value, the equivalent native Eta syntax is:

```eta
<%~ include("annotation", annotation) %>
```

In a Literature Note profile, the shortcut and native calls to `annotation` use the profile's Annotation Section. This required final section starts after the exact standalone line `--- zotlit:annotation ---` and continues to the end of the document. It uses the profile's language and can be empty.

Calls from shared partials use the calling profile's section, with isolated annotation data. Direct annotation insertion and Imported Notes use the same section for their applicable profile. Outside profile rendering, the shortcut keeps the existing named-template lookup.

## `include()`: composing templates

`include()` renders another template inline. Pass the template name and an optional data argument:

```eta
<%~ include("annotation", annotation) %>
<%~ include("content", zt) %>
```

The data argument becomes the child template's `zt` variable, direct passthrough not merged with the parent's data. When omitted, the child inherits the parent's `zt`.

The name resolves to a registered template, not to a file path. During profile rendering, `"annotation"` selects the profile's Annotation Section.

### Calling a partial [#calling-a-partial]

A partial is called by its name, with the data it needs as the second argument:

```eta
<%~ include("authors", zt) %>
```

The argument becomes the partial's `zt`. Omit it and the partial inherits the caller's `zt`. Completion inside `include("` lists every partial in the vault, and accepting a name writes the whole call, `zt` argument included. A call you have already given arguments keeps them, and only the name is replaced.

### The `content` include

When `include("content", zt)` is called from the note template and a `content` template file in your vault backs it, ZotLit wraps the output with managed-region markers (`%%zt-managed%%` / `%%/zt-managed%%`). These markers never appear in a template document. They are injected at render time. The built-in `content` template renders without markers.

## `bq()`: blockquote helper [#bq-blockquote-helper]

Wraps its content in a Markdown blockquote. Every line is prefixed with `> `. The content is trimmed. Consecutive blank lines inside the block collapse into a single bare `>`.

```eta
<% bq(() => { %>
[!note] Page <%= zt.pageLabel %>

<%= embed(zt.imgLink) %><%= zt.text %>
<% if (zt.comment) { %>

<%= zt.comment %>
<% } %>
<% }) %>
```

Rendered output:

```markdown
> [!note] Page 42
>
> ![[excerpt.png]]The highlighted passage
>
> My thoughts on this
```

`bq()` must appear in a `<% %>` execute tag. It captures all output produced inside the callback, trims the result, prefixes each line with `> ` (empty lines become bare `>`), collapses consecutive bare `>` lines into one, and writes the result to the output.

When the captured content is empty, `bq()` renders a lone `>`.

## `embed()`: embed helper

Turns a link helper into a Markdown embed by prefixing `!`. Returns `""` when the link is `null`, `undefined`, or renders empty.

```eta
<%= embed(zt.imgLink) %>
<%= embed(zt.imgLink, "alt text") %>
```

Signature: `embed(link, alias?, subpath?)`

| Input                                    | Output               |
| ---------------------------------------- | -------------------- |
| `zt.imgLink` renders `"[[excerpt.png]]"` | `"![[excerpt.png]]"` |
| `zt.imgLink` is `null`                   | `""`                 |

For image and ink annotations, `embed(zt.imgLink)` uses the prepared note image or returns an unavailable-image explanation and source link. It preserves that fallback text without adding `!`. Image preparation runs before the template, so the template executes once per render. Preview rendering creates no vault image files.

## `pandocCite()`: Pandoc Citation source [#pandoc-cite]

Formats a Citation Item array as Pandoc Citation source. Pass `zt.citations` directly to the helper.

```eta
<%= pandocCite(zt.citations) %>
<%= pandocCite(zt.citations, "prefer-author-in-text") %>
```

Signature: `pandocCite(citations, form?)`

The optional form is `"normal"` by default.

| Form                      | Output for one item | Description                                                                                                                                            |
| ------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `"normal"`                | `[@smith2024]`      | Produces a bracketed Citation Cluster.                                                                                                                 |
| `"prefer-author-in-text"` | `@smith2024`        | Produces an Author-in-text Citation when the first retained item has no prefix and does not suppress the author. Otherwise, produces a normal cluster. |

The helper handles all Citation Item properties used in Pandoc source:

| Input                                             | Output                     |
| ------------------------------------------------- | -------------------------- |
| Locator `"3"` with `labelShort` `"p."`            | `[@smith2024, {p. 3}]`     |
| Prefix `"see "` and suffix `", note 4"`           | `[see @smith2024, note 4]` |
| `suppressAuthor` set to `true`                    | `[-@smith2024]`            |
| Citation key `"KX67D9YM?"`                        | `[@{KX67D9YM?}]`           |
| `"prefer-author-in-text"` with locator `"3"`      | `@smith2024 [{p. 3}]`      |
| `"prefer-author-in-text"` with prefix `"see "`    | `[see @smith2024]`         |
| Empty array or items with null citation keys only | `""`                       |

Items with a null citation key are omitted. The helper preserves the order of the remaining items and adds braces around complex citation keys when Pandoc requires them.

Input that cannot be represented without changing its citation structure raises a render error.

## `texCite()`: LaTeX citation command [#tex-cite]

Formats a Citation Item array as one LaTeX citation command. Pass `zt.citations` directly to the helper.

```eta
<%= texCite(zt.citations) %>
<%= texCite(zt.citations, "autocite") %>
```

Signature: `texCite(citations, command?)`

The optional command is `"cite"` by default. Write it without the backslash. A starred command such as `"autocite*"` is accepted.

| Command      | Output for one item    | Bibliography package    |
| ------------ | ---------------------- | ----------------------- |
| `"cite"`     | `\cite{smith2024}`     | LaTeX, natbib, BibLaTeX |
| `"autocite"` | `\autocite{smith2024}` | BibLaTeX                |

Every retained item joins one key list. The command carries one prenote and one postnote, and both come from the first retained item:

| Input                                             | Output                           |
| ------------------------------------------------- | -------------------------------- |
| Two items                                         | `\cite{smith2024,doe2023}`       |
| Locator `"3"` with `labelShort` `"p."`            | `\cite[p. 3]{smith2024}`         |
| Prefix `"see "`                                   | `\cite[see][]{smith2024}`        |
| Prefix `"see "` with locator `"3"`                | `\cite[see][p. 3]{smith2024}`    |
| Locator `"3"` with suffix `", note 4"`            | `\cite[p. 3, note 4]{smith2024}` |
| Empty array or items with null citation keys only | `""`                             |

Items with a null citation key are omitted, and the remaining items keep their order.

<Callout type="warn" title="The prenote form needs natbib or BibLaTeX">
  The LaTeX kernel's own `\cite` takes one optional argument. The two-argument
  `\cite[see][p. 3]{smith2024}` form above compiles under natbib or BibLaTeX,
  which redefine `\cite` to take both. A citation that carries no prefix emits
  at most one optional argument and works in a plain LaTeX document.
</Callout>

An affix reaches LaTeX as source, so a prefix of `\emph{see}` renders as emphasis. These inputs raise a render error instead:

- `suppressAuthor` set to `true`, which LaTeX has no general form for.
- A prefix, suffix, or locator on any item after the first, which has no slot.
- An empty citation key, or one that holds whitespace, a comma, or a TeX special character.
- A prefix, suffix, or locator whose braces do not balance, or which holds an unescaped `%`.

## `suffix()`: filename collision guard [#suffix-filename-collision-guard]

For the `filename` template only. Appends a random string when the generated filename collides with an existing note. When the name is free, it renders nothing.

```eta
<%= zt.citationKey ?? zt.DOI ?? zt.title ?? zt.key %><%= suffix() %>
```

- First note named `Smith2020` produces `Smith2020.md`.
- A second note that would also render `Smith2020` produces `Smith2020_a1b2c3.md`.

### Signature

```
suffix(length?, prepend?, append?)
```

| Parameter | Default | Constraints                 |
| --------- | ------- | --------------------------- |
| `length`  | `6`     | Integer, 1–64               |
| `prepend` | `"_"`   | Must not contain `:` or `%` |
| `append`  | `""`    | Must not contain `:` or `%` |

The affixes appear only on collision. On a free name, the entire expression (affixes included) renders nothing.

```eta
<%= zt.title %><%= suffix(10) %>
<%= zt.title %><%= suffix(6, "(", ")") %>
<%= zt.citationKey %><%= suffix(4, "-") %>
```

The random string uses an alphanumeric alphabet. On collision, ZotLit retries up to 5 times with fresh random strings.

## Link helpers [#link-helpers]

Links on the `zt` context are functions, not precomputed strings. Call them to render. Each accepts optional overrides:

```
linkHelper(alias?, subpath?)
```

- `alias`: display text for the link. Omit to use the default (filename or note title).
- `subpath`: a `#`-fragment appended to the target, e.g. `"#heading"` or `"#page=3"`.

| Helper            | Available on                  | Default subpath               | Returns                                                                                    |
| ----------------- | ----------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------ |
| `zt.noteLink()`   | item context                  | none                          | Markdown link to the item's literature note, or `null`                                     |
| `note.noteLink()` | each `zt.notes[]` entry       | none                          | Link to the imported note, or else a `zotero://` link that opens the note in Zotero        |
| `a.fileLink()`    | each `zt.attachments[]` entry | none                          | Attachment file link                                                                       |
| `zt.fileLink()`   | annotation context            | `#page=N&zt-annotation=<key>` | Deprecated. Attachment link anchored to the annotation's page and to the annotation itself |
| `zt.imgLink()`    | annotation context            | none                          | Excerpt-image link, unavailable-image explanation and source link, or `null`               |

```eta
<%= zt.attachments[0].fileLink() %>
<%= zt.attachments[0].fileLink("Open the PDF") %>
<%= zt.noteLink("See notes", "#Summary") %>
```

`zt.noteLink()` returns `null` when the literature note path is unresolvable (collision, recursive resolution, or template error). `zt.imgLink` is `null` for annotation types other than `image` and `ink`. An unavailable image uses the [excerpt fallback](/docs/reference/excerpt-images#import-outcomes).

### The durable annotation link [#annotation-backlink]

`zt.backlink` on the annotation context is the durable link to the annotation. It is Zotero's own open link, and it names the attachment and the annotation by their Zotero keys:

```
zotero://open/library/items/<attachmentKey>?annotation=<annotationKey>&page=<pageLabel>
```

A group library has `groups/<groupID>` in place of `library`. `page` is the printed page label, and the link omits it when the annotation has none.

`zt.backlink` is a plain URL string, not a helper. Do not call it; wrap it in a Markdown link yourself, as the [default annotation template](/docs/reference/templates/defaults#annotation-template) does:

```eta
<%= zt.pageLabel ? `Page [${zt.pageLabel}](${zt.backlink})` : `[Zotero](${zt.backlink})` %>
```

<Callout type="warn">
  The annotation `zt.fileLink()` is deprecated. It holds the file path of the
  computer that rendered the note, so it opens nothing on another computer or
  after the Zotero storage folder moves. Use `zt.backlink` instead.
  `zt.fileLink()` stays available for the current release line. The attachment
  `a.fileLink()` is not deprecated.
</Callout>

While <SettingsPath page={m.settings_page_reader()} setting={m.settings_reader_open_file_links_name()} /> is on, which is the default, clicking a durable annotation link opens the PDF [in Obsidian](/docs/how-to/open-pdf-in-obsidian), with the annotation selected. When this computer does not hold the PDF, Zotero opens the link instead. See [Zotero open links](/docs/reference/protocol-links#zotero-open-links) for every case. A file link to a PDF in your Zotero library also opens in Obsidian, and an older `zt.fileLink()` link still opens on the annotation's page.

## Template document naming [#template-document-naming]

A template document sits directly inside the folder set by <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} />. The scan is flat, and the filename prefix alone says what a document is: `zotlit-profile.<slug>.md` for a profile, `zotlit-citation.md` for the citation text, and `zotlit-partial.<name>.md` for one partial. See [Template document naming](/docs/reference/templates/syntax#template-document-naming) for the full rule and the reserved partial names.

An Eta document declares its language in a YAML manifest at the top of the file, before the source:

```md
---
language: eta
---

<%= zt.title %>
```

`language` is the manifest's only legal key, and its values are `liquid` and `eta`. A document with no manifest is Liquid, so every Eta citation document and Eta partial needs this block. Switch a document between the two from the Template Workbench View's pane menu, with <UiLabel name={m.template_workbench_change_language()} />; it rewrites the manifest key and leaves the source as written.

A profile document declares its language with the `language` key of its own manifest.

## No async

ZotLit renders templates synchronously. `async`/`await` is not available inside Eta templates.
