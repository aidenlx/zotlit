ZotLit 为每种模板类型均提供了开箱即用的内置 Liquid 默认模板。本页完整展示了各个默认模板的源码，详细说明了其渲染结果，并指明了在您执行“自定义”后承载该模板的具体文档。

配置方案（Profile）文档整合承载了笔记模板、受管内容模板、笔记文件名模板以及标注格式模板。引文文本则属于单独的独立文档。在您生成自定义文档之前，ZotLit 均按下方所示的内置文本进行渲染。关于如何生成文档，请参阅[自定义模板](/docs/how-to/customize-a-template)。

## 笔记模板（Note template）

在配置方案文档中：位于标注区域（Annotation Section）上方的笔记正文部分。

```liquid
# {{ zt.title }}

[Zotero]({{ zt.backlink }}) {{ zt.attachments | map: "fileLink" | compact | join: " " }}

{% render "content" with zt as zt %}
```

| 代码行                                                            | 渲染生成的内容                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `# {{ zt.title }}`                                                | 条目标题，呈现为 H1 一级标题。                                                                                                                                                                                                                                                                                                                                                                             |
| `[Zotero]({{ zt.backlink }})`                                     | 指向 Zotero 中对应条目的 Markdown 深度链接（deep link）。                                                                                                                                                                                                                                                                                                                                                  |
| `{{ zt.attachments \| map: "fileLink" \| compact \| join: " " }}` | 指向每个可解析附件的直接 `file://` 链接。对于 Zotero 外部链接文件，该链接指向其在外部的原始位置。这些链接绝不会将文件复制到仓库中。当开启默认的 <UiLabel name={m.settings_reader_open_file_links_name()} /> 时，指向您 Zotero 库中 PDF 的链接将直接在 [Obsidian 的 PDF 阅读器](/docs/how-to/open-pdf-in-obsidian)中打开。`map` 用于提取链接，`compact` 用于过滤剔除无效项，`join` 则以空格将它们分隔排布。 |
| `{% render "content" with zt as zt %}`                            | 嵌入调用 `content` 模板，并传入完整的条目上下文数据。                                                                                                                                                                                                                                                                                                                                                      |

## 内容模板（Content template）

在配置方案文档中：位于 `{% managed %}` 与 `{% endmanaged %}` 受管块之间的正文部分。

```liquid
{% if zt.notes.size > 0 %}
## Notes

{% for note in zt.notes -%}
- {{ note.noteLink }}
{% endfor %}
{% endif %}
{% if zt.annotations.size > 0 %}
## Annotations

{% for annotation in zt.annotations %}
{% render_annotation annotation %}
{% endfor %}
{% endif %}
```

`content` 模板是其渲染输出会被严格包裹在受管区域（managed-region）标记之内的核心模板。运行 <Command inline name={m.command_update_note_name()} /> 时将专门重新渲染这部分内容，同时使笔记正文的其他部分完好保留。

| 区域        | 渲染生成的内容                                                                                |
| ----------- | --------------------------------------------------------------------------------------------- |
| Notes       | 关联子笔记的无序列表。每个 `note.noteLink` 都会解析为指向对应已导入笔记文件的 Obsidian 双链。 |
| Annotations | 通过 `annotation` 模板渲染的每条标注（见下文）。                                              |

这两个区域仅在对应数组非空时显示。

`render_annotation` 标签将每条标注作为 `zt` 传入。等效的原生语法见[标注渲染](/docs/reference/templates/syntax#render-annotation)。

## 标注模板 [#annotation-template]

在配置方案文档中：位于独占一行的 `--- zotlit:annotation ---` 之后，即文档末尾的标注区域。

```liquid
{% bq %}
[!note] Page {% if zt.pageLabel %}{{ zt | file_link: zt.pageLabel | default: zt.pageLabel }}{% endif %}

{{ zt.imgLink | embed }}{{ zt.text }}
{% if zt.comment %}

{{ zt.comment }}
{% endif %}
{% endbq %}
```

第 42 页上的一条标注包含图片摘录、高亮文本和评论，其渲染结果如下：

```markdown
> [!note] Page [42](file:///Users/me/Zotero/storage/ABCD2345/paper.pdf#page=42&zt-annotation=ANNX2345)
>
> ![[excerpt.png]]The highlighted passage
>
> My thoughts on this
```

| 元素       | 来源                                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 提示框类型 | `[!note]`：Obsidian 提示框。将 `note` 改为 `quote`、`info` 或其他支持的类型，即可更改样式。                                                                         |
| 页码标签   | 提示框标题中的 `{{ zt \| file_link: zt.pageLabel }}`：链接到附件文件的页码标签。选择该链接会打开 PDF 的对应页面并选中此标注。若无法解析文件位置，标签保持为纯文本。 |
| 图片       | `{{ zt.imgLink \| embed }}`：嵌入已准备好的图片或手写摘录。刷新失败时保留经过验证的旧图片，或返回图片不可用的说明及来源链接。其他标注类型输出 `""`。                |
| 文本       | `{{ zt.text }}`：高亮文本。                                                                                                                                         |
| 评论       | `{{ zt.comment }}`：您添加的批注，仅在有内容时渲染。                                                                                                                |

`{% bq %}` / `{% endbq %}` 块标签为每行添加 `> ` 前缀，并将连续空行合并为仅含一个 `>` 的行。

## 引文文本 [#citation-text]

位于模板文件夹中的独立文档 `zotlit-citation.md`。同一个模板处理两种引文插入操作，`zt.variant` 表示您使用了哪一种：

```liquid
{% if zt.variant == "alt" %}
  {{ zt.citations | pandoc_cite: "prefer-author-in-text" }}
{% else %}
  {{ zt.citations | pandoc_cite }}
{% endif %}
```

`zt.variant` 的取值为 `"main"` 或 `"alt"`。在引文建议列表或插入对话框中按 Enter 对应 `"main"`；按 Shift+Enter，或在建议列表的查询末尾加 `/`，对应 `"alt"`。它标识您的操作，由此模板决定每种操作的渲染结果。参见[引文变体](/docs/reference/templates/data#citation-variant)。

内置默认模板的 `else` 分支生成方括号包裹的引文组，例如 `[@smith2024, {p. 62}; -@doe2021]`。`"alt"` 分支请求 Pandoc 使用作者融入正文的形式；若保留的第一个条目带有前缀或隐藏了作者，则回退为方括号引文组。

| 输入                                         | `"main"`                | `"alt"`                                      |
| -------------------------------------------- | ----------------------- | -------------------------------------------- |
| 单个文献引用标识（citation key） `smith2024` | `[@smith2024]`          | `@smith2024`                                 |
| 两个文献引用标识                             | `[@a2020; @b2021]`      | 第一个条目融入正文，其余条目置于后续方括号中 |
| 定位信息 `62`                                | `[@smith2024, {p. 62}]` | `@smith2024 [{p. 62}]`                       |
| `suppressAuthor`                             | `[-@smith2024]`         | `[-@smith2024]`, 引文组                      |
| 前缀 `see `                                  | `[see @smith2024]`      | `[see @smith2024]`, 引文组                   |
| 没有文献引用标识的条目                       | 从输出中省略            | 从输出中省略                                 |

`pandoc_cite` 过滤器在两个分支中的行为一致：

| 行为             | 说明                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 前缀与后缀       | 保留每个条目的 `prefix` 和 `suffix`。                                                                                       |
| 隐藏作者         | `suppressAuthor` 为 true 时生成 `-@key`。                                                                                   |
| 定位信息         | 根据 `labelShort` 和 `locator` 生成明确的定位信息，例如 `, {p. 62}`。                                                       |
| 复杂文献引用标识 | 在 Pandoc 要求时添加花括号。例如，`KX67D9YM?` 渲染为 `@{KX67D9YM?}`。                                                       |
| 缺少文献引用标识 | 省略 `item.citationKey` 为 null 的条目。数组为空或所有条目的文献引用标识均为 null 时不输出内容。                            |
| 形式             | `normal` 始终生成方括号引文组；`prefer-author-in-text` 仅在保留的第一个条目没有前缀且未隐藏作者时，生成作者融入正文的引文。 |

ZotLit 会将渲染后的引文规范化为行内形式：删除首尾空白，并将包含换行符的连续空白合并为一个空格。此处理适用于所有引文渲染位置：行内建议列表、命令面板选择器、标注字段 `zt.citation`、<UiLabel name={m.annot_view_menu_copy_citation()} />，以及笔记导入时的引文解析。

系统仅内置 Liquid 版本。同一模板的 Eta 写法如下：

```eta
<% if (zt.variant === "alt") { %>
  <%= pandocCite(zt.citations, "prefer-author-in-text") %>
<% } else { %>
  <%= pandocCite(zt.citations) %>
<% } %>
```

## 文件名模板 [#filename-template]

在配置方案文档中：位于 YAML manifest 的 `filename` 键下。模板工作台视图将其标为 <UiLabel name={m.workbench_name_filename_label()} />。

渲染结果用作新笔记路径中的名称部分。ZotLit 以此名称在配置方案的[文献笔记文件夹](/docs/reference/settings#literature-note-folder)中创建笔记。

```liquid
{{ zt.citationKey | default: zt.DOI | default: zt.title | default: zt.key }}{% suffix %}
```

| 元素           | 说明                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| 回退顺序       | `citationKey` > `DOI` > `title` > `key`。`default` 过滤器会跳过 nil 和空值。 |
| `{% suffix %}` | 仅在渲染的文件名与已有笔记重名时追加一段短随机字符串。没有冲突时输出 `""`。  |
| 单行           | 渲染结果合并为一行，并删除所有换行符及首尾空白。                             |
| 扩展名         | 系统自动追加 `.md` 扩展名；模板只生成文件基本名称。                          |

<Callout type="info" title="笔记名称中的子文件夹">
  渲染名称中的正斜杠（`/`）会在文献笔记文件夹下创建子文件夹。例如，文件夹为
  `literatures`，名称为 `2024/Smith2020`，则笔记路径为
  `literatures/2024/Smith2020.md`。
</Callout>

## 实时重新编译 [#live-recompilation]

编辑仓库中的模板文档时，文件监听器会触发实时重新编译。更改立即生效，无需重新加载插件。将文档移至废纸篓后，其中的模板会恢复为上文所示的内置默认值。
