This reference lists every ZotLit setting, its default, dependencies, and storage scope.

Open settings from <SettingsPath />. The sections below follow the order of the settings tab: the main page first, then each sub-page.

Settings moved in ZotLit 2.2.0. [Where settings moved](#moved) maps each old location to its new one.

## Main page [#main]

The main page opens when you select ZotLit in Obsidian's settings. It holds the default Profile's settings. New literature notes use this Profile when no other Profile is selected.

The top of the page links to the release notes, the documentation, the community, and the bug report form. Reminders appear in the same place.

| Label                                                          | Key                         | Control                                                                                                   | Default                                                           | Dependency             | Storage |
| -------------------------------------------------------------- | --------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ---------------------- | ------- |
| <UiLabel name={m.settings_profile_folder_name()} />            | `note.literature-folder`    | Folder picker                                                                                             | `literatures`                                                     | None                   | Synced  |
| <UiLabel name={m.settings_note_import_folder_name()} />        | `note.import-folder`        | Folder picker                                                                                             | `zotero_notes`                                                    | None                   | Synced  |
| <UiLabel name={m.settings_citation_references_style_name()} /> | `citation.references-style` | Dropdown (lists installed styles)                                                                         | <UiLabel name={m.settings_citation_references_style_default()} /> | Zotero style directory | Synced  |
| <UiLabel name={m.settings_profile_document_name()} />          | (the Profile document)      | <UiLabel name={m.settings_profile_edit()} /> and <UiLabel name={m.settings_profile_document_restore()} /> | <UiLabel name={m.settings_profile_document_builtin()} />          | None                   | Synced  |

Three of these rows are bindings: the two note folders and the citation and references style. The Imported notes page holds the other two bindings. ### Template conversion reminder [#template-conversion-reminder]

A vault whose 2.1 template files still wait for conversion keeps one reminder at the top of the page. The row is <UiLabel name={m.welcome_template_conversion_title()} /> and its one button is <UiLabel name={m.settings_template_conversion_reminder_action()} />, which opens the conversion in the Welcome view. Its description reads:

> <UiLabel
>   name={m.welcome_template_conversion_body({
>     path: "templates/zotlit-profile.default.md",
>   })}
> />

The path is `zotlit-profile.default.md` inside the folder set by <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} />. See [Migrate from 2.1 templates](/docs/how-to/migrate-from-2.1-templates).

### Literature note folder [#literature-note-folder]

Where ZotLit creates literature notes. A Profile can set its own folder, and a note stays in the folder of the Profile it was created with.

### Imported note folder [#imported-note-folder]

Where ZotLit saves notes imported from Zotero. A Profile can set its own folder. ZotLit creates the folder when it is absent, and gives each filename a short random suffix so every imported note keeps its own file.

See [Import Zotero notes](/docs/how-to/import-zotero-notes) for the import workflow.

### Citation and references style [#citation-style]

CSL style used to format in-text citations and the references sidebar. Install and manage styles in Zotero.

The dropdown stores the CSL style ID. Default uses ZotLit's embedded style. ZotLit uses the embedded style only while Default is selected.

An unavailable style remains selected. In-text citations stay native, and the References Sidebar shows its minimal list. The row then reads <UiLabel name={m.settings_citation_references_style_warning()} />.

The first formatting attempt shows <UiLabel name={m.notice_citation_style_missing()} /> once per plugin lifecycle. Its <UiLabel name={m.notice_citation_style_missing_action()} /> action opens ZotLit settings.

A note can select its own style with the `zotlit-csl` property. The property takes the CSL style ID of a style installed in Zotero. Every other note keeps the vault selection.

That note uses its own style for in-text citations, the <UiLabel name={m.references_view_name()} /> Sidebar, the <UiLabel name={m.settings_citation_hover_action_popover()} />, and the copied bibliography. The built-in export dialog opens on the same style. The dialog holds a style you pick there for that run alone, and never writes it to the note.

A note whose `zotlit-csl` names an unavailable style stops instead of using the vault selection. Its citations stay native. The <UiLabel name={m.references_view_name()} /> Sidebar shows its minimal list under the banner <UiLabel name={m.references_document_style_failed_title()} />, and the copy action stays unavailable.

Built-in export of that note opens on the same unavailable style and stops with a notice, unless you pick an available style in the dialog.

An empty `zotlit-csl` property stops the note the same way, and its built-in export stops before the dialog opens. Remove the property to use the vault selection again.

### Template document [#template-document]

The document that renders a literature note: its filename, its properties, and its body.

The main page exposes it through one row, <UiLabel name={m.settings_profile_document_name()} />, whose description reads <UiLabel name={m.settings_profile_document_desc()} />. <UiLabel name={m.settings_profile_edit()} /> opens the Profile in the Template Workbench View and creates the document from the built-in Literature Note Template while it does not exist yet.

Once the document exists, the row also offers <UiLabel name={m.settings_profile_document_restore()} />, which moves it to Obsidian's configured trash and returns the Profile to the built-in template.

### Properties [#properties]

The properties ZotLit writes into every literature note it creates and updates.

The properties live in the Profile's template document, edited through the same <UiLabel name={m.settings_profile_document_name()} /> row on the main page. While the Profile uses the built-in template, ZotLit writes its built-in field list. Creating the document starts from the fields the Profile already writes, so no field is lost.

See [Configure frontmatter properties](/docs/how-to/configure-frontmatter-properties) for what each field does.

### Partials [#partials]

A partial is a piece of template text that any template renders by name, so several Profiles can share it. The list sits below the Profile list, and it covers the whole vault rather than one Profile.

Until you add one, the list reads <UiLabel name={m.settings_partials_empty_desc()} /> Its header carries one action, <UiLabel name={m.settings_partial_add()} />, which asks for a name and creates the file.

Each partial has one row with its name and its vault path:

| Action                                                                                         | Effect                                                                     |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |

| <UiLabel name={m.workbench_more_actions()} /> > <UiLabel name={m.settings_partial_delete()} /> | Moves the partial's file to Obsidian's configured trash after you confirm. |

The delete confirmation reads <UiLabel name={m.settings_partial_delete_confirm_title()} /> with the body <UiLabel name={m.settings_partial_delete_confirm_body({ path: "…" })} /> It rewrites no caller, so every template that calls the deleted partial reports a missing partial afterwards.

A partial file whose name belongs to another ZotLit template registers nothing and gets its own row instead:

### Profile Match [#profile-match]

A Profile Match is the set of conditions that select a Profile automatically for new literature notes. Each condition tests a Zotero item's Library, item type, Tags, or Collections, and the Match lives in the Profile's template document. The default Profile is the fallback: it has no Profile Match.

Nothing on this page edits a Match. A Profile row reports the status word from the table above, and the row's own controls act on the Profile rather than its conditions. Change the conditions in the Profile's document, on the <UiLabel name={m.workbench_tab_match()} /> tab of the Template Workbench View. See [Use different templates](/docs/how-to/use-different-templates) for that procedure, and [Profile Match](/docs/reference/templates/profile-match) for the condition language, its operators, and the Collection path rules.

ZotLit also spells conditions out in words where it presents a Match: the import consent dialog describes an incoming Match as <UiLabel name={m.settings_profile_match_item_type_is({ type: "…" })} />, <UiLabel name={m.settings_profile_match_library_is_not({ library: "…" })} />, <UiLabel name={m.settings_profile_match_tags_contain({ tags: "…" })} />, or <UiLabel name={m.settings_profile_match_collections_inside({ collections: "…" })} />, joined by `and` or `or` as the Match requires, with a nested group written <UiLabel name={m.settings_profile_match_summary_group({ conditions: "…" })} />.

ZotLit skips a Profile Match that it cannot evaluate. Causes include invalid expression syntax, unsupported fields or functions, incorrect arguments, an unknown Library, or an unknown item type. The Profile row then shows <UiLabel name={m.settings_profile_match_status({ state: "unevaluable" })} />, and the Match tab reports the problem in place of a result. Other Profiles continue to take part in automatic selection. A template document that ZotLit cannot load appears in <UiLabel name={m.settings_profile_excluded_heading()} /> and takes no part in selection.

#### Selection for new notes

When exactly one Profile Match fits an item, ZotLit uses that Profile and creates the literature note directly. The creation notice reports the Profile, the match reason, and the note path.

When two or more Profiles match, the Profile picker opens with the matching candidates identified. Select a Profile for the current operation. Exclusions in the Match conditions can prevent future overlaps.

When none matches, the picker preselects <UiLabel name={m.settings_profile_default_name()} />. ZotLit uses it directly when no other Profile exists.

Selection follows this order:

1. Your manual choice for the current operation.
2. A Profile supplied by a command or a link from ZotLit Companion, the Zotero add-on.
3. The one matching Profile.
4. The default Profile.

Once a creation preview is ready, its Profile and destination stay fixed for that operation. Changes to Match conditions apply to the next operation.

In a batch, ZotLit selects a Profile separately for each item. A shared fallback choice covers unmatched or overlapping items; items with one matching Profile keep that selection. <UiLabel name={m.batch_profile_override_all()} /> applies your choice to every new note in the batch.

Existing notes keep their recorded Profile when Match conditions change. The changes apply to new notes.

### Share and import [#profile-share-import]

The <UiLabel name={m.settings_profile_share()} /> dialog and import consent dialog control whether a Profile carries its Match conditions:

| Control                                             | Default | Effect                                                                                                                    |
| --------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------- |
| <UiLabel name={m.profile_share_include_match()} />  | On      | Includes the Profile Match in the shared copy or file. Turning it off omits the Profile Match from that output.           |
| <UiLabel name={m.profile_import_include_match()} /> | On      | Saves the incoming Profile Match with the imported Profile. Turning it off imports the Profile for manual selection only. |

The import consent dialog describes the incoming Match conditions in words. When the incoming Profile has no Profile Match, the dialog shows <UiLabel name={m.profile_match_absent()} /> and hides <UiLabel name={m.profile_import_include_match()} />.

Library references, Collection paths, and Tag names stay as written during sharing and import. Review the imported conditions against your own Libraries, Collections, and Tags on the <UiLabel name={m.workbench_tab_match()} /> tab of the Template Workbench View.

### Citation text [#citation-templates]

One row, after the <UiLabel name={m.settings_citation_references_heading()} /> group. <UiLabel name={m.settings_citation_text_name()} />: <UiLabel name={m.settings_citation_text_desc()} /> It covers both citation gestures; the template itself decides what the main and the alternate gesture render.

A second line under the description names the document. While the vault holds no citation document, that line reads <UiLabel name={m.settings_template_using_default()} />; once the document exists, it is the document's vault path. The document is `zotlit-citation.md` in the folder set by <SettingsPath page={m.settings_page_advanced()} setting={m.settings_template_folder_name()} />.

The row carries two icon-only buttons, whose names below are their tooltips:

| Button                                             | Effect                                                                                                                                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <UiLabel name={m.settings_citation_text_open()} /> | Opens the document in the Template Workbench View. With no document in the vault, it first creates `zotlit-citation.md` from the built-in citation text. |
| <UiLabel name={m.settings_template_reset()} />     | Moves the document to Obsidian's configured trash. Destructive, and present only once the document exists.                                               |

#### Library scope [#library-scope]

The libraries ZotLit uses for item search, citation key resolution, and library-wide commands. Everything that already names one item, note, or library keeps that exact target: a menu entry or link from Zotero runs against the library it came from, and a literature note stays tied to its own item.

<UiLabel name={m.settings_library_scope_all()} /> follows your Zotero database.
A group library you join later is in scope at once, read-only groups included,
and a group you leave drops out.

<UiLabel name={m.settings_library_scope_selected()} /> stays exactly as you set
it. A group library you join later stays out of scope until you add it.

<UiLabel name={m.settings_library_scope_add()} /> offers the libraries you have
not selected yet, and each row's delete action removes one. The last remaining
row has no delete action, so the list is never empty.

Switching to <UiLabel name={m.settings_library_scope_selected()} /> starts at <UiLabel name={m.settings_library_scope_personal()} />. Switching to <UiLabel name={m.settings_library_scope_all()} /> discards the list you had.

ZotLit stores each selection as a stable reference: <UiLabel name={m.settings_library_scope_personal()} /> as itself, a group library by its Zotero group ID. Group names and Zotero's internal library numbers are never stored, so a renamed group keeps its place in the list and shows its current name.

#### An unavailable library [#unavailable-library]

A selected group can be missing from the connected Zotero database, because you left the group or because you connected a different Zotero data directory. It keeps its place in the list and shows as **Group `{ID}`** with the note <UiLabel name={m.settings_library_scope_unavailable()} /> Rejoin the group to restore its name, or delete the row to drop it.

Search, citation key resolution, and library-wide commands run over the libraries that are available. A library-wide command states how many selected libraries it had to skip.

#### While the database is unavailable [#database-unavailable]

ZotLit lists your libraries from the connected Zotero database. While that database is unreadable, the library scope controls are disabled and read <UiLabel name={m.settings_library_scope_db_unavailable()} />.

Your saved scope is untouched. See [Fix Zotero changes that do not appear](/docs/how-to/fix-stale-data) for the connection itself.

#### Recovery from an invalid scope [#invalid-scope]

ZotLit can fail to read a saved scope, after an edited `data.json` or a vault synced from a newer ZotLit. It keeps the broken value on disk rather than overwriting it, and an unrelated settings change leaves that value in place.

ZotLit shows <UiLabel name={m.notice_library_scope_invalid()} /> as a notice once, marks the setting with a standing warning, and searches <UiLabel name={m.settings_library_scope_personal()} /> alone until you repair the setting. The first change you make here writes over the broken value and clears both warnings.

<Callout type="info" title="What an upgrade sets">
  An upgrade from an earlier ZotLit version starts at
  <UiLabel name={m.settings_library_scope_selected()} /> with
  <UiLabel name={m.settings_library_scope_personal()} />, whatever library you
  had selected before. Widen the scope here to search your group libraries. A
  fresh installation starts at <UiLabel name={m.settings_library_scope_all()} />
  .
</Callout>

### Approved folders

The folders ZotLit may copy attachments from, beyond Zotero's own storage folder, its annotation cache, and the linked-attachment base folder you set in Zotero. This setting protects imports of Zotero linked files. A linked file stays in an external folder instead of being copied into Zotero storage. See [Zotero's guide to linked files](https://www.zotero.org/support/attaching_files#adding_linked_files).

This approval applies to imported content such as annotation images and images embedded in Child Notes. The ordinary attachment links in a Literature Note point to the original files and do not copy them.

When imported content is outside all approved locations, ZotLit uses a `file://` URI. A notice reports how many files it skipped, lists the unapproved source folders, and links to ZotLit settings.

Actions: <UiLabel name={m.settings_attachment_approved_add()} /> (opens a folder picker), and delete on each row.
