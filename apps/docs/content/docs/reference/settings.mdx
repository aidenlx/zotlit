This reference lists every ZotLit setting, its default, dependencies, and storage scope.

Open settings from <SettingsPath />. The sections below follow the order of the settings tab: the main page first, then each sub-page.

Settings moved in ZotLit 2.1. [Where settings moved](#moved) maps each old location to its new one.

## Main page [#main]

The main page opens when you select ZotLit in Obsidian's settings. It holds the settings of the default Profile, the one every new literature note uses until you choose another.

The top of the page links to the release notes, the documentation, the community, and the bug report form. Reminders appear in the same place, such as the template conversion reminder.

### Literature note folder [#literature-note-folder]

Where ZotLit creates literature notes. A Profile can set its own folder, and a note stays in the folder of the Profile it was created with.

### Citation and references style [#citation-style]

CSL style used to format in-text citations and the references sidebar. Install and manage styles in Zotero.

The dropdown stores the CSL style ID. Default uses ZotLit's embedded style. ZotLit uses the embedded style only while Default is selected.

An unavailable style remains selected. In-text citations stay native, and the References Sidebar shows its minimal list. The row shows this warning:

> This style isn’t installed in Zotero. Install it in Zotero or select another style.

The first formatting attempt shows this notice once per plugin lifecycle: "The selected citation and references style isn’t installed in Zotero." Its <UiLabel name={m.notice_citation_style_missing_action()} /> action opens ZotLit settings.

A note can select its own style with the `zotlit-csl` property. The property takes the CSL style ID of a style installed in Zotero. Every other note keeps the vault selection.

That note uses its own style for in-text citations, the <UiLabel name={m.references_view_name()} /> Sidebar, the <UiLabel name={m.settings_citation_hover_action_popover()} />, and the copied bibliography. The built-in export dialog opens on the same style. The dialog holds a style you pick there for that run alone, and never writes it to the note.

A note whose `zotlit-csl` names an unavailable style stops instead of using the vault selection. Its citations stay native. The <UiLabel name={m.references_view_name()} /> Sidebar shows its minimal list with this banner, and the copy action stays unavailable.

> This note's citation and references style is unavailable

Built-in export of that note opens on the same unavailable style and stops with a notice, unless you pick an available style in the dialog.

An empty `zotlit-csl` property stops the note the same way, and its built-in export stops before the dialog opens. Remove the property to use the vault selection again.

### Template document [#template-document]

The document that renders a literature note: its filename, its properties, and its body.

Until you customize it, the Profile uses ZotLit's built-in Literature Note Template and the row reads <UiLabel name={m.settings_profile_document_builtin_desc()} />. <UiLabel name={m.settings_template_eject()} /> writes a copy into your template folder and opens it, and the row then names that file.

Select <UiLabel name={m.settings_template_open()} /> to open the customized document in the editor. Select <UiLabel name={m.settings_profile_document_restore()} /> to move it to Obsidian's configured trash and return the Profile to the built-in template.

### Properties [#properties]

The properties ZotLit writes into every literature note it creates and updates.

The template document is their editor. While the Profile uses the built-in template, the row reads <UiLabel name={m.settings_profile_properties_builtin_desc()} />. The customized document starts from the fields the Profile already writes, so no field is lost.

See [Configure frontmatter properties](/docs/how-to/configure-frontmatter-properties) for what each field does.

## Literature note profiles [#profiles]

Open this page from <SettingsPath page={m.settings_page_profiles()} />. A Profile is a folder, a citation style, and a look that some notes use instead of the default.

The first row is <UiLabel name={m.settings_profile_default_name()} />, the default Profile: <UiLabel name={m.settings_profile_default_desc()} /> Its one action is <UiLabel name={m.settings_profile_share()} />.

The <UiLabel name={m.settings_profile_other_heading()} /> list holds every other Profile. Its header carries two buttons: **+** copies the default Profile's document, names it <UiLabel name={m.settings_profile_numbered_name({ number: 1 })} />, and opens it with the name selected so you can rename it. <UiLabel name={m.command_import_profile_name()} /> reads a Profile in from your clipboard or a file. Until you add one, the list reads <UiLabel name={m.settings_profile_empty_desc()} />.

Each added Profile has one row, which summarizes what differs from the default Profile and offers these actions:

| Action                                            | Effect                                                                        |
| ------------------------------------------------- | ----------------------------------------------------------------------------- |
| <UiLabel name={m.settings_template_open()} />     | Opens the Profile's document in the editor. The document is the editor.       |
| <UiLabel name={m.settings_profile_duplicate()} /> | Creates a copy of the Profile under a new name.                               |
| <UiLabel name={m.settings_profile_share()} />     | Copies the Profile, or saves it as a file, so someone else can read it in.    |
| <UiLabel name={m.settings_profile_delete()} />    | Moves the Profile document to Obsidian's configured trash after notes switch. |

A new Profile starts identical to the default one, so give it a folder or a citation style in its document — a Profile that differs from the default in nothing has no effect on any note.

Each Profile is edited in its own document. Deleting a Profile that notes still use asks where those notes go first.

### Automatic profile selection [#profile-selection-rules]

The <UiLabel name={m.settings_profile_rules_heading()} /> list on the same page holds the rules that choose a Profile for a **new** literature note from its Zotero item. Rules run from the top; the first rule that matches selects the Profile, so place specific rules above broad ones and drag rows to reorder them. Each rule has:

| Field                                                   | Meaning                                                                                                                                                                                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <UiLabel name={m.settings_profile_rule_scope()} />      | The Zotero libraries the rule applies to. A new rule starts at <UiLabel name={m.settings_library_scope_all()} />; restrict it to selected libraries to keep personal and group work apart.                                                                          |
| <UiLabel name={m.settings_profile_rule_conditions()} /> | Conditions that must all hold (<UiLabel name={m.settings_profile_rule_operator_is()} /> or <UiLabel name={m.settings_profile_rule_operator_is_not()} />) on the item's type, a collection, or a tag. A rule with no conditions matches every item in its libraries. |
| <UiLabel name={m.settings_profile_rule_target()} />     | The Profile a matching note is created under, including <UiLabel name={m.settings_profile_default_name()} />.                                                                                                                                                       |

Rules refer to a Profile by its stable ID, so renaming a Profile or its document keeps the rule. Rules stay in this vault: sharing or importing a Profile never carries them.

A collection condition lists every collection by its library and path, so two collections with the same name stay distinct, and it stores the collection's key together with its library, so renaming the collection keeps the rule. It matches items in the collection and in any of its subcollections; choose <UiLabel name={m.settings_profile_rule_collection_direct()} /> to match direct membership only. Matching reads every collection the item is filed in, whichever collection you opened it from. A collection that no longer exists in Zotero leaves the rule broken until you pick another one.

A tag condition matches the tag name exactly, including capitalization, and counts tags added by hand and tags Zotero added automatically alike.

When you create a note from the quick switcher, the Profile picker preselects the rule's Profile, names the rule, and shows the resulting path; choosing another Profile overrides the rule for that note only. An item that matches no rule preselects <UiLabel name={m.settings_profile_default_name()} />, or uses it directly when no other Profile exists. A rule that cannot be evaluated, or one whose Profile has been deleted, stops automatic selection and asks you to choose; the rule row shows the problem so you can repair it. Existing notes keep their recorded Profile — rules never move a note.

#### Library scope [#library-scope]

The libraries ZotLit uses for item search, citation key resolution, and library-wide commands. Everything that already names one item, note, or library keeps that exact target: a menu entry or link from Zotero runs against the library it came from, and a literature note stays tied to its own item.

<UiLabel name={m.settings_library_scope_all()} /> follows your Zotero database.
A group library you join later is in scope at once, read-only groups included,
and a group you leave drops out.

<UiLabel name={m.settings_library_scope_selected()} /> stays exactly as you set
it. A group library you join later stays out of scope until you add it.

<UiLabel name={m.settings_library_scope_add()} /> offers the libraries you have
not selected yet, and each row's delete action removes one. The last remaining
row has no delete action, so the list is never empty.

Switching to <UiLabel name={m.settings_library_scope_selected()} /> starts at <UiLabel name={m.settings_library_scope_personal()} />. Switching to <UiLabel name={m.settings_library_scope_all()} /> discards the list you had.

ZotLit stores each selection as a stable reference: <UiLabel name={m.settings_library_scope_personal()} /> as itself, a group library by its Zotero group ID. Group names and Zotero's internal library numbers are never stored, so a renamed group keeps its place in the list and shows its current name.

#### An unavailable library [#unavailable-library]

A selected group can be missing from the connected Zotero database, because you left the group or because you connected a different Zotero data directory. It keeps its place in the list and shows as **Group `{ID}`** with the note "Unavailable in this Zotero database." Rejoin the group to restore its name, or delete the row to drop it.

Search, citation key resolution, and library-wide commands run over the libraries that are available. A library-wide command states how many selected libraries it had to skip.

#### While the database is unavailable [#database-unavailable]

ZotLit lists your libraries from the connected Zotero database. While that database is unreadable, the library scope controls are disabled and show "Open the Zotero database to edit the library scope."

Your saved scope is untouched. See [Fix Zotero changes that do not appear](/docs/how-to/fix-stale-data) for the connection itself.

#### Recovery from an invalid scope [#invalid-scope]

ZotLit can fail to read a saved scope, after an edited `data.json` or a vault synced from a newer ZotLit. It keeps the broken value on disk rather than overwriting it, and an unrelated settings change leaves that value in place.

ZotLit shows the notice "Library scope is invalid" once, marks the setting with a standing warning, and searches <UiLabel name={m.settings_library_scope_personal()} /> alone until you repair the setting. The first change you make here writes over the broken value and clears both warnings.

<Callout type="info" title="What an upgrade sets">
  An upgrade from an earlier ZotLit version starts at
  <UiLabel name={m.settings_library_scope_selected()} /> with
  <UiLabel name={m.settings_library_scope_personal()} />, whatever library you
  had selected before. Widen the scope here to search your group libraries. A
  fresh installation starts at <UiLabel name={m.settings_library_scope_all()} />
  .
</Callout>

### Approved folders

The folders ZotLit may copy attachments from, beyond Zotero's own storage folder, its annotation cache, and the linked-attachment base folder you set in Zotero. This setting protects imports of Zotero linked files. A linked file stays in an external folder instead of being copied into Zotero storage. See [Zotero's guide to linked files](https://www.zotero.org/support/attaching_files#adding_linked_files).

This approval applies to imported content such as annotation images and images embedded in Child Notes. The ordinary attachment links in a Literature Note point to the original files and do not copy them.

When imported content is outside all approved locations, ZotLit uses a `file://` URI. A notice reports how many files it skipped, lists the unapproved source folders, and links to ZotLit settings.

Actions: <UiLabel name={m.settings_attachment_approved_add()} /> (opens a folder picker), and delete on each row. Approval applies to future imports. Re-import previously imported notes to copy attachments that were skipped.

<Callout type="info" title="Device Overrides">
  <UiLabel name={m.settings_attachment_approved_name()} /> are stored per device
  and never sync through the vault. Approving a folder on one computer grants
  nothing on another computer, and nothing in another vault.
</Callout>

### Recovery [#recovery]

| Label                                                     | Key  | Control                                                            | Default | Dependency | Storage |
| --------------------------------------------------------- | ---- | ------------------------------------------------------------------ | ------- | ---------- | ------- |
| <UiLabel name={m.settings_citation_index_reset_name()} /> | None | <UiLabel name={m.settings_citation_index_reset_action()} /> action | None    | None       | None    |
| <UiLabel name={m.settings_language_pack_reset_name()} />  | None | <UiLabel name={m.settings_language_pack_reset_action()} /> action  | None    | None       | None    |

<UiLabel name={m.settings_citation_index_reset_name()} /> clears the stored
citation key scans and reads your notes again. ZotLit keeps a scan per note so
that a restart only re-reads the notes that changed, and the scans are rebuilt
from your vault, so nothing in your vault changes. Use it when the references
sidebar disagrees with what a note cites. The rebuild runs in the background
after you confirm.

<UiLabel name={m.settings_language_pack_reset_name()} /> removes the downloaded
language packs stored on this device and forgets whether ZotLit already offered
them. The pack loaded at startup stays in place until you restart Obsidian,
after which ZotLit offers to install it again. Use it when translated text looks
wrong or outdated.

## Where settings moved [#moved]

ZotLit 2.1 reorganized the settings tab around the literature note. Every row keeps its name, so Obsidian's own settings search still finds a setting by the name you know.

| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Literature note folder**, on the Literature note profiles page     | The <UiLabel name={m.settings_profile_folder_name()} /> row on the main page                                                                                              |
