## Database

<Command name={m.command_refresh_db_name()} />

Reloads the Zotero database from disk. Use this after making changes in Zotero when automatic watching is disabled.

| Entry point     | Details          |
| --------------- | ---------------- |
| Command palette | Always available |

## Library-wide update

<Command name={m.command_update_all_notes_name()} />

Creates or updates a literature note for every item in every library of your [library scope](/docs/reference/settings#library-scope). Opens the same batch confirmation modal as a multi-item update from Zotero.

| Entry point     | Details                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command palette | Always available                                                                                                                                              |
| Zotero          | Right-click a library or collection > <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_collection_update_all.label"]()} /> |

The Zotero entry scopes the batch to the row you right-click: a library covers every item in it, a collection covers that collection and its subcollections. That target is exact, so it runs whether or not the row is in your library scope.

## Library-wide note import

<Command name={m.command_import_all_notes_name()} />

Imports all child notes attached to regular items and all standalone notes in every library of your [library scope](/docs/reference/settings#library-scope). Opens the same batch confirmation modal as a multi-note import from Zotero.

| Entry point     | Details                                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command palette | Always available                                                                                                                                                    |
| Zotero          | Right-click a library or collection > <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_collection_import_all_notes.label"]()} /> |

The Zotero entry scopes the import to the row you right-click, subcollections included. That target is exact, so it runs whether or not the row is in your library scope.

## Citations

<Command name={m.command_insert_citation_name()} />

Opens a modal to search every library in your [library scope](/docs/reference/settings#library-scope) and insert a Markdown citation at the cursor.

Insertion remains available independently of <UiLabel name={m.settings_citation_pandoc_citations_name()} />, <UiLabel name={m.settings_citation_wikilink_citations_name()} />, <UiLabel name={m.settings_citation_show_formatted_name()} />, and <UiLabel name={m.settings_citation_open_as_links_name()} />.

| Entry point      | Details                                                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command palette  | Active when an editor is open                                                                                                                                              |
| Editor suggester | Triggered by typing `[@` in the editor, or `@` at a word boundary when **`@` trigger** is on. Both settings are under <SettingsPath page={m.settings_page_citations()} />. |

### Citation navigation

The following commands open the recognized Pandoc citation under the cursor. They have no default hotkeys.

| Entry point     | Details                                                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Command palette | Active while <UiLabel name={m.settings_citation_pandoc_citations_name()} /> and <UiLabel name={m.settings_citation_open_as_links_name()} /> are on, with the cursor on a recognized citation key |
| Hotkey          | None by default; assign one under **Settings > Hotkeys**                                                                                                                                         |

### References and export

<Command name={m.command_open_references_view_name()} />

Opens the <UiLabel name={m.references_view_name()} /> Sidebar for the active note.

| Entry point     | Details          |
| --------------- | ---------------- |
| Command palette | Always available |

<Command name={m.command_show_cited_by_name()} />

Opens the <UiLabel name={m.cited_by_view_name()} /> Sidebar, which lists the notes in your vault that cite the active literature note. Each result is grouped by source file and links to the citation inside it. The sidebar follows the active note, so it asks for a literature note before it shows results.

| Entry point     | Details          |
| --------------- | ---------------- |
| Command palette | Always available |

<Command name={m.command_set_citation_presentation_name()} />

Opens a modal that sets the citation and references style and the document language of the active Markdown note. Confirming writes the `zotlit-csl` and `lang` properties of that note together. Choosing the vault style or the language reset removes the matching property.

| Entry point     | Details                              |
| --------------- | ------------------------------------ |
| Command palette | Active on a Markdown note            |
| More options    | The note's **More options** menu (⋮) |

<Command name={m.command_pandoc_export_name()} />

Opens the built-in export modal for the active Markdown note. The command requires the <UiLabel name={m.settings_citation_engine_name()} /> when you run it.

The export uses its own citation membership. Citation source, presentation, and navigation settings do not change exported content.

| Entry point     | Details                   |
| --------------- | ------------------------- |
| Command palette | Active on a Markdown note |

## Graph view

<Command name={m.command_open_citation_graph_name()} />

Opens Obsidian's graph view with the Citation Graph preset applied, where Obsidian's own **Open graph view** opens it: the tab you are in, or the new tab, split, or window a modifier-held invocation asks for. See [Explore citations in the graph view](/docs/how-to/explore-citations-in-graph) for what the preset sets.

| Entry point     | Details          |
| --------------- | ---------------- |
| Command palette | Always available |

<Command name={m.command_open_local_citation_graph_name()} />

Opens a local Citation Graph for the active note in a vertical split, grouped to the pane it was opened from so the graph follows that pane's file.

| Entry point     | Details          |
| --------------- | ---------------- |
| Command palette | Active on a note |

Neither command has a default hotkey. Where a Citation Graph cannot be opened, the command shows a notice naming the one thing to put right: the Graph view core plugin, the <UiLabel name={m.settings_citation_graph_name()} /> setting, or Citation Graph availability.

## Literature note actions

The following commands operate on a literature note: the file currently open in the editor must be a ZotLit literature note. They also appear in the **file menu** (right-click the tab or use the file menu icon) under the **zotlit** section. The Template Workbench view and the Note preview view raise the same **zotlit** section in their pane menus, and the Note preview view adds two more: **zotlit-preview**, for the choices that shape the preview, and **zotlit-display**, for the display toggles.

<Command name={m.command_update_note_name()} />

Re-renders the full literature note (frontmatter and managed body region) from the current Zotero data.

| Entry point     | Details                     |
| --------------- | --------------------------- |
| Command palette | Active on a literature note |
| File menu       | yes                         |

<Command name={m.command_update_note_metadata_name()} />

Re-renders only the frontmatter of the literature note from the current Zotero data. Body content is unchanged.

| Entry point     | Details                     |
| --------------- | --------------------------- |
| Command palette | Active on a literature note |
| File menu       | yes                         |

<Command name={m.command_overwrite_note_name()} />

Destructively replaces the entire literature note with a fresh render. A confirmation modal appears before proceeding.

| Entry point     | Details                     |
| --------------- | --------------------------- |
| Command palette | Active on a literature note |
| File menu       | yes                         |

<Command name={m.command_import_child_notes_name()} />

Imports the Zotero notes attached to the current item into the vault.

| Entry point     | Details                     |
| --------------- | --------------------------- |
| Command palette | Active on a literature note |
| File menu       | yes                         |

<Command name={m.command_copy_item_key_name()} />

Copies the note's Zotero key to the clipboard.

| Entry point     | Details                                                                     |
| --------------- | --------------------------------------------------------------------------- |
| Command palette | Active on a file with a Zotero key                                          |
| File menu       | Label: <UiLabel name={m.command_copy_item_key_name()} />. Single file only. |

<Command name={m.command_customize_note_template_name()} />

Opens the profile document that the note resolves against in the Template Workbench View. A note with no profile stamp resolves against the Default profile. A profile the vault cannot resolve shows a notice instead. See [Profiles](/docs/concepts/profiles) for what a profile decides.

| Entry point     | Details                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------- |
| Command palette | Active on a literature note                                                                       |
| File menu       | Label: <UiLabel name={m.command_customize_note_template_name()} />. Appears on a literature note. |

<Command name={m.command_switch_literature_note_profile_name()} />

Opens the profile picker for the note, then asks for consent before writing anything. The switch re-renders the note with the chosen profile. The dialog also offers to move the note into that profile's folder.

| Entry point     | Details                     |
| --------------- | --------------------------- |
| Command palette | Active on a literature note |

## Templates and profiles

These commands open profile documents in the Template Workbench and import a profile that someone shared with you. Two of them are palette entries labelled <UiLabel name={m.template_workbench_open_layout()} />. One opens the profile document you are editing; the other brings the Workbench forward from inside the view.

<Command name={m.template_workbench_open_layout()} />

Opens the active profile document in the Template Workbench View.

| Entry point     | Details                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------- |
| Command palette | Active on a profile document                                                                 |

Opens the Template Workbench View in the current leaf for the active document. A profile document, a partial, or the citation text opens directly. A literature note opens the profile document it resolves against.

<Command name={m.template_workbench_open_layout()} />

Brings the Workbench forward for the document being edited. When its pane shares a container with unrelated panes, the editor moves into a window of its own instead.

### Template Workbench pane menu

The Workbench view's pane menu is where most template work starts. These entries sit in the **zotlit** section:

| Menu item                                               | What it does                                                                                                                                                                                                       |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| <UiLabel name={m.template_workbench_open_layout()} />   | Brings the Workbench forward, or moves the editor into its own window.                                                                                                                                             |
| <UiLabel name={m.workbench_choose_item()} />            | Picks the Zotero item the preview and the data explorer read.                                                                                                                                                      |
| <UiLabel name={m.workbench_choose_annotation()} />      | Picks the annotation to render. Not offered for the citation text.                                                                                                                                                 |
| <UiLabel name={m.template_workbench_partials()} />      | Opens another partial, creates one with <UiLabel name={m.workbench_partial_new()} />, or unpacks the partials a shared profile still carries with <UiLabel name={m.workbench_problem_bundled_partial_unpack()} />. |
| <UiLabel name={m.template_workbench_open_citation()} /> | Opens the citation text, `zotlit-citation.md`.                                                                                                                                                                     |

Four entries join the pane menu outside the **zotlit** section. <UiLabel name={m.template_workbench_change_language()} /> switches the document between <UiLabel name={m.workbench_name_language_liquid()} /> and <UiLabel name={m.workbench_name_language_eta()} />, and is not offered for a profile document. <UiLabel name={m.template_data_explorer_menu_export_json()} /> saves the current template data as a JSON file; with the annotation root selected, the same entry reads <UiLabel name={m.template_data_explorer_export_selected_paper()} /> when it can export the whole paper instead. <UiLabel name={m.template_workbench_open_markdown()} /> opens the document as Markdown. <UiLabel name={m.settings_profile_document_restore()} /> moves the Default profile's custom document to the trash, so the built-in profile applies again, and is offered on that document only.

## Template Workbench CLI

The Template Workbench registers its own commands with the Obsidian CLI, for agents and scripts rather than for the command palette. Five answer live:

- `zotlit:template-inspect` inspects one template document and verifies that its saved source is current.
- `zotlit:template-check` checks every saved component of every profile.
- `zotlit:template-status` reports the state of the Workbench for the vault.
- `zotlit:template-data` returns the template data for one root.
- `zotlit:template-guide` prints the Workbench guide.

The earlier schema, rendering, source, and managed-frontmatter commands are retired. Each stays registered and answers a `COMMAND_RETIRED` diagnostic.

See [Template Workbench CLI](/docs/reference/template-workbench-cli) for every command, live and retired, with its flags and diagnostics, and [Template Workbench](/docs/concepts/template-workbench) for the concept.
