## Library-wide update

<Command name={m.command_update_all_notes_name()} />

Creates or updates a literature note for every item in every library of your [library scope](/docs/reference/settings#library-scope). Opens the same batch confirmation modal as a multi-item update from Zotero.

| Entry point     | Details                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command palette | Always available                                                                                                                                              |
| Zotero          | Right-click a library or collection > <UiLabel name={m["zotero.menu_submenu.label"]()} /> > <UiLabel name={m["zotero.menu_collection_update_all.label"]()} /> |

The Zotero entry scopes the batch to the row you right-click: a library covers every item in it, a collection covers that collection and its subcollections. That target is exact, so it runs whether or not the row is in your library scope.

## Literature note quick switcher [#quick-switcher]

<Command name={m.command_open_lit_note_name()} />

Opens a modal to search every library in your [library scope](/docs/reference/settings#library-scope) and jump to (or create) the corresponding literature note.

| Entry point     | Details          |
| --------------- | ---------------- |
| Command palette | Always available |

A result takes five chords, listed along the bottom of the modal:

| Chord                                           | Result                                                           |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| `Enter`                                         | Opens the literature note, creating it first when none exists.   |
| `Ctrl+Enter` (`Cmd+Enter` on macOS)             | The same, in a new pane.                                         |
| `Shift+Enter`                                   | Opens the item's PDF in Obsidian's PDF reader, without the note. |
| `Ctrl+Shift+Enter` (`Cmd+Shift+Enter` on macOS) | The same, in a new pane.                                         |
| `Alt+Enter` (`Option+Enter` on macOS)           | Shows the item in the [Library View](#library-view).             |

`Alt+Enter` opens the Library View on the item's first collection, or on its library when the item is in no collection, and selects its row. It clears the view's search and turns off its reading-state filters, so nothing hides the row. When the item falls beyond the view's limit of 1,000 papers, nothing is selected and a notice says so.

The two PDF chords run <UiLabel name={m.command_open_pdf_name()} /> on the selected result, listed under [Literature note actions](#literature-note-actions).

## Citations

<Command name={m.command_insert_citation_name()} />

Opens a modal to search every library in your [library scope](/docs/reference/settings#library-scope) and insert a Markdown citation at the cursor.

Insertion remains available independently of <UiLabel name={m.settings_citation_pandoc_citations_name()} />, <UiLabel name={m.settings_citation_wikilink_citations_name()} />, <UiLabel name={m.settings_citation_show_formatted_name()} />, and <UiLabel name={m.settings_citation_open_as_links_name()} />.

| Entry point      | Details                                                                                                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command palette  | Active when an editor is open                                                                                                                                              |
| Editor suggester | Triggered by typing `[@` in the editor, or `@` at a word boundary when **`@` trigger** is on. Both settings are under <SettingsPath page={m.settings_page_citations()} />. |

### How the citation search orders papers [#citation-search-order]

Both entry points search every library in your [library scope](/docs/reference/settings#library-scope) at once, in one relevance order. While more than one library can contribute results, each suggestion names the library its item comes from. With one library in scope, that label is left off.

Before you enter a search, both lists place papers already cited in the current
note first. Each group is ordered by Last Activity, newest first. This is the same order as
[<UiLabel name={m.library_view_recent()} /> in the Library View](/docs/how-to/use-library-view#recent).

When you type a search, both lists rank all results by relevance.

A paper the current note already cites shows the <UiLabel name={m.citation_suggester_cited_in_note()} /> label, with or without a search.

### Suggester triggers and queries [#suggester-queries]

The citation suggester opens when you type `[@` (or `【@`) in the editor. A dropdown appears with items from your Zotero library.

With <UiLabel name={m.settings_citation_at_trigger_name()} /> enabled, typing `@` at a word boundary does the same thing. A mid-word `@` (e.g. in an email address) is ignored.

An `@` query ends at the first space. Type `_` where the search needs a space: `@machine_learning` finds "machine learning". Bracket trigger queries (`[@`) accept real spaces.

The modal has no trailing-`/` shortcut; `Shift+Enter` is the only way to ask for the alternate citation here.

- `alt` comes from `Shift+Enter` in either, or from a trailing `/` in the suggester query. The trailing `/` wins without `Shift`, and the `/` is stripped from the search.

#### Cited by sidebar [#cited-by]

The <UiLabel name={m.cited_by_view_name()} /> Sidebar follows the active Literature Note. It groups citation occurrences by source note and shows the citation in its surrounding text.

Use the sidebar toolbar to narrow and arrange the results:

- <UiLabel name={m.cited_by_show_search_filter()} /> filters by source-note path
  or the shown citation context.
- <UiLabel name={m.cited_by_show_more_context()} /> expands every result from a
  compact excerpt to its enclosing Markdown block.
- <UiLabel name={m.cited_by_change_sort_order()} /> sorts source notes by file
  name, modified time, or created time, in either direction.
- <UiLabel name={m.cited_by_collapse_results()} /> collapses or expands the
  visible source-note groups.

Select a citation excerpt to open its source note at that occurrence. Select <UiLabel name={m.cited_by_open_source()} /> on a group to open the note without targeting one occurrence. Hold Ctrl on Windows or Linux, or Command on macOS, to open either action in another pane.

### Follow modes [#follow-modes]

| Mode                                                        | Behavior                                                                                   |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| <UiLabel name={m.annot_view_mode_active_tab()} /> (default) | Follows your active tab: the item of a literature note, or the attachment of a Zotero PDF. |
| <UiLabel name={m.annot_view_mode_zotero_reader()} />        | Follows the attachment open in Zotero's reader. Needs live updates.                        |
| <UiLabel name={m.annot_view_mode_pinned()} />               | Stays on one item you chose, with its attachment remembered.                               |

To switch, open the menu at the top of the view (the item's title with a down arrow); its first group is headed <UiLabel name={m.annot_view_header_menu_label()} />. The same
three switches are in the view's pane menu, and each has a command of its own.

The view keeps the mode you chose until you choose another one. When its source
cannot answer, the view says so in place instead of switching for you.

<UiLabel name={m.annot_view_mode_zotero_reader()} /> needs live updates, which
carry the reader's position from Zotero to Obsidian. While live updates is off,
the view offers <UiLabel name={m.annot_view_enable_live_updates()} /> in place
of the list. See [Set up live updates](/docs/how-to/set-up-live-updates).

Closing the reader in Zotero leaves the last attachment on screen under <UiLabel name={m.annot_view_reader_closed()} />

Pinning from a Zotero PDF tab releases that tab's hold on the attachment, so you can switch between the item's attachments while the pin stands.

Select <UiLabel name={m.annot_view_mode_unpin()} /> to return to the mode you were in before the pin.

A PDF that Zotero stores with no parent item cannot be pinned; the menu offers no pin entry for it.

### Attachment picker [#attachments]

When the item has more than one attachment, a picker under the toolbar names the one on screen with its annotation count, and remembers your choice per item.

A Zotero PDF tab and the Zotero reader each choose the attachment themselves, so the picker stands down while one of them does.

To read the attachment on screen in Obsidian, open the menu at the top of the view, then select <UiLabel name={m.command_open_pdf_name()} />. The same item is in the view's pane menu. It is not shown when an Obsidian PDF tab already shows that attachment.

### Sort, group, and save the view [#more-options]

The view's <UiLabel name={m.annot_view_more_tooltip()} /> menu (⋮) has <UiLabel name={m.annot_view_sort()} />, <UiLabel name={m.annot_view_group_by()} />, and <UiLabel name={m.annot_view_filter()} /> for the cards. <UiLabel name={m.annot_view_save_as_query_file()} /> keeps what the view shows as a query file that you can open in a tab or embed in notes. See [Save the annotation sidebar as a query file](/docs/how-to/use-query-files#save-sidebar).

### Locked annotations [#locked]

A lock icon beside a card's page number marks an annotation that ZotLit cannot change. Point to the icon to see the reason. For example, Zotero imported the annotation from the PDF file, or another member of a group library created it. See [How to edit PDF annotations in Obsidian](/docs/how-to/edit-pdf-annotations) for what you can still do with a locked annotation.

### Inserting into a note [#insert]

ZotLit uses the [profile](/docs/reference/templates/how-templates-work#profiles) of the annotation item's literature note, or the Default profile when that item has no note. Edits made while you wait move the insertion position with the text. Press Escape to cancel a pending insertion. After insertion, one Undo removes the inserted content.

### Card menu [#card-menu]

Right-click an annotation row, or open its <UiLabel name={m.annot_view_more_tooltip()} /> menu, for additional options:

- <UiLabel name={m.annot_view_menu_edit_text()} />: opens an editor for the
  quoted text of a highlight or underline. See [Edit the quoted
  text](/docs/how-to/edit-pdf-annotations#edit-the-quoted-text).
- <UiLabel name={m.annot_view_menu_copy_backlink()} />: copies a link back to
  the annotation's location in the PDF.
- <UiLabel name={m.annot_view_menu_copy_text()} />: copies the quoted text, or
  the comment when the annotation has no quoted text.
- <UiLabel name={m.annot_view_menu_copy_citation()} />: copies a formatted
  citation for the annotation's parent item.
- <UiLabel name={m.indexed_key_menu_copy_annotation()} />: copies the
  annotation's Zotero key.
- <UiLabel name={m.annot_view_menu_insert()} />: inserts the annotation at the
  cursor in the active note, as a drag does.
- <UiLabel name={m.template_data_explorer_menu_explore()} />: opens the Template
  Data Explorer with the annotation's data.
- <UiLabel name={m.annot_view_menu_delete()} />: deletes the annotation from
  Zotero after you confirm. See [Delete an
  annotation](/docs/how-to/edit-pdf-annotations#delete-an-annotation).

When several cards are selected, the menu has only the items that act on all of them. See [Select several cards](/docs/how-to/use-annotation-view#select-several).

## Query files [#query-files]

Creates a query file named `Untitled.zotquery` and opens it in a tab. The file has two views. The default view, Items, is a Table of the papers in your whole library, newest first by date modified, with a limit of 100 rows. The second view, Annotations, shows the annotations of your whole library, grouped by paper, with a limit of 100 rows. See [Use query files and query blocks](/docs/how-to/use-query-files).

| Entry point     | Details                                                                                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Command palette | Always available. The file goes in the folder for new notes.                                                                                                                               |
| File explorer   | Right-click a folder, or a file in it > <UiLabel name={m.query_file_new()} />. The file goes in that folder. Hold `Ctrl` (Windows and Linux) or `Command` (macOS) to open it in a new tab. |

<UiLabel name={m.annot_view_save_as_query_file()} /> in the annotation view's

## Query CLI [#query-cli]

The Query CLI reads works, files, and reading marks for agents and scripts. One `zotlit:query` command selects a Query Dataset with `from`. [How ZotLit Query works](/docs/reference/how-queries-work#zotlit-query) explains the datasets, filters, and groups.

| Command                   | Parameters                                                                                                                  | Result                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `zotlit:query`            | `from`, `filter`, `fields`, `formulas`, `sort`, `group`, `limit`, `library`, `output`, `id`, `this-item`, `this-attachment` | One Query Row per matching Item, Attachment, or Annotation                |
| `zotlit:query-schema`     | `from`                                                                                                                      | The schema URL, source custom fields, dataset fields, and defaults        |
| `zotlit:query-values`     | `kind`, `library`, `match`, `limit`                                                                                         | The exact Collection paths or Tag names of each Library                   |
| `zotlit:query-guide`      | `topic`                                                                                                                     | Instructions for one topic, or the full guide when `topic` is omitted     |
| `zotlit:annotation-image` | `key`                                                                                                                       | The local PNG path, format, and provenance for an image or ink Annotation |
| `zotlit:query-cancel`     | `id`                                                                                                                        | Whether ZotLit found the named query and requested its cancel             |

`zotlit:query` uses these parameters:

| Parameter         | Value                                                                                                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `from`            | `items`, `attachments`, or `annotations`. The default is `items`.                                                                                                                                                       |
| `filter`          | A Filter Expression over the selected dataset and its related records.                                                                                                                                                  |
| `fields`          | A comma list of Projection Paths or a JSON array. `fields=[]` returns identity-only rows.                                                                                                                               |
| `formulas`        | A JSON object from Formula names to Filter Expressions. Read a Formula as `formula.<name>` in `fields`, `filter`, or another Formula. See [Compute a value with a formula](/docs/how-to/query-zotero-library#formulas). |
| `sort`            | A comma list or a JSON array of `{ "field", "direction" }` objects. Use `-field` for descending order and `field` or `+field` for ascending order.                                                                      |
| `group`           | One scalar Projection Path, or a path with one `[]` such as `tags[].name`. The result contains one group for each value.                                                                                                |
| `limit`           | A positive integer or `all`. The default is 100. In a grouped query, the limit applies inside each group.                                                                                                               |
| `library`         | `personal`, `group:<groupID>`, a comma list, a JSON array, or `all`. The default comes from the Library Scope setting.                                                                                                  |
| `output`          | A new absolute file path for the complete JSON result.                                                                                                                                                                  |
| `id`              | A query ID used by `zotlit:query-cancel`.                                                                                                                                                                               |
| `this-item`       | An Item Indexed Key. A filter reads that Item as `this.item`. See [Query Context](#query-context).                                                                                                                      |
| `this-attachment` | An Attachment Indexed Key. A filter reads that Attachment as `this.attachment`. See [Query Context](#query-context).                                                                                                    |

ZotLit splits `fields` and `sort` at commas outside quotes and brackets.

### Query datasets

Choose the dataset that represents one result row:

| `from` value  | One row represents | Dataset contents                                                                   | Related records                       |
| ------------- | ------------------ | ---------------------------------------------------------------------------------- | ------------------------------------- |
| `items`       | A work             | Top-level Items outside the trash                                                  | `attachments`, `annotations`, `notes` |
| `attachments` | A file or URL      | Non-trashed Attachments of top-level, non-trashed Items                            | `item`, `annotations`                 |
| `annotations` | A reading mark     | Non-trashed Annotations on non-trashed Attachments of top-level, non-trashed Items | `item`, `attachment`                  |

Standalone Attachments are outside these datasets. Relation Lists contain records from the same dataset universes. Use list methods in filters and an explicit `[]` in Projection Paths.

`notes` lists the Child Notes of an Item that are outside the trash, in note key order. A note record has `indexedKey`, `key`, `title`, `dateAdded`, `dateModified`, `library`, and its parent `item`. No dataset reads notes as rows. This query finds papers with a Child Note and lists the note titles:

```bash
obsidian zotlit:query filter='!notes.isEmpty()' fields='title,notes[].title'
```

For example, this query finds papers with no PDF that ZotLit can open on this computer:

```bash
obsidian zotlit:query filter='attachments.filter(value.contentType == "application/pdf" && value.exists).isEmpty()' fields=title,citationKey
```

Start from Attachments when each file must be one row. This query finds missing linked files:

```bash
obsidian zotlit:query from=attachments filter='linkMode == "linked_file" && !exists' fields=item.title,path
```

Select a record by Indexed Key in the filter. Use `indexedKey` for a row, `item.indexedKey` for its parent Item, or `attachment.indexedKey` for an Annotation's parent Attachment. A key outside the Target Libraries gives a Query Warning. The Target Libraries stay unchanged.

### Query Context [#query-context]

`this-item` and `this-attachment` set the Query Context of a query: the Item and the Attachment that a filter reads as `this.item` and `this.attachment`. Query files and query blocks set the same context from the note that shows them. See [`this`: the paper of the note](/docs/reference/how-queries-work#this).

| Dataset       | Records of the bound Item            | Records of the bound Attachment            |
| ------------- | ------------------------------------ | ------------------------------------------ |
| `items`       | `indexedKey == this.item.indexedKey` |                                            |
| `attachments` | `item == this.item`                  | `indexedKey == this.attachment.indexedKey` |
| `annotations` | `item == this.item`                  | `attachment == this.attachment`            |

```bash
obsidian zotlit:query from=annotations filter='item == this.item' this-item=ABCD2345 limit=all
```

A filter that reads `this.item` or `this.attachment` without its parameter fails with the `unbound-context` diagnostic.

### Projection and grouping

A path such as `attachments[].path` returns one value for each Attachment. It keeps source order and keeps `null` in its original position. A complete related record has a fixed summary:

| Record     | Summary fields                                                     |
| ---------- | ------------------------------------------------------------------ |
| Item       | `indexedKey`, `title`, `citationKey`                               |
| Attachment | `indexedKey`, `title`, `contentType`, `linkMode`, `path`, `exists` |
| Annotation | `indexedKey`, `type`, `text`, `comment`, `pageLabel`, `pageIndex`  |
| Note       | `indexedKey`, `title`                                              |

`group` accepts one scalar path. This command counts Attachments by `fileType`, which is `pdf`, `epub`, `web`, or `other`:

```bash
obsidian zotlit:query from=attachments group=fileType
```

Each group contains `value`, `count`, and `rows`. `count` is the number of matches before the per-group limit. `totalCount` counts all matched records, and `returnedCount` counts the row entries returned across all groups.

A path with one `[]` groups by each element of a list. This command counts papers per tag:

```bash
obsidian zotlit:query group='tags[].name' fields='[]' limit=1
```

A paper joins one group for each of its tags, and a paper without tags is in the `null` group. Groups can overlap, so their counts can add up to more than `totalCount`. Use `collections[]` for papers per Collection and `attachments[].fileType` for papers per file type.

This command returns the three most recent marks for each paper:

```bash
obsidian zotlit:query from=annotations group=item.indexedKey sort=-dateModified limit=3 fields=text,item.title
```

### Collection and Tag values [#query-values]

`zotlit:query-values` lists the names that a filter matches exactly. Run it before you filter by a Collection or Tag.

| Parameter | Value                                                                                      |
| --------- | ------------------------------------------------------------------------------------------ |
| `kind`    | `collections` or `tags`. Required.                                                         |
| `library` | `personal`, `group:<groupID>`, or `all`. The default comes from the Library Scope setting. |
| `match`   | Keeps the names that contain this text, ignoring letter case.                              |
| `limit`   | A positive integer or `all`, applied to each Library. The default is 100.                  |

Collection values are full paths joined by `/`, including empty Collections. Tag values are `{ name, type }`, where `type` is `manual`, `auto`, or `unknown`. Each Library reports its `library` selector, `name`, `values`, `totalCount`, `returnedCount`, and `truncated`.

```bash
obsidian zotlit:query-values kind=collections match=thesis
```

A Collection path in `collections.contains` or `collections.within` that no Target Library holds gives an `unknown-collection` Query Warning. Its `suggestions` lists the nearest paths, and a `library` value when another Library holds the path.

### Schema, guide, and results

The single `query.schema.json` catalog has `datasets.items`, `datasets.attachments`, and `datasets.annotations`. It also has the shared functions, methods, properties, and types. `zotlit:query-schema` returns the catalog URL, source custom fields, and defaults by dataset. Add `from=items`, `from=attachments`, or `from=annotations` to narrow the live response.

`zotlit:query-guide` accepts `datasets`, `filter`, `fields`, `sort`, `group`, `results`, `schema`, `values`, or `cancel` as its topic. Omit `topic` to print the full guide.

Query results use CLI Contract version 3. The JSON envelope has `command: "zotlit:query"`; `request.from` names the dataset, and `request.library` names its Libraries. The top-level `libraries` field describes the Libraries that ZotLit read.

Read `warnings` before you report an empty result. On failure, read `diagnostic.report` and follow its final recovery action.

Every Attachment Row contains the Attachment and parent Item Indexed Keys. Every Annotation Row also contains its parent Attachment Indexed Key. Annotation default values include `pageLabel`, `pageIndex`, `hasExcerptImage`, Attachment details, Item title, and Citation Key. Request `position` in `fields` when source geometry is required. Read `attachment.path` to open the source document when `attachment.exists` is true.

When `hasExcerptImage` is true, pass the Annotation Indexed Key as `key` to `zotlit:annotation-image`. The command returns a file path instead of image bytes.

The `zotlit-query` agent skill reads `zotlit:query-guide` and `zotlit:query-schema` before it composes a query. See [Ask an AI agent](/docs/how-to/query-zotero-library#agent).

## Template Workbench CLI

The Template Workbench registers its own commands with the Obsidian CLI, for agents and scripts rather than for the command palette. Five answer live:

- `zotlit:template-inspect` inspects one template document and verifies that its saved source is current.
- `zotlit:template-check` checks every saved component of every profile.
- `zotlit:template-status` reports the state of the Workbench for the vault.
- `zotlit:template-data` returns the template data for one root.
- `zotlit:template-guide` prints the Workbench guide.

The earlier schema, rendering, source, and managed-frontmatter commands are retired. Each stays registered and answers a `COMMAND_RETIRED` diagnostic.

See [Template Workbench CLI](/docs/reference/template-workbench-cli) for every command, live and retired, with its flags and diagnostics, and [Template Workbench](/docs/reference/template-workbench-cli) for the concept.
