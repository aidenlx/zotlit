This tutorial takes one note through ZotLit's built-in export and a native Pandoc export.

You will use the same citations and style for both Word documents. At the end, you can see which parts the two workflows share.

## Before you start

You need:

- Obsidian Desktop 1.14.2 or newer with ZotLit installed.
- Zotero 9 or newer with ZotLit Companion, the Zotero add-on.
- [Better BibTeX](https://retorque.re/zotero-better-bibtex/installation/) installed in Zotero.
- Pandoc 3.1.1 or newer installed on your computer.

Enable Obsidian's **Command line interface**, which needs Obsidian installer 1.13.4 or newer. Keep Obsidian open during the native run. The [native Pandoc guide](/docs/how-to/export-with-native-pandoc#requirements) lists the complete compatibility requirements.

<Steps>
  <Step>
    ### Prepare the sample items

    In Zotero, select **My Library**, then select **Add Item(s) by Identifier**. Add these two DOIs:

    | DOI                            | Item title                                     | Citation key                  |
    | ------------------------------ | ---------------------------------------------- | ----------------------------- |
    | `10.1371/journal.pmed.0020124` | Why Most Published Research Findings Are False | `zotlitTutorialIoannidis2005` |
    | `10.1126/science.aab2374`      | Promoting an open research culture             | `zotlitTutorialNosek2015`     |

    Open each item and replace its **Citation Key** with the value in the table.

    In Obsidian, run <Command inline name={m.command_open_lit_note_name()} />. Select each sample item to create its Literature Note.

    Confirm that ZotLit creates `zotlitTutorialIoannidis2005.md` and `zotlitTutorialNosek2015.md`. Create one ordinary Obsidian note named `Reading plan`.

    Create a folder named `ZotLit Pandoc tutorial` inside your Documents directory.

  </Step>
  <Step>
    ### Configure both citation sources

    Open <SettingsPath page={m.settings_page_citations()} />. Turn on <UiLabel name={m.settings_citation_pandoc_citations_name()} /> and <UiLabel name={m.settings_citation_wikilink_citations_name()} />.

    ![The Citations settings page with Pandoc citations and Wikilink citations both turned on under Citation sources](/img/tutorial/pandoc-workflow-citation-sources.webp)

    Under <UiLabel name={m.settings_citation_references_heading()} />, install the <UiLabel name={m.settings_citation_engine_name()} />. This managed engine formats the <UiLabel name={m.references_view_name()} /> Sidebar and powers built-in export.

    Open <SettingsPath /> and select **APA Style 7th edition** as the <UiLabel name={m.settings_citation_references_style_name()} />. Its author-date output makes locators and author modes easy to compare.

  </Step>
  <Step>
    ### Create the worked note

    Create a Markdown note named `Citation workflow check`, and paste this body into it:

    ```md
    # Citation workflow check

    A plain Literature Note link introduces the first source [[zotlitTutorialIoannidis2005]].

    The same source appears with its article locator [[zotlitTutorialIoannidis2005#cite:locator=e124]].

    [[zotlitTutorialIoannidis2005#cite:mode=author-in-text&locator=e124]] examines why published research findings may be false.

    Nosek et al. propose guidelines for open research [[zotlitTutorialNosek2015#cite:mode=suppress-author&locator=1423]].

    Both sources support the comparison [[zotlitTutorialIoannidis2005]]; [[zotlitTutorialNosek2015#cite:locator=1423]].

    A literal Pandoc citation names the second source again [@zotlitTutorialNosek2015].

    The wider reading list remains an ordinary vault link [[Reading plan]].
    ```

    Keep the semicolon and both Literature Note links on one line. Together they form one Citation Run.

    The note has no citation style of its own, so it uses the APA style you selected in settings. Both exports use that same style.

  </Step>
  <Step>
    ### Review the note in Obsidian

    Switch to Live Preview, then run:

    <Command name={m.command_open_references_view_name()} />

    The <UiLabel name={m.references_view_name()} /> Sidebar shows two entries. Each source appears once, even though the note cites it several times.

    Check the rendered note and sidebar:

    - The plain link renders as `(Ioannidis, 2005)`.
    - The locator link renders as `(Ioannidis, 2005, p. e124)`.
    - The author-in-text link renders as `Ioannidis (2005, p. e124)`.
    - The suppress-author sentence ends with `Nosek et al. propose guidelines for open research (2015, p. 1423).`
    - The Citation Run renders as `(Ioannidis, 2005; Nosek et al., 2015, p. 1423)`.
    - The literal citation renders as `(Nosek et al., 2015)`.
    - `Reading plan` remains an ordinary vault link.

    ![The note Citation workflow check in Live Preview with its APA citations formatted, and the References Sidebar on the right listing the Ioannidis and Nosek et al. entries](/img/tutorial/pandoc-workflow-references-sidebar.webp)

  </Step>
  <Step>
    ### Export with ZotLit

    Keep Zotero open.

    Run:

    <Command name={m.command_pandoc_export_name()} />

    Keep <UiLabel name={m.pandoc_export_format_name()} /> set to <UiLabel name={m.pandoc_export_format_docx()} />. <UiLabel name={m.pandoc_export_style_name()} /> shows **APA Style 7th edition**, and the line under it reads <UiLabel name={m.pandoc_export_style_from_vault()} /> This confirms that the export uses the style from your settings.

    Under <UiLabel name={m.pandoc_export_destination_name()} />, select <UiLabel name={m.pandoc_export_destination_browse()} /> and save the file in your `ZotLit Pandoc tutorial` folder.

    ![The Export with citations dialog set to Word document, with the citation style APA Style 7th edition, the line "Your vault settings set this style.", and a destination in the ZotLit Pandoc tutorial folder](/img/tutorial/pandoc-workflow-export-dialog.webp)

    Select <UiLabel name={m.pandoc_export_confirm()} />. The notice that follows names the style it used, for example <UiLabel name={m.notice_pandoc_export_done({ file: "Citation workflow check.docx", style: "APA Style 7th edition" })} />

    Open the resulting `.docx` file and repeat the checks from the <UiLabel name={m.references_view_name()} /> Sidebar.

    Built-in export uses Better BibTeX to fetch current bibliography data from Zotero.

  </Step>
  <Step>
    ### Save the version-matched integration pair

    Open <SettingsPath page={m.settings_page_citations()} />. Under <UiLabel name={m.settings_citation_native_pandoc_heading()} />, find <UiLabel name={m.settings_citation_pandoc_files_name()} /> and select <UiLabel name={m.settings_citation_pandoc_files_save()} />.

    Choose your `ZotLit Pandoc tutorial` folder. ZotLit saves `zotlit-cite.lua` and `zotlit.yaml` there. The pair matches your installed ZotLit version. Save a fresh pair after every ZotLit update. Files saved from a version before ZotLit 2.2.0 do not work with 2.2.0 or later.

  </Step>
  <Step>
    ### Create the native bibliography file

    Save `references.json` in your `ZotLit Pandoc tutorial` folder. Include both Zotero items used in the worked note.

    In Zotero, right-click **My Library**. Select **Export**, choose **Better CSL JSON**, and enable **Keep updated**. Save the file as `references.json`.

    Better BibTeX updates the file after the source library or collection changes.

    The citation keys in `references.json` must match the keys used in the worked note.

  </Step>
  <Step>
    ### Run native Pandoc

    Keep Obsidian open with this vault active and ZotLit loaded. Replace each path in this command with an absolute path, then run it in a terminal:

    ```sh
    pandoc "/absolute/path/to/input.md" --defaults "/absolute/path/to/workflow/zotlit.yaml" --bibliography "/absolute/path/to/references.json" --fail-if-warnings --output "/absolute/path/to/output.docx"
    ```

    Keep `--fail-if-warnings`. It stops the run when Pandoc cannot find a cited item in `references.json`.

    Pandoc prints one ZotLit line that names the style and where it comes from:

    ```text
    ZotLit: citations use APA Style 7th edition (from your vault settings).
    ```

    This line is not a warning, so the run continues and writes the `.docx` file.

  </Step>
  <Step>
    ### Compare the Word documents

    Open the native `.docx` beside the built-in export. Both documents should contain the same two formatted bibliography entries.

    Compare the repeated-source formatting, locators, author modes, grouped Citation Run, literal citation, and ordinary vault link. The citation content should agree because both routes start from the same note and style.

    The bibliography source differs. Built-in export asks Better BibTeX for current data, while native Pandoc reads the auto-updated `references.json` file.

  </Step>
</Steps>

You now have one Markdown note that you can review in Obsidian and export through either Pandoc route.

## Troubleshooting

| Symptom                                                                                                         | What to do                                                                                                    |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| A `#cite:` link stops built-in export, and native Pandoc reports `unresolved-citation-intent` for the same link | Point the link to a valid Literature Note. If you meant an ordinary vault link, remove its `#cite:` fragment. |
| Built-in export succeeds, but native Pandoc warns that a citation is not found in the bibliography              | Add the missing item to the Better BibTeX export source, update `references.json`, and run the command again. |
| Native output changes after a ZotLit update or the filter reports a contract mismatch                           | Save both integration files again and replace the old pair together.                                          |

For native error-code definitions, open <UiLabel name={m.settings_citation_pandoc_guide_name()} /> under <SettingsPath page={m.settings_page_citations()} />. The [Settings reference](/docs/reference/settings#native-pandoc) identifies the local guide and integration controls.
