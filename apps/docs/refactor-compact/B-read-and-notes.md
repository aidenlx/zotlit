## how-to/use-library-view.mdx
- Title: Browse your library in the Library View | Description: Find a paper by collection, recent activity, search, reading state, or tag, then open its PDF, write its note, or cite it.
- Archetype (judged from content): Mixed(How-to + Reference: tables of filters/keys/menu items, limits)
- Purpose: Locate a paper in the in-Obsidian Zotero library tab, then open PDF / write note / cite from it.
- Prerequisites stated: none for browsing. Zotero need not be open; ZotLit Companion NOT needed to browse/search/open PDF. "Show in Zotero" needs Zotero (system starts it if closed).
- Product facts asserted:
  - Library View = tab listing Zotero library; reads Zotero DB directly. Browsing/searching read-only. Editing an annotation in Reading Card changes it in Zotero. Reading a PDF can update read time (-> open-pdf#recently-read).
  - Open: ribbon ZotLit icon or command m.command_open_library_view_name. Tab titled m.library_view_name; cursor in search box unless setup banner shows. Existing tab brought forward (no second tab).
  - New install: Library View auto-opens with setup banner until setup complete. Steps m.welcome_step_connect_title, m.welcome_step_folder_title, m.welcome_step_library_title; finished step = one line with action at end; only next step expanded. Tiles (beside steps; under them on narrow pane): m.welcome_docs_getting_started, m.welcome_link_discussions, m.welcome_help_github_title, m.welcome_docs_templates, m.welcome_docs_citations; plus blog, changelog, sponsorship links below. Links always shown on banner.
  - Banner goes away once ZotLit reads Zotero DB AND literature notes folder exists, or on m.welcome_dismiss. Re-show (even after setup): m.library_view_help_action (question-mark icon at top of tab; looks pressed while banner shows; select again to hide) or command m.command_open_welcome_name.
  - After ZotLit update: Library View opens with banner m.welcome_update_title{version}; m.welcome_update_action opens release notes; m.welcome_dismiss hides. Either: banner says nothing more about this version; returns after next update. Turn off m.settings_update_notices_name in Advanced settings.
  - Not found (#not-found): ZotLit searches default Zotero profile; no DB there or set data folder unreadable -> list and tree pane both say m.library_view_not_found (list replaces filters, search box, papers). Banner omits Connect step meanwhile. Fix: m.library_view_locate (choose data folder) or m.welcome_action_open_settings; papers appear as soon as folder set.
  - Also notice m.notice_db_not_found_on_device with button m.notice_db_not_found_action (opens Library View); one such notice at a time; not shown while a Library View is open; clears when DB readable again.
  - Later read failure after DB was readable: view keeps last-read papers; note above list m.library_view_refresh_failed; button m.library_view_locate.
  - Tree (#tree): m.library_view_recent first, then each library in library scope (-> reference/settings#library-scope) with collections nested as in Zotero; each shows paper count. Collection lists subcollection papers too.
  - Heading above list names selection with breadcrumb (e.g. "My Library > Thesis >" over "Chapter 2"); counts papers m.library_view_heading_papers{count} and, if any, unread m.library_view_heading_unread{count} ("12 papers · 3 unread"). While filter/tag narrows: m.library_view_heading_papers_of{count,total}.
  - Unread = no Zotero read time AND no annotations AND no literature note. Unread count and tree paper counts ignore search, reading-state filters, selected tags.
  - Libraries outside library scope: m.library_view_all_libraries (under last library) adds them for current session; m.library_view_scope_libraries hides again.
  - Selected collection renamed/deleted -> selection falls back to its library.
  - Narrow pane: tree hidden; m.library_view_show_tree beside heading opens it over list.
  - Recent (#recent): all papers in library scope by Last Activity, newest first. Last Activity = newest of: opened/read/cited in Obsidian; read in Zotero; added to Zotero; Zotero note or annotation edited. Paper's own field edits do NOT count. New Library View opens on Recent.
  - Recent row reasons (table): m.library_recent_opened{time} (opened lit note or returned to its tab); m.library_recent_read_obsidian (read PDF in Obsidian); m.library_recent_cited (inserted citation or copied citekey); m.library_recent_read_zotero (read an attachment in Zotero); m.library_recent_added (added to Zotero); m.library_recent_notes_edited (edited child note/annotation in Zotero).
  - Opening and citing counted per device only; Zotero-recorded reading syncs via Zotero and can move paper on each device.
  - Recent: no paper count in tree; All libraries does not add libraries; re-sortable via m.query_view_sort in heading; select Recent again to restore newest-first.
  - Search (#search): box m.library_view_search_label at top. Ranked like literature-note quick switcher (-> reference/commands#quick-switcher), best first, restricted to selected library/collection. Heading becomes match count m.library_view_heading_search{count,query}; screen readers announce count changes. While ranked, Sort in heading present but off; clear search to sort.
  - `tag:` token: `tag:methods`, `tag:"machine learning"`; several tokens = AND; search of only tag: tokens keeps list sort (no ranking).
  - m.library_view_search_everywhere (under match count or no-match message): searches every library in scope until a tree node selected or search cleared; tree highlights no node meanwhile; not offered on Recent (already whole scope).
  - Escape in box clears search; Escape again on empty box moves to list.
  - No match: heading m.library_view_heading_search{count:0, query:"glacier"}; list says m.library_view_empty_search_widen with search-everywhere repeat; if search already covers all (on Recent or after search-everywhere): m.library_view_empty_search_clear and button m.library_view_search_clear.
  - Search shows max 500 matches.
  - Reading-state filters (#facets), buttons below tree (table): m.library_view_facet_unread (no read time, annotations, or lit note); m.library_view_facet_annotated (>=1 annotation); m.library_view_facet_has_note (lit note in this vault); m.library_view_facet_pdf (PDF attachment whose file is on this device). Active filter = chip under heading (click to turn off); m.library_view_heading_clear_filters clears all filters and releases all tags. Several = AND; work with any tree selection incl. Recent; stay on while searching; none pass -> m.library_view_empty_facets.
  - Tags (#tags): m.library_view_tags_label lists Zotero tags of papers in tree selection, by name. Select = filter; several = AND (as Zotero). While selected the tag list keeps only tags of papers still shown; each selected tag = chip under heading (click to release). Reselect releases; m.library_view_tags_clear releases all. Selected tags persist across library/collection change; stay listed even if no paper there has it. m.library_view_tags_filter box narrows tag names only. Combine with facets and search; `tag:` token equivalent.
  - Layout (#layouts): m.library_view_papers_view_name; two lines/row: title; creators, year, publication. End-of-row icon = main attachment kind; note icon = has lit note. Expand a paper: attachments, child notes, annotations, lit note.
  - Heading right: m.query_view_sort and m.annot_view_save_as_query_file (icons only on narrow pane). List max 1,000 papers; heading counts all and adds m.library_view_heading_first_shown{count:1000}. For table/other layouts/filters/grouping/properties -> save as query file.
  - Persistence: remembers tree selection, filters, selected tags, search text, sort in this vault's plugin data; shared by every Library View; syncs with vault.
  - Row keys (#rows; same as quick-switcher result): click selects, arrows move. Enter = open lit note (writes one first if none, same profile choice as quick switcher); Ctrl+Enter (Cmd+Enter mac) = same in new tab; Shift+Enter = open PDF in Obsidian; Ctrl+Shift+Enter (Cmd+Shift+Enter) = same in new tab; double-click = open PDF in Obsidian. Cite: drag row into a note; citation inserted at drop.
  - Row menu (#row-menu, right-click): m.library_view_menu_open_pdf (only for paper with PDF); m.library_view_menu_open_pdf_right (new pane right); m.library_view_menu_open_note or m.library_view_menu_write_note; m.library_view_menu_insert_citation (into last-active note, at cursor); m.graph_citations_menu_copy_citekey; m.library_view_menu_show_in_zotero (selects in Zotero; system starts Zotero if closed). No note open -> Insert citation shows m.library_view_cite_no_note.
  - Reading Card (#reading-card): opens right on row select; read-only, never changes Zotero. Top-down: item type small caps; title; creators in full (>10 names -> "et al."; m.library_view_card_all_fields lists all); journal/publisher italic + volume, issue, pages, year; DOI (opens browser) + citation key with copy button.
  - Card buttons: Open PDF (m.library_view_menu_open_pdf), Open/Write note; m.library_view_card_more = full row menu incl. Insert citation; m.library_view_card_open_in_annot_view icon -> shows paper's annotations in m.annot_view_name view, pinned to paper until unpinned.
  - Card sections (only when non-empty): abstract (few lines, m.library_view_card_show_more); m.library_view_card_where (library + collections); m.library_view_card_tags (click = filter by tag); m.library_view_card_files (PDF opens in Obsidian, other file in Zotero); m.library_view_card_notes (select shows in Zotero); date added + m.library_view_card_all_fields (all other fields, Zotero labels and order); m.library_view_card_your_annotations (count per colour, first two as short quotes with page; m.library_view_card_see_all{count} lists all as annotation-view cards; comment/tags editable as in sidebar, needs editing enabled).
  - Card remembers All fields / annotations open state for next paper. Narrow pane: card opens over list; m.library_view_card_close or Escape closes. Search/filter/tree change removing selected paper -> selection cleared, card hides.
  - Show in library (#show-in-library): quick switcher Alt+Enter (Option+Enter mac) -> Library View opens on paper's first collection (or library if none) and selects row; clears search, filters, tags. Paper beyond 1,000 cap: nothing selected, notice m.library_view_reveal_not_listed{limit:1000}.
  - Save as query file (#save-as-query-file): m.annot_view_save_as_query_file in heading; name defaults to selected library/collection, editable; choose folder; dialog says what is left out; writes query file and opens it in tab. Keeps library/collection, selected tags, sort; opens in Papers layout; max 1,000 papers. Not carried over: search (no ranked search in query files yet); Has-note filter; Unread keeps only its no-annotations half (both depend on vault notes; query files cannot filter yet); a file saved from library outside scope lists nothing until library added to scope.

## how-to/open-pdf-in-obsidian.mdx
- Title: Open an item's PDF in Obsidian | Description: Open a Zotero PDF attachment in Obsidian's own PDF reader, from a literature note, the quick switcher, or Zotero.
- Archetype (judged from content): How-to
- Purpose: List every entry point that opens a Zotero PDF in an Obsidian tab and what happens next.
- Prerequisites stated: Obsidian 1.14.2+ (ZotLit 2.2 also requires it); Zotero-side entry points need ZotLit Companion at the version released with ZotLit 2.2.
- Product facts asserted:
  - Opens in Obsidian's own PDF reader whether file is in vault or Zotero storage folder. Only PDF attachments; EPUB, web snapshots, other types stay in Zotero.
  - From lit note: command m.command_open_pdf_name, or right-click note tab -> file-menu section "zotlit" -> m.command_open_pdf_name.
  - From annotation view: pane menu -> m.command_open_pdf_name (attachment view shows); entry omitted while view follows that PDF's tab in Obsidian.
  - From Library View: double-click row, or select + Shift+Enter; right-click -> m.library_view_menu_open_pdf_right (keeps library in view); Reading Card button m.library_view_menu_open_pdf.
  - Quick switcher: command m.command_open_lit_note_name, search, Shift+Enter on result; opens PDF without the lit note.
  - From Zotero (Companion): select one PDF attachment or one item with a PDF -> top-level context menu m["zotero.menu_item_open_pdf.label"]; while reading PDF in Zotero right-click page -> m["zotero.menu_reader_page_open_pdf"] (opens PDF being read).
  - File links: lit note `fileLink` = link to attachment file; annotation `fileLink` adds page + annotation. Click -> PDF opens in Obsidian on that page, annotation selected and scrolled into view; annotation Zotero no longer has still opens page. Applies to any vault link to a PDF in Zotero library; other files (EPUB, snapshot, PDF Zotero doesn't know) open in system app as before. Per-link escape: right-click -> **Open in default browser**. Global off: clear m.settings_reader_open_file_links_name in **Settings -> ZotLit -> Reader**.
  - Result: one PDF opens at once; several -> picker listing by file name, search box placeholder m.modal_select_pdf_placeholder.
  - No PDF -> notice m.notice_no_pdf_attachment; file gone from disk -> m.notice_pdf_file_missing; ZotLit never falls back to Zotero.
  - Annotation view comes forward in sidebar with PDF (item's highlights beside it); in m.annot_view_mode_active_tab mode it follows PDF tab. Turn off via SettingsPath(m.settings_page_reader > m.settings_reader_focus_annot_view_name) (-> reference/settings#reader).
  - #recently-read: if Write Authorization granted with m.capability_enable_editing and **Always Allow**, reading a My Library PDF in Obsidian updates its last-read time in Zotero (appears in Recently Read; syncs through Zotero). ZotLit never asks for Write Authorization while reading. Without auth, Zotero closed, or update fails: read still counts on this device, no notice. Group-library PDF reads stay on this device.

## how-to/edit-pdf-annotations.mdx
- Title: How to edit PDF annotations in Obsidian | Description: Create, change, adjust, and delete Zotero PDF annotations while reading the PDF in Obsidian.
- Archetype (judged from content): Mixed(How-to + Reference: handle/key tables, undo semantics)
- Purpose: Create/edit/move/delete Zotero annotations from the Obsidian PDF view, with undo/redo and conflict handling.
- Prerequisites stated: PDF open in Obsidian; Zotero 10+; Zotero running; Zotero local-communication setting on; ZotLit editing permission (Always Allow). Reading annotations needs no setup.
- Product facts asserted:
  - Supported: highlights, underlines, note annots, text annots (typed on page), image annots, ink annots (freehand); change colors, comments, tags; adjust positions; delete.
  - Zotero 9: PDF opens and shows annotations but not editable; shows m.capability_incompatible_zotero asking to update Zotero.
  - Zotero closed: cannot edit (ZotLit sends each change to Zotero).
  - Zotero Settings -> Advanced -> **Allow other applications on this computer to communicate with Zotero** must be on; off -> m.capability_local_api_disabled.
  - Grant permission via m.capability_enable_editing, in (a) annotation view: mode button at start of toolbar -> m.capability_enable_editing; (b) SettingsPath(m.settings_page_zotero), group m.settings_zotero_editing_heading, row m.settings_zotero_editing_name, button m.settings_zotero_editing_enable. Zotero opens permission dialog at once; choose **Always Allow**; **Allow** leaves editing off (only remembered permission works); **Deny** declines. While waiting PDF reader toolbar shows m.capability_authorizing.
  - Callout warn "Edit one annotation in one application at a time": known Zotero defect (issue 1165); overlapping edits to same annotation in Zotero and Obsidian: one comment can silently overwrite other though both report success; deletion in Obsidian can remove annotation Zotero just updated. Both apps may stay open; edit in one at a time, wait for save, then switch; reduces not guarantees.
  - Locked (#locked): lock icon beside page number; tooltip gives reason. (1) Zotero imported annotation from PDF file: cannot change or delete (reimported on file change). (2) Group library, another member's annotation: cannot change, can delete. Multi-select with a locked card: a change the lock refuses applies to none.
  - Highlight/underline: select PDF text -> popup m.pdf_toolbar_highlight / m.pdf_toolbar_underline; wait for mark before continuing/switching to Zotero. Toolbar at right of PDF reader has same two tools: select to keep active, then select text repeatedly; arrow beside tool picks color. One highlight in another color: select text then color in popup; with no tool active a color creates a highlight.
  - Note annotation: toolbar m.pdf_toolbar_note; click page; note centered on click, popup opens with comment editor ready; comment saves per comment rules. Tool off after each note (as Zotero). Click on existing mark selects it; drag creates nothing.
  - Text annotation: toolbar m.pdf_toolbar_text (tool turns off when box opens); click page -> box at click; Enter newline; box grows to one line up to 300 pt then wraps (as Zotero); Escape or click outside commits -> text annotation in Zotero, stays visible while saving; empty box creates nothing; click on mark selects mark. Zotero shows annotation only when typing finishes (created once with its text).
  - Text color/size: arrow beside Text tool; menu colors then sizes under m.pdf_toolbar_text_font_size: 10, 12, 14, 18, 24, 36 pt; check marks current; default 14 pt; remembered for other PDFs.
  - Image annotation: toolbar m.pdf_toolbar_image; drag rectangle (faint until large enough to save); release -> mark appears, card shows captured area. Tool off after each capture. Esc cancels drag; Esc again turns off tool. Press on mark selects mark.
  - Ink: toolbar m.pdf_toolbar_ink; starts blue (Zotero default ink color); press+drag; release -> ink annotation, visible while saving. Each stroke = own annotation; tool stays active; tap without moving saves a dot; merge strokes in Zotero. Works with mouse, pen tablet, trackpad, touchscreen finger; while active touch drag draws instead of scrolling. Stroke draws over text and marks (press on mark starts stroke). Stroke stays on page where it started even if pointer leaves. Zotero limits annotation size: long stroke saved so far and continued as new annotation without lifting. Esc before release cancels stroke (tool stays); Esc again turns off tool; second finger (pinch start) cancels stroke.
  - Ink color/width: arrow beside Ink; colors then widths under m.pdf_toolbar_ink_width: 0.4, 1, 2, 3, 5, 8, 12 pt; check marks; default 2 pt; remembered across PDFs; stroke keeps color/width it started with.
  - Comment: select mark -> popup shows comment under button row; select comment (or m.annot_view_card_comment_placeholder if none); type; auto-saves; Esc or click outside closes; wait for save before editing in Zotero. Autosave 1 s after typing stops; during continuous typing 10 s from first unsaved change; Enter = line break; Ctrl+Enter (Windows) / Command+Enter (macOS) saves, keeps editor open. Card editing: select the card (and no other card), click comment/placeholder; Esc or click elsewhere in annotation view closes; multiple cards selected -> click on comment only selects card. Popup and card editors share one draft.
  - Comment conflict (changed in Zotero): m.annot_view_conflict_title with both versions; m.annot_view_conflict_use_comment (save draft over Zotero) / m.annot_view_conflict_keep_zotero_comment (discard draft).
  - Edit quoted text (heading "Edit the quoted text", auto-slug anchor): highlight/underline text of PDF; fix extraction errors (ligatures, split hyphenated words, wrong symbols); editing must be enabled; annotation view only (PDF popup has no control). Steps: select card alone; point to quote, click pencil at end of first line (tooltip m.annot_view_menu_edit_text), or card m.annot_view_more_tooltip menu or right-click -> m.annot_view_menu_edit_text; editor replaces quote, cursor at end; clicking quote text itself doesn't open editor (so you can select/copy). Enter = line break; bold/italic/subscript/superscript shortcuts same as comment editor. Esc or click elsewhere in annotation view saves+closes. Save timing as comments (1 s / 10 s); Ctrl/Command+Enter saves, keeps open; click outside annotation view (e.g. PDF) saves, keeps open; empty allowed -> card shows m.annot_view_card_no_text. Replaces only text; position and list-order place kept; Zotero shows new text; one session = one undo step. Conflict: m.annot_view_conflict_title; m.annot_view_conflict_use_text / m.annot_view_conflict_keep_zotero_text. Save failure keeps text; m.annot_view_text_save retries.
  - Color: select mark -> popup m.annot_view_card_color -> pick Zotero color; card palette button same. Several cards: select in annotation view, press 1-8 (palette order); one undo reverses group.
  - Tags: select mark -> popup m.annot_view_card_add_tags (m.annot_view_card_edit_tags if tags exist); type name + Enter; suggestions from item's library; cross removes; Esc or click outside saves. Card has same button; on card tags save when you select elsewhere, editor stays open; close via Esc or button again. Esc does not add typed-but-not-Entered name; comma is part of tag name; automatic tags removable as Zotero. Save failure / editing stops: tags kept under m.annot_view_tags_draft; m.annot_view_tags_save retries.
  - Adjust position: image/ink/text move+resize; note move only; highlight/underline move either end. Editing must be enabled else no handles and keys do nothing. Select mark -> handles; drag handle or mark; release sends to Zotero. Esc during drag restores without saving; drag ending where it began saves nothing; popup hides during drag, returns after.
