## how-to/use-query-files.mdx
- Title: Use query files and query blocks | Description: Create a query file, filter, sort, and group its views, add formulas, embed it in notes, and save the annotation sidebar as a query file.
- Archetype (judged from content): Mixed(How-to + Reference). Procedures for creating/embedding/saving; large option inventories for views, filters, sort/group/property lists.
- Purpose: Reader creates a `.zotquery` file, edits its views (filter/sort/group/properties/formulas/display names), limits/copies/exports results, uses Table layout, embeds a file or query block in notes, and saves the annotation sidebar as a query file.
- Prerequisites stated: none (links to the concept page for ideas).
- Product facts asserted:
  - Query file shows live annotations, files, or papers from Zotero, in a tab or in a note.
  - Command creates the file in the folder where Obsidian puts new notes; context menu on a folder, or on a file in it, also creates one.
  - New file is named `Untitled.zotquery`, opens in a tab; Ctrl (Win/Linux) / Command (macOS) on the menu item opens a new tab; rename like any note.
  - New file has two views. Items view (default): Table of whole-library papers, newest first by date modified, max 100 at a time, columns Title, Creators, Year, Literature Note. Annotations view: whole-library annotations grouped by paper, max 100 at a time.
  - Toolbar controls L to R: view menu, result count (opens Results menu), Filter, Sort, Group, Properties, Search. Narrow pane: icons without labels.
  - View menu: search views by name; Add view (opens Configure view to name it); drag to reorder; make default via Configure view page > More options (...) > Default view (moves to top; an embed without a view name shows it); Duplicate/Delete via same menu.
  - Configure view reached by chevron button on a view row (tooltip Configure view), right-click the row, or right-click the view menu button (configures the on-screen view). Opens in same menu. Each change saves at once; View name saves on leaving the field.
  - Settings: View name (name in menu and after `#` in embed); Dataset (one annotation / attachment / item per row); Layout (list offers only layouts that can show the chosen records).
  - Changing dataset keeps sort/group/properties in the file; the view ignores those the new rows lack; each is marked "Not used" in Sort/Group/Properties and a note under the toolbar names them; switching back reactivates them.
  - Layout options: Annotations layout: Card width, Show comment, Show tags, Show page. List: List markers, Indent properties, Property separator. Cards: Card size. Table: column order/widths set on headers.
  - Filter editor has two parts: All views (every view of the file showing same kind of rows as the first view) and This view (on-screen view only).
  - New condition row reads "empty value" and filters nothing until filled. Examples: Color is Yellow; Year on or after 2020.
  - Combine: Match all / Match any / Match none (hides records matching any condition); Add group nests groups (example: yellow highlights with tag #theory or #method).
  - Reorder: drag handle on condition/group (within, into nested group, out to parent), or select handle + Alt+Arrow Up/Down. Deleting last row of a nested group removes the group; deleting last row of the filter removes the filter.
  - View refreshes as you edit; result count updates.
  - Filter properties: annotations view offers color, Tags, comment, text, page, dates; every view offers paper title, creators, first author, year, item type, Collection, library; annotations+attachments views also offer file title and file type; items view also offers Literature Note properties.
  - Condition editable as Filter Expression (colored parts); Edit visually returns. On error: row shows reason; view keeps last rows and shows filter-error message.
  - Sort: Add sort, property + direction (e.g. new-old for dates); extra properties break ties; drag to change priority (first sorts first).
  - Sort properties: Annotations = position in file, page, dates, color, annotation type, paper title/first author/dates, file title and date added. Attachments = title, dates, paper title/first author/date. Items = title, first author, date, dates added/modified, item type, Literature Note properties.
  - Group: Group by + order. Group properties: Annotations = Item, Attachment, Color, Tag, Collection. Attachments = Item, Tag, Collection. Items = Item type, Tag, Collection. Order: A-Z / Z-A by value, or Manual (checkbox show/hide each group, drag reorder).
  - Record with several Tags/Collections appears in each group; no value shows under the "none" group. In Annotations, List, Cards layouts, clicking a group heading collapses its rows.
  - Properties menu: checkbox show/hide, drag reorder, search; to add a missing property type its path (e.g. `item.citationKey`) and select the add row; items view menu also offers adding a Literature Note property. Chevron (or Right arrow key) opens property settings page (display name, formula). Table/List/Cards show properties in this order; Copy and CSV export use them as columns.
  - Formula = property computed per row, same Filter Expression language as filter conditions (e.g. year, author count).
  - Formula name: letters, digits, underscore; starts with letter or underscore; case counts; property is `formula.<name>`. Check mark = no syntax errors; syntax error = warning icon, reason under field. Save adds property after the others and switches page to the new formula.
  - Formulas saved under top-level `formulas` key; every view of the file can show it. Filter by formula via expression, e.g. `formula.year >= 2020`; formulas can use other formulas (`formula.year + 1`).
  - Edit formula: Properties > chevron (tooltip Edit property) or Right arrow; expression autosaves shortly after typing stops when no syntax errors; name cannot change (remove and re-add). Back returns to list.
  - Remove formula: its page > More options (...) > Remove formula; removed from all views; filter conditions still using it show an error until changed.
  - Formula errors: formula failing on all rows (`title * 2`) shows warning icon on its row in Properties and on Table column header (hover for reason); other properties stay. A filter using a bad formula: view shows the error and no rows until fixed.
  - Per-row failure (`number(volume)`, volume "Spring"): warning icon in the cell with tooltip; Copy/CSV write `Error: ` + reason; paper with no volume shows empty cell.
  - Display name replaces property path in the view (e.g. `formula.year` shown as "Year of source"); saves on leaving field, Enter, Back, or closing menu; shows in Table header, Cards labels, Properties rows, copy/CSV header row; applies to every view of the file; can also be set when adding a formula; clear field to restore default (field name like Title, or path).
  - Results menu (click result count): Limit (clear field or "Show all (250)" shows every match; when limited, count shows both numbers e.g. 250 results, 100 shown); Copy (visible columns of shown rows to clipboard as a table; pastes as Markdown table in Obsidian, or into Excel/Google Sheets/Numbers); Export CSV (visible columns of shown rows; UTF-8 with BOM so Excel/R/SPSS read international text).
  - Copy and CSV include only displayed properties in visible order; interface buttons such as the Literature Note column are omitted.
  - Search filters on-screen rows by text; does not change the file; clear to restore.
  - Table layout: papers grid like Zotero's item list; requires dataset items + layout Table. Expand control reveals attached files, child notes, annotations; attachments expand to annotations. Attachment titles and annotation text are links: PDF opens in Obsidian PDF viewer; annotation opens PDF at page and highlights the mark; other file types open in Zotero; Ctrl/Command opens new tab.
  - Table columns: drag header to reorder; drag boundary to resize; double-click boundary resets to auto width; click/right-click header menu: Move column left, Move column right, Reset column width. Resized widths auto-save in the file.
  - Literature Note column opens the paper's Literature Note; "Create note" if none. Behaves like any property (show/hide/move/rename); omitted from Copy/CSV.
  - Embed `![[Figures.zotquery]]` shows default view; `![[Figures.zotquery#Yellow highlights]]` shows named view. Embed has same toolbar; change saves to the query file (every note embedding it sees it); "Open file" button opens in tab. Works in Reading view, Live Preview, hover popovers.
  - `this.item` in view filter (`filters: item == this.item`): in a Literature Note = paper named by `zotero-key` property. Paper's library outside Library scope setting: embed shows outside-library-scope warning. `this.item`/`this.attachment` without context (standalone tab, unlinked note): view shows suggestion where to open it.
  - Query block: code fence language `zotquery` with YAML (`views:` list with `type`, `name`, `from`, `filters`). Toolbar changes rewrite block text in the note (also via section embed or hover popover). If note text changed meanwhile: "save failed" message; reopen note.
  - Default Literature Note template puts a query block under the Annotations heading, showing the note's paper annotations; Literature Notes made with earlier version get the block at next update (STALE on next, #1687 did not edit this page: true only when they still have their managed region; the default block is written once at creation, outside any region); trashed Zotero paper shows no annotations there.
  - Annotation sidebar "more" menu (kebab): Sort (one property, either direction), Group by (color / Tag / none), Filter (opens filter editor for sidebar), Save as query file (only while sidebar shows an item).
  - Save dialog: Name, Folder, Records: "This item" (attachment the sidebar shows; with item but no attachment chosen, that item's annotations) or "Note item" (paper of each note that embeds the file; for a file embedded in many Literature Notes). File keeps sidebar sort, grouping, filters incl. colors, Tags, search text. Opens in a tab.
- Steps (procedural):
  1. Create: run New query file command, or right-click folder/file > New query file.
  2. Filter: Filter > Add condition > property/operator/value > combine (all/any/none, add group) > reorder/delete > check count.
  3. Sort: Sort > Add sort > property+direction > add tiebreakers > drag priority.
  4. Group: Group > Group by > order (A-Z/Z-A/Manual).
  5. Properties: Properties > check/drag > search/add path.
  6. Formula: Properties > Add formula > name `year` > expression `date.year` > Save.
  7. Display name: Properties > chevron on `formula.year` > type `Year of source`.
  8. Embed: type `![[Figures.zotquery]]` (optionally `#View name`).
  9. Query block: write `zotquery` fence.
  10. Save sidebar: kebab > Save as query file > name/folder > choose records > Save.

## how-to/query-zotero-library.mdx
- Title: How to query your Zotero library | Description: Use ZotLit Query to find papers, check files, count by tag or year, and export reading marks from the Obsidian CLI.
- Archetype (judged from content): Mixed(How-to + Reference). Recipe-style CLI how-to with embedded parameter and output-schema detail.
- Purpose: Reader runs `obsidian zotlit:query` commands to list/filter/count/export papers, files, annotations; lists exact names; cancels queries; uses the agent skill.
- Prerequisites stated: Obsidian desktop with ZotLit loaded; Obsidian CLI activated; run from a terminal; add `vault=<vault-name>` after `obsidian` when more than one vault is open (e.g. `obsidian vault=Research zotlit:query`).
- Product facts asserted:
  - VERIFY: Experimental (Callout warn): parameters, output schemas, diagnostic reports may change between releases.
  - `from` = items (default; papers/books/works), attachments (files and links e.g. PDFs, saved web pages), annotations (highlights, notes, images, ink).
  - Papers without PDF: count papers (items, inspect files); broken files: count files (attachments).
  - Quoting: `filter` value in single quotes with text inside in double quotes; `fields` and `group` in single quotes when they contain `[` `]`.
  - Success answer: `ok: true` + `rows` (or `groups` when grouped); read `warnings` before accepting an empty result; `truncated: true` = more matched than shown; default limit 100 rows; `limit=all` returns all.
  - Failure: `ok: false`; read `diagnostic.report`, follow its last line, rerun.
  - Filters match Collection paths and Tag names exactly, case-sensitive; list names with `zotlit:query-values kind=collections|tags match=<text>` (`match` = contains, any case). Answer: per-library entries with `library` (e.g. `personal`), `name` (e.g. My Library), `totalCount`, `values`. Collection path joins levels with `/`.
  - `collections.within("X")` includes subcollections; `collections.contains` matches one Collection only.
  - Unknown path (e.g. wrong case): zero rows, `ok: true`, `returnedCount: 0`, warning code `unknown-collection` with message and `suggestions`. If another library holds the path, suggestions also include a `library` value like `library=group:4815`; add it to read that library.
  - Tags: `kind=tags`; `library=all` lists tags of every library; each Tag value has `name` and `type` (`manual` or `auto`, auto = added automatically by Zotero).
  - Grouping: `group` gives one group per value with `value`, `count`, first rows up to `limit`; `totalCount` = matching records; `count` exact before limit. `fields='[]'` makes rows hold only the key. `[]` groups per list element; a paper with 2 tags counts in both groups so counts can exceed `totalCount`; no-tag papers form `null` group. A paper with two PDFs counts once in the `pdf` group.
  - Group examples table: papers per Collection inside "Query thesis" (`group='collections[]'` + `collections.within`); papers per file type (`attachments[].fileType`); files per file type (`from=attachments group=fileType`); papers per library (`group=library library=all limit=3`).
  - Mark counting: `from=annotations group=item.indexedKey sort=-dateModified limit=3 fields=text,item.title`; `limit` applies inside each group; `count` = marks on that paper.
  - `fileType` values: pdf, epub, web (snapshots and web-page links), other.
  - Missing linked files: `from=attachments filter='linkMode == "linked_file" && !exists' fields=item.title,path`. Papers without openable PDF: `attachments.filter(value.fileType == "pdf" && value.exists).isEmpty()`. `attachments[].path` returns one location per file, in the order of `attachments[].fileType`; a web link has `path` `null`.
  - Identity fields: `key` (Zotero key e.g. `ABCD2345`; two libraries may share a key); `indexedKey` (unique across libraries: `ABCD2345` in My Library, `ABCD2345g4815` in group 4815); `library` (`personal` or `group:<groupID>`). Select a paper's files by `item.indexedKey == "ABCD2345"`.
  - Formulas: JSON object in `formulas` (name -> expression); read as `formula.<name>` in fields, filter, other formulas. Rows hold `indexedKey` and `values` keyed by path (e.g. `formula.year`). Name rules: letters, digits, `_`, start with letter or `_`, case counts. Unused formula: `unused-formula` warning naming it. Formula mistake fails query: `diagnostic.code` e.g. `unknown-formula`, `diagnostic.location.path` names formula, `diagnostic.report` marks the mistake with carets. A per-record failure yields an error object with `code` and `message`.
  - Export: terminal answer holds at most 1 MB; `output=<absolute path of new file in existing folder>` writes the complete answer; terminal then shows counts and `file.path`; an existing file is left intact (use a new name each time).
  - `format=csv` or `format=tsv` (needs `output`; terminal answer is always JSON). Header row, then one row per result: Indexed Key, then fields in `fields` order; grouped query adds `group` column first; cells as text (creators `Ada Lovelace, Alan Turing`); columns named by field (`date.year`); item types shown by Zotero name (`journalArticle`).
  - Cancel: `id=<name>` on start (1-128 chars of letters, digits, `.`, `_`, `-`); `obsidian zotlit:query-cancel id=...` from a second terminal; answer `cancelRequested: true` if running; first terminal shows `Error: The query 'export-1' was cancelled by zotlit:query-cancel.` and unfinished export is removed; `cancelRequested: false` = already finished.
  - Agent skill `zotlit-query` (Claude Code, Codex, etc.) installed with other ZotLit skills; agent reads live guide and schema, lists exact Collection names, runs the query, reports counts with scope. `obsidian zotlit:query-guide` prints the full guide; `topic=group` prints one section.
- Steps (procedural):
  1. Choose `from` record kind.
  2. Run command with `filter`, `fields`, `limit`.
  3. Read answer (`ok`, `rows`/`groups`, `warnings`, `truncated`, `diagnostic.report`).
  4. (Exact names) `query-values kind=collections match=thesis`; use exact path in `collections.within(...)` filter.
  5. (Count) add `group`, `limit=1`, `fields='[]'`.
  6. (Export) add `output=`, optional `format=csv|tsv`.
  7. (Cancel) start with `id=`, run `query-cancel id=`.

- Title: How ZotLit Query works | Description: How ZotLit Query reads papers, files, and marks, and how filters, groups, and exact names shape the answer.
- Archetype (judged from content): Explanation
- Purpose: Reader understands datasets (items/attachments/annotations), query stages, null vs Error Values, `this` context, grouping semantics, the exact-name rule, and the agent guide/schema.
- Prerequisites stated: none.
- Product facts asserted:
  - VERIFY: Experimental (Callout warn), same wording as the sibling how-to.
  - ZotLit Query answers from the Obsidian CLI; one command `zotlit:query`; answer is JSON.
  - Three Query Datasets selected by `from`: items (paper/book/work: journal article, thesis, web page), attachments (file or link: PDF, EPUB, snapshot), annotations (mark: highlight, note, image, ink). `from=items` default. Standalone files and trashed records are outside all three.
  - Relations both ways: item has `attachments` and `annotations`; attachment has `item` and `annotations`; annotation has `attachment` and `item`. Such lists are Relation Lists. Paper `notes` lists child notes with title and dates; notes are not a dataset (`!notes.isEmpty()` finds papers with a child note).
  - Choose dataset by what you count (papers without PDF -> items; missing linked files -> attachments; highlights on one paper -> annotations selected by their paper).
  - Pipeline: Target Libraries -> filter -> sort -> limit -> fields -> rows. `library`: `personal`, `group:<groupID>`, list, or `all`; default = libraries in the Library scope setting. `filter` e.g. `tags.contains("to-read")`, may look through Relation Lists. `sort` e.g. `-date`. `limit` default 100, `limit=all`, `truncated: true`. `fields` e.g. `title,date.year`; `[]` reads per element (`attachments[].path`).
  - null = no data: missing field; calculation on null (`date.year + 1` on undated paper); empty text to `number()`/`date()`/`duration()`; index past list end.
  - Error Value = cannot compute although data is present: non-empty text unreadable by `number()/date()/duration()`; `<` across different types; wrong-type operand (list mixing texts and numbers); non-finite result (division by zero); argument out of range or non-whole index; date arithmetic leaving date range. Row form: `kind: "error"`, stable `code` (e.g. `unparseable-text`), `message`. Query view shows warning icon + tooltip; Copy/CSV write `Error: ` + message.
  - Filter treatment: Error Value propagates through every operator/method/function; as filter result is false (never selects); `!x` true when x is null or Error; Error equals nothing including itself so `!=` true; `isType("error")` true (`number(volume).isType("error")` selects papers with non-numeric volume).
  - Whole-query mistake (e.g. `title * 2`) stops the query before reading any record; answer is a failure naming the mistake.
  - `this.item`/`this.attachment` = Query Context supplied by caller; CLI params `this-item`, `this-attachment`; in Obsidian a query file/block takes it from the note showing it. Example `from=annotations filter='item == this.item' this-item=ABCD2345`. Missing context: failure naming the missing value.
  - Grouping: `group` counts per value; each group `value`, `count`, first rows up to `limit`; `totalCount`; `[]` multi-membership (tags, `collections[]`, `attachments[].fileType`); `null` group for no-value.
  - Exact names: Collection paths and Tag names match exactly incl. case; path starts at top-level Collection, joined by `/` (`Query thesis/Chapter 1`); `zotlit:query-values kind=collections match=thesis` then query; unknown path still runs, matches nothing, `unknown-collection` warning with closest paths and, if another library holds it, the suggested `library` value.

## concepts/how-templates-work.mdx
- Title: How templates work | Description: The three kinds of template document, how ZotLit finds them in the template folder, and the Liquid and Eta languages.
- Archetype (judged from content): Explanation
- Purpose: Reader understands template document kinds, discovery, manifest, languages, built-in defaults, and 2.1 conversion.
- Prerequisites stated: none.
- Product facts asserted:
  - Templates = Markdown files with embedded expressions, stored in one vault folder as template documents; the filename decides each one's role.
  - Callout info: Template Workbench CLI lets an agent edit/test templates against the Zotero library without the user writing Liquid/Eta.
  - Three kinds: Literature note profile `zotlit-profile.<slug>.md` (name, folder, properties, body, annotation format; e.g. `zotlit-profile.books.md`); Citation text `zotlit-citation.md` (every in-text citation; one per vault, exactly this name); Partial `zotlit-partial.<name>.md` (rendered by name from other templates; e.g. `zotlit-partial.authors.md`).
  - Profile doc = single authoring object for a literature note (name, properties, body, annotation format in one file).
  - Citation text is the one source for: citation suggester and command-palette insertions, annotation citations, citations inside imported Zotero notes. (NEW #1626: here "annotation citation" = `zt.citation` in the annotation template, which the new default annotation template prints after the quote; not the same thing as the "Annotation citations" setting / empty-text `[](zotero://…)` link in C.) Receives `zt.variant` = `main` or `alt`; `alt` comes from `Shift+Enter` or a trailing `/` in the suggester query; annotations and imported notes are always `main`.
  - Partials are shared by several profiles and the citation text.
  - Discovery: scan template folder for filenames starting `zotlit-`; flat (no subfolders); files without the prefix ignored (own Obsidian templates may share the folder). A `zotlit-` file that is not one of the three kinds nor a 2.1 file renders nothing and gets an "Unrecognized" row at Settings > Advanced > Template engine naming the file and the three valid names; e.g. `zotlit-citation.liquid.md` (citation text carries no language in its name).
  - Template folder: Settings > Advanced > Template folder, default `templates`; loading and file watching use it; a changed document recompiles immediately (no plugin reload).
  - Manifest: optional YAML (`---`, `language: eta`, `---`) then source, for citation text/partials; `language` is the only key; values `liquid` or `eta`; any other key = error. No frontmatter = Liquid; the file created for first-open citation text carries none. Language switch in Template Workbench View rewrites only the manifest key; source never translated. Profile document always carries a manifest (also holds name, folder, citation style).
  - Liquid: default, always active, data-to-text only (no files, network, system commands), safe to share/sync/install from community. Eta: JavaScript-based engine; arbitrary JS with ZotLit's own access; disabled by default; needs per-device "JavaScript templates" gate. An Eta document is inert while gate is off: not compiled, no fallback to built-in default; ZotLit names the skipped file and why.
  - Built-in defaults: citation text works with no file via a built-in Liquid default; settings row reads "Using default" until a document exists; opening the row creates the document from built-in text; reset moves the document to Obsidian trash. Literature notes: built-in Default profile, customized into a document of your own.
  - 2.1 conversion: 2.1 files still load and render: `zotlit-note.liquid.md`, `zotlit-content.liquid.md`, `zotlit-annotation.liquid.md`, `zotlit-filename.liquid.md`, the two citation files, any other `zotlit-<name>.(liquid|eta).md` partial. Conversion is offered in the setup banner above the Library View ("template conversion" title) and as a reminder row at the top of settings with an action; one pass folds note+content+filename+annotation into one profile document, the two citation files into one citation text, every remaining file into its own partial. Before writing, renders both citation variants and note, update, filename, annotation output and compares byte for byte with old output; a mismatch converts nothing. Old files go to Obsidian trash (recoverable).
  - Shadowing: when both `.liquid.md` and `.eta.md` exist for one 2.1 name, Liquid wins and Eta is ignored regardless of the JS gate; conversion trashes both.
