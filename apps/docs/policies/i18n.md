# i18n

- Source site-specific web copy, including accessibility labels and SEO/OG text, from `docs_*` keys in [the root message catalogs](../../../messages/en.json), configured by [project.inlang](../../../project.inlang/settings.json). Use `/paraglide-i18n` for message syntax and `/i18n-ui-text` for wording.
- Import messages from `@/paraglide/messages.js`; call `m.docs_*()` when rendering or constructing a response so the locale is resolved at use time. Edit the catalogs; the Vite plugin regenerates the facade during dev and build. Turbo checks use the generated output of the site build.
- **Shared Workbench UI:** Supply the site's generated message functions through the shared messages context. Each host compiles `workbench_*` from the root catalog and resolves translations through its own runtime; the shared package carries the typed message contract. See [ADR 0044](../../../docs/adr/0044-workbench-ui-is-headless-and-hosts-own-the-look.md).
- Keep each sentence in one message with named inputs. For embedded links, code, or dates, use [Message](../src/components/message.tsx) with named React slots; [DocsLastUpdated](../src/components/docs-last-updated.tsx) shows the call pattern.
- Keep authored MDX and frontmatter under `content/` in Fumadocs' content localization workflow. Generated template-reference prose belongs to that content pipeline. Plugin UI references follow [UI Labels](ui-labels.md).
- Preserve the `docs_` boundary: Obsidian excludes that prefix; Zotero compiles its own namespace. Keep the artifact-exclusion checks in [the Obsidian compiler tests](../../../packages/obsidian-i18n/src/compiler.test.ts) and [the Fluent tests](../../zotero/scripts/vite-fluent-plugin.test.ts) passing.
- Let the Paraglide Vite plugin own message generation. Vite config dependencies load generated messages when assets are rendered, after the plugin runs. The site build caches `src/paraglide/` alongside the site output; typecheck, lint, and tests depend on that build.
