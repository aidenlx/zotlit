# Chinese translation workflow

## Current proof of concept

The site uses native Fumadocs localization. English uses unprefixed URLs; Simplified Chinese uses `/zh-CN`. English is the fallback when a Chinese file is missing. See [locale configuration](../src/lib/i18n.ts) and [content loaders](../src/lib/source.ts).

This proof of concept adds English-copy Chinese placeholders. It adds no new Chinese translations:

- 88 `.zh-CN.mdx` files: 85 pages and 3 included partials
- 7 `meta.zh-CN.json` files for navigation
- 105 existing English `docs_*` messages copied into the Chinese catalog, plus the new `docs_locale_fallback` message

The three original Chinese redirect-notice messages remain. Each root catalog now has 109 `docs_*` keys. Existing Chinese `workbench_*` messages remain intact. Site-specific copy stays in `docs_*`; shared Workbench copy stays in `workbench_*`. See the [i18n policy](../policies/i18n.md).

## Translate and approve

1. Translate the matching `.zh-CN.mdx` file under `content/docs`, `content/blog`, or `content/changelog`. Review the title, description, body, image text, and any generated prose shown on the page. Preserve code, API names, stable anchors, and working links.
2. Translate its included partials. Chinese pages must include the actual Chinese files, such as `<include>./_field-aliases.zh-CN.mdx</include>`. Check nested includes too.
3. Translate navigation labels in the corresponding `meta.zh-CN.json` files. Preserve the page order and identifiers.
4. Have a human review each translated page, partial, and metadata file. After approval, remove its `translationStatus: placeholder` frontmatter field or JSON `translationStatus` key.
5. Translate and review the site's `docs_*` messages in [the Chinese catalog](../../../messages/zh-CN.json), using [the English catalog](../../../messages/en.json) as the source. Check the rendered UI, including accessibility and SEO text. After approval, remove the `ui` key from [`i18n/zh-CN.json`](../i18n/zh-CN.json) while preserving the `fumadocs` dictionary.

Marker removal records human approval. Any remaining marker key keeps that surface unapproved, even if its value changes to `translated`. There is no automatic language or translation-quality detection. When approved content changes and needs another review, restore its placeholder marker.

The template-data reference needs an additional review. Its [`ContractTable`](../src/components/contract-table.tsx) components still render prose from the shared English contract intermediate representation. Translate that generated surface as well as the Chinese MDX and partials before approving the Chinese reference page.

## Readiness and page metadata

The [translation scan](../src/lib/translation-scan.ts) reads actual Chinese source files. A page is ready only when its marker is absent and all of its actual Chinese Markdown includes are recursively approved. A missing file, English include, or unapproved partial keeps the page unapproved. Fumadocs fallback content does not count as a translation.

- Home, community, and Workbench readiness use the global UI approval marker.
- Blog and changelog listings require UI approval and an approved Chinese counterpart for every English post in that section.
- Sidebar metadata markers appear in release diagnostics. They are not standalone pages and do not determine individual page approval.

Until approval, a Chinese page reports English content language, uses the English canonical URL, and has no Chinese alternate link. Placeholder Chinese pages use `noindex, follow`. Approval gives the page Chinese metadata, its Chinese canonical URL, and reciprocal English/Chinese alternate links. Workbench keeps its deliberate `noindex` after UI approval. See [locale state](../src/lib/translation-state.ts) and [page SEO](../src/lib/seo.ts).

## Before production

Run from the repository root:

```sh
pnpm --filter @zotlit/docs check:translations
```

The [readiness command](../scripts/check-translations.ts) fails for any marked page, partial, metadata file, or UI, and for any missing Chinese counterpart. Failure is expected for this proof of concept. Run this check explicitly; deploy commands do not run it automatically. Finish human review and clear the reported blockers before production deployment.

This prerequisite matters for existing links: known V1 Chinese permalinks have permanent `308` redirects to their Chinese V2 pages. Complete those translations before production. V1-only items continue to redirect to the legacy site. The [redirect table](../src/lib/v1-redirects.ts) owns this behavior.

### Native UI strings and dates

`i18n/en.json` and `i18n/zh-CN.json` contain all 46 static English translation
keys used by the installed Fumadocs UI. The Chinese dictionary is an exact English
copy. Translate its `fumadocs` values along with the Paraglide catalog before
removing the Chinese file's `ui` marker. Keep the English keys stable, including
interpolation tokens such as `{url}`. The native provider reads this dictionary;
no component edits are needed to activate its translated values. Review this
inventory when upgrading Fumadocs. Visible publication dates use the requested
locale; shared English OG cards retain their existing English date formatting.
