Library view design

A read-only library browser inside Obsidian. Not a replacement for Zotero's main window: it keeps three familiarity anchors so a Zotero user is never lost, and redesigns the rest around the four things an academic actually does here while writing.

Jobs it serves

  • Resume · where was I
  • Find · that paper by X about Y
  • Browse · what do I have on this
  • Pick · what do I cite or read next

Familiarity anchors keep

  • Tree on the left: My Library, collections, groups
  • Rows show title · creators · year
  • Disclosure triangle reveals files, notes, highlights

Not here, on purpose

  • No add, edit, delete, move. Zotero owns its data.
  • No trash, unfiled, duplicates, tag pane
  • Column grid only as an alternate layout

1 · Default state: Recent, first open

Opens from the ribbon, a command, or on startup when it was open last time. Search has focus. "Recent" mirrors Zotero 9's Recently Read (per-attachment lastRead) and adds Obsidian usage (#1532, #1533). Nothing is ever empty on first run.

3 · What it is made of

The centre is the existing Query View, hosted without a file, the same way the annotation sidebar already hosts one. The tree and the reading card are new. The "Papers" layout is new; Table stays as an alternate.

How a click becomes a query

tree.select("Thesis/Chapter 2")   →  filters.all  = collections.within("Thesis/Chapter 2")
facet.toggle("Unread")            →  filters.view += lastRead == null && annotations.isEmpty() && vault.literatureNote == null
search.type("rougier fig")        →  SearchItems(scope) → keys  →  filters.search = indexedKey in [...]   (or search("rougier fig"), see Q2)
sort                               →  -lastActivity   = max(lastRead, dateModified, childNotes[].dateModified)

4 · Zotero habit → what happens here

What a Zotero user tries Here
Click a collection on the left Filters the list; counts match Zotero keep
Type in the search box Searches the whole scope by title, creator, year, tag. One mode plus tokens changed
Click the disclosure triangle Files, notes, highlights inline keep
Double-click a row Opens the PDF in Obsidian with Zotero's highlights keep
Look right for the item pane Reading card: abstract, your highlights, actions. Shown on selection changed
Sort by clicking a column header Sort menu in the list header; headers in Table layout changed
Drag a row to a collection Nothing; cursor says read-only. Drag into a note inserts a citation changed
Open "Recently Read" "Recent" node, same semantics plus Obsidian reads keep

5 · Open questions

Q1 · Where does the tree live?

A · Same leaf recommended
Three panes in one main tab, as in Zotero. Simple state, one thing to open, resembles Zotero.

B · Left-sidebar leaf
Tree drives whichever Library tab is active, like the file explorer. Always visible, but two leaves to manage and no Zotero resemblance.

Q2 · How does search reach the engine?

A · Key set recommended first
Worker's SearchItems ranks, the view filters by indexedKey in [...]. No engine change; not expressible in a query file.

B · search("…") filter function
Engine-level, so a query file can carry a search. Needs ranking inside the engine. Can follow A.

6 · Phases

Phase 1
Fileless host · ribbon + command · tree with counts · Recent node (#1532, #1533) · Papers layout · whole-scope search · row context menu · persisted state. Replaces Zotero for browsing and reading.
Phase 2
Reading card · facets (needs vault-side filter decision from #1531) · "Save as query file".
Phase 3
Pin a query file as a tree node · tag tokens with completion · Welcome collapses into a banner above this view.
