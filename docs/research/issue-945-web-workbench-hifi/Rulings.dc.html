Issue 945 · whole-surface design
One surface, from six pictures
Six accepted trials and the #938 frame, carried into one Template Workbench.
Item 1 · Composition
1.1

The middle column holds one open pane; the others are strips. The three panes — note body, Properties, Details — are always mounted; opening one folds the others into one-line strips, and the result column never moves.

1.2

The field rail is the explorer, in value-first form. One panel, open by default, shows name and this paper's value on every row with a filter box; a row click inspects Insert, Copy, and the snippet kind, Insert primary.

1.3

The header carries the surface, the document, and the paper. Row one holds the wordmark, connection state, unsaved state, Undo, and Save; row two holds the Profile name, its lede, the "Showing" paper picker, and the Advanced switch. There is no Revert — Undo is the way back.

1.4

The result column is the note as a paper sheet. Controls sit above it — preview status, the Note / Markdown toggle, the operation picker — and Problems sits below it on every screen, empty by default.

1.5

The responsive fallback is Direction C. Under 780 px the columns stack in source order: fields collapse above the editor, Editor / Preview buttons switch the middle and result columns, and the preview keeps its own scroll.

Item 2 · The final section everywhere
  • The note body shows "How one highlight looks" at the first render call and a link at every later call; the box edits the final section of the file, fixed at the end.
  • The Details strip and the Properties pane keep a pointer: "How one highlight looks — edited in the note, where the highlights appear · Show me."
  • With no render call, the pointer opens the section in Advanced instead.
  • Advanced shows the whole file with the header line highlighted and a section bar: "Annotation Section · line 24 · through end of file · Remove section." Repair appends the header.
  • Problems carries the parser's own recovery sentences — missing, duplicate, and unknown sections; a broken Managed Block; an invalid manifest; an unknown partial — and names the entry position and key for Properties engine errors.
Item 3 · Words and owned flows
3.1

The surface is the Template Workbench, and "template" is a printed word. The header names it on every screen; the lede reads "The template ZotLit uses to write every literature note." "Note layout" is retired, and the Obsidian glossary entry now covers both hosts — the agent-facing CLI in Obsidian and the human-facing web surface at /workbench. The other beginner labels from #938 stand; the surface still never prints Profile, manifest, frontmatter, Managed Block, or partial. "Reusable piece" is dropped — partials have no control here.

3.2

The web surface owns three flows. Open, Save, and the unsupported-language handoff; Switch, Create, Share, and Delete stay with Obsidian. A flow prototyped on the web ports as the shared editing core — editor extensions, source mapping, the Properties and Details forms — while dialogs, file access, and transport stay host-owned.

What the trial assets left behind
  • The {% annotation %} block layout (#938, #933) is replaced by the final section everywhere on this canvas.
  • #938's five-column Properties table becomes #934's entry list with the keyless "Several properties" entry; "If it exists" gains Append.
  • #938's vault-path banner and JavaScript-off notice become the connection state and the Obsidian-only language row.
  • #935's compact one-line Note name editor replaces #938's taller one; the live result sits beside it.
  • The trials' Run Eta, JavaScript gate, and scenario controls are not part of the web surface.
