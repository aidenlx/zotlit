# ZotLit Query is one command over three Query Datasets with Relation Lists

> Amended 2026-10-10: `zotlit:query-values` lists exact Collection paths or Tag names and types per Library, including empty Collections, with optional substring matching and per-Library limits. A literal path in `collections.contains` or `collections.within` that exists in no Target Library produces an `unknown-collection` Query Warning with nearby paths and, when found elsewhere, a Library selector. This gives researchers a discovery command while the live schema response stays small. Unreleased contract version 3 remains 3.

ZotLit Query is one Obsidian CLI command, `zotlit:query`, with `from=items|attachments|annotations` naming the Query Dataset and `items` as the default, beside `zotlit:query-schema`, `zotlit:query-guide`, and `zotlit:query-cancel`. Attachment Query is the third Query Dataset: the non-trashed Attachments of top-level, non-trashed Items, with standalone Attachments outside every universe. Each dataset reaches the others through Relation Lists in both directions: an Item carries `attachments` and `annotations` as lists of records, an Attachment carries `item` and `annotations`, and an Annotation carries `attachment` and `item`. The boolean `attachments` of an Item is gone; an empty list is falsy, so `!attachments` keeps its meaning. A filter navigates Relation Lists to any depth with the list methods the language already has, and a Projection Path reaches an element across a list with the explicit `[]` of jq, as in `attachments[].path`; array access still never vectorizes implicitly. A record projected whole is the fixed summary of its dataset. `library` is a field of every dataset. The CLI Contract moves to version 3 with no aliases for the former names.

Selection is the filter alone: `item=` and `attachment=` are gone, an Indexed Key equality lowers to a candidate set as `key ==` does, and a key that names a Library outside the Target Libraries gives a Query Warning rather than widening the scope. `fields` and `sort` take comma lists, split only outside quotes and brackets, with the JSON-array form still accepted, `fields=[]` for identity-only rows, and `-field` for descending order. One `library` argument takes `personal`, `group:<groupID>`, a comma list, or `all`. `group=<scalar path>` returns `groups` of `{ value, count, rows }` ordered by value with null last, applies `limit` inside each group, reports `totalCount` before the limit, and rejects a list path. Sortable Fields stay scalar fields and parent scalar paths; a value derived from a Relation List is projection only. One schema catalog describes the three datasets, their relations, and the shared functions. One guide has the topics `datasets`, `filter`, `fields`, `sort`, `group`, `results`, `schema`, and `cancel`.

The engine keeps one planner, one diagnoser, and one execution path over one descriptor per dataset (ADR 0066), the superset rule for candidate sets, and the responsiveness invariants. A conjunct of the form `<relation>.filter(<pred>).length > 0` whose predicate has a lowerable leaf becomes a candidate set through the parent join under the same cap; `isEmpty()`, negations, and higher counts use the scan. Relation Lists are hydrated only when a filter, a sort, or a projection names them.

Why: the two command families, the boolean `attachments`, and the one-way `item.` prefix were the assumptions of the first route, and an evaluation of 28 research questions on one sample Library showed the cost. The proposal answered 26 in one call; the version-2 contract answered 11 in one call with no caller-side work, needed caller-side merging, counting, or guessing for 11, and could not ask 4 at all, every one of them an Attachment question. The comma-list arguments carried the same information with 134 quote characters where the JSON arrays needed 354. Every borrowed form has an established home: SQL for `from`, `limit`, and `group`; Obsidian Bases for the filter language and list methods; JSON:API for `sort=-field`; `gh --json` for comma lists; jq for `[]`. The prototype that produced these numbers is on the branch `prototype/query-cli-redesign` under `packages/item-query/prototype-query-cli/`.

Considered and rejected: keeping the two commands and adding a third for Attachments, which triples the names an agent learns for one engine; `item=` and `attachment=` as sugar beside the filter, which keeps the key-versus-Library conflict rule and a second selection grammar; an Indexed Key that widens the Target Libraries, which makes `libraries` in the envelope depend on the filter text; implicit vectorization of a Projection Path over a list, which ADR 0064 excluded and `[]` makes explicit; `sort=-annotations.length`, which hydrates a relation for the whole universe before the top-K and waits for its own measurement; an output format argument, a saved query file in the `.base` shape, and a `search=` argument over the item-lookup index, all deferred as later work rather than rejected.

This decision amends ADR 0064 (the field-oriented contract: Relation Lists of records, the Attachment dataset, `library`), ADR 0065 (the CLI: the command names, the comma-list arguments, one `library`, `group`, contract version 3), and ADR 0066 (the deep module: three datasets).
