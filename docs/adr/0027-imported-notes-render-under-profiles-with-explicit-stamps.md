# Imported Notes render under Profiles with explicit stamps

Spec #865 kept Imported Notes outside the Profile system (one global folder; "Profiles for Imported Notes" out of scope). The #876 grilling overturned that: an Imported Note is created and re-imported under a Literature Note Profile, and the Profile — not vault-global settings — supplies its import folder, colored-highlights and annotations-as-template behavior, display-layer citation style, and annotation template.

**Explicit stamps, no implicit inheritance.** Every Imported Note carries the same `zotlit-profile` system frontmatter stamp as a Literature Note. The stamp is written once at creation from the creation context — a side-effect import uses the in-flight operation's Profile; an explicit import of an item-attached note copies the parent's Literature Note stamp; a standalone note (or an attached note whose item has no Literature Note) gets the default Profile — and is re-emitted on every whole-body overwrite. After creation, writes follow the stamp: changing the item's Profile changes nothing about its Imported Notes, and an absent stamp means the default Profile, never "ask the parent." The considered alternative — a dynamic chain (own stamp → parent's stamp → default) resolved at every write — was rejected as too implicit: a note's behavior could change because a *different* note was edited. The interactive Profile switch on a Literature Note may offer "also switch this item's imported notes" as an opt-in; headless surfaces follow stamps, and no import surface accepts an explicit Profile parameter.

**The default Profile is the one inheritance root.** Profile bindings widen to five sparse keys (literature folder, citation style, import folder, colored highlights, annotations-as-template); a Profile that leaves one unset inherits from the default Profile, whose bindings record is total. The vault-global settings keys behind all five retire through a silent settings-shape migration on load — users configure note behavior in exactly one place. The import folder applies at create time only; re-import overwrites in place and never relocates a file.

**The annotation template moves into the Profile document.** A zero-or-one `{% annotation %}` … `{% endannotation %}` block in the Literature Note Template document's body replaces the global `annotation` slot: isolated render scope, Annotation Root data, stripped entirely from create-time body output, rendered only on demand (drag-insert resolves the annotation's parent item's stamped Profile; Annotation Paragraph subsuming uses the Imported Note's Profile). A document-scoped block was chosen over a designated global partial so the template travels inside the Pack and the flat partial namespace ruling stays intact. The prompted one-shot converter folds an ejected `zotlit-annotation.*.md` into the default Profile's document with byte-identical verification; `cite`/`cite2` remain the only vault-global template slots.

ADR 0001 stands: Imported Notes are mirrors with whole-body overwrite — the Profile parameterizes the conversion, not the update contract. This extends ADR 0025's document format with the Annotation Block. Decided in #876 on map #835; consequences flow to #877 (Workbench annotation commands become document-aware) and #878 (the Templates settings surface shrinks to `cite`/`cite2` plus engine config).
